# canter-store

同步的 Unix 文件存盘库，根目录由调用方传入；没有默认 HOME 路径。
`Store::create(id, settings, timestamp)` 在根目录的 `.creating-*` 临时目录建好空模型历史和
第一条 `session.updated`，文件及目录同步成功后再改名为正式 id。
失败清理本次创建的目录；若发布后的根目录同步失败，也撤回本次发布。
`Store::open` 重放历史，没有任何已提交事件时按不存在处理；
`SessionWriter::append` 编排下一个序号，先验证归并，再写入并同步磁盘，最后更新内存快照。
重放和单条追加使用原地归并，不逐条复制整个快照。
`Store::list` 返回 id、工作目录、名字、状态、更新时间和最后序号，按更新时间倒序排列；
跳过不合规目录名、临时目录和单个损坏/读失败的会话，根目录本身读取失败仍报错。

```text
<root>/                 0700
  <session-id>/         0700
    events.jsonl        0600，一行一条公开协议事件
    model-history.jsonl 0600，一行一条模型历史，不发给客户端
```

会话 id 仅允许 1–128 个 ASCII 字母、数字、连字符和下划线。
`Store::new` 创建根目录或将调用方指定根目录的权限收紧为 0700；
请传入专门用于 canter 的目录。测试始终使用临时目录。
本包不接收或持有环境变量，不再创建或读取 `private.json`；已有旧文件不迁移。
环境由调用方在创建或恢复时重新交给内存中的执行器。

写入者用 Rust 标准库 `File::try_lock` 对事件文件持有排他锁，句柄释放时解锁；
该会话锁也保护模型历史写入，重复打开立即返回 `StoreError::Locked`。
列表读取和 `Store::events_after(id, seq)` 不拿写锁、不修改文件；后者返回严格大于 seq
的已提交事件。二者和恢复共用 JSONL 边界处理，仍校验会话 id 和连续序号。
只支持所有写入者遵守该锁的用法；不要替换一个仍被打开的事件文件。

换行符是事件提交边界。读取时只重放以换行结尾的完整行，最后一行没有换行则跳过，
即使它截断在 UTF-8 字符中间。写打开时在持锁状态下截去未完成尾行，再追加到同一文件；
完整行里的坏 JSON、错误会话 id 或不连续序号会报错，不悄悄丢掉中间历史。
写入或同步失败后句柄拒绝继续写，调用方须关闭并重开恢复。

`SessionWriter::append_batch` 接收 `(EventPayload, timestamp)` 序列，整批先验证，
只写一次缓冲区、同步一次磁盘，成功后提交内存快照并返回所有事件及其连续序号。
校验失败不写入任何前缀。批量预检仅克隆一次快照，随后逐条原地归并；单条 append 不克隆。
磁盘提交边界仍为每行，批量不是文件系统事务。成功返回的事件均已同步磁盘。
单条 append 在 macOS 上可能阻塞数毫秒；服务端应在阻塞线程里调用这些同步接口，
把短时间内的文字/命令增量合成一批，不能放在异步运行时的执行线程上逐条刷盘。

`SessionWriter::append_model_history<T: Serialize>(&entry)` 原样存一条模型层记录，
`Store::model_history<T: DeserializeOwned>(id)` 按调用方的类型读回；不依赖 canter-model。
条目结构和模型上下文的恢复规则留给第 4 件，本包不从显示事件反推模型历史。
模型历史与公开事件共用半行跳过/持锁截尾规则，但互相独立，不消耗事件序号；
本包不提供跨两个文件的事务。调用方负责决定记录顺序，私有记录不能通过 SSE 发送。

存盘层不处理 HTTP 请求竞争、输入排队或会话业务状态转换；调用方负责产生对应事件，
例如批准只处理一次、完成轮前解决待处理批准、PATCH 后写完整 `session.updated`。
公开设置通过事件更新。
