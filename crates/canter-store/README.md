# canter-store

同步的 Unix 文件存盘库，根目录由调用方传入；没有默认 HOME 路径。
`Store::create` 建会话并写入第一条 `session.updated`；`Store::open` 重放历史；
`SessionWriter::append` 编排下一个序号，先验证归并，再写入并同步磁盘，最后更新内存快照。
`Store::list` 返回 id、名字、状态、更新时间和最后序号，按更新时间倒序排列。

```text
<root>/                 0700
  <session-id>/         0700
    events.jsonl        0600，一行一条公开协议事件
    private.json        0600，仅含会话工作目录和环境变量
```

会话 id 仅允许 1–128 个 ASCII 字母、数字、连字符和下划线。
`Store::new` 创建根目录或将调用方指定根目录的权限收紧为 0700；
请传入专门用于 canter 的目录。测试始终使用临时目录。
`PrivateSessionConfig` 不实现 Debug，也不参与协议类型导出。

写入者用 Rust 标准库 `File::try_lock` 对事件文件持有排他锁，句柄释放时解锁；
重复打开立即返回 `StoreError::Locked`。列表读取不用写锁，不修改文件。
只支持所有写入者遵守该锁的用法；不要替换一个仍被打开的事件文件。

换行符是事件提交边界。读取时只重放以换行结尾的完整行，最后一行没有换行则跳过，
即使它截断在 UTF-8 字符中间。写打开时在持锁状态下截去未完成尾行，再追加到同一文件；
完整行里的坏 JSON、错误会话 id 或不连续序号会报错，不悄悄丢掉中间历史。
写入或同步失败后句柄拒绝继续写，调用方须关闭并重开恢复。

存盘层不处理 HTTP 请求竞争、输入排队或会话业务状态转换；调用方负责产生对应事件，
例如批准只处理一次、完成轮前解决待处理批准、PATCH 后写完整 `session.updated`。
私有配置在创建后保持不变；公开设置通过事件更新。
