# canter-tui

canter 的终端客户端：对话、批准框、会话列表、断线重连。下面写欢迎头、快捷键弹框、往上翻、输入框里的补全、选字和复制、对话里搜索、可点的链接、对话里的空行和状态行、工具卡片、diff、Ctrl+O 展开和思考、表格、代码块的画法和界面的颜色。

`/context` 按提示词顺序逐段显示 System prompt、Model notes（模型家族补充，非空才显示）、
Global AGENTS.md、Skills、Project AGENTS.md（每个文件一行）和 Environment，空段不显示。
Environment 是会话打开时固定的目录、仓库根、系统/架构和本地日期/时区。
各段估算包含标签和段间空行，System prompt 包含消息开销，合计等于整条系统消息的估算。
其后显示工具、压缩摘要、历史消息和剩余容量；查询沿用已装入的上下文，不重读文件。
结果在输入框上方弹框显示，不写进对话区：第一行 `Context …`，中间各段，最后两行说明和 `Esc close`。
数字是打开那一刻查到的，开着时不跟着变；Esc 或 Enter 关掉，对话区不留任何一行。
开着时按键归弹框（Ctrl+C、Ctrl+D 也关掉），输入框里的草稿留着，关掉后接着打。
窗口放不下时先让对话区让出地方，还放不下就让中间各段跟着 ↑/↓ 滚，上下写 `↑ N more` / `↓ N more`，
第一行、说明行和 `Esc close` 一直留着。查询失败（比如会话还没打开）照旧在对话区提示一行，不弹框。

`/files`、`/diff`、`/mcp`、`/skills` 的结果也这样弹框，打开、关闭、按键、草稿和放不下时的滚动都和 `/context` 一样。
第一行是标题（加粗）加灰色的数量摘要，节之间空一行，节标题加粗，次要信息灰色，最后一行 `Esc close`。

- `/files`：`Read`、`Changed by canter`、`Git status · <分支>` 三节，空的节写 `(none)`，不在 git 仓库里写 `(not a git repository)`。
  Changed by canter 每行前写 added / modified / deleted，一个文件改过几种用 ` / ` 连起来。
  有上游时分支名后面灰色写上游和 git 的 ahead / behind，比如 `Git status · main  origin/main · ahead 1`。
  Git status 把 git 的两位代码写成词，词那一栏对齐：modified（黄）、added（绿）、deleted（红）、renamed 和 untracked（灰）、
  conflict（红加粗；`U`、`AA`、`DD`）。只暂存了的后面灰色写 `staged`，暂存后又改过的写 `partly staged`。
  最后一行说明：`Edits made through shell commands only show up under Git status.`
- `/diff`：会话目录所在 git 仓库未提交的改动，标题 `Diff`，分 `Staged`、`Unstaged`、`Untracked` 三节，没有内容的节不写。
  diff 每个文件一行 `路径  +a −r`（新建、删除的后面灰色写 `new`、`deleted`），下面照对话里的 diff 画（行号、底色、语法色），
  不折叠；没有文本改动的文件（二进制、只改了权限）灰色写 git 的那句话；未跟踪的只列文件名，不读内容。路径相对仓库根。
  git 照 `/review` 收集本地改动的办法跑（同一份代码，`src/git.rs` 的 `local`）：关掉外部 diff、textconv、fsmonitor、hooks
  和仓库配的过滤器，暂存加未暂存最多 256 KiB、未跟踪列表最多 32 KiB，超了截断，最后写黄色
  `Truncated at 256 KiB; run git diff for the rest`（列表是 `Untracked files truncated at 32 KiB; run git status for the rest`）。
  在后台跑，最多 15 秒，跑完才弹框，界面不卡。不在 git 仓库里写 `Not a git repository`，没有改动写 `No uncommitted changes`，
  git 出错红色写 `git: <出错原因>`。
- `/mcp`：第一行 `MCP  N services · M tools`。每个服务一行，名字一栏对齐：连上了是绿色 `●` 和灰色的 `connected · N tools`，
  没连上是红色 `○` 和 `disconnected`，下一行写出错原因。工具只写短名，两个空格隔开，铺满宽度再换行，
  比整行还长的名字单独一行、截断；warnings 灰色写在服务下面。最后一行 `Tools are called as mcp__<service>__<tool>.`；
  没配服务时写 `No MCP services configured.`
- `/skills`：第一行 `Skills  N · global X · project Y`，按 Global（`~/.agents/skills`）、Project（`.agents/skills`）分节，
  没有的节不写。名字用强调色，不给模型用的在同一行灰色写 `not for model`；描述另起一行，灰色，最多两行，超出用 `…` 截。
  没技能时写原来那四行说明：两个目录放在哪、放好后重新打开会话。

## 批准框

需要批准时依次显示：1 `Allow once`、2 `Allow for this session …`、3 `Decline`、
4 `Decline and say what to do instead`、5 `Decline and stop`。
旧服务端没有提供第 4 项时隐藏它，`Decline and stop` 仍是第 4 项。

用 Enter 或数字 4 选「拒绝并说明」，框内切到 `What to do instead:` 输入行。
打字、粘贴都合成一行；非空白时 Enter 交出说明，空着 Enter 不提交；空着按退格或 ↑ 回到选项。
Esc 照旧打断本轮，300 毫秒的按键保护照旧。拒绝说明随工具结果交给模型，本轮继续；
对话里 declined 卡片下用暗色显示这句话，显示前去掉控制字符，重开会话及其它终端也能看到。

## 欢迎头

每次打开 canter（新会话、接着旧会话、`/new`、`/resume` 换过去的会话），对话最上面先画欢迎头，不画框：

```
        ▄▄█▄▄█▄    canter 0.1.0 · 37489fe
       ███  ████   ~/Developer/personal_projs/canter
▄▀▀▄▄▄▄████████▀   ? keys · /help commands · @ files · Ctrl+F find · Ctrl+O more
   █▀█▀▀▀█▀█       Shift+Tab permissions · Esc interrupt · Ctrl+C quit
```

- **左边**一匹像素小马，16 × 8 像素，一个格子画上下两个像素（`▀`、`▄`、`█`；上下颜色不同时上半用前景色、
  下半用背景色），占 16 列 4 行。颜色见「颜色」。
- **右边**空 3 列，四行字：`canter`（加粗）和版本行；会话的工作目录（家目录写成 `~`，太长按目录从中间省略，见「工具卡片」的「长路径」）；
  两行常用快捷键。后三行暗色。模型、思考档位、权限模式在底下的信息行，这里不重复。
- **版本行**是 `<版本号> · <提交号>`，提交号是编译时 git 的短提交号，工作区有已跟踪文件没提交的改动时后面加 `-dirty`；
  编译时拿不到 git（不在 git 仓库里、没装 git）只写版本号。由 `canter` 包的 `build.rs` 算一次，
  `canter --version`（`-V`）打印的是同一行：`canter 0.1.0 · 37489fe`，打印完就退出，不连服务端。
  编译脚本在提交、切分支、暂存变化后重跑；只改了文件还没暂存时，`-dirty` 要等下一次这类变化才算进去。
- **窗口窄**：小马加第一行放不下时只显示四行字，顶格；快捷键放不下就从后往前少显示几个，不折行。
- 它是对话的第一段，跟着对话往上滚，不常驻屏幕；接着旧会话时往上翻到头才看得到。改窗口宽度、Ctrl+O、`/rewind` 后照样在最上面。
- 只画在这个终端里：不进会话存档，不发给模型。拖选复制只复制右边的字，小马不复制；Ctrl+F 搜得到右边的字，搜不到小马。

## 快捷键弹框（`?`、`/help`）

输入框空着时按 `?`，或者跑 `/help`，在输入框上方打开 `Help` 弹框，和 `/context` 同一种：不写进对话区，
↑/↓ 滚、放不下时上下写 `↑ N more` / `↓ N more`，Esc 或 Enter 关掉（Ctrl+C、Ctrl+D 也关），草稿留着。
这一轮在跑时也能打开。输入框有字时 `?` 照常打进去；`/` 命令列表、`@` 文件列表、批准框、提问框、搜索框
或别的弹框、选择框开着时 `?` 照它们自己的按键，不打开。

内容按节分，每节标题加粗，键用强调色、说明灰色，前四节的键对齐成一栏：

- `Input`：输入框的键，包括发送、换行、`/`、`@`、Tab 补全、Ctrl+V 贴图、按词编辑、Ctrl+A/E/K/U、Ctrl+C、Ctrl+D、`?`，
  还有一句大段粘贴会收起成 `[Pasted #N]`；
- `Conversation`：Esc（打断、撤回刚发的）、PgUp/PgDn、滚轮、End、Ctrl+O、Ctrl+F、Shift+Tab、拖选复制、双击三击、单击链接；
- `Approvals and questions`：批准框、提问框的键；
- `Find`：Ctrl+F 搜索框里的键；
- `Commands`：每个 `/` 命令和它的说明，照命令列表的顺序，命令名另对齐一栏。

快捷键写在 `src/help.rs` 的一张表里，弹框从这张表画；改了按键要跟着改这张表。

## `/statusline`

`/statusline` 在输入框上方打开一个选择框，选底下两行状态栏显示哪几项、什么顺序、哪些放第二行：

```
 Configure status line
 Space toggle · ←/→ move · Enter save · Esc cancel

 › [x] model        deepseek-v4-pro
   [x] thinking     think high
   [x] permission   Always ask
   [x] cost         $0.12
   ─── line 2 ───
   [x] directory    ~/src/canter
   [x] branch       (main)
   [x] context      ctx 12% 120k/1M
   [x] cache        cache 95% (last 98%)
   [ ] tps          32.5 tok/s
   [ ] version      0.1.0 · a3b8fe7
   [ ] session      会话名字

 Preview
  deepseek-v4-pro · think high · Always ask · $0.12
  ~/src/canter (main) · ctx 12% 120k/1M · cache 95% (last 98%)
```

- **项**：model、thinking、permission、cost、directory、branch、context、cache、tps、version、session。
  右边是这一项现在在状态栏里的样子，写法和颜色同默认状态栏（Allow all 红色，其余暗色）：
  tps 是 `32.5 tok/s`（最多一位小数，整数不写 `.0`，同示例脚本；算法见「定制状态栏」里的 `tps`），version 同欢迎头的版本行，session 是会话名字。
  拿不到值的项（还没有花费、不在 git 仓库里、还没有 TPS、会话没名字等）在状态栏里不出现，选择框里右边空着。
  项之间隔 ` · `；branch 紧跟在 directory 后面时只隔一个空格（`~/src/canter (main)`）。
- **分行线** `─── line 2 ───` 和项一样能移：线上面的在第一行，下面的在第二行；移到最后就只有第一行，第二行空着。
- **按键**：↑↓ 选；空格开关当前项；←/→ 把当前项（或分行线）往前、往后挪一位；下面的预览跟着变。
  Enter 保存并关掉，Esc、Ctrl+C 或 Ctrl+D 不保存关掉。和单打 `/mode` 的选择框一样：选择框画到屏幕上之前按的键不算，
  刚关掉批准框时 Enter 不算，开着时 PgUp/PgDn 照旧翻对话，输入框为空时 End 照旧跳到最下面。
- **默认**（从没存过）是原来的两行：第一行 model、thinking、permission、cost，第二行 directory、branch、context、cache，
  其余不勾。不改时状态栏和原来一样。
- **窗口矮**：选择框占的是输入框上方对话区的地方，放不下时对话区先让出来。还放不下，项和分行线只显示放得下的几行，
  跟着光标滚（和其它选择框一样，光标尽量落在显示出来的最后一项），光标所在的那行总看得见；上面还有没显示的写一行
  `   ↑ N more`，下面有写 `   ↓ N more`（暗色），剩不到 3 行时不写这两行。标题、按键说明、空行、
  `Use statusLine script` 开关和预览一直留着；留给项的不到 3 行时，预览连同 `Preview` 那行和它上面的空行一起收起。
  连一行都放不下时不画，Esc 照样关。窗口够高时和上面的样子一样。
- **窄窗口和 Shift+Tab**：状态栏每行放不下时照旧从行尾截。permission 勾着且在第一行时，照旧要求权限模式完整可见，
  Shift+Tab 才切换；没勾或挪到第二行时，Shift+Tab 照样切换，上面的状态行短暂显示 `Mode: 新模式`，约 2 秒（同配了命令时）。

**保存**：Enter 存到 `~/.canter/tui.json`（设了 `CANTER_HOME` 时是该目录下的 `tui.json`），权限 `0600`，
目录不在时建一个（`0700`）；先写同目录下的临时文件再改名，不留写了一半的文件。文件里只有状态栏的项和顺序
（含分行线的位置）和下面「定制状态栏」里的脚本开关；`config.json` 不写。
保存后这个终端的状态栏立刻换；别的开着的终端下次打开 canter 才换，不监视文件。`/new`、`/resume` 换会话时沿用这个终端当前的设置，不重读。
存不了时对话里提示一行 `Could not save the status line: …`，这个终端照样换。

**读**：打开终端界面时读一次。文件不在时用默认；读不了或不是下面的格式时用默认，上面的状态行提示一次
`! Could not read tui.json; the status line uses the defaults`（约 5 秒）。里面不认识的项跳过，其余照用；
没列到的项不勾、排在最后，没有分行线时补在最后。格式（一般不用手改）：

```json
{
  "statusLine": {
    "items": [
      { "name": "model", "show": true },
      { "name": "line2" },
      { "name": "directory", "show": true },
      { "name": "tps", "show": false }
    ],
    "useScript": true
  }
}
```

## 定制状态栏

默认仍是底下的两行：模型、思考档位、权限和花费；目录、分支、上下文和缓存命中。用 `/statusline` 可以选显示哪几项（见上一节）。
在已有的 `~/.canter/config.json` 里增加可选的 `statusLine` 字符串（保留原来的模型、API key 等配置）：

```json
{ "statusLine": "~/.canter/statusline.sh" }
```

设置了 `CANTER_HOME` 时读该目录下的 `config.json`。只在打开终端界面时读这一项，修改后重新打开生效；
读不到、格式不正确、不是字符串或只有空白，均按没配置处理。保持配置文件权限为 `0600`。
终端不保存或转交配置中的其它项，服务端照旧忽略 `statusLine`。

**`/statusline` 里的脚本开关**：配了 `statusLine` 时，`/statusline` 最上面多一行 `[x] Use statusLine script`
（不参与排序，和下面的项之间隔一条线），空格开关。勾着（默认）时状态栏照旧显示命令的输出，
预览写 `From the statusLine script: <命令>`；取消勾选并保存后改用下面选的项，命令不再跑（正在跑的连同进程组停掉），
开关状态记进 `tui.json`，重开终端仍然这样；再勾上并保存就回到命令。`config.json` 不改。
没配命令时不出现这一行，`tui.json` 里记着的开关状态不影响什么。

命令用 `sh -c` 在会话目录里执行，继承终端环境，在独立会话中运行，不带控制终端。
标准输入是一行 JSON，写完关闭，标准错误丢弃。
模型输出、设置、用量、会话状态、目录或分支变化时更新，最多每 0.3 秒启动一次；同一时间只跑一个，
运行期间的变化合并成最新状态，结束后再跑。界面不会等待脚本。
超过 1 秒会停止命令及其进程组；超时、非零退出码、标准输出为空都算失败。
关闭终端（SIGHUP）或收到 SIGTERM 时正常退出，并停止运行中的状态栏命令及其子进程。
失败保留上一次成功结果；从没成功过则显示默认两行（`/statusline` 改过时是选的那些项），第一行末尾加红色 `statusline error`。

脚本标准输出的头两行替换默认状态栏：只有一行时第二行留空，其余行丢弃，每行按窗口宽度截断。
每行最多保留 4 KiB（包括 SGR），多出的字节继续读完并丢弃；按窗口宽度裁好的行会缓存，结果或窗口宽度变化时才重算。
支持 SGR 颜色和文字样式（含 16 色、256 色、RGB），其它控制序列和控制字符被去掉。
上面的转圈、用时、Copied 等状态行仍由 canter 显示。

JSON 字段如下，拿不到的值为 `null`；上下文和缓存百分比与默认状态栏一样四舍五入：

| 字段 | 内容 |
| --- | --- |
| `version` | 程序版本与编译时 git 短提交号，与欢迎头相同 |
| `sessionId` / `sessionName` | 会话 ID / 名字 |
| `cwd` / `gitBranch` | 会话绝对目录 / git 分支；分离 HEAD 时为短提交号 |
| `model` / `reasoningEffort` | 当前模型 / 思考档位（`none`、`low`、`high`、`max`） |
| `approvalPolicy` | `alwaysAsk`、`askForExecution` 或 `allowAll` |
| `status` | `starting`、`idle`、`working`、`waiting_approval`、`error` 或 `closed` |
| `context.usedTokens` / `windowTokens` / `percent` | 上下文已用 token / 窗口 token / 使用百分比 |
| `cost.usd` / `unknown` | 本会话已知美元花费 / 是否还含未知金额 |
| `cache.totalPercent` / `lastPercent` | 累计 / 最近一次请求的缓存命中百分比 |
| `tps` | 当前请求每秒输出 token；空闲和执行工具时保留上次结果 |

TPS 从本终端观察到的第一个思考或回答增量开始计时，按事件时间算到请求结束；
输出中用 UTF-8 字节数除以 3、向上取整估算（与 `/context` 相同），结束收到用量后改用真实输出 token，
思考 token 已包含在其中，不重复相加。一轮中的下一次请求重新计数和计时。
尚无可计算样本（例如刚打开一个旧会话），或首字与结束落在同一毫秒时为 `null`。
中途打开正在输出的会话时，快照没有首字时间，这次请求的 TPS 留空，下一次完整观察到的请求才开始计算。

配置了命令也能用 Shift+Tab 切换权限：自定义输出不必完整显示模式，但仍按按键所属帧的模式切换；
弹框、命令列表和 300 ms 保护期照旧。正在显示命令输出时，每次有效切换，上面的状态行短暂显示 `Mode: 新模式`，约 2 秒。
从没成功过、仍显示默认两行时，照旧要求权限模式完整可见，也不弹 Mode 提示（`/statusline` 改过时照那一节的规则）。**用 Shift+Tab 的话，脚本里显示 `approvalPolicy`。**

示例脚本（需要本机有 `jq`，保存到 `~/.canter/statusline.sh` 并执行 `chmod +x ~/.canter/statusline.sh`）：

```sh
#!/bin/sh
jq -r '
  def show: if . == null then "?" else tostring end;
```

## 输入框

Enter 发送，Shift+Enter 或 Ctrl+J 换行，Ctrl+V 贴图片，Ctrl+O 展开 / 收起对话里收起的东西，Ctrl+F 在对话里搜索。输入框上方一次只开一个列表：
选择框（比如单打 `/mode`）、`/` 命令列表、`@` 文件列表，三者不会同时开。

**编辑键**（只在输入框；列表、批准框、提问框、搜索框开着时照它们自己的按键）：

- Alt+← / Alt+→（也认 Ctrl+← / Ctrl+→、Alt+B / Alt+F）往前 / 往后跳一个词；
- Alt+Backspace 或 Ctrl+W 删掉光标前一个词，Alt+Delete 或 Alt+D 删掉光标后一个词；
- Ctrl+A / Ctrl+E 到本行行首 / 行尾（和 Home / End 一样）；
- Ctrl+K 删到本行行尾，光标已在行尾时删掉这个换行；Ctrl+U 删到本行行首，光标已在行首时删掉前面那个换行；
- Ctrl+C 有字时清空整段草稿。

「行」按换行分，不按窗口宽度折出来的行。「词」是连着的字母、数字、下划线，或连着的一串中文；中文和英文 / 数字交界、
标点、空格、换行都是分界。按词删先跳过光标旁边的分界，再删一个词，跳的范围和删的一样；`[Image #N 名字]` 整个算一个词，
删掉时附件跟着去掉，不会删出半截标记。

**大段粘贴**：一次粘贴超过 10 行或超过 1000 字（按字符数）时，输入框里只放一个标记：超过 10 行是 `[Pasted #1 · 120 lines]`，
否则是 `[Pasted #1 · 3200 chars]`，编号接着往上数，和图片各数各的；发出时换回全文，对话里显示全文。粘贴标记和
`[Image #N 名字]` 一样是一个整体：←/→ 一步跳过，↑/↓ 落进标记中间时光标放到它后面，退格、Delete、按词删整个删掉，
全文或附件跟着去掉；不能展开或改里面的内容，想改就删掉重新粘贴。文字或带图片的消息发送失败、草稿带回输入框时照旧收着；Esc 撤回放回输入框的排队消息显示全文。
粘贴到搜索框、提问框里照旧合成一行，不收起。

**发送失败**：显示 `✗ Not sent: …`，先把发送时的草稿放回输入框，再处理已有的撤回流程；新打的字保留在恢复的草稿后面。
如果服务端已收到消息、HTTP 回复却丢了，又恰好在这段时间按 Esc 撤回，输入框里可能出现两份相同的文字，可以手动删掉。
这里优先保住草稿，不按文字去重；文字和图片消息都照这个取舍。

**拖图片**：从 Finder 拖文件进来，终端把路径当粘贴送进来。按 shell 的写法拆开（认引号和反斜杠转义，
不展开变量、`~`、通配符，不执行），每一段都是 JPEG/PNG/GIF/WebP 文件时按原顺序全部挂成附件，
在光标处插 `[Image #N 名字]`，几张之间隔一个空格，编号接着排；有一段不是图片，整段当文字插进去，一张不挂。
多次拖照样插在当时的光标处，附件累加。当前模型不收图时提示一次 `… does not accept images; switch with /model …`，一张不挂。

## 往上翻

- 鼠标滚轮一次翻 3 行，PgUp/PgDn 一次翻一屏（批准框、提问框开着时 PgUp/PgDn 翻框里的内容，滚轮照旧翻对话）。
  往上翻着时新输出不把画面往下拉。
- **提示行**：往上翻着时，状态行上面常驻一行：没有新输出写 `↓ Jump to bottom`，翻上去以后对话有了新内容写
  `↓ New output below`（只有状态行变了不算）。后面灰字写怎么回去：输入框在时 `· click or End`，
  批准框、提问框或搜索框开着时 `· click`。跟着最新输出时不显示。
- **跳到最下面**：点这一行，或输入框为空时按 End，回到最底下，接着跟最新输出。点这一行不开始选字、不打开链接。
  输入框有字时 End 照旧把光标移到行尾；搜索开着时 End 照旧改关键词；批准框、提问框开着时 End 不跳。
  选择框（比如单打 `/mode`）开着、输入框为空时 End 也跳。
- 滚到最底下、发消息、跑 `/` 命令时也回到最底下，接着跟最新输出。

## `/` 命令列表

第一个词以 `/` 开头、还没打空格时，列出名字以所打内容开头的命令。↑↓ 选，Tab 补全；
Enter 在命令名没打完时只补全、不执行，打完整了才执行。Esc 只关列表。

普通消息刚发出、模型还没输出思考、回答或工具调用时按 Esc，会撤回这一轮，消息从对话里消失，
全文（多行和图片附件）回到输入框。撤回时仍在排队的输入也回来，顺序是撤回消息、排队消息
（按发送顺序）、原草稿，中间各换一行，光标在末尾。本终端保留已提交图片的原始路径，
等撤回回复和事件到齐后恢复；若因连接错误丢了回复，仍保留待恢复的输入，收到撤回事件后恢复。
没有本终端原始路径的图片改为文字 `[image: 名字]`，状态行提示 `Paste images again with Ctrl+V`，需重新贴图。
其他终端只移除这一轮，不恢复草稿或显示提示；撤回轮之前的报告和警告保留。
自动压缩摘要首次实际输出前同样可撤回；模型已经输出、或正在手动 `/compact` 时保持普通打断。
`/review` 轮的 Esc 不请求撤回；撤回普通轮时排队的 review 输入照普通打断丢弃，不放回为普通输入。
撤回的是本终端用来自动起名的那条消息时，清空会话名，下一条再起名；已被手动改过的名字保留。
选区、搜索和弹框仍优先由 Esc 关闭；旧服务端未确认撤回时只按打断显示。

`/handoff` 开出的新会话里还没发过消息时，按 Esc 先在状态行提示 `Esc again to return to the original session`，约 2 秒内再按切回原会话（交接说明丢掉，新会话留在 `/resume` 列表里）；发过消息后照上面的规矩。

## `@` 引用文件

- `@` 在输入开头或空白后面、光标在这个 `@` 词里时，弹出会话目录（信息行里显示的那个目录，
  一般就是开 canter 时终端的当前目录）下的文件和目录，相对路径显示，目录以 `/` 结尾。
  `/btw` 等命令后面的文字里也能用。光标离开这个词、删掉 `@`、按 Esc，列表关掉；Esc 不清输入。
- 照 `.gitignore`、`.git/info/exclude` 和全局 gitignore 过滤（只在 git 仓库里生效，
  上层目录的 `.gitignore` 也算）；不在 git 仓库里时不按这些过滤。`.git`、`.hg`、`.svn`、`.jj`
  从不列出。隐藏文件照列。不跟符号链接进目录。
- 遍历在后台做，界面不等它。一次最多取 **10000** 个文件和目录（按名字顺序深度优先），超了不再往下找，
  列表底部写一行 `Only the first 10000 files and directories are listed`。
  每次新出现 `@` 词时重新遍历。列表最多占 10 行。
- 筛选：`@` 后面打的字按顺序出现在路径里就算中，不分大小写。排序依次看：
  1. 全部落在文件名（最后一段）里的排前面；
  2. 落成的连续段越少越前；
  3. 文件名以所打的字开头的排前面；
  4. 路径短的排前面，再按路径字母序。
- ↑↓ 选，Tab 或 Enter 把整个 `@` 词换成 `@相对路径` 加一个空格；选的是目录时换成 `@目录/`、
  不加空格，列表接着列这个目录里的东西（目录本身不再列出）。列表开着时 Enter 只补全、不发送。
- 路径里有空白时加双引号：`@"my notes.txt" `；目录是 `@"my dir/"`，光标停在右引号前，
  可以接着往下选。`@"` 开头的词到右引号为止（没有右引号就到行尾）。名字含 `"`、控制字符或
  不是 UTF-8 的文件不列出。
- 发出去的就是这段文字：不读文件、不把内容放进消息，模型要看内容自己用 `read` 工具读。

`/rewind`：列出最近成功压缩之后可退的用户轮（最新在上），每条显示那一轮及以后改过的
文件数。选择后选「Conversation and files」「Conversation only」或「Files only」，查看
文件预览并确认，Esc 可取消。删除项显示 `will delete`，恢复项显示 `will restore`。
外部修改标为「之后在 canter 以外被改过」，超限写入无法比较时也明确要求确认，确认会覆盖。
确认只带预览中这些路径及会话序号；预览后出现新变化而冲突时，重新显示预览并要求再次确认。
退对话后把所选轮的文字放回输入框，可修改再发；已有图片附件需重新附加。
回退结果在所有连接本会话的终端里显示；正在运行时先 Esc 停下再用。

## 选字和复制

- **拖选**：在对话区按住左键拖，选中的字反白，可以跨行；松开就写进剪贴板。双击选一个词（字母、数字和
  `_-./~` 连着的算一个词，所以路径、`--release` 这类参数是一个词；连着的空格算一个；别的符号单独一个），
  三击选屏幕上的这一行；双击、三击后接着拖，按词、按行扩大。只点一下不复制（点在链接上是打开，见「链接」）。
- 拖到对话区最上面一行、最下面一行或更下面（离开按下的那一行以后），对话跟着滚，选区跟着扩大，
  大约每 50 ms 一行；鼠标停着不动时跟着界面刷新，大约每 0.1 秒一行。按住左键时对话区不跟着最新输出往下走，
  松开后照旧。
- 反白跟着字走：滚轮滚、正在写的回答往下长或末尾重新折行、运行中的命令只显示最后几行而往上挪，
  反白留在原来那段字上。那段字不再显示（命令收起后藏掉的行、出了队的排队消息）或变了，选区清掉，
  不会挪到别的字上。改窗口宽度、按 Ctrl+O 时清掉（字要重新排）。按 Esc、打字、点别处也清掉；有选区时 Esc 只清选区，不打断这一轮。PgUp/PgDn 不清。
- 只能选对话区：输入框、状态行、批准框和提问框里拖不出选区；往上翻着时状态行上面那行提示也不算（点它跳到最下面，见「往上翻」）。
- **复制出来只有内容**：不带卡片的 `●`、`◇`、`✗` 和右边的状态（`running`、`exit 0 · 1.2s`、
  `Waiting for approval`），不带用户消息前的 `›`、提示前的记号（`!`、`✗`、`✓`）、输出前的 `┃`、思考的 `┊`、
  引用的 `▌`、`btw` 标签和左边的缩进，不带 diff 的行号、`+`/`-` 和块之间 `⋯` 那行，不带
  `… N more lines · Ctrl+O` 这类只是提示的行。保留的：卡片标题从动词起（`Run cargo test`、
  `Read 路径  lines 1–20`）、列表的 `•`、`1.` 和列表嵌套的缩进、命令输出自己的缩进；
  表格照屏幕上的样子带框线。窗口窄折开的行接回一行，原来的换行保留；每行末尾的空格去掉，
  开头和结尾的空行去掉。只选了一行的一部分就只复制那一部分；选到半个中文字算整个字。
  按屏幕上画出来的字算：几个字符拼成的 emoji、带组合重音的字母都是一整个字，双击选词时重音跟着字母。
- **状态行**：复制好了显示 `✓ Copied N lines · M chars` 约 2 秒（M 里换行也算一个字），
  失败显示红字 `✗ Copy failed: <原因>` 约 5 秒；显示时占整条状态行，过后状态行照旧。
- **流光**：拖选、双击、三击松开后复制好了的那一下，选中的字（已经反白）上从左到右扫过一道青光，约 0.5 秒，
  然后就是普通反白。光是一段竖着的带子，下面一行比上面一行落后约 1.5 格，屏幕上选中的各行一起扫；
  从选中的字左边约 6 格扫到右边约 6 格，行多时多扫一段，保证最下面一行也扫完。颜色见「颜色」。复制失败不扫；
  `/copy` 和点链接改成的复制没有选区，不扫；扫的时候选区被清掉（Esc、打字、点别处、改宽度），光一起没了。
  界面平时每秒画 10 次，从松开等剪贴板回话到光扫完这一小段临时每秒约 30 次，扫完回到 10 次；不上颜色时不扫，也不加快。
- **`/copy`** 复制最后一条说完的回答的原文（markdown）；**`/copy N`** 复制这条回答里第 N 个代码块的代码，
  不带围栏。还没有回答时说 `Nothing to copy`，N 超过代码块数时说这条回答有几个代码块，输入框里的字都留着。
- **剪贴板**：写本机剪贴板（arboard）在单独的线程里，界面不等它；3 秒没写好算失败。
  在 tmux 里或 SSH 上（有 `TMUX`、`TMUX_PANE`、`SSH_TTY` 或 `SSH_CONNECTION` 时）另外用 OSC 52
  把字发给终端，由终端放进它那台机器的剪贴板；tmux 里包一层，让 tmux 转给外面的终端。
  这要终端支持 OSC 52，tmux 还要 `set -g allow-passthrough on`。终端收没收到不会回话，发出去就算复制好了。
  OSC 52 一次最多 100000 字节，再长只写本机剪贴板。

## 对话里搜索

- **打开**：Ctrl+F，输入框换成 `Find: <关键词>`；输入框里原来的草稿收着，关掉搜索后原样回来，`/` 命令列表、`@` 文件列表也跟着回来。
  批准框、提问框开着时 Ctrl+F 不打开；搜索开着时批准框、提问框弹出来，搜索停在当时的位置关掉（同 Enter）。
  选择框（比如单打 `/mode`）开着时按键先给选择框。打开时清掉鼠标选区。
- **边打边搜**：每改一次关键词（打字、删字、粘贴、Ctrl+C 清空）就重新搜，跳到最新的一处，不在画面里就滚到画面中间。
  关键词为空时不高亮、不跳。不分大小写（每个字符各自转小写比较）。粘贴的换行变成空格。
- **高亮**：当前一处反白，画面上其它匹配加下划线。按画面上画出来的字算：中文字、几个字符拼成的 emoji、
  带组合重音的字母都是整个的，不会只亮半个；`e` 加组合重音拼成的 `é` 里搜不到 `e`。
- **状态行**：`Find · 2/7 · ↑ older · ↓ newer · Enter stay · Esc back`，`2/7` 是从最早的往后数的第 2 处、一共 7 处
  （打开后先停在最新的一处，即 `7/7`；对话往下长时数字不变，只有总数变）。找不到时 `Find · No matches`，
  Ctrl+O 收着时后面加 `· Ctrl+O to search folded parts`；还没打字时 `Find · Esc back`。
  窗口放不下时从后往前去掉按键提示（先去 `Esc back`），还放不下行尾直接截掉。
- **按键**：
  - ↑ 或 Ctrl+P 到更早的一处，↓ 或 Ctrl+N 到更新的一处，到头停住，不绕圈；
  - Enter 关掉搜索，画面停在这处接着看（停在最底下的就接着跟最新输出）；
  - Esc 关掉搜索，回到打开搜索前的位置：原来跟着最新输出的回到最底下接着跟，原来往上翻着的回到原来那几行；
  - Ctrl+C 清空关键词，关键词已经空了再按就像 Esc；
  - PgUp/PgDn、鼠标滚轮照旧翻，Ctrl+O 照旧展开 / 收起；左右、Home/End、退格、Delete 照输入框改关键词；
    Ctrl+J、Shift+Enter 不换行，Ctrl+V 不贴图片。
- **搜哪些**：画面上对话区里显示的字，每一行整行都算：你的消息、回答、思考那一行、工具卡片（含右边的 `exit 1`、`declined`
  这类状态）、提示行、`… N more lines · Ctrl+O` 这类行。收起的部分（思考全文、长输出中间省略的行、长 diff）不搜，
  按 Ctrl+O 展开后就能搜到。一处匹配只在一行里：窗口窄、一个词或一句话被折到两行时，跨行的那处不算。
  输入框、状态行、信息行不搜。欢迎头只搜右边的字，不搜小马。
- **对话在变**：搜索开着、找到了匹配时，画面不跟着新输出往下走（下面有新内容时照旧出 `↓ New output below`），
  新内容里的匹配算进总数。当前一处钉在那段字上（哪一项、项里哪一行、行里第几处），正在写的回答往下长、
  运行中的命令只显示最后几行而往上挪，都不错位；那段字不再显示了，换到同一项里离得最近的一处，没有就换到离得最近的一处。
  改窗口宽度、按 Ctrl+O 时按新的画面重新找到这一处（找不到就找最近的），滚到看得见的地方。
- 不记住上次的关键词；没有正则、整词、区分大小写的开关。

## 链接

- **哪些能点**（加下划线，颜色不变）：
  - 回答里写出来的 `http://`、`https://` 网址（行内代码里的也算，代码块里的不算）；
  - markdown 链接，画成 `文字 (网址)`，文字和括号里的网址点哪个都开这个网址；
  - 工具卡片标题里读、改、新建的文件路径和改名后的新路径，按会话的工作目录补成绝对路径再开（删掉的文件不能点）；
    路径太长、按目录省过时（见「工具卡片」的「长路径」），点得到的是画出来的那一段，打开的照旧是完整路径；拖选复制、Ctrl+F 搜索照画出来的字。
  - `Fetch` 卡片的网址。
- **不能点、不加下划线**：`file:`、`javascript:`、各种应用的 `xxx://` 这类别的协议（markdown 链接指向它们时文字也不加下划线）；
  回答正文里写的路径；`Run` 卡片和命令输出里的网址、路径；思考里的网址。
- **网址到哪里为止**：到空格、引号、`<`、`>`、反引号或中文标点（`，`、`。`、`「」`、`（）` 这类）为止；末尾的
  `.`、`,`、`;`、`:`、`!`、`?`、`'` 和没有配对的 `)`、`]`、`}` 不算进去，成对的括号算
  （`https://en.wikipedia.org/wiki/Rust_(programming_language)` 整个是网址）。
- **怎么点**：按下、不动、松开算一次单击，等约 0.4 秒（和双击的间隔一样）没有第二下再打开；双击、三击照旧选词、选行，
  不打开；从链接上开始拖照旧是选字。搜索开着时（Ctrl+F）链接不加下划线、点了也不开，下划线只标匹配。
  这 0.4 秒里按 Esc、Ctrl+F 打开搜索或切换会话（`/new`、`/resume`），这一下作废，不开。
- **点到的是画出来的那个**：按下和松开都对着按的时候屏幕上那一帧画出来的链接，不按还没画出来的新内容算：
  回答还在往下写、网址还没写完时点，开的是画出来的那一截。按下、松开时对话已经被滚轮滚过（还没重画也算），
  或已经按新的窗口宽度重画过，这一下不开。
- **用什么开**（macOS）：网址用 `open <网址>`（默认浏览器）；文件用 `open -t <路径>`（默认文本编辑器，不会运行它）；
  目录用 `open -R <目录>`，在 Finder 里定位并选中它，不打开它，所以 `.app` 这类应用包（也是目录）不会被启动。
  路径跟着符号链接看指向的东西，只开普通文件和目录：路径不存在显示红字 `✗ No such file: <路径>`，
  是设备、socket 这类别的东西显示红字 `✗ Not a file: <路径>`，都什么也不开。链接原样作为一个参数交给 `open`，
  不经过 shell；看路径、起程序、等程序结束都在单独的线程里，界面不等。
- **Linux**：网址用 `xdg-open <网址>`。路径（文件和目录）不打开，改成把绝对路径复制到剪贴板，显示 `✓ Path copied`：
  `xdg-open` 按文件类型挑程序，还可能把 `.desktop` 文件里写的程序跑起来，Linux 上也没有通用的「用文本编辑器开」。
- **状态行**：打开了显示 `↗ Opened <网址或路径>` 约 2 秒，长了路径按目录从中间省（见「工具卡片」的「长路径」）、网址从中间截；程序起不来或报错退出，红字说原因约 5 秒。
  和复制的提示用同一个位置，新的盖掉旧的。
- **SSH 上**（有 `SSH_TTY` 或 `SSH_CONNECTION`，和复制的判断一样）：开了也是开在那台机器上，所以网址和路径都不开，
  改成把网址或绝对路径复制到剪贴板（走上面「剪贴板」的路子），显示 `✓ Link copied`。本机的 tmux 里照常打开。

## 空行和状态行

- **空行**：对话里每个项目（一段话、一张卡片、一行思考）之间空一行；连着的读文件（`◇ Read`）之间不空。
  用户消息本来前后各有一行空行，不再多加；铺底色时（见「颜色」）是空行里面再各一行底色边。连着的几行提示（警告、出错、谁回答了批准、`/` 命令的输出）、
  一轮结束时的 `■ Turn interrupted` 这类行、连着的排队消息各算一块，块和项目之间也空一行，块里不空。
  一项从进行中变成已说完，空行的位置不变。
- **状态行**：工作中时转圈后面的词按这一轮正在进行的那一项换，后面是 `· 秒数 · Esc to interrupt`：
  思考 `Thinking`，写回答 `Writing`，跑命令 `Running <命令第一行>`（多行命令后面加 ` …`），读文件 `Reading`，
  改文件 `Editing`，MCP `Calling`，网页抓取 `Fetching`，压缩上下文（自动的、`/compact` 的都算）`Compacting context`；
  没有进行中的项目（比如等模型开口）是 `Working`。自动压缩压完同一轮接着干活，词跟着换回 `Thinking` 这些。
  等批准、等回答、重连、中断中、出错、会话已关照旧，等批准、等回答不提示 Esc。
- 展开着时末尾还有 `· Details shown · Ctrl+O to fold`。窗口放不下时先截命令（最少留 12 列，截掉的写 `…`），
  还放不下就不显示 Ctrl+O 那句，再放不下行尾直接截掉。
- 卡片里不转圈、不计时；只有状态行变了不算新输出，往上翻着时提示行照旧是 `↓ Jump to bottom`，不变成 `↓ New output below`。
- **标签页标题**：canter 用 OSC 0 写终端标签页的标题 `<符号> canter · <目录名>`（工作目录的最后一段，家目录本身写 `~`）。
  干活时符号照状态行的转圈，每 100 毫秒一格；等批准、等回答 `✋`；一轮做完 `✓`、出错 `✗`，留到在这个 canter 里按任意键，
  才回到空闲的 `canter · <目录名>`；Esc 打断的轮直接回空闲。会话列表（`--resume`、`/resume`）开着时是空闲的样子。
  只在标题变了时写；去掉控制字符和双向、不可见字符，最长 240 字，screen 里只写 ASCII。退出时写空标题，
  终端用回自己的默认标题，不读、不恢复原来的。只有 Ghostty（`TERM_PROGRAM=ghostty` 且 `TERM=xterm-ghostty`）另发 OSC 9;4，
  在标签上显示忙（`9;4;3`）或等待（`9;4;4;100`），做完、出错、空闲和退出时清掉（`9;4;0`）；iTerm2 和别的终端只改标题，
  tmux、screen 里也不发。OSC 9 在不少终端里是弹通知，iTerm2 3.6.6 才认 9;4、旧版当通知，而套在外层终端里的模拟终端
  （paddock、herdr 等）会继承 `TERM_PROGRAM` 这些变量，只靠变量分不清，所以只认 Ghostty 自己。
- **压缩**（灰色一行）：压缩中 `── Compacting context… ──`（不扫流光），压完 `── Context compacted ──`，
  没压成功（出错、被 Esc 打断，或一轮结束了还没压完）`── Compaction did not finish; the original context is kept ──`。
  没压成功靠核心写进摘要的固定那句话（`Compaction did not finish; the original context is kept.`）或摘要为空认出来。
- **每轮用时**（灰色）：一轮正常结束，最后一项后面一行 `─ Worked for 3m 05s ─`；被中断、失败的，
  原来那行后面加 ` · 12s`（`■ Turn interrupted · 12s`、`✗ Turn failed: <原因> · 12s`）。
  时长写法和状态行一样（`12s`、`3m 05s`），不到 1 秒写 `<1s`。进行中的轮不加，状态行在计时。
  用时来自快照里轮的 `durationMs`（协议包 README「归并」）；不知道的（旧数据、打开时已在进行中的轮）
  照旧不写。失败时出错已经作为提示显示过的（实时看着失败的那次），没有那行，也就不写用时。
  服务端崩溃后补记为被中断的轮，用时算到补记那一刻。
- **一轮改了哪些文件**（P2-54）：一轮结束时（正常、被中断、失败都算），这一轮里 canter 改文件的工具改成功了文件，
  就在用时那一行上面列出来，不空行：

  ```
    ● Changed 3 files  +40 −12
        src/app.rs    +30 −8
        src/input.rs   +8 −4
        README.md      +2     new
    ─ Worked for 1m 12s ─
  ```

  第一行文件数（`1 file` / `N files`）和加删总行数；每个文件一行，路径照改文件卡片的写法（会话目录里的写相对路径，
  改名的写 `旧 → 新`），行数对齐成一栏，`+` 绿、`−` 红，没有删的不写 `−0`，只删了的不写 `+0`；
  新建的后面写 `new`，删除的写 `deleted`；其余灰色。同一个文件这一轮改了几次合成一行、行数加总，
  顺序照第一次改它的先后；改名后再改新路径也算同一行。多于 8 个文件只列前 8 个，最后一行 `… and N more`。
  只算状态是 completed 的改文件项目，失败、被拒的不算，shell 命令改的不算。从快照里的项目算，不存盘，重开会话照样有；
  进行中的轮不画；Ctrl+O 不影响；路径不可点。

## 工具卡片

对话里每次调用工具一张卡片（`src/cells.rs`）：第一行 `● 动词 对象`，右边状态；输出和结果每行以 `    ┃ ` 开头，
长行截断；`┃` 在失败的卡片（`✗`、非 0 退出码、红色 `failed`）上红色，其余灰色。
圆点进行中灰、成功绿；失败换成红色 `✗`，右边红字；拒绝的右边灰色 `declined`；
等批准的 shell 和改文件右边黄色 `Waiting for approval`。省掉的行写一行灰色 `… N more lines · Ctrl+O`。

- **shell**：`● Run <命令>`，右边 `running`、`exit 0 · 12.3s`、红色 `exit 1`，只在第一行。命令整条显示，
  按 Bash 上色（见「代码块和命令的语法色」），放不下按词折行，折出来的行对齐到命令开头那一列；多行命令每行都这样折。
  命令最多占 5 行（算折出来的行），再多一行灰色 `… N more lines · Ctrl+O`。复制时折行处接回一整条，命令自己的换行照旧。
  输出留最后几行：进行中 5 行，成功 3 行，失败 10 行。成功和进行中的输出灰色，失败的用默认色。
- **读文件**：一行 `◇ Read 路径  lines 1–21`，失败 `✗` 和红字 `failed`。
- **长路径**（`src/short_path.rs`）：一行放不下的路径从中间按目录省，留住第一段和文件名，省掉的整段目录合成一个 `…`，
  从靠近文件名的那头尽量多留：`crates/canter-tui/src/app.rs` → `crates/…/src/app.rs` → `crates/…/app.rs` → `…/app.rs`；
  `~` 开头的第一段是 `~`，`/` 开头的是 `/` 加后面第一个目录（`/Users/…/app.rs`）；文件名自己都放不下时从文件名中间截
  （`a_very…me.rs`）。按显示宽度算，不切坏中文。路径后面的说明（`lines 1–21`、`failed`、`declined`、加删行数）留着，
  先缩路径；改名的两个路径平分剩下的地方；路径最少留 10 列，还放不下才照旧从行尾截。读文件、改文件卡片的标题、
  等批准时的标题行、每轮末尾的文件行、`/resume` 列表的目录栏、`@` 引用列表、欢迎头的目录、打开链接的提示、
  `/files` 和 `/context` 弹框里的路径都这样；批准框照旧显示完整路径（折行），网址、命令和正文里的路径不按段省。
- **改文件**：`● Edit` / `Add` / `Delete`，见下面「diff」。
- **MCP**：`● Call 服务/工具  参数`，参数 JSON 压成一行（没有参数不写），放不下截断，控制字符显示成转义；
  结果留**前** 3 行。失败的结果用默认色。
- **网页抓取**：`● Fetch <网址>`，右边抓回来的大小（`12 B`、`18.4 KB`、`1.2 MB`，按 1024 进位）。
  抓回来的网页是给模型看的，不显示。结果只是一行说明时照原样显示、右边不写大小：
  跳到别的域名（`Redirected to …`，右边写 `redirect`）、图片 / PDF 这类（`[Content omitted: …]`）、
  超过下载上限（`Download exceeds … content omitted.`）。失败时下面红字写原因。
- **Ctrl+O** 展开时 shell 显示整条命令（不限 5 行）和全部输出，
  MCP 显示全部结果，网页抓取显示抓回来的内容；一项最多 500 行，再多头尾各留 250 行，
  中间一行灰色 `… N lines not shown`。

## diff

历史里改文件的卡片和批准框用同一套画法（`src/diff.rs`）：

- 统一 diff，一列行号，宽度按这份 diff 里最大行号的位数：删行用旧行号，加行和上下文用新行号。
  行号和 `+` / `-` 号是一栏（`551 - `），后面是代码。
- 不显示 `@@` 行。块和块之间一行：`⋯`（对着 `+` / `-` 号那一列）加这块在哪个函数里，灰色斜体，放不下从后面截掉加 `…`。
  函数名取 `@@ -a,b +c,d @@` 后面那段；没有（旧会话里存的 diff、找不到函数的块）就只有 `⋯`。第一块前面不画。
  这段由 canter-tools 改文件时写进 `@@` 行，照 git 默认的规则：块开头往上找最近一行以字母、`_` 或 `$` 开头的原文，
  去掉行尾空白，最多 80 个字符；找不到不写。给模型的摘要不变。
- 能铺底色时（见下面「颜色」）：
  - 加行、删行整行铺底色到行尾，行号这一栏的底色再深一点，行号和号绿 / 红。上下文不铺底，行号灰色。
  - 代码按文件的语言上色，和代码块同一套（syntect + two-face，`ansi` 配色）；语言按文件名或扩展名认
    （`main.rs`、`Makefile`），认不出时不上色：加删行默认色，上下文灰色。上下文上色时是正常亮度。
  - 加行上的绿字、删行上的红字和底色混在一起看不清，改成默认色。
  - 删行和上下文按改之前的文件、加行和上下文按改之后的文件各自连着分析，不读整份文件：
    块和块之间断开的跨行字符串、注释可能上错色。超过代码块的上限（见「代码块和命令的语法色」）整份不上色。
  - 上色算一次记着，同一份 diff 再画（批准框每帧都画）不重算；改窗口宽度、Ctrl+O 时跟着整段重画。
- 不能铺底色时（16 色、不知道深浅、`NO_COLOR`）照旧：不上语法色，加删行整行绿 / 红字，上下文灰色，行号灰色。
- 改动的词：一段连着的删行后面紧跟同样多的加行时一一配对，每对按词比较（similar 的 `inline`），
  改动的词底色再深一档，没有底色时反色。一对里相同的部分不到一半不标；删行和加行行数不一样不配对、不标。
  一对里有一行超过 1024 字节就不按词比较（每帧都要比，极长的行会卡），只铺整行底色（没有底色时整行绿 / 红字）。
- 长行折行，折出来的行对齐到行号后面的文字。
- 历史里收起：改文件每个文件最多 12 行，新建文件最多 6 行，多的写一行 `… N more lines · Ctrl+O`；
  删除文件只有标题。按 Ctrl+O 全部显示（删除文件也显示删掉的内容），见下面「Ctrl+O 和思考」。
  批准框全显示，放不下时 PgUp/PgDn 翻；控制字符照旧显示成转义。

## Ctrl+O 和思考

- **Ctrl+O** 在原地把对话里收起的东西一起展开：思考全文、命令输出全部（MCP、网页抓取的结果也是，一项最多 500 行，见上面「工具卡片」），
  历史里的 diff 全部；再按一次收起。已说完的和进行中的都算，已说完的部分像改窗口宽度一样整段重画。
  展开着时状态行末尾写 `Details shown · Ctrl+O to fold`，空闲时也显示。批准框、提问框开着时
  Ctrl+O 照样切对话区，批准框本身照旧全显示。不记住：每次打开 canter 都是收起的。
- 往上翻着时按 Ctrl+O，原来在最上面的那一项（一段话、一张卡片、一段思考）的第一行停在最上面；
  跟着最新输出时照旧贴着底。展开时输出的长行照旧截断，不折行。
- **思考**灰色斜体：
  - 进行中：一行 `Thinking… <最新写出来的那一行>`，太长只留末尾、前面加 `…`，跟着思考往下走；
    还没有内容时只有 `Thinking…`。
  - 结束后：一行 `Thought: <第一行>`，后面还有内容时以 `…` 结尾，太长截断。有摘要时用摘要，
    摘要开头的 `**标题**` 去掉星号当这一行。知道想了多久时写 `Thought for 4s: <第一行>`
    （写法同每轮用时，不到 1 秒 `<1s`），算到最后一句思考；不知道的（旧数据）照旧 `Thought:`。
  - 展开：先一行 `Thought`（知道用时是 `Thought for 4s`，还在想时是 `Thinking…`），
    下面全文按 markdown 画，整体灰色斜体，每行左边一条灰色 `┊`。用的和收起时同一份：有摘要用摘要，没有用原文。
  - 不能单独展开某一块。

## markdown 表格

模型回答里的 markdown 表格（`src/markdown.rs`）画成框线表格，不显示 `|` 和 `|---|`：

- 框线灰色（次要），表头粗体，表头下一条分隔线。数据行之间平时不画线；有格子折成多行时，
  每两行数据之间都画一条线。
- 照 `:---`、`:---:`、`---:` 左、中、右对齐，没写的左对齐，表头跟着本列。宽度按显示宽度算
  （unicode-width，中文和全角标点 2 列），用空格补齐。格子里的粗体、行内代码等照样上样式。
- 比可用宽度宽时：
  1. 先按每列最宽的内容排，放得下就这样；
  2. 放不下：每列至少留住本列最长的一个词（词按折行的规矩分：空格隔开，中文每个字单独算；
     最多 16 列，再长的也断；连这样都放不下就把 16 往下降），剩下的宽度按各列还差多少按比例分，
     取整剩下的几列先给离自己最宽内容最近的列，格子里折行；
  3. 还放不下（平均一列不到 6 列）：改成一条条记录，每行数据一块「表头: 值」，块之间一条灰线。
- 流式时表格每来一行就整张重排；分隔行还没到时照原文显示。
- 已知限制：终端设成把「东亚模糊宽度」字符（`→`、`…`、`①`，以及框线本身）画成 2 列时会错位；
  个别 emoji 在各终端里宽度不一，也可能错一格。只有表头、没有数据行的表格在改成记录时不显示。

## 代码块和命令的语法色

模型回答里的围栏代码块按语言上语法色（`src/highlight.rs`，syntect 5.3.0 加 two-face 0.5.2 的语法定义，正则用 onig）：

- 配色是 two-face 的 `ansi`：只用终端调色板的 16 色，普通文字是终端默认色，跟着终端配色走，
  不用真彩。
- 认语言只看围栏后面写的第一个词（```` ```rust ````、```` ```ts ````），按 syntect 的扩展名和语法名找，
  不分大小写；另认 `golang`、`shell`、`python3`、`csharp`。没写语言的块，第一行是 `#!` 时按它认
  （`#!/bin/bash`、`#!/usr/bin/env python3`）。都没有、认不出或是纯文本，整块青色。不按内容去猜。
- 太大的块不上色、整块青色：超过 512 KB、超过 1 万行，或者有一行超过 4 KiB。
- `NO_COLOR` 时不上色，和别的文字一样没有颜色。
- 浅色底（见下面「颜色」）上黄字看不清，黄和亮黄（数字、常量等）改成终端默认色，不加粗（代码里这类字太多，
  加粗抢眼）；深色底和不知道深浅时照旧黄色。`ansi` 配色只用调色板 1～6 号，没有白、亮白这类浅色。
- 样子不变：不显示围栏和语言名，块在正文里再缩 2 列，长行折行；行内代码照旧青色。
- 流式时每帧从头渲染，但同一个块已经写完的行记着颜色和语法分析到哪里，只算新来的行。

批准框里要跑的 shell 命令整条按 Bash 上色，规则同上（上限、`NO_COLOR`）。只改颜色：照旧先把控制字符
显示成转义再上色，折行和 `Directory:` 那行不变。命令卡片里的命令（历史里的、正在跑的、等批准的）也这样上色。

内置语法定义、配色和 Oniguruma 的许可证声明在仓库根目录的 `THIRD-PARTY-NOTICES.md`。

## 颜色

界面文字只用终端自己的 16 色，换终端配色 canter 跟着变。颜色都在 `src/theme.rs`，各处按用途取：

| 用途 | 用在哪 | 颜色 |
|---|---|---|
| 强调 | `›`、选中项、行内代码、认不出语言的代码块、转圈 | 青 |
| 成功 | 成功的 `●`、`✓`、`+N` | 绿 |
| 失败 | 失败的 `✗`、`exit 1`、失败卡片输出前的 `┃`、错误文字、`−N`、信息行里的 `Allow all` | 红 |
| 警告 | 警告 `!`、等批准、重连中、会话已关 | 黄；浅色底上改成默认色加粗 |
| 警告边框 | 批准框、提问框的边框 | 黄（浅色底也是） |
| 次要 | 卡片右边的说明、命令输出、提示、灰掉的选项 | 暗（dim） |
| 思考 | 思考 | 暗 + 斜体 |
| 旁注 | `/btw` 的回答 | 深灰 + 暗 |
| 小马 | 欢迎头的小马 | 真彩：栗色身体 `#C0703F`、深棕鬃毛尾巴蹄子 `#5B3220`、眼睛 `#1E1A18`、眼睛高光 `#FFFFFF`、奶油色鼻头 `#F1D2A6`、粉色腮红 `#E89A8C`；256 色用手挑的色号（最接近的会把鬃毛变灰、身体偏红，腮红和身体分不开；不用会随终端配色变的前 16 个）：身体 173、鬃毛 94、眼睛 234、高光 231、鼻头 223、腮红 211，深浅底一样；16 色整匹用青色、眼睛留空；不上颜色时用默认色、眼睛留空 |
| 语法色 | 代码块、批准框和命令卡片里的命令、能铺底色时 diff 里的代码 | `ansi` 配色给的 16 色之一，普通文字默认色；浅色底上黄和亮黄改成默认色（不加粗） |
| diff 加 / 删行 | `+` / `-` 号；有底色时也是行号，没有底色时整行文字 | 绿 / 红 |
| diff 加 / 删行底色 | 真彩或 256 色、且知道深浅时，整行铺到行尾 | 深色底 `#213A2B` / `#4A221D`，浅色底 `#DAFBE1` / `#FFEBE9`；256 色用色号 22 / 52（深）、194 / 224（浅） |
| diff 加 / 删行的行号栏 | 同上，行号和 `+` / `-` 号那一栏 | 比整行底色深一点，和改动的词分得开：深色底 `#1B3024` / `#3D1C18`，浅色底 `#C6EFD0` / `#FFD9D5`；256 色浅色底 151 / 181，深色底找不到比 22 / 52 更深的绿 / 红，用整行的 22 / 52 |
| diff 改动的词 | 同上 | 比整行底色深一档：深色底 `#2E5C3F` / `#73322A`，浅色底 `#ABF2BC` / `#FFCECB`；256 色 28 / 88（深）、157 / 217（浅）；没有底色时反色 |
| 用户消息底色 | 已发出的用户消息（含带图片的、review 轮的标题行），同上的条件；整行铺满对话宽度，上下各多一行同色的边。排队中的、`/btw`、欢迎头不铺 | 深色底 `#2D2E33`，浅色底 `#E9E9E5`；256 色 236（深）、254（浅） |
| 状态行流光 | 干活时转圈后面那个词（`Working`、`Thinking`、`Running`、`Compacting context` 等，两个词的整个扫），后面的命令、用时、提示不扫 | 真彩或 256 色、且知道深浅时渐变：平时灰，光到的字变亮，光中间加粗；深色底从 `#7F7B75` 到接近白，浅色底从 `#8A857E` 到接近黑；256 色取最接近的色号（不用前 16 个）。16 色或不知道深浅时分三档：离光远的暗（dim）、近一点的正常、光中间的粗体 |
| 复制流光 | 复制好了时扫过选中的字 | 同上的条件时，光从反白的底色渐变到青色，光上的字用终端底色：深色底 `#E6E4DF` 到 `#56C2CF`、字 `#1C1D20`，浅色底 `#26241F` 到 `#0F8A99`、字 `#FBFBF9`；256 色取最接近的色号。16 色或不知道深浅时是一段 4 格宽、没有渐变的青底 |

用户消息铺底色时，`›` 和文字颜色不变，折出来的行和第一行的文字对齐；选中的字和搜索当前那处反白时不铺底色，
和别处一样；别的搜索结果的下划线照样在底色上。复制时底色边那两行和文字后面铺的空格不算内容。

两道流光的位置按时间算，不按画了几帧，画得快慢不影响速度。状态行那道光照 Codex：一遍 2 秒，词两边各留 10 格空程，
光的半宽 5 格，扫完空一小段再来；复制那道光半宽也是 5 格，0.5 秒扫完。不读终端的实际颜色去混色，用上面写死的深浅两档。
`NO_COLOR` 时都不扫，状态行那个词照旧是默认色。`Interrupting…`、`Reconnecting…`、等批准、出错、会话已关时不扫。

启动时（进全屏之后、开始读键盘之前）定两件事，运行中不再变：

- **色深**：`NO_COLOR` 不为空时不上任何颜色，只留粗体、斜体、下划线、反色和暗；否则 `COLORTERM` 是
  `truecolor` 或 `24bit` 按真彩，`TERM` 里有 `256color` 按 256 色，其余按 16 色。
- **深浅**：`CANTER_THEME=dark` 或 `light` 优先（别的值不算）；否则问一次终端底色（OSC 11，用
  terminal-colorsaurus，最多等 200 ms，亮度过半算浅色）；问不到看 `COLORFGBG` 的最后一个数（0–6、8 深，
  7、9–15 浅）；还不知道就当「不知道」。只有知道是浅色底时，警告文字才换成默认色加粗。
