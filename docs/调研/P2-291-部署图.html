canter 远程部署

一台 canter 服务端只服务一个人，跑在代码所在的机器上。VPS 只做中转，不跑 agent、不放代码。图里的域名和端口都是例子。

请求方向：客户端连过去，带令牌 隧道：服务端那台机器主动连到 VPS，请求再顺着它送回来 不支持的用法

在 iPad 上发一句话，经过哪些地方

  1. iPad App 用 HTTPS 连 canter.example.com，请求头里带令牌。
  2. VPS 上的 Caddy 解开 HTTPS，交给隧道入口。
  3. 隧道把请求送回 5090。这条隧道是 5090 事先主动连出去建好的，所以家里不用开端口。
  4. 5090 上的 canter 服务端先核对令牌，不对就直接拒绝，别的什么都不处理。
  5. 服务端在 5090 上干活：调模型、在沙箱里跑命令、读写代码。
  6. 过程和结果作为事件流原路推回 iPad。断线重连后从断开的地方接着收。

谁拿着什么

东西在哪要注意
令牌5090 只存哈希；客户端存原文等于 5090 的 SSH 权限，丢了在 5090 上撤销，已连着的会被立刻断开
HTTPS 证书VPS 上的 Caddy只保护设备到 VPS 这一段
明文经过 VPSVPS 要自己管好
代码、模型 key只在 5090客户端和 VPS 都拿不到

本机用法不变

  • 在 5090 或 Mac 上直接开 canter，照旧走 unix socket，不要令牌，找不到服务端就自动起一个。
  • 不在配置里写监听地址，服务端就不开任何网络端口，和现在一样。
  • 不带 --server 永远连本机。
  • 先不接 VPS 也能试：用 SSH 端口转发把 Mac 连到 5090，先看 canter 本身通不通。
