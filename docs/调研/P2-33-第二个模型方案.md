## 1. 能不能接，条款边界在哪里

### 现在和参考实现

现在 canter 仅有 DeepSeek 的 API key，没有 OAuth、ChatGPT 账号或订阅配额状态。设计第 6 条已允许以后接 ChatGPT，第一期暂缓并未取消；第 2、8、15 条决定一个本机服务端、多客户端、Unix socket 上的 HTTP + SSE。[C1] [C2]

当前官方 Quickstart 仍写商业合作方为 limited trial，ChatGPT plan usage 对所有开源合作方和部分私有客户端开放；开源流程以动态注册取得 client ID，不需要 client secret 或 partner API key。预览限制页仍存在且描述了当前限制，不能称为稳定、完整的通用 API。开源本机 canter 可按公开流程接入；未查到要求它先提交商业申请的原文。收费或远程托管产品由官方 Overview 指向意向表。[W1] [W2] [W7] [W11]

Codex 同时有第一方登录和可配置 Responses provider。第一方 ChatGPT 登录默认选择 `chatgpt.com/backend-api/codex`，设备码也使用 Codex 的验证页面；官方另给出「应用自己取得 SIWC token，再交给 Codex app-server 调公共 Responses」的配置。因此「Codex 能登录」不能证明其第一方参数可供 canter 使用。[S1] [S2] [W9]

### 条款读到的内容与本方案的判断

这次成功读到 SIWC Terms 原文（页面日期 2026-09-29），不再使用 R49 的搜索摘要。条款要求真实应用身份、官方授权、用户控制的运行环境、后台明确同意，并限制通用代调、代其他用户请求和绕限；还要求隐私告知与必要的数据保护。它没有逐项批准 daemon、Unix socket 或多终端架构。[W10]

据此作工程判断，而非 OpenAI 对 canter 的批准：

| 场景 | 推荐边界与理由 |
| --- | --- |
| 同一个人、同一台机器，TUI/桌面/网页客户端连接其 canter 服务端 | 可作为同一个应用的不同界面。OAuth host 按安装实例生成，不按终端生成；保持现有仅本机 socket 的边界。[W2] [C1] |
| 人已交代任务，关闭终端后继续运行 | 登录时单独说明这种后台行为，取得并保存同意后才启用。常驻进程存在本身不等于持续推理。没有同意时最后一个交互客户端离开就停止后续推理请求；工具结束和保存结果不应丢弃。具体产品选择见 §7。 |

| 以后接 corral、远程消息或定时任务 | 本轮不接、不为它写特例。公开原文未点名这些集成，也未给出“某外部工具调用会话接口必然合规”的保证；实现该集成时由主控核实触发者和授权范围。 |
| 自用远程 VM | 官方有自托管 VM 的凭证迁移指南；但 Terms §1 对持久存储写了 “local and under the user’s control, not in a remote or managed environment”，§2 又容许本人独控的 remote runtime。两者与 VM 指南的边界没有解释清楚。首版推荐只做本机；远程凭证持久化先取得官方澄清，不直接断言允许。[W8] [W10] |

## 2. 登录、凭证与服务端生命周期

### 现在和 Codex 怎么做

canter 的 `Config::load` 从 `CANTER_HOME/config.json` 读取 DeepSeek key；配置没有 Debug/Serialize，模型错误也不保留原始响应体。状态目录 0700、文件 0600，read/write/edit 拒绝访问状态目录；shell 仍不是沙箱。[C1] [C2] [C3]

Codex 的 `login/src/server.rs` 提供浏览器 PKCE 和 loopback callback，`device_code_auth.rs` 提供设备码；`auth/storage.rs` 支持文件、系统钥匙串等模式，`auth/manager.rs` 管刷新和失效，`auth/revoke.rs` 退出时尝试撤销。其 OAuth endpoint、scopes、固定 client ID、撤销请求格式均不能原样当成 SIWC 契约。canter 按 [W3] [W4] 实现，参考这些源码的职责分工。[S1]

### 推荐流程：服务端持有登录事务，CLI/TUI 操作它

拟新增 `canter auth login chatgpt`、`status`、`logout` 和保存账号的选择入口；这是实现提案，不是现有命令。

1. CLI 经 canter socket 发起登录。服务端建立一个短期、可取消的登录事务，返回登录事务 ID 和授权 URL；只在发起客户端显示，不放入会话事件或 SSE 重放文件。服务端不调用系统浏览器，CLI/TUI 在用户桌面打开它；自动打开失败时允许复制链接到**同一台机器**的浏览器。
2. 服务端先监听 `127.0.0.1:<空闲端口>/auth/callback`，再生成本次独立的随机 `state`、OIDC `nonce` 和 PKCE S256 verifier/challenge。没有回调前不使用任何待登录凭证；取消或超时关闭监听并清理事务。该临时回调 TCP 口只用于 OAuth，不改变 canter 主协议只听 Unix socket 的决定。
3. 每个 canter 安装实例先生成并持久保存一个不含身份信息的 `urn:uuid:<UUIDv4>` host ID。官方更推荐公钥指纹 URI，但也明确支持 UUID；目前不验证私钥持有，本轮不为一个标识增加密钥生命周期。[W2]
4. 首次访问 `https://auth.openai.com/api/accounts/authorize`：`client_id=dynamic_agent_client`、`agent_name_hint=canter`、稳定的 `ext_agent_host_id`、`response_type=code`、准确 callback URI、state/nonce/PKCE，以及 `resource=https://api.openai.com/v1`。scopes 为 `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`。再次登录使用此前签发的 client ID，省去 `agent_name_hint`。[W3]
5. 服务端核对 state，处理拒绝；首次必须有签发的 client ID，再登录回调若给出不同 client ID 则拒绝。以 form-urlencoded 向 `https://auth.openai.com/api/accounts/oauth/token` 换 token，带同一 redirect URI、resource、PKCE verifier 和签发的 client ID，绝不能拿 `dynamic_agent_client` 换 token。[W3]
6. 用可信 OpenAI discovery/JWKS 校验 ID token 的签名、issuer、audience、有效期和 nonce；复登还要匹配已保存的 subject/client 绑定。仅解码 JWT 不算验证。检查返回 scope 中的 `chatgpt.tokens.use.direct`；缺少时显示「已登录，未授权使用套餐」，不推理、不自动切换计费。[W3] [W6]
7. 成功后原子保存，客户端只收到完成状态、用户自己起的账号标签及是否允许套餐使用。首次显示套餐使用说明及 Usage 链接；后台同意另记，不与 OAuth scope 或 `--yolo` 混用。需额外授权 scope 时仅在人主动开启时重新 OAuth，当前使用 `prompt=consent`；文档要求 `force_reconsent=true` 等 OpenAI 确认部署后才能用。[W6] [W12]

**无图形界面：**同机有浏览器时用手动 URL；纯远程 headless 的公开方案是本地完成 OAuth 后安全迁移指定注册记录，保留 VM 自己的 host ID，并让 VM 单独负责该 refresh session。不能让两机持续竞争同一个轮换 refresh token。因 §1 的条款冲突，首版不交付此导入流程。SSH 回调转发在技术上可构造，但未查到 SIWC 对它的专门说明，也不能消除远程存储问题。Codex 有设备码，**未查到公开 SIWC 动态注册对设备码的支持契约**；不借用 Codex 设备码路径兜底。[W8] [S1]

### 凭证位置、并发、刷新和退出

- 推荐 `CANTER_HOME/auth/chatgpt/host.json` 保存 host ID，注册记录各占一个 0600 文件，目录 0700；具体文件名使用本地随机 ID，不用 email。账号 subject/client ID、access/refresh/ID token、scopes、接收时间、expires_in、earliest_refresh_at 一起保存。账号注册不以 email 为主键，避免同邮箱不同 workspace 相互覆盖。[W3] [W4] [W13]
- 保存多个注册记录、由人选择一个活动账号即可；不做账号池或自动切换。会话固定到本地注册记录 ID；全局切账号不能把已有会话下一次请求悄悄记到另一账号。正在运行时拒绝切换；恢复旧会话时明确选择原账号或确认换账号并新开上下文段。
- 推荐先用本机权限文件，与现有状态目录一致。临时文件创建时即为 0600，在同目录写入并原子替换；文件及父目录同步后再发布新的内存凭证。拒绝凭证文件符号链接及错误所有者，不能先宽权限写完再 chmod。系统钥匙串是实质备选：静态存储防护更好，但 headless、钥匙串解锁和跨平台故障处理更多；不把它混进首版必需工作。[C1] [S1] [W3]
- 只有服务端管理凭证；CLI 不同时刷新或改 token 文件。每个注册记录的刷新串行化，请求取得一致的 token 代次。正常换服务端先交出原有 server lock，再由新服务端接管，避免旧新进程竞争轮换。[C2] [W4]
- 刷新向同一 SIWC token endpoint 发 form-urlencoded：`grant_type=refresh_token`、该注册的签发 client ID、最新 refresh_token、`resource=https://api.openai.com/v1`；省略 scope 以沿用授权。刷新响应的 access token、轮换 refresh token、expiry 和 granted scopes 一起替换，不能只更新 access token。[W4]
- 依据返回过期信息按需在请求前刷新，不在无任务时无限刷新保活。公开文档现在写 access token 一小时、refresh token 三十天并随成功刷新轮换；保存并尊重 `earliest_refresh_at`，具体重试/时间处理在假时钟下测试。临近过期刷新是方案，时长不另写死为 Codex 的八天回退逻辑。[W13] [S1]
- 一次 401 不等于必须清除账号：先看 scope、token 代次和是否可刷新；最多一次刷新恢复，避免循环。刷新不可用码（如 `invalid_grant`、`refresh_token_reused`、`refresh_token_invalidated`）清除不可用 token，保留注册与 host 映射，提示复登。网络故障/503 保留凭证；`invalid_client` 指向客户端配置问题。[W6]
- 退出先阻止该账号的新请求、取消尚在进行的推理并保存已完成结果；阻止后台刷新把凭证写回来。依据 OpenID discovery 的 `revocation_endpoint`，form POST refresh token、token_type_hint 和签发的 client ID。有限重试后无论远程是否确认都停止本地使用；失败明确提示远程撤销未确认及设置页入口。清 access/refresh/ID token，保留 host 与注册绑定；需要彻底移除账号时另清映射。[W4]
- OpenAI 目前不向应用推送断开通知；在请求/刷新确认撤销时停止，不伪装实时在线状态。[W6]

### 不进入日志、事件、错误和快照的具体办法

令牌类型不派生 Debug/Display/通用 Serialize；只有私有存储模块显式序列化。不把凭证放进 `SessionSettings`、`Message`、工具定义、CLI 参数或 shell/MCP 子进程环境。HTTP auth header 标 sensitive，关闭自动跨站重定向；生产 OAuth 和推理 origin 固定，测试才注入 loopback。Discovery 返回的 URL 仍要校验可信 HTTPS origin，不能任意跟随配置把 token 发去别处。[C3] [W3] [W4]

登录 URL 中 state/code 也是短期敏感数据，不记访问日志或完整错误链。首版不发送可选的 `id_token_hint` / `login_hint`，接受重新选择账号的一步，避免留存 token/邮箱进入终端链接或打开浏览器的命令参数；仍保存 ID token 于私有凭证文件供将来受控使用。callback 页面不回显查询参数或加载第三方资源。[W3] [W4]

沿用 `ModelError` 的脱敏边界，扩展白名单错误分类，而非展示服务器的任意 `message`/`detail`。只保留状态码、已识别 code、已识别参数名、退避时长、经过长度/字符校验的 request ID、响应属于 error/detail/未知结构；不存原始 body。这比官方排错文档建议保留原始 body 更保守，是按本项目“不泄漏日志”的明确约束作的取舍。[C3] [W6]

自动化测试使用虚构 token 和本地测试签名密钥；主动让假 OAuth/模型错误正文回显它们，断言 stdout/stderr、日志、公开 HTTP/SSE、存盘事件、快照均不包含。凭证文件中的虚构 token 属于预期；原始 OAuth 响应不成为快照。现有 shell 仍能以用户权限读取本地文件，0600 不防同 UID 的任意 shell；这是 DESIGN 已写明的边界，不把本方案描述成 OS 沙箱。[C1] [C3]

### 现状、Codex 与建议对照

现状出处：[C2] [C3] [C4] [C5]。Codex/协议出处：[S2] [S3] [W5] [W14] [W15]。表中最后一列是本方案设计。

### 最小模块边界和旧配置兼容

`canter-model` 增加 `Responses` 及私有 wire/SSE 模块，与 `ChatCompletions` 共存；继续使用已有 reqwest、eventsource-stream 和取消机制。只手写需要的字段，不搬整个 Codex core，不引入 agent 框架或通用全 API SDK。OAuth 作为 `canter-server` 内部模块，注入一个只返回当次可用 access token 的窄接口给 Responses；模型包不读磁盘、不决定登录 UI。[C3] [S1] [S2]

服务端拥有模型目录条目：内部路由 ID、provider、线上 slug、显示名、输入模态、思考档位/默认值、上下文窗口、工具格式和计费种类。请求开始时捕获不可变的选中模型/账号/能力快照，整个工具循环用同一份；压缩、`/btw`、`/handoff` 等辅助请求也走同一选择规则，不能留在 DeepSeek 的硬编码选项上。[C4] [C5]

旧的 `base_url/api_key/model/models/context_window/image_models/prices` 原样读作 DeepSeek provider，旧会话里的模型名仍能读，不强制迁移 config。只增加可选 ChatGPT 配置/注册引用；OAuth token 不放进通用 config。新 ChatGPT 模型路由 ID 可用 `chatgpt/<slug>`，发 OpenAI 时去掉内部前缀；旧 DeepSeek slug 保持不变。新协议模型条目增加可选 provider/billing 信息，避免相同线上名字串错账号或价表。[C2] [C5]

### 模型发现、思考档位和窗口

登录授权后，由服务端用**同一账号 token** 调 `GET /v1/models`，按文档的 `models[]` 读取，筛 `visibility == "list"`、保留排序，用 `display_name` 显示、`slug` 调用；它不是普通 API key 的 `{data: [...]}` 目录。按注册身份隔离缓存；切账号即作废对应活动目录，失败保留带“上次获取”标记的缓存。没有登录或账号无权限时，不隐藏 DeepSeek。[W5]

Codex 的 `models-manager/models.json` 和 `ModelInfo` 有档位、窗口、图片及 patch 格式等信息；比如本标签 gpt-6-astra 记录的档位含 low/medium/high/xhigh/max/ultra。但这是**参考能力表，不是用户账号在 SIWC 的权限证明**，Codex app-server 的 `model/list` 也可能返回自带目录。[S3] [W9]

推荐恢复 P2-2 暂时省略的 `supportedReasoningEfforts`、`defaultReasoningEffort`，沿用已有 `inputModalities`，并给核心提供逐模型 context window。DeepSeek 仍只有 none/low/high/max；OpenAI 只显示已确认的档位，不把 DeepSeek 的 max 偷换成 xhigh，也不向所有模型统一发 none。可选字段兼容旧客户端；新客户端连旧服务端时仍按原 DeepSeek 规则处理。[C1] [C5]

现有协议 `ReasoningEffort` 枚举还没有 medium/xhigh，实施时补所需值并保留 Unknown 兼容；旧历史省略值仍按原 high 解释。新服务端必须校验提供方和档位组合，不能因为旧客户端把未知值读作 Unknown 就静默更改真实设置；新的登录/模型能力通过现有 `/v1/info.features` 协商，旧版本不支持时给出升级提示。[C1] [C5]

首版只做普通单 agent 推理档位；即便 Codex 目录出现 ultra，也不能据此开启其自动委派模式，SIWC 预览明确排除了 `multi_agent`，当前 canter 也没有该执行语义。`high` 可作为已确认支持模型的 canter 初始推荐，用户按目录选择；当前档位在目标模型不支持时，选择器同时展示并确认目标有效档位，服务端拒绝不合法组合。[S3] [W7]

公开 SIWC 模型示例只保证 slug/display_name/visibility 的用法，没有完整承诺目录所有能力字段。实现应解析已知字段；缺省能力从**经核实的具体模型资料和版本化小表**补齐，并在真实接入步骤验证。未知模型不能直接继承 DeepSeek 的 1,048,576 窗口，也不能复制 Codex 对未知模型的 272,000 回退值：缺关键窗口时提示尚不支持选择，待补齐已核实元数据。不要本轮替用户固定一个将来的“最新模型”。[C2] [S3] [W5]

### SIWC 请求契约

请求以明确允许的最小字段构造，不能把通用 RequestOptions 全部序列化过去：[W7]

- 固定 `store:false`、`stream:true`；HTTP 每次发送完整所需 input。系统提示及 AGENTS/技能前缀转换成 developer message，保持原顺序和文字。
- 不发 `background`、`conversation`、`max_output_tokens`、`max_tool_calls`、`metadata`、`moderation`、`multi_agent`、`prompt`、`prompt_cache_retention`、`safety_identifier`、`temperature`、`top_logprobs`、`top_p`、`truncation`、`user`，HTTP 不发 `previous_response_id`。也不发 DeepSeek 的 `thinking`、`max_tokens` 或 Chat Completions 的 `stream_options.include_usage`。
- `max_output_tokens` 在现有核心同时承担预留空间和 wire 输出上限两种职责；把它拆清：本地估算/压缩仍预留输出空间，但不能宣称 SIWC 会强制这个 token 上限。保持取消和超时控制；压缩输出过长按既有失败/分块机制处理，不能悄悄截成“成功摘要”。[C4]
- 首版选**稳定 namespace**，例如 canter 内置工具与 MCP 工具分别分组；不使用 `additional_tools` 动态装载。名称映射保留 `(namespace, name)`，只分派目录中存在的工具。函数定义显式 `strict:false` 保留已有可选参数语义，参数仍由工具层校验；以后再单独评估 strict schema。[W7] [W15]
- `apply_patch` 用 custom + Lark grammar，其余是 function。不引入托管 MCP、tool_search、Code Interpreter、图片生成或浏览器工具；已有 MCP 继续由 canter 本地执行普通函数调用。图片继续用会话副本、现有预算与缺图占位规则；不依赖 Files upload API。[C1] [W7]
- 只启用已确认的 `reasoning.effort` / summary。保存返回的 reasoning items；可按 Codex 请求 `include:["reasoning.encrypted_content"]`，不在缺少密文时编造内容。文档目前说新响应默认包含密文，显式 include 与否要按实现时公开 schema 核对。[S2] [W14]

首版只做 HTTP/SSE。WebSocket 续传、官方 compact、hosted conversation 不是完成第二个模型的前提；公开套餐限制也不允许把 HTTP 会话交给 previous_response_id 保存。[W7]

### 流式状态机与私有历史：这部分不能省

现有 `ModelEvent` 只能表达文字、思考文字、工具、用量、结束；`runner.rs` 从增量拼助手历史。直接适配会丢 item 顺序、phase、reasoning 密文，恢复后与第一次请求不一致。[C3] [C4]

推荐最小扩展：保留普通 `Assistant.content` 用于可移植文字/工具记录，在助手历史中新增默认可省略的 provider replay 字段，包含 provider、模型、内部注册/上下文段标识及**按原顺序保存的 Responses output items**。只定义需要的 item 类型和可回传元数据：message 的 id/status/phase/content，reasoning 的 id/summary/encrypted_content，function/custom 的 id/call_id/namespace/name/arguments 或 input。不要把 HTTP 头、认证、任意错误 body 放入该字段。配套新增一次完整输出事件，让核心在成功收齐时存下 replay 数据，而不是仅凭 deltas 重建。[S2] [S3]

规则如下：

1. 用 `output_index` / `item_id` 关联多个交错的 item，不把所有文字/摘要混成一个。工具参数保持原样字符串；item id 与供结果关联的 call_id 分开。工具调用带输入种类，freeform 不先过 JSON parser。[W15] [S2]
2. 文字 delta 立即显示；summary delta 映射公开 `reasoning.summary`，不伪装 DeepSeek 的完整 reasoning content。密文只进 0600 私有模型历史，不解密、不显示、不写入公开 SSE。[C1] [C3] [S3]
3. `response.output_item.done` 只标志一个 item 收完，不代表整次成功。以最终 item 校正已累计内容，不能把 done 全文再拼一次；全部 output 与 `response.completed` 验证后才发 `Finished(ToolCalls)` 或 `Finished(Stop)`。已知工具批次先持久化，再进入既有批准/执行路径。[W5] [C3]
4. `response.failed`、顶层 error、`response.incomplete`、EOF、取消都不释放本批工具执行权。保留已展示的部分文字并标失败/打断；部分调用不当作完整的 provider replay。incomplete 即使有 usage 也要记录计数并报告未完成，不能当成功 stop。[W5] [W6]
5. `response.completed` 可携带 usage；把 input_tokens_details.cached_tokens 映射 cache_read，未命中用输入减命中；output_tokens_details.reasoning_tokens 是 output 子集。缺 usage 表示未知，不能杜撰零消耗。[S2]
6. 未识别的非关键事件可跳过；遇到不认识的输出工具/item，不执行也不丢弃成成功空回复，报「当前版本不支持该输出」并保留已完成的可见内容。拒答文本要能显示；显示事件不是可直接执行的命令。
7. 重试沿用“已交出任何内容或用量后不自动重试”的边界；传输未开始输出时才有限重试暂时错误。流内额度错误同样处理；不能因 HTTP 200 已打开 SSE 就忽略后续失败。[C3] [W5]

新增字段按旧数据缺省，保留 Unknown 不写回的规则。不新增第三套会话存储；provider replay 与普通内容属于同一条私有助手记录，工具结果仍按 call_id 追加。旧程序可能跳过新字段/种类，因而恢复推理能力会有损，不能承诺降级到旧版还能无损接着跑 ChatGPT；公开 transcript 至少能显示已有文字。[C3] [C4]

上下文估算针对该 provider 实际发送的历史视图，不能把普通 content 与 replay 副本重复计数，也不能把密文的字符串长度当作真实 reasoning token 数。现有字节估算仍是近似值，用返回 usage 校正并为目标模型留余量；`/context` 与压缩判断必须采用同一视图。[C4] [S2]

### 专用错误不应都变成“限流重试”

现在只有 RateLimited/Server/Authentication 等粗分类；比如所有 429 都进入有限自动重试，不足以表达套餐用尽。[C3] 推荐在 Responses 保留已识别错误码并映射到用户可操作的分类：[W6]

| 上游码/情况 | canter 行为 |
| --- | --- |
| `subscription_sharing_usage_limit_exceeded`（429，也可能在流中） | 暂停该注册账号的新套餐请求，显示 Usage 入口；不自动重试、不推测重置时间、不换付费接口。人查看限额后可以主动重试。 |
| `subscription_sharing_user_not_eligible`（403） | 显示账号/workspace/策略不符合条件；不循环登录。 |
| `subscription_sharing_usage_unavailable`、`subscription_sharing_user_unavailable`（503） | 保留凭证，未输出时有限退避；已输出则结束失败，由人续聊。 |
| `subscription_sharing_unsupported_capability`（400） | 指出已识别的不支持参数/工具/档位；修配置，不重发同一正文。 |
| `subscription_sharing_route_not_supported`（403） | 指向接入路由错误，不改去 backend-api。 |
| `subscription_sharing_invalid_user`（401） | 做一次受控认证恢复；确认永久失效才提示重新登录。 |
| `chatpass_v2_scope_not_authorized` / `chatpass_v2_invalid_authorization_context`（403） | 检查 client/grant，不能靠换计费或盲目重试解决。 |
| admission 只返回 `detail` 的 401/403/503 | 按认证/策略/暂时不可用分类，不解析 detail 的自然语言当稳定 code；不回显正文。 |
| context length、普通 429/5xx、网络断流 | 沿用压缩/有上限的退避/取消原则，但只对可确认的类别采取动作。 |

### 套餐用量和花费

现在 `usage.rs` 按模型名算美元，缺价表就是 unknown。推荐给每次请求账本加可选 provider 和 `billingKind`（例如 tokenMetered/chatgptPlan），记录当时的模型、账号本地匿名标识和实际 usage。ChatGPT 显示「使用 ChatGPT 套餐」，不套 OpenAI API 单价，也不把 cost=null 直接显示成“$0/免费”。混合会话分别显示 DeepSeek 已估美元与 ChatGPT tokens；套餐部分不使已知 DeepSeek 小计失效。[C4] [C5]

Pro 不受该五小时限制，但官方有应用限额与 credits 控制。token 数不能反推订阅剩余额度或 credits 金额；未查到这条公共 SIWC 路径保证提供 Codex 那样的额度 headers/查询 API。首版用 [ChatGPT Usage 设置](https://chatgpt.com/settings/usage) 管理实际额度，不伪造百分比。用户若在 OpenAI 设置开启 credits，不能承诺 canter 调用绝无额外花费；本方案不自动开启或购买 credits，也不在额度失败后自动改用 DeepSeek。[W4] [W6] [W12]

## 4. 改文件：加入 apply_patch，与 write/edit 共存

### 现状和 Codex

canter `write` 整文件写；`edit` 要求每个 oldText 在原文件唯一且替换不重叠。prepare 生成 diff，批准后再次核对解析路径及原内容，再由 Executor 写入；审查轮拒绝写类工具。现有 `Executor` 的文件操作主要是 open/write，没有删文件和改名接口，不能假装加个工具名即可完成补丁。[C6]

Codex 有 custom freeform `apply_patch` 和 Lark grammar，解析 Add/Delete/Update/Move hunks。`apply-patch` 包还包含路径 URI、执行服务、shell invocation 提取等依赖；它并非可以脱离 Codex workspace 原封不动使用的小库。其 fixtures 还专门覆盖「部分成功后失败保留已改文件」，不能把上游多文件 patch 描述成事务。[S4]

### 推荐的工具组合和执行边界

- DeepSeek：保持 read/write/edit/shell/ask_user/MCP。支持 patch 的 OpenAI 模型：read/apply_patch/shell/ask_user/MCP；不同时向它广告 write/edit，减少重复编辑方式。执行器仍注册旧工具供旧历史识别，但新的实时调用必须在当前模型广告的工具集合内。[C6] [S3]
- 以能力选工具，不用模型名包含“gpt”之类的字符串猜测。尚未确认 custom patch 能力的模型先用现有 write/edit，目录里说明工具能力；不要把“必须先搬 patch 才能做任何 Responses 请求”作为依赖。[S3] [W15]
- 迁入 Codex 的补丁语法、解析和纯文本匹配/变更逻辑及有价值的 fixtures，必要的路径包装改为 canter 类型。复用已有 Executor 做实际读写；对 delete/move 增加最小受控能力。不引入 Codex daemon、shell wrapper、远程执行器或其权限实现。[S4] [C6]
- 一次 patch 全量解析、解析所有源/目标路径、检查保护目录、计算所有 diff 后再请求批准。删除和移动的两端都要检查；拒绝同补丁重复/冲突路径、未知 Environment ID、非本地 URI 等本轮不支持语义。新路径父目录同样过检查，不让 patch 绕过状态目录保护。[C1] [C6]
- 批准后复查所有路径与原内容；冲突时在开始写入前失败，要求重读。复查不能消除所有并发/文件系统竞争，仍沿用现有非沙箱边界。审查轮对 apply_patch 一律拒绝，权限风险归 Write，继续复用 FileChange 和批准决策，不另开授权后门。[C1] [C6]
- 先验证全部变更，再逐文件提交；不承诺跨文件原子事务。提交中途发生 I/O 错误或取消时，报告已完成/未完成文件，不自动重放整份 patch 或用旧副本覆盖用户新改动。Move 按一项操作报告；目标成功但源删除失败也如实报告。保留单文件已有的原内容比较和替换策略。[S4] [C6]
- freeform 原文留在私有工具调用记录；批准 UI 的结构化包装可以含 patch/diff，但发回模型必须仍是 `custom_tool_call_output`，不能错发成 function 的结果。[W15] [S3]

备选是 OpenAI 也只用 write/edit，实施更小，但放弃其专门训练和工具规范中的 patch 使用方式；可以作为先通 Responses 的里程碑，不推荐作为本件最终编辑能力。JSON 包装 patch 的 function 是另一个技术备选，会减少一部分 freeform 类型工作，但本方案已有 Responses replay，推荐一次接对 custom 工具。[S4] [W15]

### 来源和许可证

本轮只参考，没有搬代码。将来迁入时每个文件头注明 `openai/codex`、`rust-v0.163.0`、完整提交、原文件路径和本地修改；保留原有版权/许可证声明。随分发保留 Apache-2.0 许可，维护 canter `NOTICE` 的相关 OpenAI Codex 归属；上游 NOTICE 中的 Ratatui 归属是否与实际迁入文件有关要按文件来源核对，不能把无关部分当成本次 patch 的来源，也不能漏掉实际随搬内容的声明。grammar 和 fixtures 也计入迁入清单；具体依赖锁定并审查，不顺手升级全仓依赖。[C1] [S4] [S5]

## 5. 会话切换和缓存

### 现状与 Codex

canter 已有 `/model` 和会话 PATCH，但只是改变 `settings.model`；核心共享一个客户端、全局窗口，工具清单在打开时固定。历史同时保存独立私有模型记录与显示事件；前缀打开时确定，压缩换上下文，图片只在预算例外下改变请求视图。现有 PATCH 也没有把切模型统一限制在空闲轮边界。[C1] [C4] [C5]

Codex 保留原生 ResponseItem、phase 和 encrypted reasoning；为请求构造固定前缀和 cache key，按模型能力处理配置更新。其缓存实现可参考，但并不解决 DeepSeek 的 reasoning_content 与 OpenAI 密文相互转换。[S2] [S3] OpenAI 缓存要求实际前缀和相关设置相容，`store:false` 不代表每次必定缓存失效，也不保证命中。[W14] [W16]

### 推荐允许同会话切换，但在明确的上下文段边界完成

1. 只有无活动普通轮、工具调用/批准、压缩和 `/btw` 时才接受模型/账号切换；忙时返回 conflict，用户等当前轮结束再选。排队而尚未开始的输入使用切换后模型，界面说明“下一轮生效”。服务端原子更新选择及上下文段，防止两个客户端交错改设置。
2. 切换前验证目标账号、模型、档位、模态和窗口；选择失败不改变原设置。保留当前打开时的 AGENTS、日期和技能内容，只替换与提供方/工具格式相关的固定部分，不顺手重读所有项目指令。[C1]
3. 同 provider、同账号、同模型、同上下文段：回传原生 output items、相应工具结果与密文，保持顺序及 phase；DeepSeek 继续回传其原有完整 reasoning_content。重启恢复仍使用原段信息和已存模型历史。
4. 跨提供方、切模型或换账号时新开一段。旧段的用户/助手可见文字、图片引用、工具名、原样参数/patch 和结果生成**确定性的可移植历史视图**；旧工具调用及结果变成标明来源的历史文本，作为数据交给新模型，不重新执行、不伪造成新 function/custom call。用户/助手角色不升格成 developer；tool 文本明确是不可信的旧输出。
5. 不把 DeepSeek reasoning_content 当 OpenAI reasoning item，也不把 OpenAI summary 或密文塞进 DeepSeek reasoning_content。跨提供方视图只携带可见回答和工具事实，保留用户输入；丢失的是不可跨家解释的推理状态，原盘内容保留。历史里已有的 DeepSeek 原生片段在跨界时也按同一转换规则处理，避免一个请求混用两种不完整工具配对。
6. 以 canter 私有原始记录重建转换视图，不能每切一次就再包一层上一次转换后的文本。新段正常请求仅追加；同一段重启时从存盘的段边界/版本恢复相同视图。切回旧提供方也新开段，不复活中间断开的旧密文状态。
7. 跨模型视图重新估算上下文，按目标窗口做原有手动/自动压缩，不能沿用切换前的 token_usage 当当前占用。旧 usage/花费仍保留在累计账本。目标不收图时明确警告并按约定使用文字占位；原图副本不删除、不悄悄声称模型看过图。[C1] [C4]

这是有意保守的转换：比“任意模型都原样回放另一家的工具项”可靠，也比“切换自动先花一次模型请求生成摘要”可预测。代价是切换后的首个请求更可能冷缓存、失去专有推理状态；用户可选只开新会话来缩小首版范围（§7）。这里没有宣称两家模型能无损互转。[C3] [W14]

### 缓存规则如何落地

- 继续遵守 DESIGN 第 17 条：同段不重写已有消息/工具结果，工具排序和 schema 固定，前缀不带每轮变化的时间。Responses 保持 item 顺序与已返回 phase，不能重新聚合成另一种结构。切模型和压缩本来就是已获准例外。[C1] [W16]
- provider/模型/账号不同，预期新缓存；不许诺 DeepSeek 与 OpenAI 共享，也不承诺切回后会命中。`prompt_cache_key` 如使用，采用无身份数据的稳定会话段随机标识，不放 email、目录路径或 token；它不能替代前缀稳定，也不是额度或命中保证。[W16] [S2]
- 原生 reasoning 密文按模型文档回放；不要因它人不可读就在恢复时丢弃。缓存命中数字来自 usage，不用“相同文本长度”估出来。预算内图片的 data URL、工具序列化和 JSON 字段顺序保持确定性。[C3] [W14] [W16]
- OpenAI 当前指南针对 GPT-6 普通单 agent 支持追加 `configuration_update` 调 reasoning effort，顶层初始 effort 保持不变；不允许相邻两个 update。推荐对**已核实 SIWC 接受此能力的模型**使用它，更新在下一条用户输入前提交，连续未发送的选择只提交最终值，重启回放其原位置。[W17]
- 未确认这项能力的模型暂不允许在同一段改变 effort：提示新开会话或明确重新选择模型开启新段；不悄悄破坏前缀。不能为了这个优化把公开示例的 `store:true`、`previous_response_id`、自动截断抄进套餐请求。原有 canter 摘要压缩另起请求/新段，不依赖 OpenAI compact endpoint。[W7] [W17]
- 不把普通 API 文档的显式缓存写入价格、保留期或高级 cache 参数当作 SIWC 的承诺；首版只记录实际 cached_tokens，先做好稳定前缀。§6 的实测可以观察命中，不能因短请求没有命中就认定适配失败。[W7] [W16]

### 哪些仍须用户在场，准备调多少次

登录成功不能证明推理权限，目录也不等于一次真实 inference 完成。[W5] [W9] 把真实验证独立成最后一件，先提交离线通过的可审实现，再由主控安排用户在场授权。默认人工现场步骤如下；**本轮实际次数全部为 0**。

| 步骤 | 默认真实请求预算 | 目的 |
| --- | --- | --- |
| 首次 OAuth、账号确认、目录 | 浏览器授权流程 1 次；authorization-code token POST 1 次；models GET 1 次；discovery/JWKS 按需只读获取，各至多 1 次 | 验证动态注册、身份/scope、所选账号目录；不自动发送测试提示。 |
| 一轮极短文字 | Responses POST 1 次 | 核对 stream/completed、摘要/usage/套餐标记，证明该模型这次可用。 |
| 一轮可审查文件修改 | Responses POST 2 次：提出一次 apply_patch、交回结果后一次总结 | 临时无隐私工作目录，用户正常批准；验证 custom tool 原文、结果类型和多轮密文回传。若模型多叫工具，暂停而非无限增加请求。 |
| 服务重启后续聊 | Responses POST 1 次 | 验证同账号/同模型私有历史恢复；使用同一次准备好的历史观察缓存，命中不是承诺。 |
| 到达可刷新时间后续聊 | refresh token POST 1 次；Responses POST 1 次 | 验证轮换、无需重新登录、重新启动不会读旧 token；不用篡改真实 token 提前强刷。 |
| logout | revocation POST 1 次 | 确认本地清除与远程撤销；不再发送故意失败的模型请求。 |

默认合计 **5 次 Responses 推理请求**，认证/目录/撤销另计；真 DeepSeek 为 **0 次**，跨提供方回归用双假服务即可。每次记录只有次数、场景、是否完成和安全错误分类，不提交真实 prompt、账号标识、令牌或原始响应。为准确计数，现场冒烟禁用自动网络重试；如需更多工具回合、换模型、图片验证、配置更新验证或因故重试，先报告剩余需求，再取得当时的明确同意。未实测的高级能力维持关闭；不用花费额度来证明每个可离线复现的失败分支。
