# 展示层方案

2026-10-26，canter/dev-display，P2-18 本轮只出方案，不写代码。

## 一句话

canter 现在只用终端自己的 16 色加灰、粗、斜体，没有底色、没有行号、没有语法色，表格原样显示，思考和长输出事后看不到全文。推荐：

- 界面颜色继续跟着终端的配色走，只有 diff 的加删行铺浅底色，铺不铺按终端深浅和色深自动判断；颜色收进一处。
- diff 用统一格式，加行号、整行底色、改动的词再深一档；历史里长 diff 收起。
- 代码块按语言上色（syntect + two-face，程序大约多 1.9 MB），用终端调色板的配色。
- markdown 表格画成对齐的框线表格，中文按 2 列算，放不下时格内折行，再放不下改成一条条记录。
- 思考默认收起成一行，进行中显示最新的一句；一个键 Ctrl+O 把思考、长输出、长 diff 全部展开或收起。
- 工具卡片统一成「● 动词 对象 …… 状态」，失败用 `✗` 加红色，失败时多留几行输出。
- 项目之间空一行；状态行写明在干什么，并提示 Esc 打断。

## 1. 配色和主题

### canter 现在

- 只用终端的 16 色里的四种：青色（`›`、选中项、行内代码、代码块、`@@` 行、转圈）、绿色（成功的圆点、`+` 行、`+N`）、红色（失败、`-` 行、`−N`、信息行里的 `Allow all`）、黄色（批准框边框、等批准、警告）；另外用灰（dim）、粗体、斜体、下划线。不铺任何底色。
- 颜色直接写在各个文件里（`cells.rs`、`app.rs`、`approval.rs`、`commands.rs`、`markdown.rs`、`picker.rs`、`question.rs`、`btw.rs`，大约 120 处），没有统一的地方。
- 不判断终端是深色还是浅色，不判断支持多少种颜色，不认 `NO_COLOR`。
- 因为只用终端调色板里的颜色，换终端主题时 canter 自动跟着变；深浅底基本都看得清，只有浅色底上的黄字常常很淡。

### 别家

- Codex：启动时向终端问前景色和底色（OSC 10/11 控制序列，最多等 250 ms，`terminal_probe.rs`），按底色深浅选 diff 底色和代码配色（深色 catppuccin-mocha、浅色 catppuccin-latte，`render/highlight.rs`）；用 supports-color 库判断真彩 / 256 / 16 色，各备一套颜色（`terminal_palette.rs`、`diff_render.rs`）；浅色底或不知道底色时不用黄色（`style.rs`）。`/theme` 从 32 套代码配色里选，`$CODEX_HOME/themes` 放自定义 `.tmTheme`，存在配置 `tui.theme`（`config/src/types.rs`）。
- pi：默认 `system` 主题，问终端的前景、底色和 16 色，按最低对比度生成整套颜色；另有 `dark`、`light`，写成 `light/dark` 时跟着终端深浅切；最多等 100 ms；可以写 JSON 自定义主题（`packages/coding-agent/docs/themes.md`）。
- opencode：自带 30 多套 JSON 主题，每套分深浅两版；`system` 主题从终端调色板生成；`/theme` 选（`packages/tui/src/theme/system.ts`、`theme/assets/*.json`）。
- Claude Code（文档，terminal-config「Match the color theme」）：`/theme` 选预设：dark、light、色弱友好的 daltonized、只用 ANSI 色的 dark-ansi / light-ansi；选 auto 时按终端底色深浅自动切。可以在 `~/.claude/themes/*.json` 按颜色名覆盖（如 `diffAdded`、`diffAddedWord`、`userMessageBackground`）。

### 推荐

- **界面颜色继续用终端的 16 色**，不自带调色板。理由：用户换终端主题 canter 自动跟着变，深浅底都不会错，16 色终端也一样；这是 canter 现在已经有的长处。
- **只有要铺底色的地方用真彩色**：diff 的加删行和改动的词（第 2 项）。这几种颜色分深色底、浅色底两套（加删行取 Codex 的值，改动的词深一档，实现时在真终端里看着调）。
- **深浅自动判断**，判断不了就不铺底色：
  1. 环境变量 `CANTER_THEME=dark` 或 `light` 优先，给判断错或问不到的时候用。
  2. 否则启动时问一次终端底色（OSC 11）。用 terminal-colorsaurus 1.0.3（bat、delta 都在用；它顺带发一个所有终端都会回的查询当「哨兵」，不支持的终端马上知道，不用等满超时）。等待上限 200 ms，支持的终端一般几毫秒就回。只在启动时、读键盘的线程起来之前问（`run.rs` 进全屏那里）。
  3. 问不到看 `COLORFGBG`（有的终端会设，形如 `15;0`）。
  4. 还不知道：当作「不知道」，diff 不铺底色，退回现在只上前景色的样子。不像 Codex 那样默认当深色：猜错时浅色底上铺暗红暗绿，比不铺难看。
- **色深**：`COLORTERM` 是 `truecolor` 或 `24bit` 按真彩；`TERM` 里有 `256color` 按 256 色，真彩色就近换成 256 色表里的颜色（跳过前 16 个，它们随终端设置变）；其余按 16 色，不铺底色。`NO_COLOR` 非空时不上任何颜色，只留粗体、斜体、下划线、反色（no-color.org 的约定）。
- **浅色底上的黄字**：警告、等批准这类文字改成默认色加粗（照 Codex）；批准框边框照旧黄色。
- **颜色收进一处**：新建 `theme.rs`，按用途取名，各处只用用途，不再直接写颜色：

  | 用途 | 用在哪 | 颜色 |
  |---|---|---|
  | 强调 | `›`、选中项、行内代码、没写语言的代码块、转圈 | 青 |
  | 成功 | 成功的圆点、`+N` | 绿 |
  | 失败 | 失败的 `✗`、`exit 1`、错误文字、`−N` | 红 |
  | 警告 | 批准框边框、等批准、`!` 警告 | 黄（浅色底：文字改默认色加粗） |
  | 次要 | 卡片右边的说明、命令输出、路径后的行号范围 | 灰 |
  | 思考 | 思考 | 灰 + 斜体 |
  | diff 加 / 删行 | `+` / `-` 号；不铺底色时整行文字 | 绿 / 红 |
  | diff 加 / 删行底色 | 真彩或 256 色且知道深浅 | 深色底 `#213A2B` / `#4A221D`，浅色底 `#DAFBE1` / `#FFEBE9`；256 色就近取 |
  | diff 改动的词 | 同上 | 比整行底色深一档；16 色下反色 |

- **不做多套主题、不做自定义主题文件、不加 `/theme` 命令**。想换颜色就换终端主题。颜色都在 `theme.rs` 里，以后真要自定义只动这一处。
- **运行中终端切换深浅不跟**（比如 macOS 自动外观切换），下次打开 canter 生效。

### 备选

- 自带一整套真彩调色板（pi、opencode 的做法）：每种颜色自己定，在哪个终端里样子都一样，可以调得更好看。代价：必须问到底色才不出错，问不到时浅色底上可能一片浅色字；深浅两整套颜色要维护；用户换终端配色 canter 不跟。
- 几套预设加 `/theme`（Claude Code 的做法）：多一个命令、一份存设置的文件。现在只有你一个人用、终端固定，收益小；颜色收进 `theme.rs` 以后，再加也不难。

## 2. diff

### canter 现在

- 工具层用 similar 生成统一 diff（上下各 3 行上下文），发给终端前限 1 MiB。
- 历史里的卡片：`● Edit 路径  +a −r`，下面整份 diff，每行 `    │ ` 开头，`+ ` 绿、`- ` 红、上下文灰、`@@ … @@` 青色。没有行号、没有底色、不标行内改了哪几个词。整份全显示，不收起：新建一个 300 行的文件，对话里就是 300 行。
- 批准框：标题 `Edit this file?`，第一行路径和 `+a −r`，下面整份 diff，标记和颜色同上；放不下时 PgUp/PgDn 翻。控制字符显示成转义（`visible()`），什么都藏不住。

### 别家

- Codex（`diff_render.rs`）：统一 diff；一列行号（加行和上下文用新行号，删行用旧行号）；加删行整行铺底色，深浅底、真彩 / 256 色各一套，16 色只上前景色；diff 里的代码也按语法上色；块和块之间一行 `⋮`；不标行内改动的词。多个文件时先一行 `• Edited 6 files (+9 -9)`，每个文件一行 `└ 路径 (+3 -0)`。
- pi（`modes/interactive/components/diff.ts`）：统一 diff，带行号；加删行只上前景色；正好一删一加时按词比较，改动的词反色。
- opencode（`routes/session/index.tsx` 的 `Edit`）：窗口宽于 120 列默认左右并排，否则统一；带行号；加删行和行号都铺底色；配置 `diffs.view` 可固定一种，`diffs.wrap` 定怎么折行。
- Claude Code（文档：颜色名 `diffAdded`、`diffRemoved`、`diffAddedWord`、`diffRemovedWord`；其余是行为）：统一 diff，带行号，加删行铺底色，改动的词底色再深一档；工具结果先一行「Updated 路径 with 2 additions and 1 removal」再跟 diff。

### 推荐

- **统一 diff，不做左右并排**。canter 常在 80～120 列的窗口里，卡片缩进 4 列，批准框再少 4 列；并排后每边不到 40 列，中文注释和长代码行一折就乱。Codex、pi、Claude Code 都只做统一。
- **行号**：一列，宽度按这份 diff 里最大行号的位数。删行用旧行号，加行和上下文用新行号（照 Codex）。有了行号，`@@` 行不再显示，块和块之间一行灰色 `⋮`。
- **底色**：真彩或 256 色、且知道深浅时，加行、删行整行铺浅底色（铺到行尾），文字用默认色，`+` / `-` 号绿 / 红。16 色或不知道深浅时不铺底，整行绿 / 红字（就是现在的样子）。
- **行内改动**：一段连着的删行和加行，行数一样时一一配对；每对按词比较，改动的词底色再深一档，16 色下反色。用 similar 的 `inline` 功能（canter 已经在用 similar 2.7.0，不加新库）。一对里相同的部分不到一半就不标，免得整行花掉。行数不一样不配对、不标。
- **diff 里的代码不按语法上色**（这一轮不做）。底色和语法色叠在一起要另算对比度，Codex 为此专门写了一套；先把行号、底色、改动的词做好。
- **收起**：
  - 历史里改文件（Edit）每个文件最多显示 12 行，新建文件（Add）最多 6 行，删除文件（Delete）只显示标题；多的部分一行 `… 40 more lines · Ctrl+O`。按 Ctrl+O 全部展开（第 5、6 项同一个键）。
  - 批准框照旧全显示、可以翻：批准之前要看全。
- **长行**：照旧折行，折出来的行对齐到行号后面的文字。
- 批准框和历史共用一套画法；批准框照旧先过 `visible()`，新画法不能绕过它。

## 3. 代码块

### canter 现在

- 围栏代码块整块青色，在模型正文的 2 列缩进里再缩 2 列；不显示围栏和语言名；不上语法色；长行折行；整块全显示。行内代码青色。

### 别家

- Codex（`render/highlight.rs`、`markdown_render.rs`）：syntect + two-face，约 250 种语言；配色按底色选 catppuccin 深 / 浅；输入超过 512 KB、1 万行或某一行超过 4 KiB 就不上色；流式输出时有专门的增量上色（`render/highlight_streaming.rs`）。
- pi（`packages/coding-agent/src/utils/syntax-highlight.ts`、`packages/tui/src/components/markdown.ts`）：highlight.js，启动时载 21 种常用语言，其余另外一次全部载入（`loadAllHighlightLanguages`）；围栏行 ```` ```lang ```` 灰色显示出来。
- opencode（`packages/tui/src/parsers-config.ts`）：tree-sitter，每种语言下载一个 WASM 语法包。
- Claude Code（文档，interactive-mode「Theme and display」）：代码块上语法色，`/theme` 里按 Ctrl+T 开关。

### 推荐

- **上语法色**。库：syntect 5.3.0 加 two-face 0.5.2（bat 用的同一套语法定义）。正则引擎用 onig（C 写的 Oniguruma，编进程序里；canter 已经在编 aws-lc-sys、ring 这类 C 代码，不多一类构建要求）。
- **实测**（相对空程序；每种连跑 3 次，上色时间含第一次用到时编译正则）：

  | 组合 | 程序多出 | 语言数 | 513 行 Rust 上色 | 载入语法表 |
  |---|---:|---:|---:|---:|
  | syntect + two-face，onig（推荐） | 1.9 MB | 220 | 14 ms | 1～3 ms |
  | syntect + two-face，纯 Rust 的 fancy-regex | 3.4 MB | 213 | 39 ms | 1～3 ms |
  | 只用 syntect 自带的语法（fancy-regex） | 2.7 MB | 75 | 42 ms | 1～2 ms |

  syntect 自带的 75 种缺 TOML、TypeScript、TSX、Swift、Kotlin、Dockerfile、Zig、Nix；two-face 都有。加上以后 canter 大约从 19.0 MB 到 21 MB。
- **配色**：用 two-face 里的 `ansi` 配色。它只用终端 16 色里的颜色，普通文字用终端默认色。理由和第 1 项一样：跟着终端走，深浅底都看得清，16 色终端也能用，不用另外判断深浅。代价：只有终端的几种基本色，没有 catppuccin 那种真彩配色丰富。
- **语言识别**：只看围栏后面写的语言名（```` ```rust ````、```` ```ts ````、```` ```sh ````……），按 syntect 的名字和扩展名找，补几个别名（照 Codex 的 `find_syntax`：`golang`→go、`shell`→bash、`python3`→python、`csharp`→C# 等）；没写语言的看第一行是不是 `#!`；都没有就照现在整块青色。不按内容去猜。
- **很长的代码块**：全显示，不收起（这是回答本身）；长行照旧折行。超过 Codex 那三个上限（512 KB、1 万行、单行 4 KiB）就不上色，整块青色。
- **流式时要缓存**：P2-16 以后，进行中的回答每次重画（100 ms 一次）都从头渲染。上色要记住已经写完的行，只算新来的；不然一个几百行的代码块每帧都要重算一遍（按上表，500 行十几毫秒）。
- **不显示围栏和语言名**（Codex、Claude Code 都不显示）。
- 行内代码照旧青色。

### 备选

- 按深浅选真彩配色（Codex 的 catppuccin mocha / latte）：颜色丰富得多。代价：问不到底色时默认深色配色，浅色底上的浅色字看不清；256 色要就近换色；16 色还得退回 `ansi`。
- 不上色、不加库：程序不变大；代价是代码块只有一种颜色，和别家差距明显。
- tree-sitter（opencode）：上色更准；每种语言一个 C 写的语法包，还要自己配高亮规则，语言越多越大。没实测大小；对终端里看一眼代码来说过重。
- 像 pi 一样把 ```` ```rust ```` 和 ```` ``` ```` 两行灰色显示出来：块的起止更清楚，按住修饰键拖选复制时带着围栏；代价是每块多两行。

## 4. markdown 表格（原 P2-17）

### canter 现在

- 没开 pulldown-cmark 的表格扩展，表格原样显示成一行行 `| a | b |` 和 `|---|---|`。

### 别家

- Codex（`markdown_render.rs` 开头的「Table rendering pipeline」、`streaming/table_holdback.rs`）：不画竖线，表头下一行粗线 `━`，行和行之间细线 `─`，列间空两格；按列内容分「长句 / 路径这类长词 / 短值」分配宽度，路径先折；放不下时改成一条条「键 / 值」记录；流式时表格那一段一直留着重排，不提前写死。
- pi（`packages/tui/src/components/markdown.ts` 的 `renderTable`）：全框线 `┌─┬─┐`，每行之间都画分隔线；先按自然宽度，放不下按比例缩、格内折行；连最窄都放不下就退回原样的 markdown。
- opencode（`routes/session/message-parts.tsx`，`tableOptions={{ style: "grid" }}`）：opentui 自带的网格表格。
- Claude Code（行为）：画带框线的表格。

### 推荐

- **开表格扩展，画成对齐的框线表格**：框线灰色，表头粗体，表头下一条分隔线。数据行之间平时不画线（紧凑）；有格子折成多行时才在行和行之间画线，不然分不清哪几行是一格。
- **对齐**：照表格里写的 `:---`、`:---:`、`---:` 左、中、右对齐，没写的左对齐；表头跟着本列对齐。
- **中文**：宽度按显示宽度算（canter 已经在用的 unicode-width，中文和全角标点算 2 列），用空格补齐；格子里的粗体、行内代码照样上样式。已知限制：终端设成把「东亚模糊宽度」字符（`→`、`…`、`①`，以及框线本身）画成 2 列时会错位；个别 emoji 在各终端里宽度不一，也可能错一格。
- **比屏幕宽**：
  1. 先按每列最宽的内容排；放得下就这样。
  2. 放不下：每列至少留住本列最长的一个词（最多 16 列，再长的词也要断），剩下的宽度按各列还差多少按比例分，格子里折行。
  3. 还放不下（列太多，平均一列不到 6 列）：改成一条条记录，每行一块「表头: 值」，块之间一条灰线（照 Codex）。
- **流式**：表格每来一行就整张重排。P2-16 以后进行中的部分每帧都重画，不用像 Codex 那样专门留着；`markdown.rs` 开头「流式时前缀不能变」那条理由已经没了（P2-16 的完成记录也提到了），表格重排不受它限制。
- 要动的接口：markdown 渲染现在不看宽度（先排版、后折行），表格要在渲染时知道可用宽度，`markdown::render` 和 `cells::agent_message` 加一个宽度参数；宽度变了本来就整段重画。

### 备选

- 放不下时退回原样的 markdown（pi）：最简单，不会把表格换成别的样子；代价是窄窗口里又回到 `|` 和 `|---|`。
- 不折行，放不下的格子截掉加 `…`：每条一行，最整齐；代价是内容看不全，表格是回答本身，Ctrl+O 也展不开它。
- 不画竖线、只画横线（Codex 的样子）：每行省 3～4 列；代价是列和列之间只靠空格分，中文多的时候不好认。

### 状态行写明在干什么

- 现在：`⠋ Working · 3s`，不说在干什么，也不提示怎么停。
- 别家：Codex `• Working (3s • esc to interrupt)`，标题会换成思考摘要的标题（`chatwidget/streaming.rs`）；Claude Code 是转圈加一个动词、秒数、token 数和 `esc to interrupt`（行为）。
- 推荐：按正在进行的那一项换词，后面统一提示 Esc：`Thinking`、`Writing`（写回答）、`Running cargo build`（命令截断）、`Reading`、`Editing`、`Calling`、`Fetching`。只改状态行；卡片里不加转圈和计时：卡片在对话区，一动就会让往上翻时的 `↓ New output below` 误报（P2-16 定的是进行中的部分有任何变化都算新输出，只有状态行的转圈和计时不算）。

```
 ⠋ Thinking · 3s · Esc to interrupt
 ⠋ Writing · 5s · Esc to interrupt
 ⠋ Running cargo build · 12s · Esc to interrupt
 ⏸ Waiting for approval · 15s
```

### 不做的

- 每轮结束一条分隔线（Codex 的 `─ Worked for 1m 23s ─`，`history_cell/separators.rs`）：一轮和一个项目都没有开始、结束时间，断线重连后拿不到，显示会前后不一致；要做得先改协议。同理思考也不写「想了几秒」。
- 用户消息铺底色（Codex、Claude Code 有）：现在 `›` 加前后空行已经分得清。
- 终端超链接（OSC 8）、限制正文宽度、运行中跟着终端切换深浅：都不是这次的痛点。

## 要用户选的

按重要程度排，每个都写了推荐。

1. **配色路线**
   - A（推荐）：界面跟着终端的 16 色；只有 diff 铺底色，深浅自动判断，判断不了就不铺；`CANTER_THEME` 可强制。
   - B：自带一整套真彩调色板（像 pi、opencode），在哪个终端里样子都一样。
   - C：几套预设加 `/theme` 命令（像 Claude Code）。
2. **代码块上不上色、用什么配色**
   - A（推荐）：上色，syntect + two-face（程序多约 1.9 MB），用终端调色板的 `ansi` 配色。
   - B：上色，按深浅选真彩配色（catppuccin），颜色更丰富，问不到深浅时浅色底上看不清。
   - C：不上色，不加库。
3. **思考默认怎么显示**
   - A（推荐）：收起成一行，进行中显示最新的一句，Ctrl+O 展开全文。
   - B：默认展开全文。
   - C：主界面不显示，只能在展开时看。
4. **事后怎么看收起的内容**
   - A（推荐）：Ctrl+O 在原地全部展开 / 收起（思考、长输出、长 diff 一个键）。
   - B：Ctrl+O 打开单独的详情页，`q` 回来。
   - C：不做，收起的就看不到（现在的样子）。
5. **diff 并不并排**
   - A（推荐）：只做统一 diff（行号、底色、改动的词）。
   - B：窗口够宽（比如 140 列以上）时自动左右并排。
6. **历史里的长 diff 收不收**
   - A（推荐）：改文件每个文件最多 12 行、新建文件 6 行、删除文件只留标题，Ctrl+O 看全；批准框照旧全显示。
   - B：照现在全显示。
7. **表格放不下时**
   - A（推荐）：格内折行；还放不下改成一条条「表头: 值」记录。
   - B：格内折行；还放不下退回原样的 markdown（pi）。
   - C：不折行，超出部分截掉加 `…`。
8. **项目之间空不空行**
   - A（推荐）：每段话、每张卡片之间空一行，连着的读文件不空。
   - B：照现在不空，更紧凑。
