# 远程连接说明：在一台机器上用 canter 干另一台机器上的活

这份是概览：三台机器各管什么、要配什么、哪些只做一次。命令细节和各种情况看 [`remote.md`](remote.md)（英文）。

## 一句话

canter 的服务端跑在**代码所在的机器**上（下面叫「服务端机器」，比如 5090）；你手上的电脑（下面叫「客户端」，比如 Mac）只开终端界面，通过网络连过去。模型调用、跑命令、读写文件都在服务端机器上发生，客户端只负责显示和输入。

两台机器不在同一个网络、互相连不到时，中间借一台有公网地址的 VPS 当「中转」。

## 三台机器各管什么

```
 客户端（Mac）                 中转 VPS                     服务端机器（5090）
┌─────────────────┐        ┌──────────────────┐        ┌──────────────────────┐
│ canter 终端界面   │        │ 只有 sshd         │        │ canter 服务端          │
│ remotes.json     │        │ 不装 canter       │        │ 代码、模型 key、会话    │
│ （地址 + 令牌）    │        │ 不存代码和令牌     │        │ remote-tokens.json    │
│                 │        │                  │        │ （令牌的哈希）          │
│ 127.0.0.1:8791 ─┼─ ssh -L ─▶ 127.0.0.1:8790 ◀─ ssh -R ─┼─ 127.0.0.1:8790       │
└─────────────────┘        └──────────────────┘        └──────────────────────┘
        两条连接都是客户端、服务端机器各自「主动连出去」到 VPS；VPS 不主动连谁
```

| 机器 | 装 canter 吗 | 要配什么 |
|---|---|---|
| 服务端机器 | 要，而且是主角 | `config.json` 里开一个**只听本机回环**的端口；给每个客户端发一个令牌；开一条 `ssh -R` 到 VPS |
| 客户端 | 要（只用它的终端界面） | `canter remote add` 记下地址和令牌；开一条 `ssh -L` 到 VPS |
| 中转 VPS | **不用** | 只要能 SSH 登录（有你两台机器的公钥），sshd 用默认设置就行 |

## VPS 上到底要做什么

**用 SSH 隧道的方式（现在用的），VPS 上什么都不用装、不用改：**

- 只要 sshd 在跑，`authorized_keys` 里有客户端和服务端机器各自的公钥。
- sshd 默认允许端口转发（`AllowTcpForwarding yes`），默认 `GatewayPorts no`：`ssh -R` 开的端口只绑在 VPS 自己的 `127.0.0.1` 上，**公网连不进来**，不用改防火墙。
- VPS 上不跑 canter，不存代码、不存令牌、不存模型 key。它只是把两条 SSH 连接在自己的回环地址上接起来。

**建议加的一项（P2-302 加了）：** sshd 心跳。加一个单独的文件 `/etc/ssh/sshd_config.d/canter-relay.conf`，写 `ClientAliveInterval 15`、`ClientAliveCountMax 3`，`sudo sshd -t` 查过再 `sudo systemctl reload ssh`（不断现有连接）。这样悄悄断掉的旧连接约 45 秒就被清掉，服务端机器重连时不会因为旧的 `-R` 还占着端口而连不上。退回就删这个文件再 reload。

**以后才要做的（可选，P2-300）：** HTTPS，给网页、手机用。那时才要在 VPS 上装 Caddy、开 80/443、配域名或证书。手机、网页不能开 SSH 隧道，所以要走 HTTPS。

## 第一次怎么配（只做一次）

**服务端机器上：**

1. 装好 canter，模型和 key 照常配在这台机器的 `~/.canter/config.json`。
2. 在 `config.json` 里加（端口自己挑一个没用的）：
   ```json
   { "remote": { "listen": ["127.0.0.1:8790"] } }
   ```
   只接受回环地址，不会对外开端口。然后 `canter serve --replace` 换一下服务端，`canter doctor` 应该显示 `Listening on 127.0.0.1:8790`。
3. 给客户端发令牌：`canter remote token add mac`。令牌**只显示一次**，自己复制下来，私下带到客户端。服务端只存它的哈希。撤销用 `canter remote token remove mac`。

**客户端上：**

4. 记下这台服务端：
   ```sh
   canter remote add 5090 http://127.0.0.1:8791
   ```
   提示 `Paste the token, then press Enter` 时把令牌粘进去（不显示）。存在 `~/.canter/remotes.json`（权限 0600）。令牌不放进命令行、网址、仓库或日志。

**SSH 准备：**

5. 两台机器都能 `ssh <VPS>` 免密登录（各自的密钥，公钥放进 VPS 的 `authorized_keys`）。建议在各自的 `~/.ssh/config` 里给 VPS 起个别名（比如 `gcp-relay`）。密钥不要设密码，下面的系统服务没有终端，没法输密码。

**让隧道和服务端一直开着（交给系统管）：**

6. 服务端机器（Linux）：`sudo loginctl enable-linger "$USER"` 一次（你没登录时用户服务也跑；开了就生效，不用重启）。再写两个 systemd 用户服务，`systemctl --user enable --now` 起来：
   - `canter-relay-tunnel.service`：跑上面那条 `ssh -R`，`Restart=always`，断了 10 秒后重连；
   - `canter-server.service`：跑 `canter serve`，开机自起，`Restart=on-failure`（崩溃了 5 秒后重起；`serve --replace`、`canter upgrade` 换服务端时旧的是正常退出，systemd 不插手）。
7. 客户端（Mac）：写一个 launchd 用户代理（`~/Library/LaunchAgents/` 下的 plist），跑那条 `ssh -L`，`KeepAlive`，登录时自起、断了自己重连。

单元文件和 plist 的完整内容见 [`remote.md`](remote.md)「Keep the tunnels and the server running」。

## 每次用的时候

1. **隧道不用管**：配好第 6、7 步后，开机、登录、断线、换代理节点、睡醒，都由系统自己重连（实测 3～13 秒）。手动开隧道只在临时试用时用：
   ```sh
   # 服务端机器上
   ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 \
     -R 127.0.0.1:8790:127.0.0.1:8790 gcp-relay
   # 客户端上
   ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 \
     -L 127.0.0.1:8791:127.0.0.1:8790 gcp-relay
   ```
2. **连过去**：开新会话要写 `--cwd`，接旧会话不用。

   | 用法 | 要不要 `--cwd` |
   |---|---|
   | 开新会话：`canter --server 5090 --cwd /服务端机器上的/项目/绝对路径` | **要**。不写会报错；客户端的当前目录对服务端机器没意义，canter 不猜 |
   | 从列表接回：`canter --server 5090 -r` | 不用，每个会话带着自己的目录；写了就只列那个目录的 |
   | 接回指定会话：`canter --server 5090 --resume <会话 id>` | 不用，用那个会话原来的目录 |
   | 接回最近一个：`canter --server 5090 -c` | 不用；写了就接那个目录最近的 |
   | 不开界面跑一轮：`canter exec --server 5090 --cwd /…/项目 "要做的事"` | 开新会话时要；`--last` 接最近的不用 |

   路径是服务端机器上的绝对路径，长的话在客户端的 `~/.zshrc` 里给常用项目起个短命令：
   ```sh
   alias proj='canter --server 5090 --cwd /home/<用户名>/<项目>'
   ```
   之后 `proj` 开新会话，`proj -c` 接回这个项目最近的会话。

两台机器能直接 SSH（比如同一个局域网）时，不需要 VPS：客户端直接 `ssh -L 127.0.0.1:8791:127.0.0.1:8790 <服务端机器>` 一条就够。

## 安全上要知道的

- 令牌等于「能以服务端那个用户的身份让 agent 干活」，像密码一样保管；一个客户端一个令牌，丢了就在服务端 `token remove`。
- 令牌只会发往 https 地址或 `127.0.0.1` 这类回环地址；canter 拒绝把它发到明文的远程 http 地址，也不跟随重定向、不走环境代理。
- 现在这种两段 SSH 隧道：网络上两段都加密，但**在 VPS 上是解开的**（VPS 能看到经过的内容和令牌）。所以 VPS 要当成自己的机器来管（只用密钥登录、不给别人用）。端到端加密到服务端机器是 P2-300 的方向。
- 一台服务端只服务一个人，不支持多人共用。

## 远程和本机有什么不一样

大部分一样：本机其实也是终端连服务端，只是走 unix socket。远程时的区别：

- 文件在服务端机器上：点文件链接只复制路径；想在客户端编辑器里看代码，另想办法（比如编辑器的远程插件）。
- 模型账号、key、MCP、`/memory` 的编辑、ChatGPT 登录，都在服务端机器上管。
- 贴图和拖文件：客户端读出图片内容发过去，和本机一样能用。
- 分支名、改动行数、`/diff`、`/files`、`@` 补全、`/review`：都由服务端查，显示的是服务端机器上的仓库。
- 状态栏脚本在客户端跑，数据来自服务端。
- 断线：服务端上的会话照常跑；隧道回来后终端自己接上，按事件编号续收，不丢不重。断线时点的批准不会被偷偷补发，接上后再点一次。
- 两边版本最好一致：版本不同会提示升级（现在这句提示总是叫你去服务端升级，客户端旧时方向是反的）。

## 出了问题先看哪里

| 现象 | 先看 |
|---|---|
| 一直 `Reconnecting…` | `curl --noproxy '*' http://127.0.0.1:8791/v1/info` 回 401 说明整条链路是通的。不通就分段看：Mac `launchctl print gui/$(id -u)/<代理名>`；服务端机器 `systemctl --user status canter-relay-tunnel canter-server`、`journalctl --user -u canter-relay-tunnel` |
| 升级后服务端崩溃没自己回来 | `canter upgrade`、`serve --replace` 起的新服务端不归 systemd 管，到下次开机前崩溃不会自己重起（P2-304 记着）。在服务端机器上 `systemctl --user start canter-server` |
| 401 / unauthorized | 令牌被撤了或粘错了：服务端 `canter remote token list`，客户端 `canter remote remove` 后重新 `add` |
| 连上但提示升级 | 两边 `canter --version` 对一下，旧的那台 `canter upgrade` |
| `doctor --server 5090` | 看的是服务端机器上的情况（监听、令牌、模型） |
| 服务端机器上 `@` 补全没候选 | 升级后没换服务端：在服务端机器上 `canter serve --replace` |
