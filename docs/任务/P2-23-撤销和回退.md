## 要做的

- **记下改前的样子**：每次 canter 自己的 `write`、`edit` 改文件之前，把这个文件当时的内容（或者「原来没有这个文件」）记到会话目录里，记在哪一轮名下。shell 命令和 MCP 工具改的文件不记、不退。不依赖 git，不在 git 仓库里也能用。单个文件太大的不记（上限你定，写进 README），退回时说明哪些没法退。会话目录的权限照现有的。
- **怎么操作**：`/rewind` 弹出列表，列本会话里以前发过的话（最新在上），每条后面写那一轮及以后改过几个文件。选一条后再选三种之一：
  - 对话和文件一起退；
  - 只退对话；
  - 只退文件。
  退对话的，把选中的那句话放回输入框，可以改了再发。正在跑的那一轮不能退（先 Esc 停下）。最近一次压缩以前的轮不列（压缩后那些内容已经不在发给模型的历史里）。
- **文件之后又被改过**：要退的文件在 canter 记下以后，又被 shell 命令、MCP 工具或用户自己改过的（现在的内容和 canter 最后一次写进去的不一样），确认前列出来、标明「之后在 canter 以外被改过」，用户确认后照样退回。
- **退文件**：每个文件退回到所选那一轮之前的样子；那时还没有的文件删掉。退完在对话里留一条记录（退了哪些文件、哪些没法退、为什么），所有开着这个会话的终端都看得到。
- **退对话**：存盘照旧只往后追加，不改写、不删除已有的行；加一种表示「退回到某一轮之前」的事件和模型历史条目，重新打开会话、服务端重启后看到的都是退回后的对话。退回点之前发给模型的请求内容和原来一个字节都不差，只是后面的去掉（缓存命中，DESIGN 第 17 条）。
- **协议**：加一个退回的命令（参数结构参考 Codex `thread/revert` 的 `beforeTurnId`，加上退不退文件、退不退对话），和 Codex 不同的地方（多了退文件）写进 DESIGN 第 8 条，说明为什么。
- 旧版本 canter 打开退回过的会话会看到什么，写进完成记录（`HANDOFF.md` 的退回办法要用）。
