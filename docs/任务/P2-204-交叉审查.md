## 重点看

1. **不用 GPT 时什么都不变**（用户最在意的）：DeepSeek、Kimi、opencode go 等 Chat Completions 的家，发给模型的请求逐字节不变；存盘的模型历史不变（`replay` 为空时不写）；prompt 拼接、压缩的触发、压缩提示词和摘要、压缩后带回文件和待办、上下文估算和 `/context` 的数字都不变；核心逻辑里没有按 OpenAI、DeepSeek 的名字或地址分支。developer 消息只是把现有系统提示换个外壳，内容和顺序没变。
2. **流的状态机**：收到 `response.completed` 才把工具交给批准和执行；failed、顶层 error、incomplete、EOF、取消、先 200 再报错都不执行工具；`output_item.done` 不重复拼接；只在还没输出内容和用量时重试；额度用完不重试、不换家。
3. **回传加密思考**：一轮里的输出项按原顺序原样回传（密文、phase、item id、call_id、参数）；只回传当前这一轮的（`scope`），更早轮次、压缩后、重启后只发普通内容，不会把别的轮次或别的模型的密文发出去；密文和令牌不进公开事件、SSE、日志、`Debug`、错误。
4. **请求和令牌**：官方禁止的参数一个都不发；地址写死，配置写 `base_url`、`api_key` 报错；令牌只发到 `api.openai.com`；401 只恢复一次；GPT 专有报错映射对，不回显服务器原文。
5. **后台运行同意**：没同意的账号，最后一个界面离开后不再发新请求（包括重试和排队的），正在跑的工具照常结束、结果保存，界面回来能接着做；子 agent 按根会话的界面状态；本轮账号绑定在工具循环里不变。
