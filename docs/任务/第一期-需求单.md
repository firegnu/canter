**第一版范围：** DESIGN 第 10 条。不做的：ChatGPT 套餐登录、Responses 接口、apply_patch、提问框、技能、MCP、子 agent、网页搜索、图片、远程连接、网页客户端、桌面应用、执行器子进程和套墙、排空式升级、单机模式、自带系统沙箱。

下面每件的「建议验收」是主控提的，用户 10-24 全部同意：「都行，按你的建议来」。

## 包怎么分

一个 Cargo workspace，`crates/` 下每块一个包。一件活基本只动自己的包，这样能并行、不抢文件。

| 包 | 放什么 | 哪件活 |
| --- | --- | --- |
| `canter-protocol` | 协议类型：会话、一轮、项目、待处理请求、事件、命令；导出 JSON Schema、TypeScript | 1 |
| `canter-store` | 会话存盘 | 1 |
| `canter-model` | 模型接入：各家通用的一层 + Chat Completions | 2 |
| `canter-tools` | 工具、权限闸门、执行器接口 | 3 |
| `canter-core` | 一轮的循环、上下文、压缩 | 4 |
| `canter-server` | 常驻服务端，HTTP + SSE | 5 |
| `canter-tui` | 终端客户端 | 6、7 |
| `canter`（可执行程序） | 命令行入口：`canter`、`canter serve` | 5、7 |

## 先后和并行

```text
1 协议包 + 存盘
 ├─→ 2 模型接入 ───┐
 ├─→ 3 工具 + 权限 ─┴─→ 4 循环 + 上下文 + 压缩 ──→ 5 服务端 ─┐
 └─→ 6 终端客户端（一）（对着假服务端做）──────────────────┴─→ 7 终端客户端（二）+ 命令行
                                                                      └─→ 最后：真模型试用（用户在场）
```

- 1 先做完，再开 2、3、6 三件并行。
- 4 等 2 和 3；5 等 4；7 等 5 和 6。

## 1. 协议包 + 会话存盘

- 建 workspace，定第一期用的依赖和版本（tokio、axum、reqwest、serde、schemars、ts-rs 等）。
- `canter-protocol`：照 DESIGN 第 8 条和报告 §5.5 的命令和事件清单。结构和字段名照 Codex app-server v2，只参考，不拷代码。事件带序号；有协议版本号；导出 JSON Schema 和 TypeScript 类型。
- `canter-store`：每个会话一个只追加的 JSONL 文件，一行一条事件，带序号；每个会话一把文件锁；从盘重建会话的完整样子；列出会话。
- 建议验收：
  - 存盘写进去的会话，重开后还原成一样的样子，序号接着编。
  - 同一个会话被两处同时打开，后一处拿不到锁。
  - 能导出 JSON Schema 和 TypeScript 类型文件。

## 2. 模型接入

- 各家通用的一层：送上下文和工具清单，流式收回文字增量、思考内容、工具调用、用量、错误；能中途取消；能重试的错误自动重试。以后加 Responses 接口时，这一层不用改。
- Chat Completions 接口，接 DeepSeek。base_url、key、模型名都能配置，所以别家兼容接口（Kimi、本机模型等）也能用，但第一期只对 DeepSeek 负责。
- 测试用本机假服务端回放录好的流式响应，不调真接口。
- 建议验收：
  - 能收齐文字、思考内容、工具调用和用量；出错能重试；中途取消能停下。
  - 日志、错误信息、测试快照里不出现 API key。

## 3. 工具 + 权限 + 执行器

- 第 1 件审查带过来的：存盘重放出不认识的权限模式（`PermissionMode::Unknown`，退回旧版时会遇到）一律按「每次问」处理，权限闸门不能用兜底分支放行。

- 执行器接口：真正读写文件、跑命令的一层；第一期在服务端进程里。命令用会话的工作目录和环境。
- 工具：
  - read：带行号读，能分段读；
  - write：整文件写；
  - edit：按文字替换，旧的那段在文件里必须只出现一次，一次能改好几处；
  - shell：有超时，输出太长就截断，打断时杀掉整个进程组。
- 权限闸门：三种模式：每次问、只问执行、全放行。回答四种：允许这一次、本会话都允许、拒绝、拒绝并停下。
- 建议验收：
  - 每个工具在临时目录里能正确干活；edit 找不到或找到多处时报清楚的错，不改文件。
  - shell 超时或被打断后，不留下还在跑的子进程。
  - 三种权限模式下，该问的问，不该问的不问。

## 4. 循环 + 上下文 + 压缩

- 第 1 件审查带过来的：
  - 排队的话现在只在开新一轮时移出（`turn.started.inputId`）；打断丢弃、插进当前轮、几句合成一轮、会话关闭时也要能移出，加一条移出事件或改成多个 id，README 补上插话时回复的约定。
  - 模型历史条目的类型要能容忍以后新增的种类（`#[serde(other)]` 兜底或带版本），否则升级或退回后这个会话接不着聊。

- 一轮的循环：调模型 → 执行工具 → 再调，直到模型不再要工具。干活时人又说的话能排队或插话。打断时掐断模型请求和正在跑的工具，回复被截断时不执行工具。每一步都变成协议事件，写进存盘。
- 上下文：系统提示词、环境信息（目录、系统、时间）、`AGENTS.md`。
- 压缩：手动压缩，加上快到上限时自动压缩（照报告 §2.5：触发照 pi，提示词照 Codex）。
- 建议验收：
  - 用假模型跑完一轮，中间调几次工具。
  - 打断后这一轮记成「被打断」，没有命令还在跑。
  - 从存盘恢复后接着聊，模型收到的上下文和恢复前一样。
  - 超过上限自动压缩，压缩后能接着聊。

## 5. 服务端

- 第 1 件审查带过来的：建会话时进程被杀或掉电会留下 `.creating-*` 临时目录，里面有环境变量；服务端启动或列会话时清理（拿得到其中事件文件的锁就删）。

- `canter serve`：一台机器只许一个（文件锁）；写登记文件（目录 0700、文件 0600）；客户端找不到服务端就在后台起一个。
- 只听本机 unix socket，上面跑 HTTP + SSE。命令和事件照协议包；断线后从序号接着收；几个客户端能同看一个会话；批准请求谁先答算谁的。
- 会话里的命令用客户端交来的工作目录和环境；环境里的东西不进事件流。
- 配置文件：模型、base_url、key 从哪读（配置文件或环境变量；文件 0600）。第一期没有登录界面，key 照这里配。
- 升级照 DESIGN 第 11 条：等在跑的轮跑完（有上限）再重启；版本不同不自动换，只提示。
- 建议验收：
  - 用 curl 能建会话、送一句话、订事件。
  - 两个客户端看同一个会话，一个答了批准，另一个收到「已处理」。
  - 断开再从序号续订，事件不漏不重。
  - 已经有一个服务端在跑时，第二个起不来。

## 6. 终端客户端（一）：对话

- 不占全屏：说完的话写进终端自己的滚动区，只有底部输入区归程序管（报告 §8.2）。
- 输入框（多行、粘贴）；流式显示 markdown；工具卡片（命令、输出、退出码）；改文件的 diff。
- 先对着假服务端做，不等第 5 件。
- 建议验收：
  - 对着假服务端回放一段会话，文字、命令卡片、diff 显示正确。

## 7. 终端客户端（二）+ 命令行

- 批准框；Esc 打断；会话列表和接着聊；服务端重启后自动重连、从断开处续上。
- 命令行：敲 `canter` 就开（找服务端，没有就起）；带首句启动；`--yolo`（全放行）；`--resume`；`-m` 选模型。
- 建议验收：
  - 「这样我随时可以在任何terminal中启动。」：在任意目录敲 `canter` 就能开。
  - 两个终端同开一个会话，都看得到同样的内容。
  - 重启服务端后，客户端自动接上，内容不丢。
