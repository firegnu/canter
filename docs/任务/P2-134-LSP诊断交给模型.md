## 要做的

1. **快的附在结果里**：write / edit 成功后最多等 500 ms（从写成功起算，包括服务器还在起的时间），到了的诊断附在这次工具结果末尾；没到的工具照常成功、注明诊断还在等；语言服务器没装、出错不影响改文件成功。
2. **晚到的补上**：没赶上的按会话合并，最多留 60 秒，文件又改了就作废；在下一次本来就要发的模型请求前，追加一条诊断说明；不为它开新的一轮（不叫醒）；流式输出中不插。

### 发给模型的英文原文

建议统一用下面的模板。花括号表示运行时填入的值，不是实际输出的花括号；只有适用的状态行才出现。每个诊断块最后固定附上：

```text
These are partial, asynchronous diagnostics. Run the checks required by the project; these diagnostics do not replace them.
```

快速结果接在原工具结果之后，前面空一行；晚到的结果合并成一条独立通知，只在下一次本来就要发出的模型请求前追加。块的开头分别为：

```text
[LSP diagnostics]
```

```text
[LSP diagnostics update]
These results arrived after the file-change tool returned.
```

收到可交付结果时，第一份按文件和诊断来源标明：

```text
First delivery for this file and source: pre-existing problems may be included.
```

同一文件和来源之后的交付改为：

```text
Only new or changed diagnostics are listed below.
```

每个文件/来源分组的元数据与计数使用以下原文。行列显示从 1 起；`source` 保留服务器给出的诊断来源，`code` 没有时省掉。`Selected` 首次是所有可交付错误/警告，之后是新增、变化及之前因限额未展示的条目，不包含未变的已交付条目；`omitted` 只数这次选中但没展示的条目，不把未变的条目算成省略。

```text
File: {path}; server: {server}; collected: {UTC timestamp}.
Freshness: current.
Reported in available results: {errors} {error|errors}, {warnings} {warning|warnings}.
Selected for delivery: {selected}; shown: {shown}; omitted: {omitted}.
Resolved since the last delivery: {resolved}.
{path}:{line}:{column}: {error|warning} [{source}/{code}] {message}
```

首次没有可对照基线，或版本/覆盖不足以判断已解决数量时，最后一条计数行写：

```text
Resolved since the last delivery: unknown.
```

块级计数放在所有分组后、固定提醒前；最多 20 条、8 KiB 的预算覆盖整个块（包括开头、元数据、计数和提醒），单条展示最多 1 KiB，超长消息截断处用 `[truncated]`。来源数据本身不完整时，下面的总数只是实际收到的数据，不推测未收到的数量。

```text
Delivery total: {selected} selected; {shown} shown; {omitted} omitted.
```

状态及降级的确切写法：

| 场景 | 英文原文 |
| --- | --- |
| 500 ms 没等到，附在成功工具结果后 | `The file change succeeded. Diagnostics are still pending after 500 ms.` |
| 没装、启动失败或其它不可用，附在成功工具结果后 | `The file change succeeded. Diagnostics are unavailable: {reason}.` |
| 晚到结果不可用 | `Diagnostics are unavailable for {path}: {reason}.` |
| 60 秒交付窗口到期 | `The 60-second diagnostic delivery window has expired. No current result is being delivered for this change.` |
| 当前且完整的来源报空列表 | `This source reported no errors or warnings for this document version. This is not a project check result.` |
| 版本未确认，替换 `Freshness: current.` | `Freshness: version unconfirmed. These results may be out of date; they cannot confirm that earlier problems are resolved.` |
| 版本未确认的空列表 | `This source returned an empty diagnostic list without a confirmed document version. Earlier problems are not confirmed resolved.` |
| 不完整 | `Diagnostic coverage is incomplete: {reason}. Counts include only the available results.` |
| 已知可能过期，不列旧诊断或已解决数 | `Diagnostics may be stale: {reason}. No current result is being delivered for this file.` |
| 删除文件 | `The file was deleted. Its previous diagnostics are no longer applicable; this is not a project check result.` |

上表的状态也保留固定提醒。不向模型发送已知旧版本/旧实例的条目；版本未确认或不完整的结果不据此增加已解决数量。已删除文件的诊断失效不叫作修复。到期状态只在本来发生的请求上交付，不因状态或诊断开新轮。动态 `reason` 沿用底层的英文原因，不附环境变量、stderr 或原始服务器错误。

```text
File: src/main.rs; server: rust-analyzer; collected: 2026-10-29T09:00:00Z.
```


### 协议与压缩的建议，等主控定

1. 协议沿用方案 4.5 的名字：`diagnostics` 项目、`languageServer.updated` 事件、可选快照 `languageServers`、`GET /v1/sessions/{id}/languageServers`，再加 `GET /v1/sessions/{id}/diagnostics` 供客户端查询当前有界缓存。控制端点为 `POST /v1/sessions/{id}/languageServers/{serverId}/stop` 和 `.../retry`；能力标识为 `lsp`。这里的路径参数 `serverId` 指本会话内一个服务器/项目根订阅的稳定、不透明 id，状态另带配置名 `name` 和 `root`，避免同名服务器在两个项目里歧义。另一种做法是按配置名停掉本会话里所有同名服务器；建议按单个订阅，符合方案的共用边界。停止不影响其它会话，重试健康的共享实例只重新订阅和同步。
2. `diagnostics` 项目建议为 `id/sourceItemId?/status/files/totalCount/shownCount/omittedCount/resolvedCount?`。`status` 为 `pending/available/unavailable/timedOut`；文件记录带 `batchId/path/serverId/source/collectedAt/documentVersion?/freshness/incomplete/reason?/diagnostics`，条目带 `severity/range/source?/code?/message`。`range` 保留 LSP 的零起始 UTF-16 行列，文字显示时再转成从 1 起；`freshness` 为 `current/versionUnconfirmed/deleted/stale`。`totalCount` 是该项目涉及的缓存结果中错误/警告总数，`shownCount/omittedCount` 只针对本次交付，`resolvedCount` 省略表示未知。一次合并通知可对应多个项目，各自关联原来的改文件项目；整条通知共用 20 条/8 KiB 上限。pending 项目完成后不回写，晚到结果创建新项目。状态记录建议为 `id/name/root/state/reason?/rssBytes?/sharedReferences/updatedAt`；RSS 查询返回最新采样，只在其它状态改变时随事件带出，不为 RSS 单独存盘。旧存盘缺字段默认空，恢复后运行态改为待重连，不恢复旧进程或 pending。
3. 晚到通知建议用独立私有历史记录 `diagnostics_notice` 标记来源，在完整工具结果批次后追加一条 `Message::User`（沿用当前模型消息类型，通知不登记到 `user_messages`）。压缩拼稿标成 `Tool diagnostics`，不进入 `User's words`；快速结果本来就在工具结果里。来源按结构化记录识别，不靠用户文本前缀判断。另一种做法是新加模型层消息类型，影响面更大；建议本件沿用现有通知机制，单独保存诊断身份，并且不接后台叫醒。回退按修改所属轮丢掉尚未交付的诊断；恢复历史只恢复已交付内容，不恢复待发队列。
