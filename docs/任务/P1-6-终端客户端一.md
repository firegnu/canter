### 做了什么

新建 `crates/canter-tui`（约 2,800 行，含测试和示例）：

- **界面**（`terminal.rs`、`app.rs`、`cells.rs`）：不占全屏。说完的行写进终端自己的滚动区；正在流式写的部分、空一行、状态行、输入框、信息行归程序管，每帧重画。一行能不能写进滚动区，看它前面是不是都已经完了，所以顺序不会乱；模型的话按「写完的整行」边流边写进去，没写完的那行留在下面的区域里。
- **显示**：照线框。`›` 用户的话；模型的话按 markdown 渲染（标题加粗、列表 `•`、代码块和行内代码青色、引用、链接）；思考灰色，进行中一行「思考中…」，写完折成一行「思考：第一行…」；`◇ 读 README.md  1–21 行`；`● 改 README.md  +1 −3` 带 diff（加的绿、删的红、@@ 青色、上下文灰色）；`● 跑 cargo build … 退出码 0 · 12.3s`，跑的时候显示最后 5 行，跑完留最后 3 行并注明共几行。服务端来的文字先去掉颜色码等控制序列、展开 tab、按 `\r` 处理进度条，再画。
- **输入框**（`input.rs`）：多行、自动折行；Enter 发送，Ctrl+J 换行，终端支持键盘增强协议时 Shift+Enter 也换行；bracketed paste 整段插入；左右、上下（按折行后的行）、Home/End、Backspace/Delete。
- **连服务端的客户端**（`client.rs`）：unix socket 上的 HTTP + SSE，取快照、订事件、从序号续收、送一句话；SSE 自己解析。
- **假服务端**（`fake.rs`）：照协议回放 `fixtures/demo-session.jsonl`（34 条事件：用户的话、思考、流式的话、读文件、改文件带 diff、跑命令带输出（含颜色码）和退出码、最后一段 markdown）。
- **真终端运行**（`run.rs`）：raw mode、bracketed paste、键盘增强，退出时都恢复（panic 也恢复）；每帧包在 synchronized update 里，减少闪。
