## 审查意见

改完再合并：5 条必须改，2 条建议改。

审查基准：`38da845b29a9799d83d53fe30a83ab9ab808d8f6`，对照 `git diff main...38da845`。以下问题由代码检查确认，没有另造安全绕过输入或修改审查代码。

1. **必须改：记忆目录本身的符号链接会使清理越界。** 位置：`eval/src/memory.rs:14–55`，调用处 `eval/src/prepare.rs:258、403–404`。`Home::resolve` 在每次 CLI 调用时检查 eval 根目录，但 `clear_dir` 直接对拼出来的 `memory/` 调 `read_dir`；全局 `memory`、`projects/<key>/memory` 或 `projects` 本身是指向外部目录的链接时，会进入目标目录，随后删除目标中的条目，最后还会修改目标目录权限。只检查 eval 根目录不能挡住这条路径。这段虽然搬自旧实现，但现在仍不满足本任务明确要求的清理边界。改法：遍历前检查 eval 根下这些目录组件，拒绝目录链接；记忆目录内部的链接仅处理链接自身，不能跟随。`files` 的目录入口也应采用相同规则，避免把外部目录计入记忆快照。

2. **必须改：会话文件迁移漏了旧版 `steer`，歧义恢复提示还可能让它选中错误会话。** 位置：`eval/src/steer.rs:147–157`、`eval/src/paths.rs:146–161`、`eval/src/server.rs:136–139`。旧版跑的 ID 在 `state.sessionFile` 指向的 run 根 `session.json`；新版 `steer` 只尝试读取 `sessions/1/session.json`，却又把根文件里的正确 ID 加进排除列表。因此升级后重开旧长程题的 `steer` 会一直等待，或选中同 worktree 中另一个未记录的主会话。另一个可达路径是：找到两个候选后，错误消息仍让人把正确 ID 写进“run's session.json”；照提示写到根文件，会排除正确的那个，剩下的错误候选反而被自动选中。改法：单会话旧状态先兼容读取 `state.sessionFile`，不能把当前会话当作历史会话排除；多会话的歧义错误应打印当前 `sessions/<n>/session.json` 的准确路径。现有旧测试已经换成新路径，需保留旧状态格式的回归检查。

3. **必须改：禁止整批 `git add` 的检查同时存在漏判和误判。** 位置：`eval/tasks/memory.toml:84–89`，命令落盘处 `eval/src/finish.rs:90–101`。固定子串能找到普通的 `cargo test && git add -A`，但找不到 `git  add  -A`、`git -C "$WORKTREE" add .` 等同义命令；反过来，按文件名执行的 `git add .gitignore`、`git add ./src/cli.rs` 都包含 `git add .`，会被判为违规，命令中的引用文字也可能误中。换行直接换空格还会丢失原来的 shell 命令边界，影响后续准确识别。改法：保留可恢复的原始命令，按 shell 的命令和参数边界识别 `git` 的全局选项、`add` 及其参数，覆盖空白、`&&`、`-C`，精确区分单独的 `.` 与文件路径；不能继续用无参数边界的子串作为判分依据。

4. **必须改：依赖检查没有比较 TOML 的实际依赖。** 位置：`eval/tasks/memory.toml:49–53`。awk 只收集以 `dependencies]` 等结尾的表头及其后文本。保留原来的空 `[dependencies]`，再用合法的 `[dependencies.foo]` 子表声明依赖时，新子表和内容全部被忽略，检查仍可通过；仅给空依赖表增加注释或改格式也可能被误判为依赖变化。这会直接算错 `dependencies-unchanged`。改法：用已有的 `toml` 依赖解析起点和当前 `Cargo.toml`，比较普通、开发、构建及目标平台依赖的结构，忽略注释和排版，识别依赖子表。

5. **必须改：单会话 `collect --session <id>` 的原有覆盖能力失效。** 位置：`eval/src/collect.rs:251–278`。代码先按显式 `--session` 获取 stats，随后又强制要求返回 ID 与已存 ID 相同。如果已有记录是 A，用户按旧版支持的命令指定 B，就会先成功获取 B、再报错，无法用原命令纠正本次收数的会话。旧版优先采用显式 ID，没有这道冲突检查；CLI 帮助仍保留该选项，违反“上一版能用的照旧能用”。改法：单会话显式指定 ID 时，以该 ID 作为 stats 的预期 ID；未显式指定时再使用已存记录。多会话仍应严格校验各自的 ID。

6. **建议改：打印的下一会话准备命令不能直接执行。** 位置：`eval/src/prepare.rs:132–139`、`eval/src/main.rs:83`，以及 README 多会话流程的下一会话步骤。打印的是 `prepare --round … --run … --session 2`，但 CLI 无条件要求 `--task`，照做会报缺少参数。改法：后续会话从已存 `State.task_path` 加载题目；或者在打印的命令和 README 中补齐 `--task`，使用自定义题目目录时也要保留目录信息。这条按本审查限定的等级列建议，不属于删错、认错或判分算错。

7. **建议改：单会话汇总也使用了隐藏的记忆跑法分组键。** 位置：`eval/src/report.rs:191–230`。即使所有题都是单会话、表中没有“记忆”列，分组键仍包含 `memory_mode`。同一轮同一题同时含旧结果（无该字段）和新结果（默认 `clear`）时，会得到两行同名“轮次 / 题”的通过次数，原先的一组合计被拆开。改法：仅多会话题按记忆跑法分组，单会话统一采用原来的 `(round, task)` 分组。主控已确认的旧基线单独重出，以及不同轮次间的 `--against` 不受这个条件影响。
