## 要做成什么

1. **取目录**：用 ChatGPT 当前账号的 access token 调 `GET https://api.openai.com/v1/models`，读 `models`，只留 `visibility == "list"` 的，保留返回的顺序。什么时候取：服务端启动时有已登录的当前账号、登录成功、切换当前账号之后各取一次；打开 `/model` 时目录已经超过 5 分钟就在后台再取一次。取目录不能挡住 `/model` 打开、不能挡住发消息。
2. **合进 `/model`**：目录里的模型和配置里手写的 GPT 模型一起列在 GPT 那一家下面，路由名照现在的 `<家名>/<slug>`，界面显示 `display_name`。同一个 slug 两边都有时只列一条。配置里手写了、目录里没有的照旧列出。目录里的模型能用来新建会话、`/model` 切换、`canter exec` 指定。
3. **资料从哪来**：一个模型的窗口、思考档位和默认档位、能不能看图，按这个次序取：配置里手写的 → 目录这一条带了的（字段名照 Codex `ModelInfo`：`context_window`、`supported_reasoning_levels[].effort`、`default_reasoning_level`、`input_modalities`；目录没带、带了但读不懂的都算没有） → 下面的未核实默认值。三样都有来源（配置或目录）的算「核实过」，缺任何一样的算「未核实」。
4. **未核实的模型**：照样列出、能选。
   - `/model` 里在名字后面标 `(unverified)`。
   - 缺窗口：按 128000 算（压缩和 `/context` 都用它）。
   - 缺档位：按只支持 `medium`、默认 `medium` 算，请求照常发 `reasoning.effort:"medium"`（`summary:"auto"` 照旧）；`/think` 只列 `medium` 并说明这个模型的档位未核实。不能不发档位：P2-213 实测不发档位时 GPT 一条思考都没有（11-05 用户提醒）。模型拒绝 `medium` 时照现有的请求错误显示，不自动换档重试。
   - 缺看图：按不能看图处理（沿用现在附图前的提示）。
   - 切到这样的模型时，在界面上提示一次，例如：`Model details for <显示名> are unverified: using a 128000-token context window, no image input, and medium thinking effort.`（只写真的缺的那几样）。
   - 常用的模型想要完整资料，照旧手写进配置，手写的优先（第 3 条）。
5. **按账号缓存，失败用上次的**：目录按 ChatGPT 账号记录分开存到 canter 自己的状态目录，服务端重启后还在；文件里只有目录内容，没有令牌，权限 0600。取失败（网络、超时、401 恢复一次后仍失败、回复读不懂）时用这个账号上次存的目录，`/model` 里 GPT 那一家标出是旧的，例如 `ChatGPT models from <本地时间>, refresh failed`。这个账号从没取成功过时，只列配置里手写的，并标出取目录失败（例如 `Could not load ChatGPT models`）。
6. **换账号、退出、没登录**：切账号后 `/model` 只列新账号的目录（新账号没有缓存时按第 5 条「从没取成功过」处理）；旧账号正在取的结果到了也不能落到新账号上。某个账号退出登录时删掉它的缓存。没登录、或当前账号没有套餐授权时，不取目录、不列目录里的模型；配置手写的 GPT 模型和别家照现在显示，不隐藏 DeepSeek 等别家。
7. **会话里的模型从目录里消失了**：已经在用、或存盘里记着这个模型的会话照旧能打开、恢复、继续发（沿用「已存的旧模型仍可恢复」的规则），按最后一次知道的资料走；目录里没了的模型不再列进 `/model`。
8. **协议**：`GET /v1/models` 给每条模型带上是否核实过、给 GPT 那一家带上目录是不是旧的和取的时间（可省略的新字段，字段名你定）；旧客户端忽略新字段照常能用。窗口、档位、看图仍走已有的 `contextWindow`、`supportedReasoningEfforts`、`defaultReasoningEffort`、`inputModalities`。
