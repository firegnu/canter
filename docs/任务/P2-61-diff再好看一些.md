## 要做的

- **代码上色**：加行、删行、上下文都按文件的语言上色，和代码块用同一套（syntect + two-face，`ansi` 主题），语言按文件扩展名认，认不出照现在不上色。上下文行改成正常亮度的上色文字（不再整行灰）。底色照旧铺到行尾，改动的词照旧深一档。
  - 加行上绿色的字、删行上红色的字和底色混在一起看不清时，那几个字改用默认前景色。
  - 跨行的字符串、注释在 diff 里可能断开，上色不准可以接受；不为它读整份文件。
  - 不要每画一帧都重新上色：和代码块一样，算一次留着，宽度变了、展开收起时再算。
- **行号一栏**：行号和 `+` / `-` 号放在一栏（`551 - `），加行、删行的这一栏底色比整行再深一点；行号和号的颜色：加行绿、删行红，上下文灰。上下文行这一栏不铺底。真彩色给深浅两种终端各定一个值，写进 `theme.rs`，和改动的词那一档要分得开；256 色找不到既比整行深、又和改动的词不同的格子时，这一栏就用整行的底色（行号照样红绿），在完成记录里写用了哪些色号。
- **块和块之间**：`⋮` 换成 `⋯` 加这块在哪个函数里（灰色斜体），太长从后面截掉加 `…`。函数名从 `@@` 行 `@@ -a,b +c,d @@` 后面那段来；没有就只画 `⋯`（旧会话里存的 diff 没有这段，照样能画）。
- **生成 diff 时写函数名**（`canter-tools`）：改文件工具生成统一 diff 时，每个块的 `@@` 行后面照 git 默认的规则补上函数名：块开头往上找，最近一行以字母、`_` 或 `$` 开头的原文（去掉行尾空白，最多 80 个字符）；找不到就不写。只改 diff 文本里的 `@@` 行，给模型的那句摘要不变，协议不变。
- **16 色、不知道深浅、`NO_COLOR`**：照现在（不铺底、不上色），只有函数名那一行照新的写法。
- 历史里的改文件卡片和批准框一起改；P2-45 拖选复制照旧只复制代码文字（不带行号、号、`⋯` 那行）；P2-44 搜索照旧。
- README 的「diff」「颜色」两节跟着改。
