### 重点看的几项

1. 本机用法：`git.rs`、`review.rs` 逐行对比 main，只多了 `env` 参数和模块路径，分支、改动行数、`/diff`、`/review` 文本、`/files` 状态的逻辑、超时（2 秒 / 15 秒）、截断（256 KiB / 32 KiB）都没变；`@` 遍历（`workspace_walk.rs`）和原 `mention.rs::walk` 一样（忽略规则、名字顺序、跳过的目录、不能输入的名字、每个目录 1 万条、`truncated` 累计），终端的过滤、排序没动。`/files` 的路径显示 `display_path` 和终端的 `shorten_home` 逻辑一样。启动和切会话多了 `/v1/info` 加只取分支的 `summary` 两个请求，本机很快，不会卡；会闪的地方见第 1 条。旧服务端：启动和切会话给一条带 `serve --replace` 的警告，`/diff`、`/files`、`/review`、`@` 都先查能力，远程用在服务端机器升级的说法，不回退本机实现。
2. git、gh 子进程：`command()` 的加固项原样保留，只有 PATH 从终端进程换成会话环境；本机会话的环境就是终端建会话、每次恢复时交的环境，和原来一致。gh 仍是 `env_clear` + 会话环境，再去掉 `GIT_*`、`GH_DEBUG`，加固项不变。`kill_on_drop`、超时丢弃 future 杀掉并收回子进程的做法不变；HTTP 请求中途断开时 handler 被丢弃，git 一并被杀。

### 意见

1. **建议改**：`crates/canter-tui/src/statusline/git_diff.rs:59-69`
   - 问题：请求失败（`.ok()` 得到 None）也会把分支清空，计数请求失败时把行数也清空。本机 `serve --replace`、`canter upgrade` 换服务端的那几秒，以及会话被别的终端关掉以后（`sessionNotResumed`），信息行和状态栏的分支、行数会消失，等重连成功再出来。原来本机读文件，不会这样。只是显示，不影响别的。
   - 改法：只在拿到服务端结果时更新；传输或接口出错时保留上一次的值。cwd 变了照旧清空。
2. **建议改**：`crates/canter-server/src/workspace/mod.rs:162`
   - 问题：用 `std::env::current_exe()` 起 worker。Linux 上 `canter upgrade` 先换掉程序文件，再等手上的轮跑完才换服务端；如果中途按 Ctrl+C 取消，就一直等到手动 `serve --replace`。在这段时间里，旧服务端的 `/proc/self/exe` 读出来是 `…/canter (deleted)`，起不来，每次 `@` 都提示 `could not start workspace file scan`，没有候选。macOS 起的是新装的程序，现在能用，但以后 worker 的输入输出格式一改，新旧就对不上。PDF worker（`canter-tools/src/pdf.rs:132`）原来就是这个写法，问题一样。
   - 改法：Linux 上直接起 `/proc/self/exe`（文件被换掉以后照样能执行旧程序）；PDF worker 可以另开一件一起改。
3. **建议改**：`docs/DESIGN.md:5`
