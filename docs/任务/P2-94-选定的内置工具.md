## 决定

### 1. 两处小改：做，合成一件，随时插

- **`rg`、`grep` 搜不到时不画成失败**：卡片改成灰色的 `No matches`，不再是红色 `exit 1`。
  - 理由：搜不到是正常结果，画成红色看着像出错，用户得停下来判断。Claude Code 专门把这类退出码 1 当正常（报告 2.1、[CL1]）。
  - 范围：只认整条命令就是一个 `rg` 或 `grep`、退出码 1、没有输出的情况。`diff`、`git diff` 等命令的退出码 1 是另一个意思，不一刀切。
  - 给模型的结果照旧带退出码，模型看得懂；只改界面显示。
- **系统提示词加一句**：搜内容用 `rg`，找文件用 `rg --files`。
  - 理由：Codex 提示词就这么写（报告 [C7]）。`rg` 默认跳过 `.gitignore` 里的东西，比 `grep -r` 快、输出少；DeepSeek 不知道就可能用 `grep -r` 把 `target/` 也翻一遍。
  - 代价：所有会话的缓存冷一次，只冷一次，可以接受。DESIGN 第 20 条要求改提示词经用户点头，用户 10-27 已点头（见用户原话）。
- 大小：小件，改终端和提示词，不碰协议。

### 2. P2-34 计划 / 待办：默认开，可以关；做完真调一次 DeepSeek

- **默认开**。
  - 理由：用户 10-25 要的是「长任务里模型先列步骤，做一步勾一步，用户随时看得到进度」；默认关，用户平时就看不到，等于白做。
  - Codex、Claude Code 近来默认关，理由是新模型不靠清单也能记住进度、工具说明占上下文（报告 1.3、4.2）。那说的是对模型的好处；这里要的是让用户看得见进度，所以这个理由不直接适用。
- **做轻，免得模型空转**：
  - 工具说明写「三步以上的活才用，简单的不用」，不逼模型每件事都列；
  - 一个工具，每次整份替换；
  - 配置里能关。
- **真调一次**：拿两三个多步的活，清单开着和关着各跑一遍，看 DeepSeek 用不用、会不会反复更新浪费 token。上限 60 次请求或 1 美元，到了先停下报告，用户在场时跑。
  - 理由：DeepSeek 用得好不好没有公开数据（报告 4.2、第 7 节），花这点钱就能知道「默认开」对不对。

### 3. LSP：以后再说，触发点是 P2-28 做完

- P2-28 后台命令做完后再评估。真做时先只做 Rust 的「改完拿诊断」，默认关。
- 理由：
  - rust-analyzer 在大项目上十几 GB 内存（报告 3.2），挂在常驻服务端上不合适；
  - 完整的错误还是 `cargo check` 给，提示词已要求改完跑检查（报告 3.4）；
  - Codex 没有 LSP，opencode v2 去掉了（报告 3.1）；
  - P2-28 会做后台进程管理，到时起语言服务器能用上一部分，那时评估成本更准。
- 不定成「不做」：canter 一台机器一个常驻服务端，同一项目的几个会话能共用一个语言服务器，这一点比别家合适（报告 3.3），留着这条路。
- 10-29 评估（P2-28 已做完）：P2-28 只能复用进程起停和服务端退出时一起停掉，和语言服务器通信、文件同步、收诊断都要新写，仍是大件；对长任务帮助不大（提示词已要求改完跑检查，`cargo check` 的错误更全）。用户先选挪到第三期；随后问 LSP 是不是不只 Rust，改为：「挪到这一期，通用的改完拿诊断，第一版接哪几种语言，做的时候再定」，见 P2-126。
