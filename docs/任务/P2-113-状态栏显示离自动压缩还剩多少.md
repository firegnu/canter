## 要做的

1. **压缩线可调**：config.json 加可选项 `auto_compact_tokens`（正整数）。不设时压缩线和现在一样（窗口 − 输出上限 − 16384）；设了用它，比窗口算出来的线大时按窗口的线。`input_limit` 返回生效的那条线，自动压缩触发和压缩后留多少用户消息都跟着它；压缩请求本身能用多大（`compaction.rs` 第 256 行附近按窗口算的 `budget`）不变。和 `context_window` 一样服务端启动时读，改了重启服务端生效。不是正整数时照 `context_window` 校验的样子报错。
2. **服务端带上压缩线**：`TokenUsage` 加一个可选字段 `autoCompactTokens`（生效的那条线，取 `input_limit`，不另算一份），旧事件里没有这个字段照常能读。导出的 TypeScript 里也是可选。
3. **状态栏加一项 `compact`**：写成 `93% to compact`，百分比 =（压缩线 − 当前占用）÷ 压缩线，向下取整，超过压缩线时写 `0%`。拿不到压缩线（旧服务端）时这项不显示。放在 `context` 后面，默认打开；已经存过 `tui.json` 的用户也要看到（新项照默认加在 `context` 后面），在 `/statusline` 里关掉后照存下来的。`/statusline` 选择框里能开关、调顺序，预览里看得到。
4. **状态栏上色**（只用终端 16 色，颜色加进 `theme.rs`，`NO_COLOR` 时照旧不上色）：
   - 模型青色，思考档位品红，花费黄色，目录蓝色，分支绿色。
   - 权限模式照旧：`Allow all` 红色，另外两种灰。
   - `ctx` 和 `to compact`：字灰，百分比数字按离压缩线还剩多少变色，剩 ≥50% 绿、20%～50% 黄、<20% 红；两项用同一个「剩多少」，拿不到压缩线时 `ctx` 的数字按离窗口还剩多少算。
   - `cache`：字灰，百分比数字青色。
   - 默认不显示的三项：`tok/s` 的数字青色，版本号、会话名照旧灰。
   - `/statusline` 预览照同样的颜色。配了状态栏脚本时照旧显示脚本的输出，不上色。
5. **状态栏脚本的 JSON**：`context` 里加 `autoCompactTokens` 和 `autoCompactPercentLeft`，拿不到时为 `null`。
6. `docs/DESIGN.md`：第 8 条写一句 `TokenUsage` 比 Codex 多 `autoCompactTokens`、为什么；配置写 `auto_compact_tokens` 的那处（照 `context_window` 写在哪）加一句；第 19 条状态栏那段补上颜色。
