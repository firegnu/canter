### 意见

**建议改 1：临时目录路径太长，在 `$TMPDIR` 下建 unix socket 的程序会失败**
- 位置：`crates/canter-tools/src/scratch.rs:24`。
- 问题（已查证）：目录名里是完整的 64 位十六进制 SHA-256，规范化后是 `/private/tmp/canter-shell-501-<64位>`，一共 94 字节。macOS 的 `sockaddr_un.sun_path` 只有 104 字节（含结尾的 0，SDK `sys/un.h:79`），所以 `$TMPDIR` 下只剩约 9 个字节给 socket 路径。改之前：沙箱开着时是 `/private/tmp/canter-shell-XXXXXX`（32 字节），沙箱关着时是系统的 `/var/folders/.../T/`（约 49 字节）。
- 影响（推测，没实测）：模型写的脚本如果在 `$TMPDIR` 下建 unix socket，会报 path too long。例子：Python 3.14 以前的 `multiprocessing.Manager()`（路径是 `$TMPDIR/pymp-xxxxxxxx/listener-xxxxxxxx`）、`ssh-agent`、Go 或 Node 测试在临时目录下监听 socket。这正是本件要支持的「临时写个脚本跑一下」的场景。
- 改法：把摘要截短，比如取前 16 个十六进制字符（64 位，同一用户的会话之间撞上的概率可以忽略），路径约 46 字节。同时改 DESIGN 里的路径写法。

**建议改 2：用户 `!` 命令的 `$TMPDIR` 也换成了会话临时目录，任务和 DESIGN 都没写**
- 位置：`crates/canter-tools/src/executor.rs:227-232`。这里不看 `sandboxed`，只要有路径就设 `TMPDIR`；`spawn_user` 走的也是这个 `launch(..., false, None)`（`executor.rs:567-572`）。
- 问题（已查证）：任务第 1 条写的是「模型 shell 的 `$TMPDIR`」；DESIGN P2-123 写的是用户 `!` 不套沙箱、原样执行。现在不管沙箱开不开，用户 `!`（包括 `!cmd &`）的 `$TMPDIR` 都指向会话临时目录：会话一关，里面的东西就没了，而且也受建议改 1 的长度限制。开发者的测试里，`sandbox_session_applies_configuration_add_dir_and_closes_private_temp` 重开那段就是用 `shell_command`（用户 `!`）读 `$TMPDIR`，可见是有意这么做的，只是没写进 DESIGN。
- 改法：二选一，主控定。
  - (a) 只给模型 shell 设：在 `launch` 里区分调用方，或把设置挪到 `spawn` / `spawn_with_sandbox_request`；测试改成用模型 shell 读 `$TMPDIR`。
  - (b) 保留现状，在 DESIGN「会话临时目录」一节写明用户 `!` 也用这个 `$TMPDIR`。

  我倾向 (b)：用户在同一会话里跑模型写的脚本时，环境是一致的，代价只是补一句文档。

**建议改 3：目录建不起来时的提示里没有路径；残留删不掉时，这个会话以后每次打开都没有临时目录**
- 位置：`scratch.rs:33`、`36`、`72`。
- 问题（读代码确认了这条路径，没实测）：两种情况会触发：已存在的目录权限不是 0700；或目录里有删不掉的东西，比如脚本 `chmod -w` 过的子目录（关会话时 `TempDir::drop` 删不掉也不报错，东西就留下了）。之后每次打开这个会话都会提示类似 `Scratch directory unavailable: Permission denied (os error 13)` 的话，但不说是哪个目录。路径是固定的，不会自己恢复，用户也不知道该去删哪个。
