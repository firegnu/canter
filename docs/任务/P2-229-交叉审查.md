1. **退出后本机不留令牌**
   - 远程作废成功 / 没确认 / 本来没令牌：`manager.rs` `logout` 里 `Some(token)` 分支不管 `revoke` 结果都把 `pending_revocation` 置 `None` 再落盘；`sign_out` 已把 `tokens` 取走，所以三种情况落盘的 `tokens`、`pending_revocation` 都是 null。公开的 `RecordInfo.pending_revocation` 只是 `is_some()`，不带令牌。`remote_revocation_failure_is_bounded_and_clears_all_local_tokens` 读盘断言 `tokens`、`pending_revocation` 为 null，重开后 `pendingRevocation` 为 false。
   - 退出和刷新同时发生：刷新在 `blocked` 后完成时，两个分支（身份校验失败、成功）都是 `record.tokens = Some(fresh); record.sign_out()`，把新 refresh token 交给等着的 logout，logout 拿到锁后作废并清掉；`logout_blocks_new_requests_and_revokes_inflight_rotation_without_resurrection`、`logout_revokes_rotated_refresh_token_even_if_new_id_token_is_invalid` 都过。没有看到令牌复活的路径。

   - 旧客户端：协议 `AccountLogoutResult::Pending`、`AccountInfo.pendingRevocation` 字段和类型都没变，旧客户端反序列化不会出错。见可以不改第 1 条。

### 建议改

1. **位置**：`chatgpt_auth/manager.rs` `logout`、`storage.rs` `begin_logout`。**问题**：退出先把 refresh token 作为 `pending_revocation` 落盘，再去远程作废（最坏约 3×(10 s discovery + 10 s revoke) + 0.75 s）。这段时间里服务端被杀或崩溃，盘上会一直留着这枚 refresh token，直到用户再跑 logout 或复登；`auth status` 会显示 `revocation pending`，但不再提示怎么清（CLI 的重试提示本件已删）。正常使用碰不到，属于本件之前就有的设计，DESIGN 里「退出完成后恒为 false」的说法也没错。**改法**：记进 HANDOFF，以后再定：比如服务端启动时对 `signed_out` 且带 `pending_revocation` 的记录尽力作废一次后清掉，或 `auth status` 看到它时提示再跑一次 logout。本件不用改。

### 可以不改

1. 旧版 CLI 连新服务端收到 `Pending` 会照旧提示「Run `canter auth logout chatgpt` again to retry」；照做只会得到 `No token needed revocation.`，不出错，误导很轻。CLI 和服务端一起升级时碰不到。
2. 流里报错的那行 `status` 永远是 200（流的 HTTP 状态）。DESIGN 写的就是「实际 HTTP 状态」，和代码一致；要分清 HTTP 报错和流里报错，靠 `request_id` 和 `code` 已经够了。
3. JWKS 拿到了但里面没有 ID token 的 `kid`，现在按 `InvalidIdToken` 清登录。官方轮换密钥、JWKS 缓存还没更新时有可能误清，但这和任务写的「签名不对」分不开，主控也已审过这个归类，维持现状。
