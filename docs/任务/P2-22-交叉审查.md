### 意见

**建议改 1：记忆目录出问题时，坏的不只是记忆**
- 位置：`crates/canter-tools/src/memory.rs:44`（`roots()`）、`:237`（`validate()`）、`:72`（`list()` 里 `open(&path)?`）、`:204`（`git_metadata(&cwd)?`）；`executor.rs:420`、`:510`（`memory.roots()….transpose()?`）、`:607`；`sandbox.rs:193`；`crates/canter-core/src/session.rs:1889`。
- 问题：下面两种情况是读代码推出来的调用链，没有实测。
  - a. **会话中途**：用户手动删掉或改名 `<CANTER_HOME>/memory` 或 `projects/<key>/memory`（比如 `rm -rf ~/.canter/memory` 清空全局记忆）后，`validate()` 的 `symlink_metadata` 报 NotFound，`roots()` 返回 Err。执行器的 `resolve_path` 和 `write_file`、文件工具沙箱检查、shell 沙箱生成配置都用 `?` 把这个错传上去。结果是所有已加载的可信会话里，read、write、edit 对任何路径（包括项目文件）都失败，报 `No such file or directory`；开了沙箱的话 shell 也起不来。已加载的会话再 `/resume`，信任没变，`set_folder_trust` 直接返回，不会重建目录；要等会话卸载后重新打开才恢复。
  - b. **打开时**：两种情况会让 `Session::create` 和 `Session::open` 直接失败，这个目录开不了会话：一是记忆目录里有一个读不了的 `.md`（如果它在全局记忆里，所有可信目录都开不了）；二是可信工作目录的 `.git` 指针解析不了，比如 worktree 的 gitdir 已被 prune，`git_metadata` 里的 `canonicalize()?` 会报错。改动前打开会话只用 `.git` 是否存在来判断，不会因此失败。仓库里已有先例 `unavailable_scratch_warns_without_preventing_session_open`：临时目录不可用时只警告，不挡打开。
- 改法：
  - 执行器和沙箱里取记忆根时，出错就当作没有例外，照 `permission.rs:183` 的 `memory_write` 已经在用的 `.ok().flatten()`。这样记忆路径照旧被保护挡住，其它路径不受影响。
  - 打开时记忆加载失败（建目录、认项目、列索引）改成：不开例外、不加记忆段，加一条英文的打开警告。
  - 单个读不了的文件按无效条目处理：不进索引，`/memory` 里仍按文件名列出。
  - 这几处都是失败时收紧，不放宽。

**建议改 2：受限转可信时，记忆加载成功后的写失败没有撤回例外**
- 位置：`crates/canter-core/src/session.rs:610` 起的 `set_folder_trust`，以及 `:692`。
- 问题（读代码）：`set_enabled(true)` 和 `refresh_memory` 都成功之后，最后一步 `journal.append(SessionUpdated)`（:692）如果失败，会直接 `?` 返回。这时共享的 `Memory` 已经打开，运行态仍是受限，前缀里已经有记忆段。下次以受限打开时，`restricted_mode != trusted` 不成立，函数提前返回，例外就一直留在受限会话里，直到会话卸载。要触发这种情况得先有会话日志写失败（比如磁盘满），所以不列必须改。
- 改法：`set_enabled(true)` 之后的任何出错都走撤回，例如 :692 失败时同样 `set_enabled(false)`；或者先追加 SessionUpdated，再开例外。

**可以不改 1**：`refresh_memory` 在 `prefix_segments` 为 None 时只用记忆段重建前缀（`crates/canter-core/src/memory.rs:60`）。只有一种情况会走到：P2-15 之前没存分段的旧会话被可信分叉，这个分叉还加载着，信任又变了。`refresh_tools`（session.rs:326）对 None 本来就是同样的写法，下次普通打开时会整段重算。

### 出错时有没有放宽

没有。所有新的出错分支只做两件事之一：把 `roots` 置为 None，或者把 `roots()` 的 Err 当作 None。例外只在 `roots()` 返回 Some 且 `validate` 通过时才生效，这一条没动。记忆根被换成符号链接、被删、被改成文件这几种情况，`validate` 失败后都退回整个状态根受保护；状态根以外的路径本来就和记忆根的判断无关。

### 意见

**建议改 1：信任升级时的记忆警告，正在打开的客户端看不到**
- 位置：`crates/canter-core/src/session.rs:643`（在 `set_folder_trust_inner` 里直接 `journal.append(Warning)`）；`crates/canter-server/src/http.rs:776` 起（resume 已加载的会话时，先 `set_folder_trust`，再 `snapshot()`，把它的 `event_seq` 返回给客户端）；`crates/canter-core/tests/support/memory.rs:342`。
- 问题（读代码）：
  - 记忆警告写在返回给客户端的游标之前。快照的 reducer 不收 Warning 事件（`crates/canter-protocol/src/reducer.rs` 里把 Warning 归到「不处理」），TUI 从返回的 `last_event_seq` 之后订阅（`crates/canter-tui/src/run.rs:517`）。所以发起这次 resume 的客户端看不到这条警告，只有之前已经连着的客户端看得到。
  - 测试在调用 `set_folder_trust` 之前取游标，和服务端实际的取法不一样，所以没测出来。
  - 同一处 `trust.warning` 是故意放在 `snapshot()` 之后的。
  - 这条只影响「已加载的受限会话、在打开时转可信、且记忆加载失败」这一条路，例外和前缀都是对的，所以不列必须改。
  - 顺带一点（和这次改动无关的既有写法）：带 `input` 的新建会话请求，返回前会再取一次快照，所以临时目录警告和现在的记忆警告都落在游标之前。
- 改法：`set_folder_trust` 不在内部追加记忆警告，改为把警告返回给调用方（或者留在 `Memory` 里），由 resume 处理在 `snapshot()` 之后用 `opening_warning` 追加，和 `trust.warning` 一样。测试的游标改在 `set_folder_trust` 之后取。

**可以不改 1**：出错时只改内存里的前缀，不记 Context（session.rs:712 起）。这是因为日志可能已经写不进去了，注释也写明了。这时前缀是收紧方向（去掉记忆段），下次普通打开会整段重算；可信分叉要是沿用日志里那份带记忆的快照，也要看分叉自己的信任来开例外，不会放宽。

**可以不改 2**：会话中途 `/memory` 列表遇到读不了的文件时，`list()` 也会把警告存进 `Memory.warning`。它不会显示出来，下次 `set_enabled`（信任变化）时就被清掉，打开时取到的只会是这次打开产生的警告，不会串到别处。

**可以不改 3**：日志写失败的测试用 `dup2` 把会话日志已打开的写描述符换成只读的。它只按本测试临时文件的设备号和 inode 选描述符，`Drop` 时恢复，只在 macOS 上编译；nextest 每个测试一个进程，不影响别的测试，生产代码里也没有加测试开关。
