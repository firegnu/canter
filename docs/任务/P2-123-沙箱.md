## 开工时要用户定的

照报告 §7.3 原文问，每题带报告的推荐；开工前先看 Codex、Claude Code 那时的做法和 Apple 对 `sandbox-exec` 的说法有没有变，变了先补报告：

1. 第一版用哪种沙箱、默认开不开（推荐 macOS Seatbelt，模型命令默认开，起不来就失败）。
2. 沙箱里怎么少问，P2-108 的放行规则出不出沙箱。
3. read / write / edit 要不要和 shell 守同一套路径边界（会扩大 P2-118 定的范围）。
4. 怎么联网（默认关、单条命令批准，还是按域名代理）。
5. `.git` 能不能写。
6. 临时脚本和工具缓存放哪。
7. 用户的 `!` 命令套不套。
8. 第一版能不能接受 MCP、`web_fetch` 还在沙箱外。

## 用户的决定（10-30）

开工前核对过：Codex `rust-v0.166.0` 的 macOS Seatbelt 实现和 0.163 一样，报告不用补。主控先补了一题（第 0 题），报告原推荐在「全部允许」下会让提交、push、装依赖都失败。

- 用户：「权限的问题我觉得接受你的建议」「选 A，其余都按推荐」。
- **沙箱和权限模式分开**，各管各的：权限模式管问不问，沙箱管命令能碰什么。沙箱做完后默认开，`config.json` 加 `sandbox`，不写就是开，`"sandbox": false` 加 `canter serve --replace` 关掉；第一版界面里不做临时开关；状态栏显示开还是关。
- **第 0 题 B**：「全部允许」下沙箱只守「不写项目外、不读敏感文件」，联网和写 `.git`（按第 5 题的范围）照常放行，不弹框；越界直接失败。
- **`--yolo` 选 A**：只等于「全部允许」，沙箱照开；`--help` 写清楚。和 Codex 的 `--yolo`（不问也不套沙箱）不一样，要完全不套只能 `"sandbox": false`。
- **第 1 题 A**：macOS Seatbelt，模型命令默认套，起不来就让命令失败，不偷偷在外面跑。
- **第 2 题 A**：「只问执行」下墙内命令不问；「每次问」照旧；P2-108 的放行规则只管免问，不能把命令放到墙外。
- **第 3 题 A**：沙箱开着时 read / write / edit 守同一套边界：敏感文件不能读，「全部允许」下的 write / edit 也不能写项目外；询问档可以单次批准目录外的普通路径，敏感路径普通批准解不开。超出 P2-118 原定的范围，用户同意。
- **第 4 题 A**：「每次问」「只问执行」默认断网，某条命令要联网时单次批准，批准的是这条命令及其子进程的全部 IP 网络（包括本机和内网），界面写明；「全部允许」照第 0 题联网。
- **第 5 题 B**（主控改了推荐，用户接受）：`.git` 里提交用到的部分（索引、对象、分支指针等）可写，`config` 和 `hooks` 一直锁住。代价：模型能改本地历史。
- **第 6 题 A**：每会话一个独占临时目录（作 TMPDIR）；不开放整个 `/tmp` 和真实的 `~/.cargo`、`~/.npm`，缓存另放可写位置，代价是新依赖可能要重新下载。
- **第 7 题 A**：用户 `!` 不套，界面标明没在沙箱里；模型不能用这个入口。
- **第 8 题 A**：MCP、`web_fetch` 第一版在沙箱外，各自批准照旧，界面写明；以后各开一件。
