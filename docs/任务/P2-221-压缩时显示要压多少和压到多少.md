## 要做成什么

手动 `/compact` 和自动压缩都一样：

1. 压缩开始时，服务端把这次要压缩的上下文有多少 token 放进压缩条目，客户端一收到就显示：压缩中的卡片和状态栏写 `Compacting context… 152k tokens`。数字和 `/context` 用同一种估算，格式照界面现有的 token 写法（`152k`）。
2. 分段压缩（一次放不下、分几段发去总结）时，服务端随进度更新第几段/共几段，界面在上面那句后面加 ` · part 2/3`。只发一次就压完的不显示这项。共几段事先算不准时，按实际能给的写，不编数字；做法写进完成记录。
3. 压完后，服务端把压缩后的上下文有多少 token 放进压缩条目，卡片写 `── Context compacted · 152k → 9k tokens ──`。没压成的照现在写。
4. 数字由服务端算好、经协议的压缩条目（或现有的条目更新机制）给客户端；新字段可省略，旧客户端忽略、新客户端读旧服务端和旧存盘时没有这些字段就照现在显示。这是在 Codex v2 压缩条目上的扩展，写进 `docs/DESIGN.md`。

屏幕上的文字都用英文。
