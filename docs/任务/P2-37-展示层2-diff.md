## 要做的

照方案第 2 项「推荐」做，要点：

- **统一 diff**，一列行号，宽度按这份 diff 里最大行号的位数；删行用旧行号，加行和上下文用新行号。不再显示 `@@` 行，块和块之间一行灰色 `⋮`。
- **底色**：真彩或 256 色、且知道深浅时，加行、删行整行铺底色（铺到行尾），文字默认色，`+` / `-` 号绿 / 红。16 色或不知道深浅时不铺底，整行绿 / 红字（现在的样子）。底色用 `theme.rs` 里已定的用途。
- **256 色就近取**：P2-36 审查发现深色底的加行色 `#213A2B` 就近取成了灰 236，绿色几乎没了。换一种取法，让 256 色下加行看得出绿、删行看得出红；`theme.rs` 里 `colorfgbg` 的注释顺手改对（0–6 不是「黑到浅灰」，7 才是浅灰）。
- **行内改动**：连着的一段删行和加行，行数一样时一一配对，每对按词比较，改动的词用「改动的词」底色，16 色下反色。用 similar 的 `inline` 功能（开 feature，版本不变）。一对里相同的部分不到一半就不标；行数不一样不配对、不标。
- **收起**：历史里改文件每个文件最多 12 行，新建文件最多 6 行，删除文件只留标题；多的写一行 `… N more lines`（先不带 `· Ctrl+O`，第 5 件 P2-40 接上展开）。
- **批准框**：和历史共用一套画法，但照旧全显示、可以翻；照旧先过 `visible()`，新画法不能绕过它。
- **长行**：照旧折行，折出来的行对齐到行号后面的文字。
- README 里讲 diff 的地方照新画法改。

## 完成记录

**做了什么**

- 新文件 `crates/canter-tui/src/diff.rs`（`lib.rs` 加一行 `mod diff;`）：`Diff::parse` 把统一 diff 拆成带行号的行（删行旧行号，加行和上下文新行号，块和块之间一个 `⋮`），`Diff::rows(缩进, 宽度, 最多几行)` 画出来。历史卡片（`cells.rs`）和批准框（`approval.rs`）都用它；`cells.rs` 里原来的 `DiffKind`、`diff_style`、`parse_diff` 删掉了。批准框照旧先 `visible()` 再交给 `Diff::parse`。
- 画法：`行号 记号 文字`，行号灰色，宽度按整份 diff 最大行号的位数；不画 `@@`。能铺底色时加删行从行号到行尾铺底色、文字默认色、只有 `+` / `-` 绿 / 红；不能铺时整行绿 / 红字。上下文灰色、不铺底。长行折行，折出来的行对齐到文字（折行那段也铺底色）。
- 改动的词：一段删行后面紧跟同样多的加行时一一配对，每对单独 `TextDiff::from_lines` 再 `iter_inline_changes`（similar 自己的规则：相同部分不到一半不标）。改动的词叠 `diff_*_word()`：有底色时底色深一档，没有时反色。只为显示得出的行算。
- 收起：历史里 Edit 最多 12 行、Add 最多 6 行，多的写 `… N more lines`；Delete 只画标题。批准框不限行数。
- `theme.rs`：256 色不再就近取，每种用途写死色号（照 Codex `diff_render.rs`）：加行 22 / 194、删行 52 / 224（深 / 浅），改动的词 28 / 157、88 / 217；`nearest_256` 删掉。`colorfgbg` 注释改对（0–6 是黑和各种暗色，7 是浅灰）。
- `crates/canter-tui/Cargo.toml` 加 `similar = { workspace = true, features = ["inline"] }`（版本还是 workspace 的 `=2.7.0`，根 `Cargo.toml` 没动）；`Cargo.lock` 只在 canter-tui 的依赖里多了 `similar`。

**拿主意的地方**

- 新建 `src/diff.rs`，没把解析和画法继续放在 `cells.rs`：历史和批准框共用，放在一处清楚。任务文件写的范围是 `crates/canter-tui/`，在范围内；`lib.rs` 只加一行。
- 256 色的取法：写死色号，不再就近取。就近取的问题不只是加行：改动的词 `#2E5C3F` 会取成青色 23、`#73322A` 会取成橄榄 / 棕色，色相都丢了。色号用 Codex 的 22 / 52 / 194 / 224，改动的词取同色相深一档的 28 / 88 / 157 / 217。
- 位置：历史里行号从第 6 列开始（和命令输出的文字对齐，照方案线框），批准框里紧贴左边距；`⋮` 和说明行在记号那一列；`…` 右对齐在行号列里（照线框 `… 406 more lines`）。卡片的 6 列缩进不铺底色，底色从行号铺到行尾。
- 收起按 diff 的行数算，不按折行后的屏幕行数：`N more lines` 说的是 diff 的行。`⋮` 占 12 行里的一行，但不算进 N；收起时不以 `⋮` 结尾。

- 配对按每一对单独比：similar 2.7.0 对整段做 inline 时不要求行数一样、「一半」也是按整段算，和要求（每对、行数一样才配）不同。
