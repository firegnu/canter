## 要做的

1. **模型放后台**：`shell` 工具加可选参数 `background`（默认 false）。为 true 时命令起来后等一小会儿（1～2 秒，或命令先结束），把这段输出、编号（会话里从 1 起的小整数）和「还在跑 / 已退出」交给模型，这一轮接着走。批准规则和普通命令一样（放后台不绕过批准）；后台命令没有 `timeout_ms` 的超时。
2. **两个新工具**：
   - `shell_output`（参数：编号）：返回上次读过之后的新输出，以及还在跑还是已退出、退出码。新输出超过现有的模型输出上限（32 KiB）时留末尾，写明跳过了多少。
   - `shell_stop`（参数：编号）：停掉整个进程组，返回最后一段输出和结果。
   - 工具说明写清楚什么时候用后台（开发服务器、监视文件、长测试）、怎么看输出、用完记得停。
3. **结束时告诉模型**：后台命令自己结束（或被用户停掉）后，下一次请求前往历史末尾加一句英文（编号、命令、退出码、怎么看剩下的输出）。只往后加；没有轮在跑时不因此开一轮。
4. **用户的 `!` 放后台**：`!` 命令去掉末尾空白后以单个 `&` 结尾（`&&` 不算）时，去掉这个 `&`，照第 1 条放后台、进同一套编号和管理；模型能用 `shell_output`、`shell_stop` 看它、停它。卡片照 P2-111/P2-112 的 `!` 样式，标「后台运行中」。不以 `&` 结尾的 `!` 命令照旧，结束时杀掉进程组。
5. **Ctrl+B 转后台**：模型的 `shell` 命令或用户的 `!` 命令在前台跑着时，按 Ctrl+B 把它转到后台：命令不停，这次工具调用马上返回（交给模型的结果和第 1 条一样：到这时的输出、编号、还在跑），这一轮接着走。没有前台命令时 Ctrl+B 什么都不做；搜索框、批准框、提问框、弹框开着时照它们自己的规矩。命令卡片下面、状态行在有前台命令时提示 `ctrl+b to run in background`。`?` 帮助里加上。
6. **活多久**：跟着会话。一直跑到模型或用户停掉、它自己结束、或服务端停掉（包括 `canter serve --replace`）；关终端窗口、`/new`、`/resume` 换到别的会话都不停。服务端停的时候杀掉所有后台进程组，不留孤儿进程。
7. **上限**：每个会话同时最多 8 条后台命令，超了起不来、回一句说明；每条只留最后 1 MiB 输出。
8. **界面**：
   - 对话里后台命令的卡片标「后台运行中」，结束后标退出码；结束时对话里出一行提示（编号、命令、退出码）。
   - 有后台命令在跑时，输入框上方常驻一行 `N background commands · /ps`（和 P2-34 的清单不挤：两样都有时都显示）。
   - `/ps`：弹框列出这个会话的后台命令（编号、命令、跑了多久、在跑 / 退出码），选中一条看最后的输出，按键停掉它。`/stop` 停掉这个会话所有后台命令。`?` 帮助和命令列表里有这两个。
   - 从历史打开会话、另一个终端打开同一个会话，看到的一样。
9. **计划模式**（P2-103）：放后台照 `shell` 的只读规则（只读白名单上的才放行）；`shell_output`、`shell_stop` 能用（不改文件）。
10. **协议和文档**：后台命令的状态（列表、输出、结束）怎么从服务端到终端，照 Codex app-server 的结构定，比 Codex 多的写进 DESIGN 第 8 条；DESIGN 加一条写后台命令（上面这些和用户 10-28 的选择）。
