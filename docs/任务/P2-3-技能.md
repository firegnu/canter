## 要做的

### 找技能

- 两个地方：全局 `~/.agents/skills/<目录>/SKILL.md`；项目里 `<项目根目录>/.agents/skills/<目录>/SKILL.md`。项目根目录和找 `AGENTS.md` 用同一个（往上找到有 `.git` 的那层，没有就是工作目录）。技能目录是符号链接的照常跟着走。
- 每个 `SKILL.md` 只读开头 `---` 之间的那段，取 `name` 和 `description`；正文不读。
- 同名时项目里的算数，全局那个不列。
- 开头带 `disable-model-invocation: true` 的，是给人手动点名用的，模型不该自己用：不进系统提示词；`/skills` 里照样列出，标明不给模型用。
- 没有开头那段、缺名字或简介、读不了、不是 UTF-8 的，跳过，照 `AGENTS.md` 的警告办法发一条警告（只在打开会话时发）。两个地方都不存在的不算错，不警告。

### 进系统提示词（DESIGN 第 17 条）

- 技能列表在建会话、打开会话时和日期、`AGENTS.md` 一起定下来，会话中途不变；按名字排序，顺序固定。会话中途加、删、改技能，下次打开会话才用上。
- 系统提示词里加一段：每个技能一行，写名字、简介和 `SKILL.md` 的绝对路径；再加一两句话告诉模型：任务和某个技能对得上时，先用 read 工具读那份 `SKILL.md` 全文，再照着做。一个技能都没有时不加这一段。措辞用英文，和现有系统提示词一致。
- 打开已有会话时，技能变了，开头就变了：照 P2-15 的做法在模型历史里记一条新开头；没变不记。P2-15 的「每次请求都是上一次的延续」那条测试要照样过。

### 终端和协议

- 协议加一个只读接口，返回这个会话打开时定下的技能：名字、简介、来源（全局 / 项目）、`SKILL.md` 路径、给不给模型用。路径、字段名你定，结构尽量照现有的只读接口；和 Codex 不一样的地方写进 DESIGN 第 8 条，说明为什么。
- `/skills` 列出本会话的技能，每个一行：名字、简介（窗口窄就截断）、来源；不给模型用的标出来。一个都没有时说没有，并提示放在哪两个目录。命令说明写进命令表（`/help` 和命令列表里看得到）。

## 怎么算做完

- 在有 `tdd` 技能的机器上，说「用 tdd 的方式改 X」，模型会去读那份 `SKILL.md` 再照做。（用户 10-24「照草稿」）
- 验证只做这些：
  - 针对验收写测试，先写、确认因为还没有技能而失败：在临时 HOME 下放一个 `tdd` 技能，用假模型的真服务端建会话，检查发给模型的系统提示词里有 tdd 的名字、简介和 `SKILL.md` 的绝对路径；假模型接着调 read 读那个路径，不弹批准、读到全文。模型会不会自己去读要真模型才看得到，本件不真调，用户装好后自己试。
  - 边角用例：项目和全局同名时项目的算数；`disable-model-invocation: true` 的不进系统提示词、`/skills` 里标出；缺开头、缺名字或简介的跳过并警告；两个目录都没有时系统提示词里没有技能那一段；会话中途加一个技能，下一次请求的开头不变，重开会话后才有；`/skills` 有技能、没技能两种画面（TestBackend）。
  - 协议改了，重新生成 Schema/TypeScript。
  - 做完跑一次 `cargo test --all-targets`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`（都带上面的 `CARGO_TARGET_DIR`）。
  - 觉得不够，在回复里说，不要自己加。

## 不要做

- 不调真实模型。
- 不做 `/tdd`、`/skill <名字>` 这种直接点名技能的写法；不跑技能目录里附带的脚本；不另加「读技能」的专用工具，读全文就用现有的 read。
- 不读技能正文进系统提示词；不改 read 的权限规则和受保护路径。
- 不改 `~/.agents/skills` 和用户别的文件；测试用隔离的 HOME、`CANTER_HOME`、临时项目目录和临时 socket，不碰用户正在跑的服务端（别读、别停它的 pid）。
- 不升级依赖；要加新依赖（比如解析 YAML 的库）的，停下来问。
- 不要按项目名或路径批量杀进程（`pkill -f canter` 这类）：主控和别的 agent 的进程命令行里都带着项目名和工作目录，一条命令能把它们全杀掉。停自己起的服务端用起的时候记下的 PID。
- 碰到要拿主意的事（包括技能开头的写法本机样例里没覆盖到、要动上面范围以外的文件），停下来，在回复里写清问题、可选办法和你的建议，然后结束这一轮，等主控回复再接着做；不在自己窗口里问用户，不开着命令等，不要自己换别的办法。主控的决定写进完成记录。
- 不合并到 main，不推送。只在 `p2-3-skills` 上提交。
