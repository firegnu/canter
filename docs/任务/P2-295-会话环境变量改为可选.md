## 为什么做

- 现在客户端把整份环境变量交给服务端（`crates/canter/src/lib.rs:280`）。服务端用这份环境替换命令、钩子、LSP 的环境。沙箱按其中的 HOME 定不可读名单（`crates/canter-tools/src/sandbox.rs:52-60`）。技能、全局 AGENTS.md 和 `~` 展开也看这个 HOME。
- 以后远程客户端（另一台机器、iPad、网页）交不出服务端机器上有意义的环境。硬交的话，沙箱会去保护客户端机器的 `~/.ssh`，服务端机器上真正的 `~/.ssh` 不受保护。
- 详见 `docs/调研/P2-291-远程连接方案.md` 1.3、2.1、2.2 和第 6 节第 1、6 件。

## 要做的

1. **协议**：新建、恢复会话请求里的 `env` 改为可选。复用这两个请求参数的入口也一样，比如 fork、`/new`、`/handoff`、计划开新会话、子 agent。旧客户端照旧交，行为和现在一样。
2. **服务端默认会话环境**：请求没带 `env` 时就用这一份。
   - 来源：
     - passwd 里服务端用户的 HOME、USER、SHELL；
     - 服务端启动时跑一次登录 shell，取它的整份环境，要设超时；
     - `config.json` 里可写的覆盖项。
   - 只放内存，不落盘，不进日志。
   - 登录 shell 探测失败或超时，就退回 passwd 加服务端进程自己的环境。`canter doctor` 里显示用的是哪种、为什么。
3. **服务端只有一条路**：带了 `env` 用 `env`，没带用默认。沙箱名单、技能、全局 AGENTS.md、`~` 展开、命令、钩子、LSP 都从这份会话环境来。这些现在就是这么取的，只是环境的来源多了一个，不另写分支。
4. **`/v1/info` 加字段**：
   - `instance`，供以后远程客户端判断重连的是不是同一个服务端；
   - `home`，服务端用户的 HOME，供客户端缩写显示服务端路径；
   - `features` 里加一个能力名，表示 `env` 可以不交。
5. **客户端不改**：本机终端、`canter exec` 照旧交 `env`，本机用法不变。
6. **文档**：
   - 协议 README：写清 `env` 可选，以及默认环境从哪来；
   - DESIGN 第 14 条：补上不交 `env` 时用默认环境，注明 P2-291 和用户 11-14 原话。

## 不要做

- 不改客户端发送 `env` 的逻辑，不开 TCP，不加 `--server`，这些是 P2-296、P2-297 的事。
- 不改沙箱规则本身，只改它拿到的 HOME 从哪来。
- 不改别的仓库。squire 用 `canter-protocol` 这个 Rust 包，`env` 类型变了它可能要跟着改。在完成记录里写清它要改哪里，主控交给用户。
- 不针对某一家模型写特例。
- 不调真实的模型接口。测试用假服务端、临时 `CANTER_HOME` 和隔离的 HOME，不碰用户的 `~/.canter`。测试里的登录 shell 探测，不能读用户真实的 shell 配置。
