## 要做的

### 1. 思考分步，下面的动作用竖线连起来

- 现在：思考、模型说的话、命令卡片、读文件一行行排下来，左边都对齐，看不出哪些动作属于哪一次思考。
- 要的：
  - 每段思考是一步的开头（小标题），从它往下、到下一段思考或这一轮的最后回答为止的条目（模型中间说的话、命令、读文件、改文件、计划、提问、批准结果行、重试行等），都属于这一步。
  - 这一步里的条目左边加一条细竖线 `│`（最淡的灰），条目整体往右缩两格；条目之间原有的空行也带上竖线，步骤之间的空行不带。
  - 一轮里第一段思考之前就有的条目（比如关了思考、模型直接开始跑命令），照现在的样子画，不加竖线。
  - 这一轮还在跑时同样按步骤画。
  - Ctrl+O 展开时：思考全文照现在的样子（`┊` 开头）放在步骤小标题下面，再往下是这一步的条目，都在竖线里面。
- 终端很窄（比如 60 列以下）时，竖线照样画；放不下的照现有的办法截断或折行。

### 2. 回答前一条横线

- 一轮最后的回答前面画一条横线（暗色 `─` 铺满可用宽度，前后各空一行），横线下面是回答，不在竖线里。
- 最后的回答 = 这一轮模型最后一段文字，后面没有再调工具。
- 模型还在写这段文字时 canter 不知道后面还调不调工具：等确定了（这次模型回复结束、没有工具调用，或这一轮结束）再画横线；之前照普通的模型文字画。画上横线时下面的内容往下挪一行，这个用户接受。
- 一轮里只有回答、前面没有任何思考和动作时，不画横线。
- 被打断、出错的轮：最后一段文字后面没有工具调用也算回答，照样画横线。

### 3. 回答里的标题和行内代码分开颜色

- 现在：`##` 标题是加粗 + 强调色（P2-187 定的），行内代码也是强调色，一样的颜色混在一起（浅色背景下最明显）。
- 要的：`##` 标题换成主题里现有的另一个颜色，和行内代码、正文、链接都分得开；深色、浅色背景都看得清。`#` 加粗下划线、`###` 加粗斜体不变。

### 4. 可点的路径不加下划线

- 现在：卡片标题里能点的文件名、路径都有下划线，一屏十几条（`links.rs` 的 `underline`）。
- 要的：可点的文件和路径不加下划线，改用主题里现有的一个颜色表示能点（和行内代码、标题的颜色分得开）；网址仍加下划线。点的行为不变。
- `NO_COLOR` 下没有颜色可用：路径照现在加下划线。

### 5. 连着的读文件对齐

- 现在：`◇ Read README.md  lines 1–37`，`lines …` 紧跟在文件名后面，长短不一。
- 要的：连着的几行读文件（中间没有别的条目），`lines …` 那一列对齐到其中最长的文件名后面两格。某个文件名太长、对齐后放不下时，那一行照现在的样子不对齐，别的照样对齐。

### 6. 思考行的样子

- 现在：`Thought for 2s: <内容>` 整行同一个颜色、斜体（`cells.rs` 的 `reasoning`）。
- 要的：
  - 折叠时：`✻ Thought for 2s` 用正常的灰色（`theme::secondary` 那一档），后面 ` · ` 加内容，内容更淡、斜体，放不下截断加 `…`。没有用时的写 `✻ Thought`。
  - 还在想时：`✻ Thinking…` 加最新一行，同样分两种颜色。
  - Ctrl+O 展开：标题行同样加 `✻`，全文照现在。

### 7. `exit 0 · 0.0s` 紧跟在命令后面

- 现在：卡片标题行右边对齐的状态（`exit 0 · 0.0s`、`running` 这些）在宽屏上离命令很远。
- 要的：这些状态紧跟在标题后面，空两格，用更淡的颜色；标题折成多行时，状态单独放在标题下面一行（和标题文字左对齐）。内容不变，失败的退出码颜色照现在。
- 所有工具卡片标题行右边对齐的状态都这样改，以代码里实际有的为准。

### 8. 文档

- DESIGN 里写到展示层的地方照本件改，写上用户原话；`crates/canter-tui/README.md` 照改。
