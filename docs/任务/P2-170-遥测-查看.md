## 要做的

1. **`canter stats` 不带参数**：列最近的会话，每行一个编号、最后活动时间、文件夹、第一句话（太长截断），最新的在上面。只列最近 20 个；`--all` 列全部。
2. **看一个会话**：`canter stats <编号>`（编号就是第 1 条列出来的），`canter stats --last` 看最近活动的那个，`canter stats <会话 ID>` 也认。打出：
   - 会话概况：文件夹、模型、时间段、标签、轮数、请求数、总用量和花费（沿用 `usage` 的算法）。
   - **按请求一行**：时间、用途（对话 / 压缩 / btw / handoff）、结局、用时、首片段用时、重试次数、上下文各部分（固定前缀、工具定义、对话、工具结果）和合计。看得出上下文怎么涨。
   - **压缩**：在发生的位置插一行，写自动还是手动、触发时的占用、压缩前后大小、去掉几条消息、成功与否，加下面第 4 条的三个信号。
   - **工具统计**：按工具名列调用次数、失败次数、被截断次数、结果平均和最大大小。
   - **批准等待**：次数、总等待时间、最长一次。
3. **`--json`**：第 2 条的全部内容（加上每条请求、每次压缩、每个工具调用的明细）以 JSON 输出，给以后的 eval 用。字段名写进 DESIGN，以后只加不改。第 1 条的列表也支持 `--json`。
4. **压缩效果的三个信号**（只是信号，不下「丢没丢」的结论）：
   - 重读：这次压缩前读过的文件（`read`），压缩后到下一次压缩前又读了几个，列出名字。
   - 摘要漏提：这次压缩前改过的文件（`write`、`edit`），压缩摘要里没提到的有几个，列出名字。按路径或文件名在摘要文字里找。
   - 待办：压缩前最后一份 `update_plan` 待办和压缩后第一份比，哪些项没了、哪些项状态变了。压缩前没有待办就写没有。
   - 怎么判「同一个文件」「提到了」，开发定，写进 DESIGN。
5. **`--html`**：把第 2 条写成一个网页文件：上下文占用随请求变化的曲线（各部分分色叠起来）、压缩处打标记，下面是请求表、工具统计和压缩信号。写到 canter 状态目录下，打出路径，再用系统浏览器打开。网页是单个文件，不从网上加载脚本、字体和样式，离线能看。
6. **旧会话和关了遥测的会话**：P2-169 之前的会话、`telemetry` 关着写的会话照样能看。现有记录能算的（用量、花费、重试次数、工具次数、压缩摘要）照算；没有记录的列写「unknown」，不报错，不按 0 算。`private-telemetry.jsonl` 里读不出的行和半截尾行跳过。
7. **服务端算，客户端排版**：统计由服务端读存盘算出、走协议给客户端，终端表格、`--json`、网页都是客户端排出来的（以后 GPUI、网页客户端照用）。接口照 Codex v2 的风格加，和 Codex 不同的地方写进 DESIGN。info 的 features 加一项，新客户端连没这项的旧服务端时报错，提示运行 `canter serve --replace`，不发请求。
8. **不拖慢正在跑的会话**：看统计只读存盘，不往会话里写任何东西，不改会话的活动时间、事件序号和列表排序。读正在跑的会话时不长时间挡住它的写入。
