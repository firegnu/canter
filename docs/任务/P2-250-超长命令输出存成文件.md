## 现状（主控查过的）

### 截断现在怎么做

- 命令（模型的 `shell` 和用户的 `!` 走同一处，`crates/canter-tools/src/shell.rs`）：输出一边流给客户端（最多 1 MiB），一边进 `BoundedText`（`crates/canter-tools/src/output.rs`），超过 32 KiB（`MAX_MODEL_OUTPUT_BYTES`）时只给模型开头 16 KiB 和结尾 16 KiB，中间写一行 `[truncated N bytes]`。中间那段哪儿都没留下，模型想看只能重跑命令。
- 读文件（`read`）超过 64 KiB 时已经会写 `Byte limit reached: read with startLine=N`，模型能接着读，不丢内容，**这件不管**。
- `web_fetch`、`web_search`、MCP、`ast_grep`、子 agent 结果也用同一个 32 KiB 头尾截断，**这件不管**（用户 11-08 定只管命令）。

### 11-08 统计用户本机 239 个会话（`canter stats`，只读）

- 有截断记录的工具调用 6299 次（另有 856 次是早期会话，没记录是否截断），截断 12 次：命令 9 次、读文件 3 次，都在 11-03 之后的长任务里。
- 9 次命令截断之后：
  - 3 次是搜索太宽，模型缩小范围重搜，各几十毫秒；
  - 2 次 `cargo nextest` 输出 20 多万字，一次换过滤条件重跑（0.5 秒），一次拿到需要的就往下走了；
  - 1 次 `cargo test` 跑了 66 秒，结尾的汇总够用，没重跑；
  - 3 次在测试仓库里，模型的脚本打出太多结果，改了 3 次脚本重跑（5、21、31 秒），多花了约 1 分钟。
- 没有看到因为缺中间那段而判断错的。风险最大的情况还没碰到：一条十几分钟的命令，要看的东西恰好在中间，只能整条重跑。

### 会话临时目录（存文件的地方）

- `crates/canter-tools/src/scratch.rs`：每个会话一个 `/tmp/canter-shell-<uid>-<digest16>`，0700。会话关闭时删掉；**同一会话重新打开（包括服务端重启、升级）时先清空再建**。模型命令的 `$TMPDIR` 就是它，沙箱开着时也能读写。建不出来时 `path()` 是 `None`，只有一条警告。
- 读文件不分目录，不要批准（`crates/canter-tools/src/permission.rs` 的 `outside_directories` 只管写、改、补丁）；只读命令（`rg`、`sed -n`）读它也不弹框。

## 对核心稳定性的影响（主控评估，11-08）

| 方面 | 影响 | 怎么守住 |
|---|---|---|
| 没超 32 KiB 的命令（统计里 99.8% 的调用） | 一个字节都不变：不建文件，给模型的文字、客户端事件、遥测都照旧 | 测试锁住：短输出不建文件，文字和现在逐字节一样 |
| 超了的命令 | 给模型的开头、结尾照旧，只在 `[truncated N bytes]` 那行加上文件路径 | 测试锁住格式 |
| 缓存命中 | 只影响新产生的工具结果，之前的历史不变，不会让缓存失效 | 不改已有历史 |
| 存文件失败（目录没建成、磁盘满、写出错） | 退回现在的样子：照旧截断，不写路径；命令本身的成败、退出码、输出不受影响 | 测试锁住：临时目录不可用时结果和现在一样 |
| 磁盘 | 一条命令可能打几个 GB | 每份文件有上限，整个会话有总上限，超了就不再存（见「用户定的」第 2 件） |
| 命令的速度、取消、超时、杀进程组 | 只在现有的读输出循环里多写一份文件，不加进程、不改超时和取消 | 写文件不能卡住读输出：大输出时速度不明显变慢；取消、超时的现有测试都要过 |
| 服务端重启、会话重新打开后 | 临时目录被清空，旧结果里的路径失效；模型去读会得到「文件不存在」，和读一个不存在的文件一样，不会出错 | 路径那行写明「本会话内有效」 |
| 安全 | 存的就是模型本来就能看到的命令输出，放在 0700 的会话目录里，随会话删除；不新增可读范围，不改沙箱 | 不放进项目目录、不放进 `~/.canter` |
| 后台命令（`&`） | 不动，照旧用自己的 1 MiB 缓冲 | 「不要做」里写明 |

结论：改动集中在 `shell.rs` 收输出这一处。最坏的情况是存文件这一步出问题，退回到现在的行为；命令执行、对话历史和缓存都不受影响。

## 用户定的（11-08）

1. **管哪些工具**：只管命令（模型的 `shell` 和用户的 `!`，同一处代码）。统计里截断几乎都在这；`web_fetch`、`web_search`、MCP 以后真碰到再说。（用户先选了连这三样一起存，随后改回只管命令。）

3. **交给谁**：canter，模型用服务端配置的那个。

## 要做的

1. 命令输出超过 32 KiB 时，把完整输出（按上限）存进会话临时目录下的一个文件，一次调用一份，文件名用工具调用的 id。
2. 给模型的文字：开头、结尾照旧，`[truncated N bytes]` 那行改成也写出文件路径，并用一句英文说可以用 `read`（带 `startLine`）或 `rg` 看中间的内容、路径只在本会话内有效。路径用 `$TMPDIR` 那个写法（`/tmp/canter-shell-…`），和系统提示词一致。超过每份上限时写明只存了前面多少。文字是给模型看的，用英文。
3. 没超 32 KiB 的不建文件，给模型的文字和现在逐字节一样。
4. 存不了（临时目录没建成、写出错、会话总量满了）就照现在的样子只截断，不写路径；命令本身照常。写出错记一条服务端日志，不报给模型。
5. 写文件不能拖慢读输出、取消和超时。
6. 文档：`docs/DESIGN.md` 记这件的做法、上限和理由；`docs/usage.md` 里如果写了截断，一并改。
