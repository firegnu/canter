## 要做的

1. **计划模式是会话的一项设置，和权限模式分开**：会话设置加一项「在不在计划模式」，进计划模式时记下当时的权限模式，用 `/plan` 出来时回到它（Shift+Tab 出来照轮换到下一档，批准方案时换到批准框里选的那一档，见第 5 条）。存进会话，重开会话（`/resume`、`-c`）还在计划模式。
2. **进出**：
   - Shift+Tab 的轮换多一档：Always ask → Ask for execution → Allow all → Plan → Always ask。
   - 加 `/plan` 命令：不在计划模式时进，在计划模式时出（回到进之前的权限模式）。`?` 帮助和命令列表里有它。
   - 状态栏权限那一项在计划模式里写 `Plan`，用一个和三种权限模式都不同的颜色（终端 16 色）。
   - 模型干活时也能切，从下一次调工具起生效（和现在切权限模式一样）。
3. **计划模式里只能查、不能改，在执行工具时硬挡**，不只靠提示词：
   - 能用：`read`；`shell` 里只读白名单上的命令（`readonly.rs`，和现在自动放行的同一套）；`web_fetch`（照现有批准规则）；`ask_user`；`submit_plan`。
   - 挡掉：`write`、`edit`、不在只读白名单上的 `shell` 命令、所有 MCP 工具、`update_plan`。挡掉的不弹批准框，直接给模型回一句英文（说明这是计划模式、不能用这个工具、该怎么办），对话里这张卡片标成被挡。
   - 工具列表不随模式变（照顾缓存）：`submit_plan` 一直在列表里，不在计划模式时调它照样回一句英文说明。
4. **进出时告诉模型**：进计划模式时往历史末尾追加一段英文说明（先查清楚、有不明白的用 `ask_user` 问、不要改任何东西、最后用 `submit_plan` 交一份完整方案；写法参考 Codex 的 `plan.md`，自己写），出计划模式时再追加一句已经出来了。只往后加，不改前面的历史。这两段不显示在对话里、不进 `/export`。
5. **交方案**：新工具 `submit_plan`，参数是整份方案（Markdown）。模型调它时，终端弹批准框，整份方案按 Markdown 画出来（太长能滚）。方案下面一行 `Mode: <档位>   (shift+tab to change)`，在框里按 Shift+Tab 照三档的顺序轮换（不轮到 Plan）；默认是进计划模式前那一档，那一档是 `Allow all` 时默认 `Always ask`。下面三个选项，两个「批准」都用这一行选的档位干活：
   1. `Yes, implement this plan`：出计划模式、换到选的那一档，模型在这一轮里接着照方案做。给模型的工具结果说已批准；P2-34 清单开着时（`plan_enabled`），让模型先用 `update_plan` 把方案的步骤列成清单再做。
   2. `Yes, clear context and implement`：出计划模式；照 `/handoff` 的办法在同一个工作目录新开一个会话，权限模式是框里选的那一档，第一条消息是整份方案加一句「照这个方案做」（清单开着时同样先列清单），终端切到新会话并开始跑；原会话这一轮结束（工具结果说用户选了在新会话里做），留在 `/resume` 列表里。
   3. `No, keep planning`：可以在框里写一句意见（照 P2-51 拒绝并说明的写法），交给模型，留在计划模式接着改。
   - 对话里这次 `submit_plan` 显示成一张方案卡片：标题写批准结果，下面是方案全文（照长输出的规矩收起、Ctrl+O 展开）。从历史打开会话时画法一样；`/export` 里写方案全文和结果。
6. **模型不能自己进计划模式**，只有用户能进。
7. `docs/DESIGN.md`：加一条写计划模式（上面这些定下来的事和用户 10-28 的选择）；第 8 条写协议里比 Codex 多了什么、改了什么、为什么（Codex 是靠提示词和 `<proposed_plan>` 块，canter 用工具交方案、在工具层硬挡）。
