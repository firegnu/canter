## 要做的

### 给服务端的会话接口

服务端（P1-5）只管 HTTP 和连接，会话的事都交给本包。至少要有：建会话、打开已有会话、送一句话（排队或插话）、打断、回答批准请求、手动压缩、改设置、关会话、订阅事件。每个操作都返回它对应的事件序号（协议里命令回复的 `eventSeq`）。

- 事件先写存盘、再发给订阅者，发出去的和存盘里的是同一条、同一个序号。
- 订阅者从某个序号接着收时，拿到的事件不漏不重：先从盘上补（`Store::events_after`），再接上实时的。
- 存盘是同步接口，放到阻塞线程里调；文字、命令输出这类增量，把短时间内的合成一批写（`append_batch`）。

### 会话的环境（DESIGN 第 14 条）

- 建会话、打开已有会话时，调用方（服务端）交来环境变量和受保护路径（`protected_paths`），本包拿它们建执行器。环境只放内存，不写盘。
- 现在 `canter-store` 把环境存进会话目录的 `private.json`（`PrivateSessionConfig`）。改成不存环境；`private.json` 留不留、留了放什么，你定，`canter-store` 的 README 和测试跟着改。已经存在的旧 `private.json` 不用迁移。

### 一轮的循环

照报告 §1.3：

1. 送一句话：空闲就开新一轮；在干活时照参数排队，或者插话（插到下一次调模型之前）。
2. 拼上下文，调模型，流回来的文字、思考内容变成 `item.*` 事件。
3. 模型要调工具：先问权限闸门。要问人时，发 `request.opened`，会话状态变成 `waiting_approval`，等任意一个客户端回答，先到先得；回答后发 `request.resolved`。
4. 执行工具，输出边跑边变成增量事件，结束时发 `item.completed`。
5. 结果放回上下文，再调模型，直到模型不再要工具，发 `turn.completed`。
6. 回复被截断时（结束原因是「被截断」），不执行里面的工具调用。
7. 回答「拒绝并停下」：这一轮停下，像打断一样收尾。
8. 一轮结束后，队列里还有话，接着开下一轮。

### 打断

照报告 §1.3「按 Esc 打断时」：掐断正在进行的模型请求，取消正在跑的工具（杀进程组），还没处理的批准请求都标成取消。往模型历史里记一条「被打断」，让模型下次知道。这一轮以 `interrupted` 结束，会话回到 `idle`。

### 排队的话怎么移出（第 1 件审查带过来的）

现在只有开新一轮时会把排队的话移出（`turn.started.inputId`）。打断时丢掉队列、插进当前轮、几句合成一轮、会话关闭时，也都要能移出。办法二选一，你定：加一种移出事件（带原因），或者改成可以带多个 id 再加丢弃事件。改协议包的部分照「不要做」最后一条，先停下来说你的方案；协议包 README 要补上插话时回复的 `eventSeq`、`turnId` 指什么。

### 上下文和模型历史

- 每次调模型前拼上下文：系统提示词、环境信息（工作目录、系统、日期）、项目的 `AGENTS.md`（从 git 根目录到工作目录一路上的都读），再加对话。
- 系统提示词自己写。参考了 Codex、pi 的提示词，照搬的段落注明来源；有 Apache-2.0 的原文，照 `CLAUDE.md` 维护 NOTICE。
- 发给模型的每条消息，原样写进模型历史（`append_model_history`，DESIGN 第 13 条），用 P1-2 的消息类型。打开已有会话时，模型的上下文从模型历史还原，不从显示用的事件反推。
- 模型历史条目以后可能加新种类，旧版本读到要能跳过，不能整个读失败（第 1 件审查带过来的）。

### 压缩

- 手动压缩（协议的 compact 命令），加上快到上限时自动压缩。上下文窗口大小可配置（DeepSeek 的默认值你查文档定）。
- 照报告 §2.5：触发照 pi（超过「窗口减去预留 16,384 token」）；保留最近约 2 万 token 的用户原话，更早的让模型写成摘要；摘要提示词照 Codex 的写法。
- 压缩作为一个项目（`contextCompaction`，带摘要）发事件、存盘；模型历史里也记一条，还原时从压缩处接着。

### P1-2 审查带过来的

- 打断时，已经写进模型历史、还没有结果的工具调用要补上占位结果（`canter-model` 发请求时也会补，但历史本身要完整）。
- 自动压缩的阈值要把输出预留算进去：DeepSeek 判断超长时算的是「输入 + `max_tokens`」，思考模式默认 `max_tokens` 是 64K。
- `ModelStream<'_>` 借用了模型对象；放进 `tokio::spawn` 的任务里时持有 `Arc<dyn Model>`，在任务里面再调 `stream`。
- 收到 `Finished(Length)` 或 `Finished(Other)` 时回复不完整，要让用户看到。
- 模型层重试期间调用方收不到任何东西（最坏要等很久），要不要给界面一个「正在重试」的信号，你定。
