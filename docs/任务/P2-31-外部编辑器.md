## 要做的

1. **按键**：普通输入框里按 Ctrl+G（Codex、Claude Code 都用这个键）打开外部编辑器。搜索框、批准框、提问框、弹框、会话列表开着时不起作用。
2. **用哪个编辑器**：先 `VISUAL`，再 `EDITOR`，按 shell 规则拆成程序和参数（比如 `code --wait`）；都没设时状态栏提示一句 `Set $VISUAL or $EDITOR to use an external editor`，草稿不动。
3. **写什么进去**：当前草稿写进一个只有用户能读写的临时文件（扩展名 `.md`，放在新建的私有临时目录里），`[Pasted …]` 标记换成粘贴的全文；`[Image …]` 标记照原样写进去。用完删掉临时文件和目录。
4. **交出终端**：退出全屏、原始模式、鼠标和键盘增强，让编辑器用整个终端；编辑器退出后恢复原样、整屏重画。这期间服务端来的事件不丢，回来后照常显示；读终端的线程不能和编辑器抢按键。
5. **放回来**：编辑器正常退出，文件内容（去掉末尾多出的一个换行）替换整个草稿，光标放到末尾；`[Image …]` 标记还在的，图片附件留着，删掉了的附件跟着去掉；粘贴的全文不再收成标记。编辑器退出码不是 0、启动失败或文件读不了时，草稿保持原样，状态栏写原因。内容清空了就是空草稿。
6. 加进 `?` 帮助弹框的输入框快捷键一节；DESIGN 第 19 条补一句定法，提交说明里写。

- 拿主意的地方：
  - shell 拆参数自己写了一个三十来行的小函数，没加 shlex：加依赖要改根目录 `Cargo.toml` 和 `Cargo.lock`，超出任务说的只动 `crates/canter-tui`。规则和 shlex 的 POSIX 模式一样（不展开 `$`、`~`、通配符）。
  - `VISUAL` 设了但是空的，往下用 `EDITOR`（Codex 是报「命令为空」）。`VISUAL` 有没闭合的引号时直接报这个，不往下找 `EDITOR`。
  - 编辑器起来之后、退出之前，canter 忽略 SIGINT 和 SIGQUIT（照 git 的 `launch_editor`）。原因：交出终端时关了原始模式，canter 和编辑器在同一个前台进程组，在 `code --wait` 这类不接管终端的编辑器里按 Ctrl+C，信号会连 canter 一起杀掉（终端已经交出去，草稿也丢了）。在起编辑器之后才忽略，所以编辑器自己照常收到 Ctrl+C；退出后放回原来的处理方式。
  - 编辑器退出后用 `tcflush` 丢掉终端里还没读的输入（照 Codex `with_restored` 里的 `flush_terminal_input_buffer`），免得编辑器退出时多敲的键、终端对编辑器查询的迟到回答被当成按键打进草稿。
  - 交出和收回终端放进 `FrameSync`（公开 trait）的两个新方法，有默认空实现，原来实现它的地方不用改。
  - 失败时状态栏的写法：没设编辑器照任务原话；其余是 `Editor exited with code N`、`Could not start <程序>: …`、`Could not read the edited message: …`、`$VISUAL has an unclosed quote` 后面加 `; draft unchanged`。
