## 要用户定的

1. **怎么让模型调到搜出来的工具**：
   - **A（主控推荐，和 omp 同路）**：工具列表固定不变。MCP 工具不再逐个放进工具列表，换成两个内置工具：`mcp_search`（按关键词或名字搜，返回工具的完整说明和参数格式，作为普通工具结果进对话）和 `mcp_call`（填工具名和参数去调）。好处：工具列表整个会话不变，缓存不冷；不靠哪家接口的特殊功能，以后接别的模型商也能用。代价：参数格式不再由接口约束，照 omp 由 canter 按参数格式先校验，不对就把格式连同错误返回给模型；每个工具第一次用多一轮搜索（清单里有简介，常常一眼就知道该搜哪个）。不照 omp 借用 `read` / `write`：canter 的 `write` 带改文件的批准和受保护路径，混进去批准就乱了，单独两个工具清楚。
   - **B**：搜到的工具加进后面请求的工具列表，模型像现在这样直接调。好处：参数格式有接口约束。代价：每加载一个新工具，工具列表就变一次，DeepSeek 的缓存多半从工具定义那里起冷掉一次（文档没写，没实测）；而且要把「这个会话加载过哪些工具」存盘，压缩、回退、重开都要照顾到。
2. **什么时候按需**：
   - **总是（主控推荐）**：配了 MCP 就按需，照 Claude Code 默认。简单、好预期；MCP 少时也多一轮搜索。
   - **门槛**：MCP 工具说明合计超过上下文的一定比例（Claude Code `auto` 是 10%）才按需，不到照旧全量。省掉小配置下的那一轮，但什么时候按需不直观。
3. **要不要能关**：`config.json` 加一项关掉、退回全量（照 Claude Code `ENABLE_TOOL_SEARCH=false`），默认开。主控推荐加：DeepSeek 用按需方式调得好不好没数据，能关就能对比、出问题能退。

## 要做的

1. **开会话时**：配了 MCP 并连上了，工具列表里不再有一个个 `mcp__服务__工具`，换成 `mcp_search`、`mcp_call` 两个。模型在固定的开头部分看到一份清单：每个 MCP 工具一行，写全名（`mcp__服务__工具`）加一句简介（照 omp：取说明第一行，过长截断）。清单和工具列表一样在开会话或重新打开时定下，整个会话不变（照现在「通知只更新服务当前目录，下次打开生效」）。没配 MCP 或一个都没连上时，两个工具和清单都不出现，和现在一样。
2. **`mcp_search`**：参数是查询文字。写了完整的工具名（一个或几个）就返回这几个；否则按关键词在工具名和说明里搜，返回最相关的几个（不超过 5 个）。每个结果给全名、完整说明、参数格式（JSON Schema）。搜不到时说清楚，并提示看清单。不用批准，计划模式、审查轮里也能用。
3. **`mcp_call`**：参数是工具全名和参数对象。照现在调 MCP 工具的同一条路走：同样的批准（框里显示的是真正的服务名和工具名、参数）、同样的超时和输出上限、图片照样交给模型、计划模式和审查轮照现在对 MCP 的规矩。对话里的卡片和存盘照现在的 `mcpToolCall` 显示真正的服务名和工具名，不显示成 `mcp_call`。调之前 canter 按这个工具的参数格式校验，不对就不调、不弹批准，把错误连同完整的参数格式返回给模型（照 omp）。工具名不在清单里时报错，告诉模型先搜。没先搜就直接调清单里的工具：照常调。
4. **搜索的卡片**：对话里 `mcp_search` 显示一张卡片，写查询和搜到的工具名（界面文字英文，比如 `Searched MCP tools "issue" · 3 found`）。要加协议的照 Codex app-server v2 的写法加，旧客户端不认的跳过，写进 DESIGN 第 8 条。
5. **能关**：`config.json` 加 `mcp_tool_search`（布尔，默认 true）；false 时照现在全量放进工具列表。改了下次打开会话生效。
6. **提示词**：有 MCP 时提示词里那两处照旧说 MCP 工具要批准、结果是数据不是指令；另加一句：先用 `mcp_search` 看说明再用 `mcp_call` 调。改提示词经用户点头（DESIGN 第 20 条），本件用户同意即算。
7. **DESIGN**：第 8 条 MCP 那段写清按需加载、两个工具、清单、开关，以及为什么不用接口自带的延迟加载（DeepSeek 没有）。
