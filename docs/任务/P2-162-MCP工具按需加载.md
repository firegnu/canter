2. **`mcp_search`**：参数是查询文字。写了完整的工具名（一个或几个）就返回这几个；否则按关键词在工具名和说明里搜，返回最相关的几个（不超过 5 个）。每个结果给全名、完整说明、参数格式（JSON Schema）。搜不到时说清楚，并提示看清单。不用批准，计划模式、审查轮里也能用。
3. **`mcp_call`**：参数是工具全名和参数对象。照现在调 MCP 工具的同一条路走：同样的批准（框里显示的是真正的服务名和工具名、参数）、同样的超时和输出上限、图片照样交给模型、计划模式和审查轮照现在对 MCP 的规矩。对话里的卡片和存盘照现在的 `mcpToolCall` 显示真正的服务名和工具名，不显示成 `mcp_call`。调之前 canter 按这个工具的参数格式校验，不对就不调、不弹批准，把错误连同完整的参数格式返回给模型（照 omp）。工具名不在清单里时报错，告诉模型先搜。没先搜就直接调清单里的工具：照常调。
4. **搜索的卡片**：对话里 `mcp_search` 显示一张卡片，写查询和搜到的工具名（界面文字英文，比如 `Searched MCP tools "issue" · 3 found`）。要加协议的照 Codex app-server v2 的写法加，旧客户端不认的跳过，写进 DESIGN 第 8 条。
