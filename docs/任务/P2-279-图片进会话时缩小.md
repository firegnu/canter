## 要做的

1. 图片存成会话副本（`image-<随机名>.<格式>`）之前，长边超过 1568 像素的，等比缩到长边 1568。三条来源都算：用户附的图（P2-5）、`read` 和 MCP 返回的图（P2-130）、PDF 按页转出的图（P2-226）。
2. 缩小只在存副本时做一次。之后每次请求发的都是这份副本，请求字节不再变（DESIGN 第 17 条）。
3. 格式不变，PNG 还是 PNG，JPEG 还是 JPEG。缩完反而比原文件大、或者解不开的，存原图，照旧能用。动图（GIF、动画 WebP）不缩，存原图。
4. 单张 8 MiB 的上限照旧按原图算，40 MiB 预算、每张 1024 token 的估算、不收图模型的占位、卡片和导出都不变；卡片上显示的大小是副本的大小。
5. 解码和缩放不卡住服务端，别的会话照常收发。
6. 各家模型一样处理，不按模型或服务商分支（DESIGN 第 23 条）。
