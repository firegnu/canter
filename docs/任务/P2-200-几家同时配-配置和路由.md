## 要做成什么

1. `config.json` 能同时写几家，每家有自己的地址、API key、额外请求头；每个模型有自己的上下文窗口、能不能看图、价格（有的话）。
2. 会话用哪个模型，请求就发到那一家；同一个服务端上，不同会话可以同时用不同的家。
3. 上下文窗口、自动压缩线、空间提示（P2-175）、看图、搜网页，都按会话当前的模型来。
4. 改配置照 P2-154：保存后下一轮生效，不重启服务端；改坏了照现在沿用旧配置并提示。
5. 旧的单家写法照样能用：用户不改 `config.json` 就能升级，行为和现在一样。

## 要用户定的（主控建议，用户定了再派）

1. **同一会话中途换到另一家**：建议能换，空闲时换（现在 `/model` 本来就只在空闲时换）。现在几家都是 Chat Completions，历史不用转格式，只是缓存会失效。换到窗口更小、当前占用已经超过新压缩线的模型时，先压缩再发。备选：只能换同一家的模型，换家要开新会话。
2. **模型名怎么写**：建议 `<家名>/<模型名>`（照 opencode），在第一个 `/` 处分开（OpenRouter 的模型名本身带 `/`）。旧会话里存的模型名、旧配置的 `model`、`-m` 参数不带家名的，按旧的单家配置认。
3. **搜网页**：现在只有 `base_url` 是 DeepSeek 官方地址时才有（P2-106）。建议：只要配了 DeepSeek 官方这一家，不管当前用哪家的模型都给 `web_search`，搜索走 DeepSeek 的 key、扣 DeepSeek 的钱；没配就不给。备选：只在当前模型是 DeepSeek 官方时给（和现在一样）。
4. **凭证放哪**：建议照旧写在 `config.json`（0600），每家配一次；不做 opencode `/connect` 那种界面登录。

## 主控补的（用户没说到的地方）

- 子 agent、提示建议（P2-102）、压缩、顺口问、交接、审查，都用发起它的会话当前的模型，也就走那一家（现在就是跟着会话的模型）。
- 用量和遥测照旧按模型记，模型名带上家名，`/usage`、`canter stats` 能看出是哪家。价格按带家名的模型名查；没写价格的（订阅）照现在没有价格的模型处理，`/goal` 预算的算法不改。
- 一家连不上或额度用完，只影响正在用这家的会话，报错和重试照现在（P2-110）；不自动换到别家。
- 以后接 GPT（P2-80）要加「登录拿令牌」的认证和 Responses 接口。本件不做，但每家写成一个对象，以后加一种认证或接口时只往那一家的写法里加字段，不用改已有家的写法。
- 配置里某一家写错（地址不对、少了 key）：照 P2-154 整份沿用旧配置并提示，不要只丢掉那一家；第一次启动就写错的，照现在启动失败、说清哪一家哪一项。错误信息不带 key 和请求头的值。
- `/v1/models` 每个模型带上家名、窗口、能不能看图，给 P2-201 用；旧客户端照常能用（只加字段）。
