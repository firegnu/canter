## 要做的

1. **一个工具 `update_plan`**，形状照 Codex：可选 `explanation`，`plan` 是 `[{step, status}]`，`status` 为 `pending` / `in_progress` / `completed`，至多一个 `in_progress`；每次整份替换。给模型回一句短的（照 Codex 回 `Plan updated`）。不合规的（两个 `in_progress`、空的 `step`）回错误让模型重发，不改现有清单。不弹批准框，哪种权限模式都一样。
2. **做轻**（P2-94 第 2 条）：工具说明写明三步以上的活才用、简单的不用，开始做一步时标 `in_progress`、做完马上标 `completed`，不要为了更新而更新。系统提示词核心不加句子，只靠工具说明（改核心要用户点头，DESIGN 第 20 条）。
3. **可以关**：`config.json` 里一个开关，默认开。关了就不给模型这个工具，界面上也没有清单。工具集在打开会话时定下来（照顾缓存，DESIGN 第 17 条），所以改开关从下一个会话起生效。
4. **用户看得到进度**：
   - 对话里：每次更新出一张卡片，标题行写进度（参考 Codex `Updated Plan · 2/5 complete`），下面列步骤：做完的打勾、变暗，进行中的高亮，没开始的普通。
   - 常驻：照「用户定的」第 1 条。
   - 别的终端连上同一个会话、重开会话，看到的是当前那份清单。
5. **压缩以后不丢待办**（10-27 晚用户同意记进来）：压缩以后模型还看得到当前清单、能接着勾；压缩前清单的状态原样带过去。
6. **回退**（P2-23）：退到某一轮之前，清单也回到那时的样子。
7. 协议：怎么加（新的项目种类，还是照 Codex 发 `turn/plan/updated` 通知、再在会话快照里带当前清单）由做的人按现有机制定，新字段可选，旧客户端读成 Unknown 跳过；和 Codex 不一样的地方写进 DESIGN 第 8 条，说明为什么。`/export` 照对话里的样子带上清单。
