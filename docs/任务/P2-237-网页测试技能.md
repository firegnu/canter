## 现状（主控查过的）

- **沙箱里起不了浏览器**：主控 11-06 用和 canter 沙箱同样的 Seatbelt 规则（`crates/canter-tools/src/sandbox.rs` 的 `command`）跑 `Google Chrome --headless=new --screenshot`，不论加不加联网那段、加不加 `--no-sandbox`，都在启动时 `abort()`（退出码 134，没有输出）。崩溃报告：主线程 `TransformProcessType` → `_RegisterApplication` → `abort`，即 Chrome 向 macOS 登记应用时要连的系统服务被沙箱挡住。沙箱外同一条命令正常出图。模型能申请的 `sandboxRequest` 只有 `network` 和 `writePaths`（P2-164），解决不了。所以沙箱开着时，模型自己写的浏览器脚本跑不起来；`--yolo`（沙箱关）或配置 `"sandbox": false` 时可以。
- **模型怎么知道沙箱开没开**：沙箱开着时 shell 工具才有 `sandboxRequest` 参数（P2-164），系统提示词里会话临时目录那句才有 "needs no approval"（`crates/canter-core/src/prompt.rs`）。被挡时 shell 结果里可能没有沙箱拦截的提示（Chrome 直接崩，不打印 denied）。
- **Playwright MCP**（P2-128）：不在沙箱里，每个工具第一次用要批准。用户本机配的是 `@playwright/mcp@0.0.83 --isolated`，开窗口。工具里有 `browser_navigate`、`browser_snapshot`、`browser_click`、`browser_type`、`browser_fill_form`、`browser_take_screenshot`、`browser_console_messages`、`browser_network_requests`、`browser_evaluate`、`browser_run_code_unsafe`（一次跑一段 Playwright 代码）等。模型一般经 `mcp_search` / `mcp_call` 用 MCP 工具。用户不一定配了它，名字也不一定叫 `playwright`。
- **测本机网页要起开发服务器**：沙箱开着时开端口要申请联网（`sandboxRequest.network`），沙箱关着不用。canter 有后台命令（`shell` 后台运行、`shell_*` 管理）。
- **技能机制**（P2-3、P2-232）：`~/.agents/skills/<名字>/SKILL.md`，系统提示词只列名字、说明和路径，模型要用时自己 read。自带技能在 `crates/canter/skills/<名字>/SKILL.md`，`crates/canter/src/skills.rs` 的 `BUNDLED` 用 `include_str!` 编进程序，`canter skills install [--force]` 安装；测试在 `crates/canter/tests/support/skills_install.rs`。
- **用户本机**：`~/.agents/skills` 里已有 `docx`、`pptx`、`xlsx` 等，没有叫 `web-testing` 的；装了 Google Chrome、`node`/`npx`、`uv`。
- **参考**：Anthropic 官方 `webapp-testing` 技能（Apache-2.0）的思路：静态页先读 HTML 找选择器；动态页先确认开发服务器起了，等 `networkidle`，先截图或看 DOM 摸清页面，再用找到的选择器操作；脚本里浏览器一律无头。只参考思路，不搬原文和脚本，canter 的技能自己写。

## 要做的

1. **技能** `web-testing`，一个英文 `SKILL.md`。说明（`description`）写清：验证、调试网页或前端（元素、交互逻辑、页面样子、控制台报错）时用。正文写清：
   - **两种做法怎么挑**：只是验证页面、截图、看控制台和网络、跑一段固定流程的，写无头 Playwright 脚本跑，跑完看截图和输出；要一步步摸索页面、来回试、或用户说想看着它点的，用 Playwright MCP。用户没说的，模型按情况自己挑，不去问用户要前台还是无头。
   - **先看沙箱**：shell 工具有 `sandboxRequest` 参数就说明沙箱开着，浏览器起不来，申请联网或写路径也没用；这时直接用 Playwright MCP，不要反复试脚本。MCP 也没配的，告诉用户两条路：配 Playwright MCP（指向 `docs/usage.md` 的 MCP 一节），或用 `canter --yolo` 开会话再测。
   - **找 MCP**：用 `mcp_search` 找浏览器工具（Playwright 的工具名形如 `browser_navigate`、`browser_snapshot`），不假定服务名一定是 `playwright`。MCP 下优先读页面结构（`browser_snapshot`）按元素操作；要看样子才截图，只有能看图的模型看得到截图。一段固定流程可以用 `browser_run_code_unsafe` 一次跑完。
   - **写脚本**：先查本机有什么（`uv`、`python3`、`node`、Chrome）。脚本放会话临时目录；装库用不污染全局的办法（比如 `uv run --no-project --with playwright`，或临时目录里的 Node 项目）；浏览器优先用本机装的 Chrome（Playwright 的 `channel="chrome"`），没有 Chrome 才下载 Chromium，下载前告诉用户（几百 MB）。截图、控制台输出存临时目录，再用 read 看截图。
   - **测本机网页**：先确认开发服务器在不在跑；没在跑就用后台命令起，等端口通了再测，测完停掉自己起的服务（用记下的进程，不按名字杀）。静态页可以先读 HTML 找选择器。
   - **怎么验证**：等页面加载完（动态页等网络空闲或等目标元素出现）；先摸清页面再操作；断言写具体（文字、数量、状态、网址），报结果时说清查了什么、哪些只是看截图判断的；有控制台报错一并报告。
   - 篇幅照 `xlsx` 技能，以说明为主，可以有很短的示例片段，不带一大套现成脚本。
2. **编进程序**：加进 `BUNDLED`，`canter skills install` 一起装；已有同名不覆盖、`--force` 覆盖的规则不变。
