## 要做的

方案里每一项写：canter 现在怎么画；别家怎么做（各一两句，标出处：源码文件或文档）；推荐怎么做、为什么；有实质备选的写备选和取舍；文字线框（等宽字符画，画出推荐的样子，必要时画备选）。

要覆盖的项：

1. **配色和主题**：深色 / 浅色终端怎么适配（自动判断还是让用户选）、终端只支持 16 色或 256 色时怎么退、要不要多套主题、用户能不能自己配。
2. **diff**（改文件的工具结果和批准框里）：统一 diff 还是左右并排、行号、加删行的底色、行内改动高亮、很长的 diff 怎么收起。
3. **代码块**：要不要语法高亮、用什么做（写明要加的库和大小）、语言识别、很长的代码块怎么办。
4. **markdown 表格**：画成对齐的表格（原 P2-17），中文等宽字符的对齐，表格比屏幕宽时怎么办。
5. **思考过程**：显示不显示、默认收起还是展开、怎么和正文区分、能不能事后展开看。
6. **工具调用和结果**：shell、读文件、改文件、MCP、网页抓取（P2-13 在做）这些怎么显示，长输出怎么收起，失败怎么标。
7. 其它你觉得影响「看起来像不像一个好用的 coding agent」的展示问题（比如进行中的转圈、标题、空行节奏），只列确实有差别的，不凑。

最后两节：

- **要用户选的**：把真有取舍、要用户拍板的点列成问题，每个给选项和你的推荐，最多 8 个，按重要程度排。
- **分件**：照推荐拆成能分别派出去的小活，每件写标题、做什么、动哪些文件、大小（小 / 中 / 大）、依赖哪件、先后顺序。改同一批文件的排先后，不并行。
