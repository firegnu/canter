### 建议改

1. **换行后的 `cd ~` 让后面的受保护路径检查算错目录（相对 main 是退化）**
   - 位置：`crates/canter-tools/src/readonly.rs:840`（决定 `~` 要不要当家目录的后一个字符清单）；`readonly.rs:78,87`（`cd` 之后的目录）。
   - 问题：本件给规则判断加了换行分段，但 `~` 只在后面跟 `/`、空格、Tab、`&`、`|`、`;` 或结尾时才当家目录，漏了换行。`cd ~` 后面直接换行时，解析器把目标当成字面的 `<cwd>/~`，bash 却去了家目录；后面各段的受保护路径检查（服务端设的 `~/.canter` 和 `config.json`，`canter-server/src/http.rs:76`）和 git 配置检查都按 `<cwd>/~` 算。结果：`cd ~` 单独一行、下一行用相对路径碰 `.canter`，只读命令（不需要任何规则）或已放行前缀的命令（比如 `cp`）会不问就跑。main 上带换行的命令一律要问，没有这个问题；计划和审查轮仍走老的只读判断，不受影响。需要 `cd ~` 单独成行再用相对路径进 `.canter`，属于罕见组合。
   - 改法：清单里加 `'\n'`。更稳的写法（不靠清单写全）：扩展模式下 `cd` 的目标以 `~` 开头却没被认成家目录时，算判断不了，不放行。

2. **会话放行框开着时规则文件被改，点「本会话放行」后这一轮直接失败**
   - 位置：`crates/canter-tools/src/permission.rs:231-237`；`crates/canter-core/src/runner.rs:965-966`；服务端在 `crates/canter-core/src/session.rs:991` 已经先记了 `RequestResolved`。
   - 问题：会话放行的回答到了以后，`resolve_with_prefixes` 按当前规则重算；这时规则文件写坏了（用户手改到一半），或刚给这个前缀加了 prompt 规则，重算的请求没有 `session_prefixes`，返回错误。客户端已经收到成功，随后这一轮以 `invalid approval decision` 失败结束，命令没跑，模型也没收到这条工具的结果。临时测试：`touch first` 出框 → 把 rules.json 写成 `{` → 回答 `acceptForSession` → resolve 返回成功，`TurnCompleted` 为 `Failed`，`first` 没建。不会放宽，只是不稳；要手改文件时恰好有框等着，属于罕见组合。
   - 改法：重算确认不了会话范围时不报错，按「只放行这一次」处理（仍先查禁止规则），不记会话前缀，提示一句没记成。

3. **禁止规则认不出带前缀或包一层的写法，「全部允许」下会直接跑**
   - 位置：`permission.rs:269-279`（禁止只看每段开头的词）；`readonly.rs:665`（开头是 `X=...` 的段整段当不认识）；`readonly.rs:708`（有括号、花括号、反引号时不再找后面的字面段）。
   - 问题：禁止规则按「段开头是这个前缀」判断。`RUST_LOG=debug cargo publish`、`CARGO_TARGET_DIR=$HOME/x cargo publish`（赋值里有变量时一个词也认不出）、`timeout 600 cargo publish`、`env`/`nohup`/`sudo` 加命令、`(cd x && cargo publish)`、`bash -c "cargo publish"` 都匹配不上 `["cargo","publish"]`。「总是问」「只问执行」下这些仍会弹框（没有前缀选项），用户看得到；「全部允许」下不弹框直接执行，禁止规则没拦住。任务要求是「尽量管」，完成记录也没说拦得全，而且要模型恰好用这种写法跑被禁止的命令，所以记建议改。其中 `名字=值 命令` 是常见写法，主控如果判断常见，可以升为必须改。
   - 改法（不靠解析完美）：(a) 禁止判断时跳过段开头的 `名字=值` 再匹配；(b) 判断不了就问：某条禁止规则的词按顺序连续出现在某段的词里（不只在开头），或命令没解析全而原文里按顺序出现这些词，就改为询问（「全部允许」下也问），不直接拒绝，免得误拦 `git log --grep "cargo publish"` 这类命令。

4. **命令里有 `~/` 时，放行规则和会话前缀都用不上，框上也没有前缀选项**
   - 位置：`permission.rs:269`（`scan_commands(&args.command, None, true)`，没传 HOME）；`permission.rs:295-296`（`parsed.is_ok()` 才看放行）。
   - 问题：判断时不传 HOME，遇到要展开的 `~` 就算解析失败。临时测试，有 `cargo test` 放行规则时：`cd proj && cargo test` 直接执行；`cd ~/proj && cargo test`、`cargo test --manifest-path ~/proj/Cargo.toml` 每次都问，框上也没有两种前缀选项。方向是更严，不是安全问题，但长任务里会多卡批准框，和「下次不问」对不上。
   - 改法：用会话环境里的 HOME 解析（`LocalExecutor` 已有 environment，比如给 `Executor` 加一个取 HOME 或直接返回解析结果的方法）。

5. **自动建议清单里有几项等于「包一层」**
   - 位置：`crates/canter-tools/src/rules.rs:120-176`。
   - 问题：任务要求太宽的不给，范围包括「包一层的命令」。下面这些选了以后任意命令都不问，用户在框上看到的只是 `["uv","run"]`、`["find"]`：
     - 子命令本身就是「再跑一条命令」：`uv run`、`npm exec`/`pnpm exec`/`yarn exec`、`pnpm dlx`/`yarn dlx`、`rustup run`、`docker run`/`docker exec`、`kubectl exec`（`npm run` 已经排除，这些同理）。
     - `find` 在「没有子命令」清单里：`find … -exec/-execdir/-ok 命令 \;` 能跑任意命令，`-delete` 能删文件；`sed` 有 `-i`、`w` 写文件（GNU sed 还有 `e` 执行命令）。
     - 光名字的相对路径程序（`./build.sh`）会建议；写进全局文件后，别的项目里同名的另一个脚本也不问。
   - 改法：上面的子命令加进不建议的范围；`find`、`sed` 移出「没有子命令」清单；相对路径程序不给永久项（会话项可以留）。用户自己在文件里写的规则不受影响。
