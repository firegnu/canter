## 要做的

1. **退出时清掉本机的 refresh token。** 现在远程作废没确认时，refresh token 作为 `pending_revocation` 留在盘上，提示再跑一次 logout。改成照官方 D4「End the renewable session」：作废没确认也清掉本机全部令牌，告诉用户 OpenAI 没确认作废，可以去 ChatGPT 设置里断开 canter（照官方页面的说法写英文提示）。已经留着 `pending_revocation` 的旧记录，下次 logout 或复登时照旧尽力作废一次，然后不管成不成都清掉。协议里 `pendingRevocation`、`Pending` 这类字段旧客户端还在用的，保留字段、改含义要写进 DESIGN。
2. **GPT 报错时留下诊断信息。** 现在 `responses/error.rs` 只把已知错误码映射成固定种类，错误码原值、出错字段（`param`）、request ID 都丢了。改成照官方 D6：HTTP 报错和流里的 `response.failed` / `error` 事件，都在服务端日志（`~/.canter/server.log`，就是现在 `eprintln!` 写的地方）留下 HTTP 状态、`error.code`、`error.param`、响应头里的 request ID。这几样只在是短的、只含字母数字和 `_.-` 这类字符时原样写，否则写成占位；错误的 `message`、`detail` 和正文一律不写（上游可能把凭证回显在里面）。只进服务端日志，不进会话事件和界面。
3. **验证服务临时出错不清登录。** 刷新令牌成功、轮换完以后，取 discovery 或 JWKS 来验证新 ID token：现在只有网络错按「保留新令牌、ID token 留上一个已验证的」处理，403、404、正文不是 JSON 这些也会走「ID token 无效」分支，把新 refresh token 作废、清凭证、要求重新登录。改成只有确实证明 ID token 无效（签名或 claims 不对、subject 不一致）才走那条分支，其余验证材料取不到的情况都按网络错处理。

三处都改 DESIGN 对应的条目（P2-203 退出规则、P2-202 交叉审查返工、P2-204 只留哪些错误信息），写清改了什么、依据是 P2-208 文档核对的哪一条。
