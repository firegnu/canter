## 样子

`~/.canter/config.json` 里加一项：

```json
{ "statusLine": "~/.canter/statusline.sh" }
```

命令从标准输入收到一行 JSON（字段见下），比如脚本打印：

```
 deepseek-v4 · high · ctx 42% · $0.31 · 38 tok/s
 ~/Developer/canter (main)
```

这两行就替掉现在的两行状态栏。

## 要做的

- **配置**：`config.json` 加可选 `statusLine`（字符串，一条 shell 命令）。终端打开时读它，只取这一项；读不到、不是字符串、空的，都当没配。API key 等别的项不读进来、不传给命令、不写进日志和报错。服务端照旧忽略这一项（核对一下，不用改服务端）。读配置放在 `crates/canter` 还是 `canter-tui` 由你定。
- **跑命令**：配了就用 `sh -c <statusLine>`，工作目录是会话目录，继承终端的环境变量；标准输入写一行 JSON 再关掉，标准错误丢掉。
  - 状态有变化时跑（出了新字、换了模型或档位、权限模式、用量、会话状态、目录、分支变了），最多每 0.3 秒一次；同一时间只跑一个，跑着时又有变化就等它结束后再跑一次最新的。
  - 最多等 1 秒，到时把它（连同它起的子进程）停掉。超时、退出码不为 0、没有输出都算出错。
  - 画面不等它：命令在后台跑，结果回来下一帧再画。
- **JSON**（字段名照协议的驼峰写法，没有的值给 `null`）：

  ```json
  {
    "version": "0.1.0 · 87259d5",
    "sessionId": "…", "sessionName": "…",
    "cwd": "/Users/…/canter", "gitBranch": "main",
    "model": "deepseek-v4", "reasoningEffort": "high",
    "approvalPolicy": "askForExecution",
    "status": "working",
    "context": { "usedTokens": 85000, "windowTokens": 200000, "percent": 42 },
    "cost": { "usd": 0.31, "unknown": false },
    "cache": { "totalPercent": 92, "lastPercent": 99 },
    "tps": 38.2
  }
  ```

  数和现在状态栏显示的同一来源（`info_rows` 用的那些）。
- **TPS**：输出 token 数除以从第一个字（思考或回答）到这次请求结束的时间。输出中按已收到的字估算 token（和 `/context` 同一套估算），这次请求结束、拿到真实输出 token 后改用真实值；空闲时是上一次回答的；一次都没有时是 `null`。一轮里有多次请求（调工具后再请求）时按当前这一次算。
- **显示**：命令输出的头两行替掉现在的两行状态栏（一行就只占一行，另一行空着；多出的行丢掉），每行截到窗口宽度。保留颜色代码（SGR），去掉别的控制字符。上面的状态行（转圈、用时、Copied 等）照现在，不归它管。
- **出错**：超时或出错时继续显示上一次成功的结果；一次都没成功过就显示默认的两行状态栏，第一行末尾加一个红色 `statusline error`。后来成功了就换成命令的输出。
- **不配置**：和现在完全一样，不跑任何命令。
- 现在第一行状态栏完整显示了权限模式时，Shift+Tab 那类提示才省掉（`mode_in_full`）。配了命令时当作权限模式没显示全，提示照常给。
- README 写上怎么配、JSON 各字段、一个示例脚本（放 README 里，不放进仓库的可执行文件）。
