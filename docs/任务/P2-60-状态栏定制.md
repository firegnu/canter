## 要做的（待分解时补全）

- 「TTS」是每秒出多少 token（TPS），canter 算好交给用户的命令（用户 10-26：「TPS，A」）。
- 怎么定制（用户 10-26 定 A）：照 Claude Code 跑用户自己的命令，canter 把会话信息（模型、思考档位、上下文占用、花费、分支、权限模式、目录、TPS 等）以 JSON 从标准输入交给它，它打印的内容就是状态栏。待分解时定：配置写在哪、多久跑一次、命令慢了或出错怎么办、能不能带颜色。
- 不配置时照现在的两行状态栏。
- 用户 10-26 定（「都按你的建议」）：
  - 配置写进 `~/.canter/config.json`，加一项 `statusLine` 填命令。
  - 状态有变化时跑（出了新字、换了模型、用量变了），最多 0.3 秒一次。
  - 最多等 1 秒；超时或出错时继续显示上一次的结果，一次都没成功过就照默认状态栏，末尾标一个小的红色 `statusline error`。
  - 能带颜色（只留终端颜色代码，别的控制字符去掉），最多两行，占现在两行状态栏的位置。
  - TPS：正在输出时是这一次回答的实时速度，空闲时是上一次回答的；输出 token 数除以从第一个字到结束的时间。
- 10-26：主控问「TTS」指什么、怎么定制（A 跑用户的命令；B 配置里挑固定几项），用户：「TPS，A」。
