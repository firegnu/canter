## 完成记录

- 做了什么：新加 `crates/canter-tui/src/input_history.rs`。↑↓ 的判断照 Codex `should_handle_navigation`：输入框空着时 ↑ 从当前目录最新一条调起；调出来的没改过、光标在开头或末尾时 ↑↓ 接着走，到最旧停住，↓ 过了最新一条清空输入框；别的时候照旧 `vertical` 移光标。斜杠命令、`@` 列表、搜索框、批准框、弹框都在 `key_action` 里先拿键，没改它们。在 `enter()` 发消息（文字、带图）和 `run_command` 成功时各记一条；排队的消息走的是同一条发送路径。历史文件是 `CANTER_HOME`（否则 `~/.canter`）下的 `input_history.jsonl`，一行一条 `{"cwd","text","ts"}`，0600。几个终端靠旁边的 `input_history.lock`（`File::lock`）轮流写；超过 2000 条时把最新的 2000 条写进临时文件再改名替换。打开 canter 时读一次：坏行（不是 UTF-8、不是 JSON、缺字段、写到一半）跳过，读不了就从空开始，状态栏提示一次；写失败也提示一次，不崩。本终端发过的整份草稿留在内存里，调出来时 `[Pasted …]` 标记和图片附件照原样带回；`/new`、`/resume` 换会话时用 `with_input_history_from` 带过去。文件里存的是粘贴全文、去掉图片标记的文字，以前会话的只能调回文字。连着一样的：记的时候和当前目录上一条相同就不记；读文件时别的终端写进来的连着重复，翻的时候跳过。`?` 帮助加一行 `↑ / ↓ (empty input)`。DESIGN 第 19 条末尾补了定法。
- 验证了什么：`input_history.rs` 里 7 个单元测试，覆盖文件 0600 和字段、坏行跳过和只提示一次、读不了不崩、超过 2000 条裁掉、8 个线程同时追加 400 条不写坏、按目录、最新在前、连着重复只算一条。`tests/input_history.rs` 8 个界面测试，覆盖要做的 1、2、4、5、6，另带 3（排队的和斜杠命令）。全部用临时目录当 `CANTER_HOME` 和 `HOME`。临时去掉 ↑↓ 的接线后这 8 个都失败，恢复后通过。标准测试：`cargo nextest run --all-targets` 753 个全过，`cargo test --doc --workspace`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check` 都过。用户真实的 `~/.canter` 里没生成历史文件。
- 拿主意的地方：
  - 文件名用 `input_history.jsonl`，加锁用的另一个文件 `input_history.lock`。不直接锁历史文件本身，因为裁剪是改名替换，锁在旧文件上会失效。
  - 斜杠命令只在跑成功时记；打错的命令（`Unknown command`）、不收参数却带了参数的、模型不收图没发出去的都不记。
  - 只有图片、没有文字的消息只记在内存里，不写进文件（去掉标记后是空的）。
  - 调出来的斜杠命令（比如 `/help`）会让命令列表打开，这时 ↑ 归列表管，不再往前翻历史。这是照「列表开着时照它们自己的规矩」做的。`@` 结尾的消息同理。
  - 每次写都读一遍整个文件来数行数（最多 2000 行）。存的是粘贴全文，要是很多条都是大段粘贴，文件可能到几 MB，每次发消息会多读这一遍。任务没要求按字节限制，没做。
