### 建议改

1. **当前账号已退出或要重新登录时，`canter auth login chatgpt` 加不了另一个账号**
   - 位置：`crates/canter-server/src/account.rs:214-225`（不带 accountId 时，当前记录不是 loggedIn 就复用它的注册）；`chatgpt_auth/login.rs:130-139`、`174-179`（复用注册时用旧的 client id，换回来的 `sub` 不一样就报 `IdentityMismatch`）。
   - 问题：比如机器上只有 A 一个账号，`canter auth logout chatgpt` 之后当前账号仍是 A（signed_out）。这时想登 B，`login` 一定复用 A 的注册，浏览器里登 B 只会失败（`sub` 不一样报 `canter: ChatGPT credentials: IdentityMismatch (HTTP None, code None)`，或者授权服务直接拒）。A 的记录不受影响，不会选错、不会串号，所以不算必须改。可是命令行里没有任何办法新建注册：`use` 只能选已有记录，所有记录都不是已登录时，连「先选一个已登录的再 login」也走不通，只能手动删 `~/.canter/auth/chatgpt/` 里的文件。A 的 refresh token 失效、变成 needs sign-in 以后想换 B，也是一样。
   - 改法（要动命令形状或 P2-202 的规则，交主控定）：(a) 给 CLI 一个明确新建注册的办法（比如 `login` 加个选项，协议加对应字段），命令形状要问用户；或者 (b) 不带 accountId 时一律新建注册，换回来的 client id 或 issuer+subject 和已有记录相同，就当作复登那条记录（先作废它的待作废令牌），不再报 `ClientMismatch`。至少把这条错误换成看得懂、说明下一步怎么做的英文提示。

2. **新登录一个账号，可能让已有账号的序号整体变掉**
   - 位置：`chatgpt_auth/mod.rs:33`、`74-81`（记录放在按记录 ID 排序的 `BTreeMap` 里，ID 是随机 UUID）；`account.rs:128-139`（序号按这个顺序解析）。
   - 问题：新账号的 UUID 可能排在已有账号前面。用户先 `status` 看到 1=a、2=b，再登 c，b 可能变成 3；`login` 成功后不打列表，用户照记住的 2 去 `use` / `logout`，选中或退出的就是别的账号。服务端每次都按当时的列表解析，本身没错，只是序号不稳。
   - 改法：按加入顺序排（比如记录里存创建时间，或者在 `host.json` 里存顺序），新账号排在最后，已有账号的序号不变。

### 可以不改

1. **`login/start` 返回之前按 Ctrl+C 没反应**（`crates/canter/src/auth.rs:234-245`）：SIGINT 处理在发 `login/start` 之前就装上了，从这时起 Ctrl+C 不再结束进程，要等 `start` 返回才处理。平时 `start` 很快；只有当前记录有待作废令牌、OpenAI 又连不上时，`start` 要先重试作废，最长约一分钟，这段时间按 Ctrl+C 没反应。可以让 `start` 也和 Ctrl+C 一起 select，或者等 `start` 返回后再装。
2. **错误提示是内部枚举名**（`chatgpt_auth/mod.rs:252`）：CLI 直接打出 `ChatGPT credentials: Network (HTTP None, code None)` 这类文字。不泄露东西，但用户看不出下一步该做什么。属于能用但不好看，记 HANDOFF 即可。
3. **`status` 的列没有对齐**（`auth.rs:328-342`）：示意里 email 一列补了空格对齐，实现是固定两个空格，邮箱长短不一时对不齐。

### 五个重点逐项核对（上面几条之外没发现问题）

1. **不外流**：`AccountInfo` 只有 id、email、status、planAuthorized、backgroundConsent、pendingRevocation 六项（`account.rs:80-94`，测试断言了键名）。含 `state` 的 `authUrl` 只出现在 `login/start` 的响应里，`AccountLoginStartResponse` 没有 Debug；`login/wait` 的结果和 `read`、`logout` 都不带网址，错误文字只来自 `AuthError` 的 Display（错误种类、状态码、认得的错误码）。账号接口是单独的 Router，不写会话事件、不进 SSE；服务端非测试代码没有任何日志调用，socket 是 0600。CLI 只在 `open` 失败时把网址打在发起登录的终端里，`status` 和错误输出里没有 state、nonce、challenge（有测试）。loginId 是随机 UUIDv4，只回给发起的客户端，`wait`、`cancel` 都要凭它；就算拿到它，也只能看到完成结果（没有网址和令牌），完成后 60 秒清掉。
2. **测试入口不进正式构建**：假授权服务、`Http::for_test`、`ChatgptAuth::for_test`、`account::test_router` 都在 `cfg(any(test, feature = "test-support"))` 下；`test-support` 只在 `canter` 的 dev-dependencies 里打开，workspace 是 resolver 3，`canter upgrade` 用的是 `cargo install --locked --path crates/canter`，不会带上。就算带上了，也只是多几个 Rust 函数，没有环境变量或配置能调到它们：`Http::new()` 写死 `ISSUER`，`for_test` 还断言地址只能是 `127.0.0.1`；HTTP 客户端 `no_proxy`、不跟随跳转，代理环境变量也改不了请求去哪；chatgpt_auth 和账号接口的非测试代码都不读环境变量。
3. **退出和重试**：`manager.rs:19-27` 里，远程确认了就清掉待作废令牌，返回 Revoked；没确认就留着，返回 Pending；本来就没有 refresh token（needs_login 等）返回 NoToken。三种判断都对。待作废期间记录是 signed_out，读盘时 `Entry::new` 直接封住，`access_token` 报 NotLoggedIn，重开后标记还在（`failed_logout_can_retry_revocation_after_reopening`、改过的 `remote_revocation_failure_is_bounded_and_retains_only_pending_revocation`）。再跑 logout 会拿同一个令牌重试。复登时 `start_login` 先调一次 logout（`login.rs:33-37`）；作废还是没确认，也照常登录，覆盖记录时丢掉旧令牌，和 DESIGN 写的「尽力一次」一致，测试分别覆盖了 200 和 400。改后台同意时，如果退出正在进行（`blocked`），先按退出处理再落盘（`preferences.rs:44-50`），不会把盘上的 signed_out 改回 logged_in，也不会丢掉待作废令牌。P2-202 的七条测试：五条只是把布尔改成三态；两条失败用例改成断言 Pending，还多断言了重开后待作废仍在；`tokens` 为空、取不到令牌这些断言都留着，没有放松。
4. **后台同意和当前账号**：同意存在每条记录文件的 `background_consent` 里，旧文件没有这个字段时按 false 读；协议的 `backgroundConsent` 缺省 false；CLI 默认 N，stdin 不是终端时不问、发 false。当前账号和首次套餐标记写进 `host.json`，用的是原来的 `write`（同目录 0600 临时文件、fsync、rename、同步目录，查符号链接和权限）；旧 `host.json` 没有这两个字段时按缺省读。选账号时先当序号解析（从 1 起，0 和超出范围都报错），不是数字就按记录 ID 或 email 精确匹配，email 匹配到两条就报错、要求用序号；序号、email、ID 三者不会混淆。序号稳不稳见建议改 2。
5. **协议和命令**：七个接口的请求和成功响应都带 `provider`，不是 `chatgpt` 就报 `Unsupported provider. Providers: chatgpt`，CLI 也先在本地查。字段名和 Codex `rust-v0.163.0` 的 `loginId`、`authUrl`、`success`、`error`、`canceled/notFound` 一致；不一样的地方（provider、用长等待代替全局通知、select、逐账号同意、三态退出、首次套餐标志、no-store）都写进了 DESIGN 第 8 条和协议 README。屏幕文字全是英文（diff 里 crates 下没有中文字符串），第一行是 `Continue with ChatGPT`，其余和示意一致，或者在完成记录里说明了差别。没改 TUI。
