### 意见

1. **建议改**：`crates/canter-tools/src/rules.rs:235`（`write`，第 245 行 `persist`）。
   - 问题：`rules.json` 是指向别处（比如 dotfiles）的符号链接时，删除成功后链接被换成普通文件：临时测试结果是 `removed=1`、`link still symlink: false`、目标文件内容不变（被删的规则还留在目标文件里）。用户文件本身没写坏，但链接没了，之后改目标文件不再生效。这是 main 上 `append` 原有的写法（本件只是把它提成共用函数），删除跟着一样；只有用户自己把规则文件做成链接时才碰到。
   - 改法：在 `write` 里先 `symlink_metadata`，是链接就报错（比如 `rules.json is a symbolic link; edit the target file`），或者解析到目标、在目标目录建临时文件再替换目标。会同时改到 `append` 的行为，本件「不要做」里不许改 `append`，建议记进 HANDOFF 另开一件。
2. **可以不改**：`crates/canter-tui/src/app.rs:2266`。
   - 问题：列表（不在确认框）还没画出来或在 `send_guarded` 那一小段时间里按 Esc，会被吞掉，不关框；别的弹框的 Esc 不看这些都会关。只是要再按一次，不会误删。
   - 改法：不在确认框时的 Esc 也放到 `seen` 判断前面，直接交给 `report_key` 关框。
3. **可以不改**：`crates/canter-tui/src/run.rs:687`、`crates/canter-tui/src/permissions.rs:128`。
   - 问题：删除请求失败（比如列表打开后文件被改坏）也显示 `Could not read command rules: ...`，说的是「读」不是「删」。服务端带回的原因里有 `read or update`，意思不会错。
   - 改法：删除失败用单独的一句，比如 `Could not delete command rule: ...`。
4. **可以不改**：`crates/canter-server/src/http.rs`（`/v1/info` 的 features）。
   - 问题：新终端连旧服务端时，`/permissions` 会弹 404 的错误说明；`/lsp`、目标续跑用了 features 标识，这里没有。任务只要求旧客户端连新服务端能用，服务端和终端一起装，不影响。
   - 改法：要的话在 features 里加一个 `commandRules`，终端没有这个标识时提示服务端太旧。
