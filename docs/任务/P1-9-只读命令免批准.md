## 现在怎样

- `permission.rs` 的 `PermissionGate::evaluate`：「每次问」模式下只有 read 工具（风险是 Read）不问；「只问执行」模式下 shell 也问；shell 一律按 Execute 算。
- 状态目录 `~/.canter/`（或 `CANTER_HOME`）和配置文件是 read、write、edit 的受保护路径，由服务端传进执行器（`executor.rs` 的 `protected_paths`）。shell 拦不住；现在 shell 每条都问，这次批准是挡住「`cat ~/.canter/config.json` 把 key 发给模型」的唯一一关。

## 要做的

1. **判断只读用白名单。** 只放行认识的命令和参数：列目录、看文件、搜索、统计、git 查看类（例如 `ls`、`cat`、`head`、`tail`、`wc`、`grep`、`rg`、`find`、`git status/diff/log/show`、`pwd`、`cd`，具体由你定）。会写东西或执行别的程序的参数不放行（例如 `find -exec/-delete`、`rg --pre`、`git diff --output`、`sed -i`）。组合命令（`&&`、`||`、`;`、`|`）每一段都在白名单里才放行；有写文件的重定向、命令替换、子 shell、后台 `&` 的一律问；解析不了的一律问。参考 Codex `rust-v0.163.0`（只读克隆在 `/tmp/r49-src/codex`，丢了照 `HANDOFF.md` 重新克隆）里判断命令安全的做法；要搬代码的，先停下来报给主控搬哪些、多少行、带什么依赖。
2. **碰状态目录的照旧问。** 命令里写出的路径（展开 `~`，相对路径按会话目录算）落在受保护路径里的，即使是只读命令也照旧问。`$HOME/.canter`、环境变量、符号链接这类绕法挡不全，这是已知限制：写进 `crates/canter-tools/README.md`，合并时主控写进 DESIGN。
3. 「每次问」和「只问执行」两种模式下，白名单里的 shell 命令都不问；「全放行」不变；未知模式照旧按「每次问」。「本会话都放行」的现有行为不变。
4. 免批准跑的命令，界面上照常显示命令和输出，事件和现在一样，只是没有批准框。
