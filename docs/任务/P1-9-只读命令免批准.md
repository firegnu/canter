# 任务：只读命令不弹批准框

依据：P1-8 试用发现，默认权限模式下 shell 每条都要批准，只读的 `ls`、`grep` 也要；pi 不问。本件让明显只读的命令直接跑，其余照旧问。

## 现在怎样

- `crates/canter-tools/src/permission.rs`：「每次问」模式下，只有 read 工具（风险是 Read）不问；shell 一律问。
- 状态目录 `~/.canter/` 和配置文件对 read、write、edit 工具是受保护路径，shell 拦不住（DESIGN 第 14 条）。现在 shell 每条都问，这次批准是挡住「`cat ~/.canter/config.json` 把 key 发给模型」的唯一一关。

## 要的结果

- 默认的「每次问」模式下，明显只读的命令不弹批准框，直接跑，界面上照常显示命令和输出。
- 会写文件、删东西、联网、装东西、改 git 状态、起后台进程的照旧问；判断不了的照旧问。
- 碰到 canter 状态目录（包括 `CANTER_HOME` 指的地方）的命令照旧问，即使是只读的。

## 主控建议（待用户确认）

1. 怎么判断只读：用白名单，只认识的命令和参数才放行（列目录、看文件、搜索、`wc`、`git status/diff/log/show` 这类）。组合命令（`&&`、`;`、`|`）每一段都在白名单里才放行；有写文件的重定向、命令替换、子 shell 的一律问。参考 Codex `rust-v0.163.0` 里判断安全命令的做法，搬不搬代码由做的人看过后报给主控。
2. 碰状态目录的命令照旧问：只按命令里出现的路径判断。`cat $HOME/.canter/...`、经过符号链接这类绕法挡不全，这是已知限制，写进 DESIGN；要挡全得等第二期以后的套墙。
