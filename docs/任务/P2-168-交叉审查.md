- **1 坏记录**：用上一轮同样的步骤（尾逗号的 `trusted_folders.json`），在 `778be5b` 编出的 canter 上复测：建会话、恢复已打开的会话都成功，`restrictedMode: true`。`GET /v1/folderTrust` 返回 `trusted:false`，警告里有记录文件完整路径和 `trailing comma at line 3 column 1`。记录文件原样没被覆盖；`POST` 记录信任仍报错，信息里带文件路径。警告作为事件写在打开响应的游标之后，开发方用例从游标之后读到了（快照里没有，本来也不该有）。终端查询失败时按受限打开、显示警告、不退出（`run_trust.rs` 新用例和 `folder_trust_corrupt_record_opens_terminal_restricted_with_warning`）。
- **2 目录删了**：复测已打开会话的恢复、重启服务端后从存盘恢复，都成功且 `restrictedMode: true`；对这个目录新建会话返回 `Directory does not exist: …`。终端 `-r` 和 `/resume` 由 `folder_trust_deleted_directory_resumes_via_cli_and_slash_restricted` 覆盖。

### 二、worktree 认回主仓库：实现对，伪造的 `.git` 蹭不到信任（读代码 + 开发方用例）

- **实现**（`crates/canter-server/src/trust.rs:12-71`）：
  - 当前 checkout 的 `.git` 必须是普通文件，不接受符号链接，从里面读出 gitdir。
  - gitdir 必须是真目录，上一级必须叫 `worktrees`。
  - gitdir 里 `gitdir` 文件反指的目录，规范化后必须等于当前 checkout。
  - `commondir` 规范化后必须等于公共目录。
  - 公共目录的上一级当作主仓库，它自己的 `.git`（目录，或 separate-git-dir 的 gitdir 文件）规范化后必须正好是这个公共目录。
  - 所有元数据文件只接受 64 KiB 以内的普通文件。
  - 这和 Codex `resolve_root_git_project_for_trust` 的反向链接、commondir、主仓库所有权三项校验对得上。信任查询、exec 打开、LSP 按文件检查都走同一个 `repository_root`。
- **伪造为什么蹭不到**：要被认到某个已信任的仓库 T，需要 T 的元数据目录里有一条 `worktrees/<id>/gitdir` 反指回伪造目录，并且 T 自己的 `.git` 指向那个公共目录。这两样都在 T 里面，只有 T 的主人能写。
  - 把真 worktree 的 `.git` 复制过来，或做成指向它的符号链接：反向链接对不上，按伪造目录自己判断。开发方用例 `folder_trust_worktree_shares_main_only_with_valid_reverse_links` 覆盖了这两种，也覆盖了 `gitdir`、`commondir` 被改的情况。
  - 在伪造目录里自造一整套 `.git/worktrees/…`：最后一步要求主仓库是公共目录的上一级，结果只会认回伪造者自己的目录，借不到别人的信任。
  - 按规矩没有另造输入去试。
- **认不出时的退路**：bare 仓库的 worktree、主仓库 git 目录不在仓库根下（separate-git-dir 放在别处）、子模块（上一级叫 `modules`）、路径大小写不一致导致比较不等，都退回按 worktree 自己判断。结果只是多问一次，不会放行。

### 三、这次改动带来的问题

**必须改：恢复时降为受限，正在等诊断的那一轮会 panic，会话卡死（已查证，附复现）**

- **位置**：`crates/canter-core/src/lsp.rs:371`、`383`，`inline()` 里两次 `shared.runtime().tools.lsp().unwrap()`。触发方是本次新加的 `crates/canter-core/src/session.rs` `set_folder_trust(false)`：拿着 state 锁关掉 LSP，再把运行时换成没有 LSP 的那份。由 `crates/canter-server/src/http.rs` 的 resume 调用。
- **怎么走到**：
  - `inline()` 先等诊断票据。票据返回 Ok 以后，它调 `diagnostics()`、等 state 锁，拿到锁后第二次 `tools.lsp().unwrap()`。
  - 降级如果发生在「票据已返回 Ok」和「`inline()` 拿到 state 锁」之间，`inline()` 拿到锁时 `lsp()` 已是 None，就会 panic。
  - 降级如果发生在票据返回之前，票据会收到 Stopped，走现有分支，是安全的。
  - 改之前，轮进行中换运行时只有升级这一种（加 LSP，不会是 None）；热加载换 LSP 只在轮的边界（P2-154 的租约）。所以这条是本次新引入的。core 里 `tools.lsp().unwrap()` 只有这两处。
- **正常使用里怎么碰到**：一个已信任的会话正在跑改文件的轮，这时另一个终端 `canter -r` 或 `/resume` 这个会话（或 `canter exec --resume`），而信任记录刚被手改坏、目录被删，或者客户端因查询失败带了 `restrictedMode: true`。窗口是毫秒级，单次碰上的概率低，但每次改文件都会开一次这个窗口。
- **复现**：
  - 做法：在 scratch 里用 `git archive` 导出 778be5b（没动 worktree）。只在 `inline()` 票据返回 Ok 之后插一段 1.5 秒延时和一个标记文件，把这个本来就有的窗口撑大，没有改别的代码。用 `reload_tests` 的夹具：隔离 HOME、本地假模型、已有的假语言服务器。
  - 对照（不降级）：延时过去后这一轮照常往下走，下一个模型请求按时到。
  - 降级：在窗口里写坏记录，再 `POST …/resume`。返回 200、`restrictedMode: true`。服务端日志出现 `panicked at crates/canter-core/src/lsp.rs:386:46`（即原第 383 行，前面插了 3 行）。之后不再有模型请求，会话一直是 Working，这一轮一直是 InProgress。对这一轮发 interrupt 返回 HTTP 500，3 秒后仍是 Working；再发输入返回 409 `turn is stopping`。
  - 服务端进程没退出，但这个会话要重启服务端才能恢复；属于「服务端崩」一类。拷贝和它的编译目录 `.target/review-p2-168-trust-inject` 已删。
- **改法**：
  - `inline()` 别每次都从运行时重新取 LSP 再 `unwrap()`。开头取一次句柄，例如 `let Some(lsp) = shared.runtime().tools.lsp().cloned() else { return Vec::new() };`，后面两处都用这个句柄。
  - 句柄已经关掉时，`diagnostics()` 只会返回空，走现有的「诊断不可用」那条路。
  - 改完 core 里不应再有 `tools.lsp().unwrap()`。
  - 回归测试很难确定性地撞上这个窗口：能写就补；写不了，在返工记录里写明靠什么保证。

**`restrictedMode` 请求字段：只能更严（读代码 + 用例）**

- 判断式：
  - 建会话、从存盘恢复：`!trust.trusted || params.restricted_mode`。
  - 恢复已打开的会话：`set_folder_trust(trust.trusted && !params.restricted_mode)`。
- 带 false 或不带都放行不了未信任的目录。旧客户端不带这个字段，按 false 处理。生成的 TypeScript 是 `restrictedMode?: boolean`，和已有的 `nonInteractive` 写法一致。用例 `folder_trust_clients_can_request_restricted_but_cannot_grant_trust` 覆盖。
- 任何客户端带 true 恢复一个已打开的会话，会让所有连着它的客户端一起变成受限。DESIGN 已写「每次恢复也重新判断」，方向是更严，可以接受；不过这正是上面那条 panic 的触发方式之一。

**降级路径的其他部分**：关 LSP、清待交付诊断、把语言服务器标为 Stopped 并写原因、更新 `restrictedMode`，做法和热加载换 LSP 一致。轮中途降级后，这一轮再写文件不会重新起 LSP（`folder_trust_lost_on_resume_detaches_running_lsp` 覆盖）。除上面的 panic，没发现别的问题。

**exec 改了订阅游标**：现在从 resume 响应的游标开始订阅，会多收到 PATCH 产生的事件和打开时的警告。exec 不比对轮 id 就按 `TurnCompleted` 结束，但非交互输入要求会话空闲，别的轮不会在这段时间里结束，看不出实际问题。

**建议改**：worktree 解析让 `file_access` 每检查一个路径，还要多读最多四个元数据文件（`.git`、`gitdir`、`commondir`、主仓库 `.git`），外加几次规范化。这叠加在上一轮已转 HANDOFF 的「LSP 每次读信任记录」那条上，记进同一条 HANDOFF 即可，合并前不必改。

和这次改动无关的问题：复核时没有新发现。
