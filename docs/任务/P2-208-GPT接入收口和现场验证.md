### 与现有做法一致的部分

- **登录和保存**：D2、D3 对照 DESIGN 第 6 条 P2-202/P2-203；`chatgpt_auth/login.rs`、`http.rs`、`storage.rs` 使用 canter 名称、新注册 `dynamic_agent_client`、已注册 issued client ID、每次独立 state/nonce/PKCE S256、先监听 `127.0.0.1` 的 `/auth/callback`、授权和换令牌使用同一回调 URI。校验 ID token 签名/issuer/audience/nonce/有效期及复登 subject，按返回 scope 判断套餐授权；注册独立保存、目录 0700/文件 0600、原子替换。未发现正常成功路径与这些要求冲突。
- **刷新主路径**：D4、D6、D11 对照第 6 条 P2-202；使用 issued client ID 和 resource，刷新时不发 scope，逐注册串行，成功后一起替换轮换令牌与期限；终止性 refresh 错误停用凭证，网络/503 和 invalid_client 不当成已撤销。401 最多恢复一次。异常身份校验分支另列差异。
- **请求与预览限制**：D5、D7 对照第 6 条 P2-204；`responses/wire.rs` 固定 `store:false`、`stream:true`、数组 input、developer 提示，HTTP 不发 `previous_response_id`。未发送 D7 禁用的 background、conversation、max_output_tokens、max_tool_calls、metadata、moderation、multi_agent、prompt、prompt_cache_retention、safety_identifier、temperature、top_logprobs、top_p、truncation、user。本地后台续跑不等于 Responses 的 background 参数；本地 MCP 执行也不等于 hosted MCP。
- **工具、图片和终态**：D5、D7、D13 对照第 6 条 P2-204/P2-205；function/custom 放入有 description 的 canter/mcp namespace，function 显式 `strict:false` 是官方允许的非严格模式；apply_patch 用 custom/Lark 并按 call_id 配对结果。图片转为 input_image，能力门槛由模型资料决定；不接音视频、Files 上传或禁用的 hosted 工具。`responses/sse.rs` 仍以 `response.completed` 为成功条件，failed/incomplete/断流不会确认执行工具，P2-211 从 output_item.done 拼内容不改变这一点。
- **目录和历史**：D5、D12、D15 对照第 6 条 P2-216、第 13 条 P2-210/P2-207；账号目录取自 `/v1/models`，按 visibility、服务端顺序、display_name/slug 处理并在切账号时切换。模型目录不是永久访问保证。相同模型/注册的有效 replay 保留密文、phase 和工具项；换家只用可移植历史，不把摘要当原始思考。
- **额度与一般恢复**：D4、D6 对照第 6 条 P2-204/P2-217；额度错误不自动重试、不自动换家，给 Usage 链接；无输出前临时错误有界重试，已有输出/用量时停止自动重试。套餐 token 不折算 API 美元，也不推算剩余额度。官方仍区分 Plus 的共享五小时限额与 Pro，不代表 Pro 无其他限额。
- **条款边界**：T1 §1、§2、§3.1 与第 6 条 P2-80 的本机存储、本人任务、后台明确同意、免费开源接入方向一致；不提供账号轮换绕限或通用 API 代调。`auth.rs` 登录前说明本机存储、项目上下文外发和退出入口。T2 §2 不承诺预览稳定性，§15 指向 SIWC 条款。本轮是工程核对，不认定 OpenAI 已批准 canter，也不认定这段简短告知已完成所有隐私法律义务。

### 差异：逐项交主控决定，不在本件改实现

1. **本机退出完成后仍保留 refresh token。** D4 的 End the renewable session 要求：未确认远程撤销而完成本机退出时，清除本地令牌并告知用户可在 ChatGPT 设置断开。canter 在三次撤销失败后仍把 refresh token 以 `pending_revocation` 留盘，提示再次 logout；`signed_out` 会阻止推理取用，但凭证并未全部清除。依据：DESIGN 第 6 条“P2-203 退出规则覆盖 P2-202”；`chatgpt_auth/manager.rs::logout`、`canter/src/auth.rs`。**主控需决定是否改为清除及设置页退路，或先向官方澄清待撤销令牌的保留边界。**

2. **新注册换令牌失败时没有可复用的 issued client ID。** D3 要求 code exchange 返回 invalid_grant 后，以本次取得的 issued client ID 开始新授权。canter 在 `login.rs` 中只把回调 client ID 保存在本次局部变量，token exchange 和身份校验都成功后才 save_record；失败结束后再 login 会重新走动态注册。依据：DESIGN 第 6 条 P2-202 的已验证注册保存规则，未定义这段中间状态。**主控需决定是否另开失败恢复任务，保留尚未完成身份绑定的注册信息。**

3. **套餐权限被拒后缺少明确的再次同意路径。** D6 要求用户主动启用套餐时用已保存 client ID 重走完整 scopes；在尚未获官方确认 force_reconsent 部署前可用 `prompt=consent`，不能每次普通登录都强制同意。canter 的 PlanNotAuthorized 提示让用户再 login，但 `login.rs` 所有复登都没有上述 consent 参数，CLI 也没有专门启用套餐的操作；D3 描述的普通复登恰好可能跳过 consent。依据：DESIGN 第 6 条 P2-202/P2-203。**主控需决定如何区分主动再授权与普通复登；本轮不能声称被拒后已可恢复。**

4. **账号管理缺少部分官方交互。** D4 要求可以新增注册，并用稳定且可区分的标签识别各注册。canter 当前账号 signed_out/needs_login 时，`account.rs::login_start` 默认绑定该注册；CLI 没有强制新注册入口。`auth.rs::print_status` 用列表序号及邮箱标识，`records()` 按随机记录键遍历，新加入记录可改变旧序号，同邮箱也未显示稳定 ID。依据：DESIGN 第 6 条 P2-203、第 8 条账号接口；HANDOFF 已记录这两项。**主控需决定是否把新增入口与稳定标签纳入后续收口修复。**

5. **套餐使用提示未覆盖官方要求的场景。** D10 要求首次确认可由用户关闭，以及在输入区/模型选择附近显示当前正用套餐和管理入口。canter 首次只打印说明，没有确认动作；状态栏 Cost 根据累计 `cost.chatgpt_plan` 显示，因此第一笔请求前可能没有标记，切到别家后仍可能显示历史套餐用量，且附近没有 Usage 链接。`/usage`、CLI 用量页及额度错误已有链接。另有已知 `/goal` 仍显示纯 `$0.00` 的缺口。依据：DESIGN 第 6 条 P2-203/P2-217、第 22 条目标预算；`auth.rs::login`、`canter-tui/src/app.rs` 的 Cost、`goal.rs::bar`。**主控需决定终端对首次确认的等价交互，以及是否补当前计费标记和目标显示。**
