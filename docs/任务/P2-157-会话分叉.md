## 要做的

1. **服务端分叉**：加一个分叉接口（名字和形状你定，照 DESIGN 第 8 条写进 DESIGN，对照 Codex `thread/fork` 说清哪里一样、哪里不一样）。新建一个会话，id 是新的；带过去的有：
   - 原会话到「最后一个已完成的轮」为止的对话：终端能看到的历史，加上模型看到的历史，包括中途的压缩、`/rewind`、计划模式说明这些记录；
   - 会话设置：工作目录、追加目录、模型、思考强度、权限模式、计划模式、标签。

   不带过去的：
   - 正在跑的那一轮、排队输入、等批准或回答的请求；
   - 目标（goal）、后台命令；
   - 遥测（`private-telemetry.jsonl`）、临时目录。

   名字是原名加 ` (fork)`，原会话没名字就留空。`/v1/info` 的 features 加一项，新终端连旧服务端时给出清楚的提示（照 `require_tags` 的写法）。
2. **原会话不动**：分叉只读原会话，不改它的存盘、状态、名字，不打断它正在跑的轮，也不挂在它上面当客户端。用 P2-173 的按会话排队保证读的时候它不会写到一半（只锁原会话那一下，不挡别的会话）。
3. **模型看到的一样**：新会话里下一次发给模型的请求，历史部分和原会话在那个时刻接着发的请求一字不差（DeepSeek 前缀缓存能命中）。分叉不改提示词。
4. **用量不重算**：原会话花过的 token 和钱，不在新会话里再算一遍。`/usage`、`canter usage`、`canter stats` 的总数，分叉前后一样；新会话只算分叉以后它自己花的。
5. **`/rewind` 的边界**：新会话里 `/rewind` 最多退到分叉那一刻，再往前的轮在原会话里。canter 自己改文件的备份不复制。
6. **终端**：`/fork` 斜杠命令。分完切到新会话，屏幕上显示新会话的历史，加一行英文提示：分出来了，原会话还在 `/resume` 列表里。分叉失败就留在原会话，显示原因。
7. **钩子**：新会话按新建会话的规矩发钩子事件；原会话不发任何事件。

屏幕上的字（命令说明、提示、报错）一律英文。
