## 要做的

1. **模型 shell 在墙里跑**：模型的前台命令、后台命令、Ctrl+B 转后台的命令都用 Seatbelt 启动（入口在 `crates/canter-tools/src/executor.rs` 的 `LocalExecutor::spawn`）。命令从启动到退出一直在同一份规则里，后代进程也在里面。现有的看护进程、超时、进程组清理照旧可用。
2. **墙的范围**，照 DESIGN「沙箱」：
   - 可写：会话 cwd、P2-118 的新增目录（按启动时的列表，后加的目录只对之后启动的命令生效）、每个会话一个独占的临时目录（作为命令的 TMPDIR，不在 canter 状态目录里，会话结束后清掉）、canter 指定的可丢弃缓存位置。路径按规范化后的真实路径算。
   - `.git`：提交用到的部分可写（索引、对象、分支指针、日志等，worktree 的实际元数据目录也算），`config` 和 `hooks` 只读。
   - 不能读也不能写：canter 状态目录（默认 `~/.canter`，支持 `CANTER_HOME`，包括里面的控制 socket，命令连不上它）、`~/.ssh`、`~/.aws`、`~/.gnupg`。
   - 其余地方可读不可写；不开放整个 `/tmp`，也不开放真实的 `~/.cargo`、`~/.npm`。缓存放在哪、怎么让 cargo、npm 用上（例如设环境变量），由你定，写进完成记录；目标是 cargo、npm 在墙里能下依赖、能编译，代价可以是第一次要重新下载。
3. **联网**：「全部允许」下命令可以联网；「每次问」「只问执行」下默认断网（批准联网是 P2-164 的事，本件里这两档联网的命令就失败）。
4. **「全部允许」越界就失败**，不弹框、不自动换权限重跑。命令被墙挡住时，给模型的输出保留原来的退出码和输出，另加一句英文说明这是沙箱挡的，并提示用户真要做可以自己用 `!` 跑。
5. **配置开关**：`config.json` 加 `sandbox`，缺省为开，`false` 关闭，服务端启动时读取。关闭时一切照现在的行为。沙箱起不来（比如找不到 `sandbox-exec`、规则生成失败）时命令失败并说明原因，不在墙外跑。
6. **`--yolo` 说明**：`canter --help` 里 `--yolo` 改成说清楚沙箱照开，英文，例如 `use permission mode Allow all (never ask); commands still run in the sandbox`。
7. **不改的**：用户 `!` 命令不套墙；P2-161 的危险命令判断、P2-108 规则、只读白名单、计划模式、审查轮的判断照旧，在沙箱之前执行；MCP、`web_fetch`、read / write / edit 不在本件里动。
