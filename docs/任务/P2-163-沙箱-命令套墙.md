## 要做的

1. **模型 shell 在墙里跑**：模型的前台命令、后台命令、Ctrl+B 转后台的命令都用 Seatbelt 启动（入口在 `crates/canter-tools/src/executor.rs` 的 `LocalExecutor::spawn`）。命令从启动到退出一直在同一份规则里，后代进程也在里面。现有的看护进程、超时、进程组清理照旧可用。
2. **墙的范围**，照 DESIGN「沙箱」：
   - 可写：会话 cwd、P2-118 的新增目录（按启动时的列表，后加的目录只对之后启动的命令生效）、每个会话一个独占的临时目录（作为命令的 TMPDIR，不在 canter 状态目录里，会话结束后清掉）、canter 指定的可丢弃缓存位置。路径按规范化后的真实路径算。

   - 不能读也不能写：canter 状态目录（默认 `~/.canter`，支持 `CANTER_HOME`，包括里面的控制 socket，命令连不上它）、`~/.ssh`、`~/.aws`、`~/.gnupg`。
   - 其余地方可读不可写；不开放整个 `/tmp`，也不开放真实的 `~/.cargo`、`~/.npm`。缓存放在哪、怎么让 cargo、npm 用上（例如设环境变量），由你定，写进完成记录；目标是 cargo、npm 在墙里能下依赖、能编译，代价可以是第一次要重新下载。
3. **联网**：「全部允许」下命令可以联网；「每次问」「只问执行」下默认断网（批准联网是 P2-164 的事，本件里这两档联网的命令就失败）。

6. **`--yolo` 说明**：`canter --help` 里 `--yolo` 改成说清楚沙箱照开，英文，例如 `use permission mode Allow all (never ask); commands still run in the sandbox`。

## 完成记录

### 做了什么

- 模型 shell 经 `LocalExecutor::spawn` 用固定 `/usr/bin/sandbox-exec` 启动。规则从 deny default 起，只开放所需操作；前台、后台、Ctrl+B 及后代沿用同一份启动规则。原看护进程、超时和进程组清理不变；用户 `!` 走 `spawn_user`，环境和执行行为不变。
- cwd、新增目录、Git 实际 gitdir/commondir 均按真实路径生成规则；元数据内 config、config.worktree、hooks、gitdir/commondir 指针及相应真实目标只读，包括共用 `.git/worktrees` 下的配置。保护相关祖先目录不被改名。canter 状态目录（服务端实际路径、环境 CANTER_HOME、默认 `.canter`）与 `.ssh` / `.aws` / `.gnupg` 拒绝读写及 socket 连接；原 `.cargo` / `.npm` 始终只读。
- 每会话在系统 `/tmp` 下建独占 `canter-shell-*` 临时目录，规范化后作为 TMPDIR，TMPPREFIX 指向其中的 `zsh` 前缀。仅开放这个子目录；关闭会话先停命令再删除临时目录。持久缓存和临时目录不能落在受保护目录里。
- `config.json` 的 `sandbox` 缺省 true，服务端启动时冻结，false 保留旧行为；无法建立沙箱或生成规则时命令失败，不回退墙外。底层 `LocalExecutor::new` / `CoreOptions::default()` 保留嵌入调用者的旧行为，由服务端配置明确开启，不新增协议字段。`--yolo` 帮助已说明沙箱照开。
- allowAll 开放 IP 网络（含本机）及 mDNSResponder socket；alwaysAsk / askForExecution 断网。其他 Unix socket 仅开放普通可写范围，状态目录硬拒绝。权限、危险命令、计划模式、审查轮等原判断仍先执行。
- 保留退出码和原始输出。仅当输出包含典型拒绝错误时，模型结果另附英文沙箱范围说明和用户 `!` 提示；原始前台 commandExecution 输出不混入说明。识别在截断前进行，支持错误跨管道读取块及错误后 shell 继续、最终退出 0 的情形；普通非零退出不附说明，不自动提权重试。
