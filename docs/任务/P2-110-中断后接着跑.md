## 要做的

1. **还没开口就失败时多重试**：能重试的错误照现在（限流、5xx 和过载、网络、超时）；认证、请求不合法、上下文超长这些照旧不重试。
   - 默认最多 10 次。间隔从 0.5 秒起翻倍、最长 32 秒，加一点随机抖动；加起来约两三分钟。
   - 服务端给了 `Retry-After` 就照它等，一次最多等 60 秒。
   - 重试次数在 `config.json` 的 `model_max_retries` 里能改（0 到 100，0 就是不重试），服务端启动时读。
   - 这套规矩放在模型层各家共用的地方，Chat Completions 调它；以后加别家接口直接用，不再各写一份。
2. **回复到一半断了**：模型层能告诉核心「哪些内容已经收完整」（思考、一段回答、一个工具调用各算一项；Chat Completions 要到整段收完才算完整，别家可以更早）。断了以后核心照下面两种做，不管是哪家接口：
   - **一项都没收完整**：丢掉半截，整个请求重发，算一次重试。DeepSeek 现在只会碰到这种。
   - **已经有收完整的**：留下收完整的项（收完整的工具调用照常执行，和这一轮正常收到的一样），只丢掉没收完的半截，然后照常发下一次请求接着做，不把已经收完的再要一遍。
   - 没收完整的一律不算数：半截思考、半截回答不当成模型的回答记进模型历史，半截里的工具调用不执行，所以不会让工具跑两次。界面上已经显示的半截标成断开了；重发或接着做的回复接着显示。
   - 碰到要拿主意的事（比如「收完整」的信号怎么加进模型层、半截内容在界面和存盘里怎么标、要不要给协议加东西），停下来问主控。
3. **重试时看得见**：等着重试时，对话里出一行，写第几次、几秒后再试、为什么（比如 `Retrying in 4s (3/10): server error 503`）。重试成功后这一行留着，重开会话、另一个终端、导出看到的一样，用户回来能看出它停过。重试用完还是失败，照现在的做法这一轮失败，错误里写明试了几次。
4. **按 Esc**：等重试的时候按 Esc 马上停，不再重试，和现在一样。
5. **压缩、`/btw`、`/handoff`** 用同一个模型请求，跟着得到同样的重试，不另做。
6. **协议和文档**：重试那一行怎么给客户端，照 Codex app-server 的结构定，比 Codex 多的写进 DESIGN 第 8 条；DESIGN 写一条模型请求的重试规矩（上面这些和用户 10-28 的选择）。旧客户端遇到新的项目照未知项目跳过，不坏。
