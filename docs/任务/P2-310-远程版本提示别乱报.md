## 现在的样子（11-17 主控读代码）

- `crates/canter/src/remotes.rs` 的 `Remote::connect`：协议版本不同就报错退出；协议相同、`server_version` 和客户端 `VERSION` 不同，就带上 `warning`（`client.upgrade_hint("")`）。
- `crates/canter-tui/src/client.rs` 的 `upgrade_hint`：远程时一律写「upgrade it on that machine」。服务端缺客户端要的功能（`features`）时也用这句，那种情况方向是对的。
- 提交号分不出谁新谁旧，所以协议不同时，客户端也没法说哪边旧。

## 要做的

1. **协议相同、只是提交号不同**：终端和 `canter exec` 都不再提示；`doctor --server` 不算问题，只写一行两边各是什么版本。
2. **服务端缺客户端要的功能**：照现在提示去服务端机器升级（这时确实是服务端旧），不改。
3. **协议版本不同**：照现在不连，提示改成写出两边的版本，叫用户把两边升到同一版，不说是哪边（分不出）。英文，比如 `This client runs canter <版本>; server '<名字>' runs canter <版本> with a different protocol. Upgrade both to the same version.`，措辞你定。
4. 文档：`docs/remote.md`「What differs remotely」里写版本提示的那句、`docs/远程连接说明.md` 里那句，跟着改。
