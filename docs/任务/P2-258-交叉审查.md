## 审查意见

改完再合并：7 条必须改、3 条建议改。

审查对象为 `98ef9dfdaf7e5bc20741aa9bd32fb216a47861f1`。以下缺陷由静态代码及真实服务端的事件、输入处理路径确认，没有新增探测测试，也没有调用真实模型或启动真实 canter 服务端。

1. **必须改：报告在已有轮次里被处理完时，第 5 句一直等到超时。** 位置：`eval/src/steer.rs:296–310`。`ready(Report)` 先判断 `!report_woke`，只有进过独立的 background 轮才检查 `all_children_done()`。真实服务端允许报告在开跑轮或插话轮里送入模型：`crates/canter-core/src/runner.rs:385,467` 会展示并消费报告，`background.rs:237–243` 随之取消后续叫醒。因此，两个子 agent 在前四句期间完成、报告也都已经处理完，但从未另开 background 轮时，主会话空闲仍只会得到 `Ready::Wait`；第 5 句不记跳过，整次等待到 30 分钟并误记超时。改法：先处理「没有子 agent / 所有子 agent 已结束」的跳过条件；只有仍有子 agent 在跑、确实要发送第 5 句时才要求 `report_woke`。跳过后仍须等主会话处理完报告再退出。

2. **必须改：失败的 spawn 会被当成已经派出，且可能留下永远结束不了的假子 agent。** 位置：`eval/src/session_data.rs:197–201,282–283`、`eval/tasks/subagent.toml:62`、`eval/src/steer.rs:402–405,419–424`。第一轮的 `spawn_agent` 只要有 `item.completed` 就加一，不检查工具结果；参数错误、角色不存在、权限拒绝等失败也让 `spawned-subagents` 通过。并且，真实 `agent_tools.rs:198–205,331–355` 在参数解析成功但执行失败时，会保留 `agents: [{id:"", status:null, ...}]` 的占位项。`View` 把这个空 ID 登记为尚未结束的孩子，此后既不走「没有子 agent」的跳过，也无法满足全部结束，即使后来重试成功也会等到超时。改法：工具调用次数可以继续包含失败尝试，但判定「第一轮确实开了子 agent」应另看该轮成功 spawn 返回的非空 ID；等待状态只登记真实非空 ID，不把失败调用的占位项算进去。

3. **必须改：子 agent 继续调查后仍被当成已结束，可能提前退出。** 位置：`eval/src/steer.rs:419–424`，影响 `ready` 和 `chat` 的退出条件。`*entry |= done` 把「结束」做成不可逆状态。真实 canter 支持主会话对已完成的子 agent 调 `send_input`，同一个 ID 会重新变为 Running（`crates/canter-core/src/agents.rs:459–532,763–771`）。例如主会话读完第一份报告后让它补查，之后另一个孩子也结束；eval 仍认为二者全已结束，会错误跳过第 5 句，并在主会话空闲满 grace 后退出，漏等补查报告。改法：按最新的权威 `AgentUpdated` 状态更新运行/结束状态；工具卡片的旧快照不能覆盖更新后的状态，不能用累计 OR 代替当前状态。

4. **必须改：发送成功但进度未落盘时，重开会重复发送。** 位置：`eval/src/steer.rs:191–222,252–270`。先 POST，收到响应后才把句子加入 `progress.chats`，最后才保存。服务端已经接收并写入事件，但 HTTP 响应丢失/超时，或者此时停止 steer，再开时进度里没有这句；`match_turns` 只补已有记录的 `turnId`，不会从已有 `input.queued` / `turn.started` 恢复缺失记录，于是把同一句再发一次。现有重开测试只覆盖所有进度已正常保存后的重开。改法：发送前保存该句的发送意图及事件游标，重开或响应不确定时先按 `clientName`、原文、事件序号与队列/轮次事件核对；已经接收的补记进度，不能直接重发。正常响应的 `eventSeq` 也应保留用于关联，不必改 canter 协议。

5. **必须改：找不到主会话时，总时限不生效。** 位置：`eval/src/steer.rs:58–66,140,497–520`。30 分钟的 deadline 到 `chat()` 才建立，前面的 `wait_for_session()` 没有 deadline。eval 服务端正常返回空列表、主会话没有成功启动时，steer 会无限找会话，不退出，也不写 `timedOut`。现有超时测试预先写好了 `session.json`，没有覆盖这条入口路径。改法：对 chat 题在进入找会话流程前建立总 deadline，让找会话、发送、轮询共用剩余时间；找会话耗尽预算也落盘超时记录后退出。老的按提交数插话可保持原行为。

6. **必须改：重新采集失败时沿用旧判分数据，造成假过。** 位置：`eval/src/grade.rs:43–53,129–155`。某次 grade 已成功写出 `session-data.json` 后，再次 grade 若因 `canter stats` 失败、事件缺失或解析失败而无法重建，只打一行 note，旧文件仍在。后续检查读取旧文件，甚至可以把旧的全通过结果重新记成这次判分。改法：开始本次采集时使旧数据失效，或者采集失败直接把本次数据相关检查记为不可用/失败并返回失败；不能在未取得本次数据时继续用旧文件判过。首次运行根本没有文件时，现有 jq 检查会失败；空 `turns` 的 `no-wait-in-chat` 已由主控安排，不另计意见。

7. **必须改：事实检查把错误数字判过，并漏认明确要求支持的写法。** 位置：`eval/tasks/subagent.toml:86–101`。`seconds 10/300/60` 没有数字左边界，分别会匹配 `110 秒`、`1300 秒`、`160 秒` 的尾部；`grep '124'` 也接受 `1124`。这些是错误事实，却仍可通过对应检查。各数字还只在整篇查找，没有绑定 codex shell / codex MCP / pi MCP，两个项目的默认值写反也可通过。另一面，`millis` 实际只支持可选下划线或逗号、且强制接单位，不支持注释承诺的 `10 000 ms` 和任务明确要求的裸 `10_000`；现有回答夹有其它秒数写法，所以通过测试掩盖了这个缺口。改法：补数字边界，按项目和工具所在的句子/段落核对对应数值，明确支持列出的秒、毫秒及源码常量写法；保留第九次原文通过及逐条缺事实不过的验证。

8. **建议改：子 agent 汇总行的总花费实际上还是主会话花费。** 位置：`eval/src/report.rs:360–372`。花费格式是「总额（主 X · 子 Y）」，但总额与主会话用了同一个 `cost(row.metrics.cost_usd, ...)`，没有加上 `child_cost`。改法：把两部分相加，并合并 unknown 状态；或者去掉外面的总额，只显示主/子。用时的「共」是并行会话时长相加，也建议标明「累计会话时长」，避免被当成整次跑的墙钟耗时。

9. **建议改：`blockedRgReplace` 的短旗标识别会错数。** 位置：`eval/src/session_data.rs:358–375`。按空格分词并扫描 `rg` 后所有以 `-` 开头的词，没有处理引号、`--` 结束选项和选项参数。例如带引号的 `rg '-rn' ...` 会漏记，`rg -- -r src` 则把作为搜索词的 `-r` 误记成替换旗标。这里指的是已被拦命令的统计，不涉及执行或绕过检查。改法：做最小的 shell 参数分词及 rg 选项边界处理；继续只统计题目要求的短 `-r`，无需扩大到 `--replace`。

10. **建议改：原文回退匹配缺少发送范围和一对一约束。** 位置：`eval/src/steer.rs:252–270,431–434`、`eval/src/session_data.rs:210–224`。回退从所有历史轮次中找相同原文，不限定 `clientName` 或发送前的事件游标；`match_turns` 的 `taken` 在循环里也不更新，`opener` 的原文回退没有排除已绑定到另一轮的记录。当前固定的五句话互不相同，常规路径又会得到直接返回的 turnId，因此暂不作为阻塞项；但重开后的同文输入、排队时的重复句会配错轮。改法：优先使用响应的 turnId/eventSeq，原文回退限定本次发送之后的 canter-eval 输入，并在每次匹配后立即占用该轮。不要为适配假事件的时间戳而取消真实运行需要的顺序约束。
