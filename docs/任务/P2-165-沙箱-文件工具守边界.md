## 要做的

沙箱开着时（`config.json` 的 `sandbox` 缺省开）：

1. **敏感路径不能读写**：read / write / edit（包括 write / edit 准备 diff 时的预读）不能读写 `~/.ssh`、`~/.aws`、`~/.gnupg` 和 canter 状态目录（现在已经挡了状态目录，沿用同一套判断），和 P2-163 墙里的名单一致；任何权限档、任何批准都解不开。
2. **`.git` 的 config / hooks / 元数据指针**：write / edit 不能改（和墙里一样，包括 worktree、子模块的元数据），read 可以读。原来的 `~/.cargo`、`~/.npm` 可读不可写。任何批准都解不开。
3. **「全部允许」下 write / edit 不能写范围外**：范围是 cwd 和新增目录（P2-118 的判断，比较规范化后的真实路径）。写范围外直接拒绝，不弹框。
4. **询问档写范围外**：`alwaysAsk`、`askForExecution` 下照 P2-118 弹文件修改批准框，但只给单次批准，不提供「本会话都允许」（沙箱开着时，目录外的写不能变成整个会话的 write / edit 授权）。范围内的 write / edit 照原来的规矩（`askForExecution` 不问，`alwaysAsk` 照问）。
5. **read 范围外照旧可读**（墙里也是全盘可读，只挡敏感路径），不加批准。
6. **沙箱关闭时**：read / write / edit 一切照 P2-118 和现在的行为，包括目录外 `acceptForSession`；给模型的请求逐字节不变。
7. 计划模式、审查轮、受保护路径的原规则照旧，在这些判断之前。
