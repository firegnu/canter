## 要做的

- **工具**：内置工具 `web_fetch`，参数是网址（只收 `http://`、`https://`）。服务端取回内容：
  - HTML 转成 Markdown（主控建议：只给 Markdown 一种，不让模型选格式）；`text/*`、JSON 原样；图片、PDF、压缩包等其它类型回一行占位说明（类型和大小），不交内容。
  - 照现有工具的输出上限截断；下载本身也有上限（比如几 MB，你定），超了停止下载、回一行说明。
  - 请求有超时（你定，写进 README）；Esc 打断时取消正在进行的请求。
  - 4xx、5xx、连不上、超时、证书错误，作为工具错误回给模型，这一轮继续。
  - 请求头里带一个固定的 User-Agent，写明是 canter；不带用户的任何凭证、cookie。
- **跳转**（主控建议）：同一个域名内的跳转自动跟，次数有上限；跳到别的域名时不跟，回给模型一句「跳到了 <新网址>」，模型要的话再调一次（再过一次批准）。
- **权限**（主控建议）：
  - `web_fetch` 算「执行」：一直问、问执行两种模式下弹批准框，全都允许模式下直接跑。批准框写明完整网址。
  - 「本会话都允许」按域名放行：只放行这个域名（含端口），别的域名照问。
  - `/review` 的审查轮里一律拒绝（`review is read-only`），不弹批准框。
  - 本机和内网地址不另外拦（本机开发服务也可能要看），靠批准框把关；全都允许模式下的风险写进 README。
- **代理**：不做（用户 10-26 定）。和模型、MCP 一样不走代理（`no_proxy`）。
- **缓存命中**：`web_fetch` 加进内置工具列表，位置固定；会话的工具列表照旧在创建或打开时定下。已有会话下次打开时多了这个工具，属正常。
- **依赖**：HTML 转 Markdown 可以加一个成熟、活跃维护的 Rust 库，版本你核实后钉死，写进完成记录；取网页用现有的 reqwest。除此之外还要加别的依赖，停下来问。
- **显示**：终端里 `web_fetch` 的调用和结果照现有工具的样子显示（网址、状态、截断后的长度），`/help` 不用改。
