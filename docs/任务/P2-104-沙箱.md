## 要做的

报告里写这些：

1. **Codex 怎么做**：macOS 上怎么套（seatbelt / `sandbox-exec`，配置怎么生成），Linux 上怎么套；有哪几种沙箱模式，能写哪些路径（工作目录、临时目录、额外加的目录、`.git` 怎么处理），能不能联网；沙箱和批准怎么配合：沙箱里哪些直接跑、不问；被挡住了怎么知道、怎么问用户放行、放行后怎么在沙箱外重跑（P2-88 报告第 7 节「Codex 沙箱怎么定免批准」没查清，这次查清）。
2. **Claude Code 怎么做**：`/sandbox`、sandbox-runtime，文件和网络各怎么限（网络是不是走代理按域名放行），沙箱里的命令是不是自动放行，哪些命令排除在沙箱外，挡住时怎么办。
3. **在这台机器上能不能用**：本机 macOS（Darwin 27）上 `sandbox-exec` 还能不能用、Apple 有没有弃用或替代的说法；起一次沙箱要多少时间。可以在临时目录里用很简单的命令（比如在允许的目录写文件、在不允许的目录写文件）确认基本行为，只为确认能用、写多少毫秒；不要去试怎么逃出沙箱。
4. **canter 要套什么**：逐项列出 canter 里会动文件或联网的东西，每项说别家套不套、建议 canter 套不套、怎么套：
   - 模型的 `shell`、后台长命令（P2-28）、用户的 `!` 命令（P2-26）；
   - write / edit 这类在服务端进程里直接改文件的工具（OS 沙箱管不到，靠 P2-118 那条按路径的边界）；
   - stdio 的 MCP 服务、`web_fetch`；
   - 临时脚本（P2-91）。
5. **范围怎么定**：能写哪些（工作目录、add-dir 加的目录、临时目录、`.git`），能不能读家目录里的敏感目录（`~/.ssh`、`~/.canter` 这类），能不能联网（全关、全开、按域名），git、cargo、npm 这类常用命令在沙箱里会不会坏（比如写 `~/.cargo`、`~/.npm` 缓存），坏了别家怎么处理。
6. **和 canter 现有规矩怎么接**：三种权限模式、只读白名单、受保护路径、计划模式和审查轮的只读、P2-108 按命令放行的规则；沙箱开着时哪些可以不再问。
