## 要做的

### 1. 终端把当前会话写进文件

- 交互式的 `canter` 加一个选项 `--session-file <path>`（`--help` 里英文说明）。带了这个选项，终端把它当前所在的会话写进这个文件；不带时什么都不变。
- 文件内容是一个 JSON 对象，至少有 `sessionId`（会话 ID）和 `cwd`（会话的工作目录）。外面的程序还要靠什么找到服务端，由你看现有的服务端发现方式定：要么在文件里多写一个字段，要么把现有的发现方式写成公开约定；选哪种写进完成记录和 DESIGN。字段名 camelCase，以后只做兼容新增。
- 什么时候写：
  - 会话有了就写（新建的、`--resume` / `-c` 恢复的）。如果终端打开时还没有会话（要等第一句话才建），就等建了再写，之前文件不存在。
  - 终端换到另一个会话时重写：`/new`、`/resume` 选了别的会话、分叉后换过去、交接（handoff）过去和回来。
  - 服务端升级、终端重连后再写一次（会话 ID 不变也写）。
  - 进子 agent 的子会话一屏只是查看，不算换会话，文件不变。
- 怎么写：同目录先写临时文件再改名，整份替换，读的人不会读到半份；文件权限 0600。终端退出时不删这个文件（外面的程序可能还要用它里面的会话 ID 收尾）。
- 写不了怎么办：启动时第一次写就失败（比如目录不存在、没有权限），终端报错退出，不打开界面，退出码非 0；之后某次重写失败，终端在界面上显示一行英文错误、照常继续，下次切换再试。
- 只写会话 ID、目录和找服务端要的东西；不写环境变量、令牌、API key。

### 2. 「只看」的事件流订阅

- `GET /v1/events?session=<id>` 加一个可选参数，表示只看（参数名你定，写进协议文档）。只看的订阅事件内容、补发（`after`、`Last-Event-ID`）、心跳都和现在一样。
- 区别只在不算客户端：不调 `attach_client`，不增加客户端计数，不会让 SessionEnd(client_exit) 迟迟不发，也不会触发 SessionStart(resume)。会话关着时照现在的规则返回。
- 不带这个参数的订阅行为完全不变。终端界面自己的订阅照旧算客户端。

## 怎么算做完

- 带 `--session-file` 启动的终端，文件里始终是它当前所在会话的 ID 和目录：新建、恢复、`/new`、`/resume`、分叉、交接和回来、服务端升级重连后都对；进子会话一屏不变。不带这个选项时行为不变。
- 只看的订阅能收到和普通订阅一样的事件；有只看的订阅挂着、终端断开时，SessionEnd(client_exit) 照 P2-172 的规则照常发出。
- 验证只做这些：
  - 写针对的测试（隔离的 HOME 和 canter 状态目录、假服务端或假模型，不调真实模型），先确认它们在改之前失败：
    - 终端带 `--session-file` 启动：建会话后文件里是那个会话；`/new` 后换成新会话；`/resume` 换回旧会话；分叉后是新会话；进子会话一屏不变（这几种挑现有测试能方便造的，造不出的写进完成记录说明）。
    - 启动时文件写不了：终端报错、退出码非 0。
    - 只看的订阅：收到事件；只剩只看的订阅时，客户端离开照样发 SessionEnd(client_exit)；只看的订阅连上不触发 SessionStart(resume)。
