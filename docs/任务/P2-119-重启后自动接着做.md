# 任务：第三期 - 服务端重启后自动接着做

类型：功能变更
依据：服务端重启（升级 `--replace`、崩溃、被杀）后，正在跑的那一轮标成中断，模型历史补一句「被打断了，接着做」，然后停下等用户。本件让它自己开一轮接着做。从 P2-110 拆出来，第二期不做。
依赖：P2-101（服务端自己开一轮）、P2-110
执行：派出
待用户：10-28 挪到第三期，第二期不做

## 用户原话

- 10-28 分解 P2-110 时，主控对照了 Codex 和 Claude Code：两家重启后默认都只恢复对话、等用户开口（Claude Code 另有默认关的 `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`），canter 已经一样；差距在重试。用户：「重启之后自动接着这个放到第三期去，开一个task。上面的建议我都接受」。

## 现状（10-28 主控读代码）

- `crates/canter-core/src/session.rs` 重开会话时：补齐没有结果的工具调用（「No result: the server stopped…」）、后台命令标成已退出、取消等着回答的批准和提问、模型历史加「[The server stopped and the previous turn was interrupted; continue from the results so far.]」、没跑完的轮标 Interrupted、排队没发的输入丢掉（`discard_queue(Interrupted)`）、会话回到 Idle。
- 终端连上新服务端时，只对停机关闭（`serverShutdown`）或缺少原因的会话自动 resume（DESIGN 第 8 条 P1-13）。

## 分解时要定

- 哪些情况接着做：用户按 Esc 停的、用户主动关的会话不接。
- 接着做是不是走 P2-101 的叫醒、算不算进 `auto_wake_limit`（10-28 主控建议算进去）。
- 后台命令被停了、`monitor` 条件没了，怎么告诉模型（10-28 主控建议不自动重起后台服务，在接着做的那一轮里明说被停了，让模型自己判断）。
- 排队没发的消息要不要保留下来，接着做完再发（10-28 主控建议保留）。
- 参考：Claude Code `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`、`CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS`（code.claude.com 的 env-vars 文档）。
