### 逐项核对（重点看的 5 项）

1. **存盘兼容**（已查证）
   - 旧会话只有 `messages`：`restore()` 得到 `segments = None`，`initialize_prefix` 里 `self.prefix_segments.as_ref() != Some(&segments)` 成立，只追加一条，旧行不动（`session.rs:132`；`prompts.rs` 断言 `upgraded[0] == original[0]`、`upgraded[1] == legacy`，第二次重开不再追加）。
   - 旧版读新记录：`main` 的 `HistoryEntry` 是内部标签枚举，没有 `deny_unknown_fields`（全仓只有 canter-tools 的工具参数用了它），所以会忽略 `segments`、照旧读 `messages`。旧版重开时用自己的格式重拼，和新记录不同，追加一条只有 `messages` 的记录；新版再开时 `segments` 为空，再追加一条。版本来回切换只会多出记录，不丢、不改旧行。
   - 未知 `kind`：结构相同就读成 `Unknown`；`ordered()` 不会选出它，读进来的段只拿来比较、从不写回，所以不会把 `"unknown"` 写进文件（上面实测 1）。结构不同的情况见建议改第 1 条。
   - 去掉 `known` 过滤（`context.rs:110`）：没有坏后果，反而更严。读进来的前缀只在 `initialize_prefix` 里比较（重开和新建都在 `from_state` 之前调它，`from_state` 只有这两个调用点）；混进未知消息就和新算的不同，一定会被换掉（实测 3）。原来过滤后可能「相等、不追加」，请求用的是过滤后的前缀，和存盘最后一条的字节不一样。现在保证了「请求用的前缀 = 存盘最后一条 `context`」。
2. **前缀不变**（已查证）
   - 生成前缀只有一处：`context::prefix()`，只被 `initialize_prefix` 调，而它只在 `open_inner`、`create_inner` 里跑。压缩（`compaction.rs:119` 用 `state.prefix.clone()`）、切模型（`update_inner` 只改 settings）、`/btw` 和 `/handoff`（`btw.rs:79` 用 `context::request`）、退回和撤回（只截 history 和 users）都不重拼。
   - 段和 `messages` 存进 JSON 再读回，字符串原样往返；不变就沿用存盘字节，变了就先记再用。所以请求、存盘和 `/context` 的分段三者一致。
   - P2-15 的 `request_prefix_is_frozen_until_reopening_and_only_compaction_replaces_history`、`reopening_restores_the_exact_model_context_and_skips_future_history_entries` 都没改，照旧过。
3. **转换器**（已查证）：`chat_completions` 不读文件、不读时钟，同样的输入输出同样的字节；标签、只在两种说明段写 `path`、先换 `&` 再换 `"<>`（不会重复转义）、正文原样、不以 `\n` 结尾才补、段间 `\n\n`、整条末尾不加换行、空段和只有空白的段不出现（`ordered()` 和读文件时都做了 `trim().is_empty()`），都和方案 §2.1 的渲染表一致。技能说明句和 §2.1 第 3 条逐字相同；环境段四行和 §5 一致（`%:z` 输出 `+08:00`），日期由 `prefix()` 在打开时取 `Local::now()` 一次，格式化函数吃固定输入。

### 建议改

1. **未知种类的段缺 `text` 时，整个会话打不开**（`crates/canter-core/src/prompt.rs:45`）。
   - 问题：`Segment.text` 是必填字段。以后的版本如果加一种不带 `text` 的段（比如只做标记的段），这一版读到时 `model_history` 整份解析失败，`Session::open` 返回 Internal（实测 2）。只在降级到这一版时发生；文件不会被改，不丢数据。
   - 改法（二选一）：给 `text` 加 `#[serde(default)]`。缺了就读成空串，比较时和新算的不同，会照规矩追加一条，不会误用。或者不改代码，在 `Segment` 上写一句注释，或写进 DESIGN 第 20 条：以后新增的种类也必须带字符串 `text`。

### 可以不改

1. `chat_completions` 里 `SegmentKind::Unknown => continue`（`prompt.rs:78`）走不到，因为 `ordered()` 只按 `SEGMENT_ORDER` 选段，而这张表里没有 `Unknown`。留着无害。
2. `/context` 没有技能时不再显示 `Skills (0)` 那一行。`main` 上不管有没有技能都记一个 skills 段（`main:context.rs:247`，0 token）。现在空段不出现，和方案「空段不出现」、终端 README「空段不显示」一致。这是用户看得见的小变化，完成记录没提，告诉主控一声。
3. `prompts.rs:175` 的「不变不追加」和 P2-15 的冻结测试，要求新建和重开在同一个本地日期内完成。正好跨过本地零点会失败。原来跨 UTC 零点也一样，只是换了零点，窗口只有几毫秒。
4. `server.rs:943`、`:981` 用 `!contains("<global_instructions ")`（带空格）判断没有全局段。全局段总是带 `path`，渲染出来一定有这个空格，判断成立；写成不带空格的 `<global_instructions` 会更稳一点。
