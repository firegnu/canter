1. **macOS 目录用 `open -R <路径>`**：在 Finder 里定位并选中，不打开，`.app` 这类应用包不会被启动；跟着符号链接看是目录的（指向 `.app` 的链接、改名后的新路径）一样。不靠后缀判断。测试 `an_app_bundle_is_shown_in_the_finder_not_started`（`Tool.app` 目录、指向它的符号链接、改名到这个链接）；原来的目录测试改成期望 `open -R`。
2. **Linux 上路径改成复制**：网址照常 `xdg-open`；路径（文件和目录，不看在不在）不打开，复制绝对路径，提示 `✓ Path copied`（走 P2-45 的复制，同 SSH）。为了在 macOS 上也能测，加了公开的 `LinkSystem`（`MacOs`、`Linux`、`Remote`），默认按 SSH 变量和编译平台定；`App::with_link_opener` 的第一个参数从 `remote: bool` 改成它，测试默认按 macOS，不再按编译平台分支。`Copier::copy_link` 多一个参数，传提示的字。测试 `on_linux_an_address_opens_and_a_path_is_copied`（`.desktop` 文件、目录、不存在的路径都只复制、不开）。
3. **命中检测查画出来的那一帧**：每次画对话时记下这一帧画出来的链接（屏幕第几行、哪几列、目标）和当时对话的首行、宽度；这一帧真正上屏（`frame_on_screen`）后按帧号存下来，留最近 8 帧（和按键用的 `shown` 一样）。运行循环把鼠标事件的帧号传进来（改调新的 `App::handle_mouse_on(mouse, frame, at)`，原来丢了帧号）；`handle_mouse_at` 按最新上屏的那帧。按下、松开都查事件那一帧画出来的链接。下面几种都不开：那一帧之后滚轮滚过或按新宽度重画过（现在的首行、宽度和那一帧的不同）；按下和松开两帧的首行、宽度不同；帧太旧、不在留着的几帧里；帧比本屏最新上屏的还新（会话列表画在这里）。测试：
   - `an_address_opens_as_drawn_before_the_answer_grew`：流式更新还没重画时点，开的是画出来的那截；
   - `after_the_wheel_turns_a_click_opens_nothing_until_drawn`：滚轮后还没重画就点、按下和松开之间滚，都不开，重画后再点照常开；
   - `across_a_change_of_width_a_click_opens_nothing`：上一帧的点击到新宽度重画后才处理、按下和松开跨了两个宽度，都不开；
   - `a_click_is_on_the_frame_on_screen_when_it_came_in`：Ctrl+O 展开把链接挤下去以后，带旧帧号的点击开的是旧帧上的链接，同一格在新帧上点不开。
4. **取消等着打开的一下**：Esc、Ctrl+F 打开搜索、切换会话（按键得到 `NewSession`、`PickSession`）时清掉；到点打开前再看一次是不是在搜索，在就丢掉。测试 `esc_the_search_or_a_session_switch_drops_a_click_waiting_to_open`（Esc、Ctrl+F、`/new`、`/resume` 各一次）。
5. **先建线程，在线程里起程序**：先建 `canter-open` 线程，在线程里看路径、起程序、等它结束；线程建不起来时状态行红字 `✗ Could not open <链接>: <原因>`，什么都不起。结果经 channel 回到界面，每帧收一次：程序起来就报 `Opened`，之后报错退出再报红字。测试 `the_screen_does_not_wait_for_the_program_to_start`（假 opener 卡住时界面照画、不出 `Opened`，放开后才出）、单元测试 `a_thread_that_cannot_start_is_said_so`（把起线程的函数换成失败的）。
6. **只开普通文件和目录**：文件检查和起程序在同一个线程里；跟着符号链接看，普通文件 `open -t`、目录 `open -R`，别的（设备、socket、FIFO 等）红字 `✗ Not a file: <路径>`。测试 `only_a_file_or_a_directory_opens`（指向 `/dev/null` 的符号链接、Unix socket）。

另外：
- README「链接」一节跟着改：0.4 秒内会取消的操作、点到的是画出来的那个、macOS 的 `open -R` 和 `Not a file`、Linux 复制路径。
- 顺手修了第 0 轮我自己写的测试 `a_double_or_triple_click_on_an_address_selects_and_does_not_open`。它在机器忙时偶尔失败：复制线程只写攒着的最新一次复制，三击的复制盖掉了双击的。改成每次复制等写好了再按下一下（测试用的是模拟时钟，三下仍算连着的三击），断言没有放宽。

### 拿主意的地方

- 流式更新还没重画时点：开画出来的那一截（可能是没写完的网址），不开后来长成的那个。
- 「滚动、改宽度」按对话首行和宽度判断：事件那一帧的和现在的不同，或按下和松开两帧的不同，就不开。内容变了而首行、宽度没变时（比如 Ctrl+O 展开），按事件那一帧画的算。
- Linux 上的路径不看在不在、是不是文件，直接复制（同 SSH）。
- 平台做成公开的 `LinkSystem` 传给 `with_link_opener`，测试可以测 Linux 的行为，不再按编译平台分支。
- 切换会话在 App 里按 `NewSession`、`PickSession` 两个动作清。真的换了会话时整个 App 本来就换掉了，这一条主要管 `/resume` 打开列表后又取消、回到原来会话的情况。
