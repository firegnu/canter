## 要做的

### 1. 选项和归属

- 交互式 `canter` 加选项 `--close-on-exit`（`--help` 里英文说明）。不带时行为完全不变：终端退出，会话照旧留在服务端。
- 带了这个选项，这个终端这次运行里新建、恢复、`/new`、`/resume`、分叉、交接打开过的会话都归它负责，退出时一起收尾。切换会话本身不关任何会话。
- 服务端要能认出「哪些会话归哪个负责的终端」，以及这个终端还在不在。怎么认（终端每次运行一个随机标识、一条一直连着的连接、在建会话和打开会话的请求里带上标识，或者别的办法）由你定，写进 DESIGN 和协议文档；只能用 canter 自己的客户端连接来判断，不看外面是谁起的终端，不看别的进程。归属只记在服务端内存里，不存盘、不进快照和事件、不进模型上下文。
- 只看的订阅（P2-191 的 `observe=true`）和别的普通终端都不影响归属，也不能让负责的终端「算还在」。

### 2. 正常退出：马上收尾

- 带 `--close-on-exit` 的终端正常退出（用户退出、收到 HUP、TERM）时，请服务端把它负责的会话全部收尾，然后退出。
- 收尾和现在关会话（`DELETE /v1/sessions/{id}`）一样：打断在跑的轮、停掉后台命令、关掉会话；会话留在盘上，以后能恢复。子 agent 的子会话照现有关会话的规则跟着处理。
- 终端从收到退出信号到退出不超过 5 秒，不等会话真正关完；关完是服务端的事，终端走了也要关完。服务端连不上时终端照样退出。
- 还有别的普通终端连着同一个会话，照样收尾（那个终端会看到会话关了）。

### 3. 异常消失：10 秒后收尾

- 负责的终端被强杀、崩溃、或者和服务端的连接断了，服务端等 10 秒；10 秒内这个终端连回来（同一次运行）就照旧，没连回来就把它负责的会话全部收尾，收尾方式同第 2 节。
- 10 秒宽限和 P2-172 的 10 秒是两件事：P2-172 只发钩子通知、不关会话，规则不改。两者都会触发时，钩子的 SessionEnd 照现有规则只发一次；收尾时 SessionEnd 的 `reason` 用哪个现有值（或者要不要加新值），由你按现有钩子规则定，写进 DESIGN 和完成记录。

### 4. 服务端升级和重连

- `canter serve --replace` / `canter upgrade` 换服务端时，旧服务端停下本来就会关会话。负责的终端连上新服务端后，重新声明自己负责的会话（新服务端里它打开的那些），继续受管。
- 换服务端过程中，不能因为「连接断了」把会话误收尾；终端在换服务端期间死掉，新服务端里没有它打开的会话，也就没什么要收尾。
- 期限：不能让 `--replace` 的现有期限链（等锁 90 秒、命令期限 105 秒，见 DESIGN 第 11 条）变长。

### 做了什么

- 交互式 CLI 增加 `--close-on-exit` 和英文帮助。每次运行从系统随机源生成 ID，独立 SSE 保活；创建、恢复、分叉请求携带可选 `x-canter-managed-client` 头。`/new`、`/resume`、分叉、交接及返回均沿用同一客户端，切换不释放旧归属。不带选项保持原路径，exec 不加选项。
- 服务端增加 `GET/DELETE /v1/managedClients/{id}` 和 `managedClients` feature。归属只保存在内存，按会话实际实例记录；正常退出立即接受并返回 202，断线等 10 秒，代次排除过时计时器。退出先封住该 owner，再独立调用原 HTTP DELETE 共用的关闭路径；已接受、仍在打开中的请求完成后也收尾，不能靠重连撤销收尾，也不会误关其它终端后来重开的同 ID 实例。
- 终端独立续接保活，退出时最多等待服务端请求 4 秒；外层信号处理覆盖正在等待网络或切换会话的情况。受管界面被取消时释放事件任务；普通界面的退出路径不变。旧服务端开始排空即停用租约收尾，不额外等待；新服务端重新保活，只认领实际重新打开的会话。
- 更新 DESIGN、协议 README、CLI README。核心关闭、子 agent 处理、P2-172 的连接数与钩子规则、P2-191 的发布和观察规则均未修改，没有新增依赖或改变已有 JSON 字段。

### 拿主意的地方

- 正常关闭和租约过期都复用 `ClientRequest` / `client_request`；P2-172 若先发了 `client_exit`，沿用原去重标记，不再补发。并发时由原核心状态锁决定哪条先发，不增加原因枚举。
- 归属是每个终端自己声明过的会话实例集合；两个受管终端明确恢复同一会话时，各自都有关闭责任，任意一个退出都收尾。仅普通订阅、观察订阅不声明归属。退出后的 ID 在该服务端内保留空墓碑，避免迟到重连复活。
- 期限没有增加：终端关闭请求预算 4 秒，加既有终端输入线程退出最多 0.1 秒，为本地恢复终端和调度留出余量；服务端保活任务不加入升级等待，排空仍按原关闭路径处理，等锁 90 秒、命令 105 秒及原本地 I/O 边界不变。没有需要主控决定的事项。
