## 中转 VPS 调研（主控 11-15）

用户 11-15：「我现在有一个google AI ultra 5x的订阅。这个我记得GCP是有每个月的返现的，我正好可以弄一台GCP的vps。你调研一下」「把这个调研写进P2-297任务书里吧」。

**用户 11-15 定：「那就把这个设置为这个任务的vps。」本任务试用时的中转就用 GCP，只花 Ultra 5x 每月送的 $40。**

开发 agent 照旧不搭 VPS；VPS 由用户自己在合并后、试用时搭。第 10 条的文档照旧写通用做法，不绑定哪一家云（仓库是公开的）。

**额度**
- Google AI 套餐附带 Google Developer Program 权益，每月给 Google Cloud 额度：AI Pro $10，**Ultra 5x $40**，Ultra 20x $100。早期新闻里的「Ultra 每月 $100」现在只对应 20x。
- 领取：在 Developer Program 权益页选一个 Cloud 结算账号，点领取。勾上「Always use this billing account」以后每月自动入账，发放日是第一次领取那天，每月同一天。
- 每笔额度发放后 12 个月过期，最多攒一年。订阅停了就不再发。家庭组成员不能共享。
- 要先有一个 Cloud 结算账号，一般要绑卡。额度用完后，多出来的费用从卡里扣。
- 能不能付虚拟机：官方只说可以用在「符合条件的 Google Cloud 产品」上，并套用 Cloud 通用的折扣排除表。排除表里和 Compute Engine 有关的只有：承诺使用折扣、Spot/抢占式虚拟机、部分特殊机型（大内存型、计算优化型、带 GPU/TPU 的）。普通 e2 虚拟机不在表里。官方没有专门点名 Compute Engine，领到后要在账单里确认确实抵扣了。

**机型和区域**（中转只转发 HTTP + SSE 文本，流量很小）

| 选法 | 每月大概多少钱 | 合适的情况 |
|---|---|---|
| e2-micro，放美国 Oregon（us-west1）/ Iowa（us-central1）/ South Carolina（us-east1） | 免费层本来就免算力费和 30 GB 标准盘，只剩公网 IP 和流量的小钱 | 能接受跨太平洋的延迟。文字流式输出，多一两百毫秒基本感觉不到 |
| e2-micro / e2-small，放东京、台湾或香港 | 不在免费层，大约每月 $8～15（含 IP） | 想要延迟低。$40 额度足够付 |

- 这两项价格是主控凭记忆说的，没在官方价格页上核实，以控制台显示为准：公网 IPv4 在用时大约 $0.005/小时（每月约 $3.6）；流出流量按 GB 收费，到中国大陆的流出单价比别处高。
- 已经从官方免费层页面核实：免费层每月只送 1 GB 流出流量，不包括到中国大陆和澳大利亚的流量。

**和本方案对照**
- 符合 P2-291 定下的做法：VPS 上跑 Caddy 管 HTTPS，服务端机器用 `ssh -R` 或 frp 连上来；VPS 只转发，不跑 agent，不放代码。
- VPS 能看到明文，用 GCP 就是 Google 的机器能看到。所以 P2-296 要求所有 TCP 请求先核对令牌，这一点照旧是重点。
- 先试再定：手机或服务端机器在中国大陆时，GCP 的 IP 从大陆连不连得上、稳不稳，一直有不确定性。先开一台美国区 e2-micro，从服务端机器做 `ssh -R`，用手机连几天，稳定了再定区域。

**只花赠送的 $40**（用户 11-15：「我的意思是只使用这个赠送的40美金。」）
- 两种选法的花费都远低于 $40：美国区 e2-micro 每月只要几美元，亚洲区 e2-small 大约 $15 以内。正常使用不会超。
- 唯一会变的是流出流量。中转只转发文字，就算有人一直请求你的地址，没有令牌也只拿到很短的拒绝回复，流量也不大。
- GCP 没有「到 $40 自动停」的开关。预算只发提醒，不会自己停机。要保证不扣卡里的钱，有两层做法：
  - **预算提醒**：预算按扣掉额度以后的净花费算，金额设 $1。一旦出现要从卡里扣的钱，就会发邮件。
  - **自动停机（可选）**：官方有做法，预算提醒发到 Pub/Sub，由一个 Cloud Run 函数自动关掉虚拟机（官方文档「Control resource usage with notifications」）。还有一种更狠的做法是直接把项目和结算账号断开，但会停掉项目里所有服务，资源最后会被删除。
  - 预算数据要几小时才更新，提醒总比实际花费晚一点，所以做不到一分钱都不超。按上面的花费，离 $40 余量很大，这点延迟没关系。

**没有域名怎么办**（用户 11-15：「我还没有域名。。。。呜呜呜」「所以说现在tailscale暂时不用了吧？」；主控答：不用，11-14 已定不走 Tailscale）
- 试用 Mac 终端时不需要域名：5090 用 `ssh -R` 把 canter 的本机端口挂到 VPS 的 127.0.0.1，Mac 用 `ssh -L` 把它转到 Mac 的 127.0.0.1，客户端连 Mac 本机地址。第 3 条允许把令牌发给回环地址；加密由 SSH 负责，不用 Caddy，也不用证书。
- 以后手机、网页客户端要 HTTPS 时，按这个次序试：
  1. 直接给 IP 签证书。Let's Encrypt 从 2026-01-15 起正式支持 IP 证书，有效期 6 天，Caddy 选 `shortlived` 档会自动续期，配 GCP 静态 IP，不花钱。Caddy 早先有一个 IP 证书报错的 issue（caddyserver/caddy#7399），到时用新版 Caddy 试。
  2. DuckDNS 免费子域名。它在公共后缀列表里，证书申请次数不和别人共用，比 nip.io、sslip.io 稳。
  3. 买域名，一年大约 $10，要花用户自己的钱，不在 $40 里，放最后。
- 来源：https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability.html 、https://caddy.community/t/shortlived-certificates-from-lets-encrypt/33399

## 要做的

1. **服务端列表**：
   - 存在客户端的 `<CANTER_HOME>/remotes.json`，权限 0600，每条 `{name, url, token}`。
   - 命令：`canter remote add <名> <网址>`，令牌从标准输入读，不放命令行参数里；`canter remote list`；`canter remote remove <名>`。
2. **选服务端**：
   - 加 `--server <名>` 的命令：`canter`、`canter exec`、`canter usage`、`canter stats`、在线的 `canter doctor`。
   - 不带 `--server` 永远连本机，照旧自动找、自动起。不设「默认远程」。
3. **令牌只发给安全的地址**：只发给 `https://` 地址和回环地址，别的 `http://` 地址拒绝连接，并说明原因。
4. **工作目录**：
   - 远程时用 `--cwd <服务端上的路径>`，不给就报错，不猜。
   - 服务端拒绝相对路径的 `cwd`。这是服务端改动，属于这件。
   - `-c`、`--last` 和会话选择器：远程时有 `--cwd` 就按它过滤，没有就不过滤。
5. **连上以后**：
   - 先请求 `/v1/info` 比协议版本。不一致时提示 "Server '<名>' runs canter <版本>; upgrade it on that machine"，不提示远程用户去跑 `serve --replace`。
   - 重连时用 `/v1/info` 的 `instance` 判断是不是同一个服务端。
6. **断线**：SSE 设空闲超时，大约连续 3 次心跳收不到就重连，照现在的重连办法从断开处接着收。
7. **远程时的差别**（照调研第 6 节第 1 件 (a)）：
   - 不交 `env`；
   - 服务端路径的链接只复制不打开，沿用 `links.rs` 的 SSH 规则；网址照常打开；
   - `/memory` 不打开编辑器，提示 "Edit memory on the server machine"；
   - `/export` 的相对路径按客户端当前目录解析。
8. **只管本机的命令，远程时拒绝**：
   - `canter serve`、`serve --replace`、`upgrade`、`service`、`mcp`、`skills install`、`auth login` 带 `--server` 时直接拒绝，提示 "Run this on the server machine"；
   - 远程时也拒绝 `--session-file`。
9. **还没做的功能，远程时给提示**：贴图、拖文件、`/diff`、`/review`、`/files`、`@` 补全，提示 "Not available on remote servers yet"；分支名和状态栏改动行数不显示。不报错，也不显示错的内容。
10. **文档**：写一份「远程连接怎么搭」。放哪由你定，写进完成记录。内容：
    - 服务端配 `remote.listen`、加令牌；
    - VPS 上用 Caddy 管 HTTPS，用 SSH 反向隧道（`ssh -R`）或 frp 转回服务端本机端口，给一份最小可用的示例；
    - 客户端用 `remote add`；
    - 先不接 VPS、用 SSH 端口转发直接试的办法。
