## 要做的

1. **自动重新读**：服务端盯着 `~/.canter/config.json` 和 `rules.json`，保存了就重新读、照 `Config::load` 现有的规矩校验。编辑器常常一次保存触发几次改动或先写一半，要合并成一次读，不能因为读到写了一半的文件就把错误当最终结果（之后读到好的就恢复）。`rules.json` 如果现在已经是每次检查都重新读，就不用改，在完成记录里写明。
2. **哪些生效**：`config.json` 里的设置都能不重启生效：接口地址和密钥（换模型客户端）、`model`（新会话的默认）和 `models` 列表、上下文窗口、压缩线、沙箱、遥测、自动唤醒次数、目标预算、重试次数、价格、图片模型、`plan_enabled`、`mcp_tool_search`、`mcp_servers`、`lsp`。已经开着的会话也用新配置，不只是新开的会话。会话自己用 `/model` 选过的模型照旧；它不在新的 `models` 列表里了怎么办，你提出办法写进完成记录（建议：照旧用，下一轮请求出错由用户自己换）。
3. **什么时候生效**：正在跑的那一轮从头到尾用开始时的配置；下一轮（包括自动唤醒、目标续跑开的轮）用新的。
4. **MCP 和 LSP**：新加的 MCP 服务下一轮就能用；删掉或改了的，等正在用它的那一轮结束后再关掉、按新配置重开。LSP 配置照同样的规矩：正在跑的轮用旧的，轮结束后按新配置起停。
5. **改坏了**：校验不过或读不了时，照旧用旧配置，服务端不崩，正在跑的轮不中断。错误经协议推给客户端，终端界面显示一行英文提示，写明哪个文件、哪里错了（照现有错误文字，不带出密钥和配置内容）；改对了自动生效，提示消失或换成恢复的说法。
6. **协议和 DESIGN**：协议里加的通知或字段，和 Codex app-server v2 结构不同的地方写进 `docs/DESIGN.md`，说明为什么；DESIGN 里写一节「改配置不用重启（P2-154）」，写清上面 1～5 条。HANDOFF 里「改了要重启服务端」这类说法由主控改，你不改。
