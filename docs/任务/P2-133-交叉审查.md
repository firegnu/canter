### 重点看的四项

1. **不拖累原来的工具**

     - shell 改了配置文件（比如 `cargo add`、`npm install x`、用 `sed` 改 `pyproject.toml`）时，要等语言服务器完全停掉，shell 结果才返回。
     - 临时测试：服务器不回 shutdown 时，普通 shell 11 ms；改 `Cargo.toml` 的 shell 3.01 秒（P2-132 的 shutdown 上限）。
     - 有上限，不会一直卡住；正常回 shutdown 的服务器会快很多。
   - 改法：核对发现要重起实例时，标 stale、停监视，然后把「等实例停完」放进后台任务，shell 不 await 它。

6. **可以不改**：`sync.rs:439-482`（文件不存在时的分支）
   - 事实（读代码）：
     - 回退删掉一个当前实例里没打开的文件（比如之前被 64 个上限挤掉了），后台直接返回 Ok，不发 Deleted 批次。
     - 这张票据会一直等到调用方超时；票据表里这一项要等这个文件下次变了才清掉。
     - 调用方有超时，不会卡住。
   - P2-134 接票据时顺手给这种情况回一个 Deleted 批次就行。

7. **可以不改**：`sync/pull.rs:132-135`
   - 事实（读代码）：一次 pull 出错（包括 30 秒超时，以及服务器回 ServerCancelled 这类可以重试的错误），会把这个实例所有已打开的文档都标 Stale，不只是出错的那一个文件。
   - 这样偏保守，不会把旧的当成新的。
   - P2-136 接 pull 型服务器实测时，再看要不要改成只标这一个文件、遇到可重试的错误再拉一次。

### 对完成记录里取舍的表态

- 只有实际写入成功才发票据；回退恢复、删除也通知；失败和拒绝不发：同意。
- 服务端把共享池传给核心，会话持有 `LspSession`，关会话释放订阅：同意。
- 只在普通修改轮主动同步，计划、审查期间暂停，恢复后有界核对：部分同意。暂停期间不起实例、不主动打开新文件，同意；但暂停时直接丢掉监视事件和推送会漏，见第 4 条。
- 实例内串行同步，用实例代数、单调递增的版本和内容摘要；Incremental 用整篇替换的范围：同意。
- 每个实例最多打开 64 个，按最近同步回收，重开后版本继续递增：上限和版本做法同意；但一大批外部改动会全部打开，把本会话自己改的文件挤掉，见第 2 条。
- 用 notify 原生事件、Tokio 约 200 ms 合批（主控已定）：同意。逐个目录装监视在 macOS 上代价随目录数陡增，见第 1 条。
- shell 前台、后台和用户命令走同一个完成路径，核对已打开文件和已知配置；纯 shell 不起实例：同意。另有两个问题：配置没变也发 Changed（第 3 条）；配置变了时 shell 要等实例停完（第 5 条）。
- 删除、改名清掉旧 URI；配置变化、运行中监视失败时标 stale 并重建：同意。
- 监视第一次装失败重试一次，还失败就明确报错，下次修改再试：不同意。监视失败不该连 write / edit 的同步一起放弃，也不该每次修改都重扫，见第 1 条。
- 排除目录和受保护目录；不跟符号链接，读文件逐级 `O_NOFOLLOW`：同意。
- 关注文件最多 1024 个，路径元数据最多 1 MiB；监视最多 4096 个目录或配置，第一次扫描最多 10 万项；事件队列 1 MiB / 4096 个路径：数字本身可以。有两个问题：关注集合只增不减（第 2 条）；目录一超限整个不可用（第 1 条）。
- 诊断缓存和待交付队列各 1 MiB，单文件 256 KiB，都是内部常量（主控已定）：同意。
- stderr 排空不存：同意。
- 超过 16 MiB 只让这一条报 Protocol 错误，3 秒写超时不放宽：同意先不放宽，P2-136 用真实服务器测大文件的 didOpen / didChange 时再定。
- push 按「实例 + URI」整表替换，pull 按 provider 分开；空表清除；收到时和交付时都核对；无版本标 `VersionUnconfirmed`：同意。
- pull 支持 full / unchanged、resultId、refresh，文件变了取消旧请求、不收迟到的回复：同意。出错时的处理范围见第 7 条。
- `ChangeTicket::wait(Duration)` 的等待时长由调用方定，取消等待不取消启动；票据走内部的 `ToolOutput.change_ticket`，另有 `subscribe()` / `diagnostics()`：同意。
- 新依赖 notify 8.2.1 加 6 个传递依赖：同意。核对了 `Cargo.lock`，只新增 7 个包，已有的包版本没变。
- 两个会话的批次 id 在插入各自队列时分配，订阅不会跳号：同意。
- 没做的（不交给模型、不加客户端事件、不做全工作区 pull、内置服务器表为空；没用真实服务器和 Linux 后端实测）：同意，按任务分工留给 P2-134 / P2-136。建议 P2-136 实测时一并看第 1、3 条和上面「未知」里的三项。
