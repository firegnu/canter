## DeepSeek 的规矩（10-25 读文档）

- 只有 `deepseek-flash` 收图片；`deepseek-v4-pro` 文档里没说收。
- 图片只能放在 `user` 消息里，放在 system、assistant 里返回 400。user 的 `content` 写成数组：`{"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}`，和 `{"type": "text", ...}` 混排。`detail` 不填（默认 `auto`，保留原图）。
- 格式只认 JPEG、PNG、GIF、WebP，按文件内容判断。单张最大 32 MiB，整个请求最大 48 MiB。每张图按尺寸折算 token，最多 1024 个，和文字一起计费。
- 文档没说：多轮对话里历史图片要不要每次重发、图片影不影响缓存命中。按 OpenAI 格式的惯例，历史消息原样重发，图片也跟着发。

## 要做的

### 终端里怎么附图片

- **粘贴路径**：粘贴（或从 Finder 拖进终端）的文字整段是一个存在的图片文件路径时（引号、反斜杠转义按终端拖拽的习惯去掉），不当文字插入，当作一张图片附件。不是图片或文件不存在的，照常当文字插入。
- **剪贴板截图**：输入框里按 Ctrl+V，剪贴板里有图片就附上（macOS 截图到剪贴板的那种）；没有图片就什么也不做。读剪贴板的办法你定；要加依赖的，停下来问。
- 附上的图片在输入框里显示成占位，比如 `[Image #1 screenshot.png]`，可以和文字一起编辑；删掉占位就不发这张。发出去以后，对话里那条消息也显示占位，不在终端里画图。
- 当前模型不收图片时（见下面「哪些模型收图片」），附图片直接提示，比如 `deepseek-v4-pro does not accept images; switch with /model deepseek-flash`，不附上。

### 协议、存盘和发给模型

- 协议的用户输入加一种图片类型，结构尽量照 Codex v2 的 `UserInput`（`Image` / `LocalImage`）；客户端和服务端在同一台机器上，可以传本机路径。字段名你定，和 Codex 不一样的地方写进 DESIGN 第 8 条，说明为什么。
- 服务端收到消息时就把图片读进来，校验格式和大小，存进这个会话自己的状态目录（和事件、模型历史同目录，权限照它们）；之后每次请求、压缩、服务端重启后重开会话，都从这里读，不再依赖原文件（剪贴板的临时文件、原图被删了也不影响）。格式不对、超过上限、读不了的，整条消息拒绝（`invalid_request` 一类），不进会话，终端显示原因、草稿留着。
- canter 自己的单张上限定 8 MiB（远低于文档的 32 MiB：历史图片每次请求都要重发，整个请求不能超过 48 MiB）。
- 发给模型时，这条 user 消息的 content 写成文字加图片的数组；没有图片的消息照旧发字符串，已有会话发给模型的内容一字不变（DESIGN 第 17 条：P2-15 的前缀延续测试照样过）。
- 估上下文占用时，每张图按 1024 个 token 算（文档的上限）。

### 哪些模型收图片

- `config.json` 加一个可选字段，列出收图片的模型（字段名你定，写进服务端 README）；没写时默认只有 `deepseek-flash`。
- 会话中途 `/model` 换到不收图片的模型，而历史里已经有图片时：发给这个模型的请求里，图片换成一段文字占位（比如 `[image omitted: screenshot.png]`），不报错；换回收图片的模型时照原样发图片。存盘的历史不改。（换模型本来就让缓存全丢，这里不再另算。）
