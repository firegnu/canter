1. **建议改：在终端输入令牌之前，没有先检查名字和网址**
   - 位置：`crates/canter/src/remote.rs` 的 `AddServer` 分支。
   - 问题：返工后先调用 `terminal_token` 读令牌，再进 `remotes::add` 检查名字和网址。比如 `canter remote add work http://example.com`，用户先粘完令牌，才看到 "Use an HTTPS server URL…"；同名已存在也是粘完才报错，只能再粘一次。走管道时 `add` 本来就是先检查后读输入，终端这条路把顺序反过来了。
   - 改法：终端分支在提示之前先做名字和 `remote_url` 检查（可以把 `add` 开头的两项检查抽出来共用），同名检查也可以提前读一次 `remotes.json`。

2. **可以不改：被 SIGQUIT、SIGTERM、SIGHUP、SIGKILL 这类信号直接终止时，不恢复终端**
   - 这几种信号按默认动作结束进程，`Drop` 不会执行，终端会留在关回显的状态，而且 `O_NONBLOCK` 是设在和 shell 共用的终端描述上的。只有在等输入令牌的那一刻收到这类信号才会碰到，Ctrl+C 和 Ctrl+Z 不受影响。

3. **可以不改：exec 续接时其他非 401 的错误仍然无限重试**
   - 比如断线期间会话被删了，`read_session` 一直返回 404，exec 只打一次原因，然后一直挂着。这和返工前一样，只在断线期间删会话时出现。
