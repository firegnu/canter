## 要做的

1. **服务端加会话级只读接口**，放在 `/v1/sessions/{id}/workspace/...` 下面：
   - 分支名和改动行数（信息行、状态栏用）；
   - 未提交改动（`/diff`）；
   - `/review` 要的准备工作，含 `gh`；
   - `/files` 的状态；
   - `@` 补全的文件列表：服务端按 git 忽略规则遍历一次，最多 1 万条，分批返回；过滤照旧在终端做。
2. **代码从 `canter-tui` 原样搬过去**：
   - 在会话 `cwd` 和新增目录里跑，环境用会话环境（P2-295）；
   - `git.rs` 的环境加固原样保留。
3. **终端改调接口**，本机和远程都这样，不在终端里留本机实现。
   - 状态栏脚本照旧在客户端跑，喂给它的分支、改动数改为来自接口。
   - 去掉 P2-297 加的远程提示，远程也显示分支和改动行数。
4. **兼容**：
   - `/v1/info` 的 `features` 加一个能力名；
   - 新终端连上没有这个能力的旧服务端时，提示 `serve --replace`，沿用现在的能力提示写法。
5. **文档**：协议 README 加这组接口；DESIGN 里写这些功能的地方跟着改。

## 不要做

- 不做通用的执行命令接口、读写文件接口，只做上面这几样只读查询。
- 不改 `/review` 发给模型的内容，不改 `@` 的过滤和排序。
- 不放宽 git 的环境加固。
- 不针对某一家模型写特例。
- 不调真实的模型接口；测试不碰用户的 `~/.canter`，也不用用户的 `gh` 登录，用假的 `gh` 或跳过联网部分。
