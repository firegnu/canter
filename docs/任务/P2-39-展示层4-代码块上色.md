## 要做的

照方案第 3 项「推荐」做，要点：

- **依赖**：加 syntect `=5.3.0` 和 two-face `=0.5.2`，正则引擎用 onig；关掉用不着的默认特性（比如 syntect 自带的语法表和配色，two-face 已经带了）。做完记下 `canter` 程序 release 编译实际变大多少。
- **配色**：用 two-face 的 `ansi` 配色。它把颜色写成终端调色板的编号（不是真彩），普通文字是终端默认色；照这个换成 ratatui 的 16 色和默认色，不要当成 RGB 用。颜色经 `theme.rs` 出去，`NO_COLOR`（`Depth::None`）时不上色，照现在的样子。
- **语言识别**：只看围栏后面的语言名，按 syntect 的语法名和扩展名找，补几个常见别名（`golang`→Go、`shell`/`sh`/`zsh`→Bash、`python3`→Python、`csharp`→C#、`ts`、`tsx`、`js` 这类找不到时补上）；没写语言的看第一行是不是 `#!`；都没有、或者认不出，照现在整块青色。不按内容去猜。
- **上限**：一个代码块超过 512 KB、1 万行，或者有一行超过 4 KiB，就不上色，整块青色。
- **流式缓存**：进行中的回答每帧从头渲染；上色要记住已经写完的行，同一个代码块后面来新行时，前面的行不重算。缓存放哪、怎么失效你定；宽度变了照旧整段重画。
- **样子不变的部分**：不显示围栏和语言名；代码块的缩进照旧；长行照旧折行；行内代码照旧青色。
- **批准框的命令**：`shell_body` 里显示的整条命令按 Bash 语法上色。只改颜色，字一个不变：照旧先过 `visible()`，再上色；折行、`Directory:` 那行不变。命令超过上面的上限时不上色。
- **许可证**：核对 syntect、two-face、onig / Oniguruma 和 two-face 内置语法定义、配色的许可证。内置语法定义要求随程序附带声明的，照 two-face 的说明在仓库里补上（比如根目录一份第三方说明）；放哪、什么形式拿不准，停下问。
- README 里讲 markdown 显示的地方写上代码块上色的规则（怎么认语言、上限、`NO_COLOR`）和批准框命令上色。
