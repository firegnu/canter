### 1. 必须改：子 agent 被父会话从盘上重新打开时，沿用存盘里的 `--yolo` 豁免

- 位置：`crates/canter-core/src/agents.rs:388` `open_agent`；起作用的是 `crates/canter-core/src/session.rs:865-871`（子会话打开时 `options.sandbox` 取存盘的 `settings.sandbox_enabled`）；调用方 `crates/canter-server/src/agent_sessions.rs:50`（`send_input` 发给没打开的子 agent）、`:75`（`close_agent`）。
- 问题：子 agent 建出来时存盘 `sandboxEnabled = 父会话当时的实际状态`，`--yolo` 开的父会话建出的子 agent 存的是 false。服务端重启或升级（或会话被关）以后，用户不带 `--yolo` 打开父会话（`canter -c` / `-r`），父会话按配置开着沙箱、状态栏显示 `Sandbox on`；父会话的模型再对这个子 agent 用 `send_input`，服务端走 `open_agent` → `Session::open`，子会话的 `options.sandbox` 被存盘的 false 盖掉，执行器为 `false && !false = false`，子 agent 的命令在墙外跑；之后配置重读也不会改它（`apply_configuration` 对子会话保留 `old.options.sandbox`）。这正是「上一次 `--yolo` 的选择存进了盘、跟着会话走了」，违反第 6 条「不带 `--yolo` 打开……照配置（默认开）」、「沙箱照配置开回来」，以及第 9 条「套沙箱的会话开出的照旧」。终端明确恢复子会话（`http.rs:935` 冷打开后补的 `set_sandbox_disabled`）已经把存盘值改回去，只漏了父会话重开子 agent 这条路。P2-198 之前存盘的 false 只可能来自配置，所以这是本件新带出的问题。
- 改法：`open_agent` 里 `Self::open(...)` 之后、`attach_agent` 之前，补 `child.set_sandbox_disabled(runtime.context.sandbox_disabled, runtime.options.sandbox).await?`（`runtime` 是父会话当时的运行时），让父会话重开的子 agent 跟父会话当时的实际沙箱，和终端明确恢复子会话一致。加一条测试：带 `sandboxDisabled` 的父会话建子 agent → 关掉或重启服务端 → 不带它恢复父会话 → 父会话 `send_input` 给子 agent → 子会话 `sandboxEnabled == Some(true)`，命令写不了项目外。DESIGN 第 510 行「沙箱……取创建时父会话的有效值」和第 427 行 P2-198 那句补半句：父会话重新打开已经关掉的子 agent 时，按父会话当时的实际状态。还活着（在内存里）的子 agent 照第 9 条字面维持创建时的状态，本条不要求改。
