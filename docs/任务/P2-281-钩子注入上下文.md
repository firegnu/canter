## 要做的

1. **SessionStart**：钩子成功退出、stdout 是 JSON 且带 `hookSpecificOutput.additionalContext`（字符串，非空）时，这段文字交给模型。
   - 会话打开不等钩子，界面照常打开。
   - 会话这一段第一次向模型发请求前，等还在跑的 SessionStart 钩子出结果，最多等到钩子自己的 timeout；拿到的文字放在这次请求的用户输入前面。
   - 第一次请求已经发出后才到的，放在下一次请求前面，不叫醒、不另开一轮。
   - 新建会话（`startup`）和打开存盘的会话（`resume`：`--resume`、服务端重启后再打开）注入。客户端离开发过 SessionEnd、又重新连上时发的那次 SessionStart（source 也是 `resume`）照旧运行、照旧是通知，不注入：会话接着原来的上下文，重连一次塞一份会白占上下文（用户 11-11 选 A）。
2. **UserPromptSubmit**：钩子放行时，同样识别 `additionalContext`，这段文字和这条输入一起交给模型，放在用户的话前面。排队输入、插话都一样。被拦下的输入不注入。
3. **放在哪、怎么存**：
   - 照 DESIGN 第 17 条只往后加，不改已经发出的内容，不进系统提示词和环境段。
   - 写进模型历史，标明来自哪个钩子事件，是内部上下文，不是用户原话。压缩时按内部上下文处理，不算用户原话。
   - 重开、分叉、回退、撤回照原样重放或随所属轮去掉。
   - 同一事件有几条命令都给了文字的，按配置顺序拼起来。
4. **钩子输入带对话记录路径**：
   - 所有事件的钩子 stdin 加 `transcript_path`：这个会话的 `events.jsonl` 的绝对路径（子会话给子会话自己的）。字段名照 Claude Code。
   - DESIGN 写明这个文件对外公开的部分，只加不改：文件只往后加行、不改写已写的行；哪种行是一条完成的用户消息、哪种是一条完成的模型回复，取哪些字段拿到文字；回退、撤回去掉的轮靠哪种后加的行认出来。读的人照这份约定逐行读，不认识的行和字段跳过。
   - 别的内容（工具输出、思考、遥测、模型私有历史）不算公开约定，以后照常可以改。
5. **不变的**：
   - 受限会话照旧不跑钩子；
   - 子 agent 照旧不发 SessionStart，SubagentStart 照旧不注入；
   - 钩子起不来、超时、出错、输出不是合法 JSON，照旧放行加英文警告，会话照常跑；
   - stdout 32 KiB 的上限不变；
   - 别的事件的输出照旧不进模型；
   - 钩子的配置格式不变（还是只在全局 `~/.canter/config.json`）。
6. **DESIGN**：「钩子（P2-153）」一节改成新的规则：事件表里 SessionStart、UserPromptSubmit 的「作用」一栏跟着改，共同字段加 `transcript_path`，删掉「没有 transcript_path 等数据的字段不硬造」里 transcript_path 那部分；写明参照 Claude Code 钩子文档的 `additionalContext` 和 `transcript_path`。会话记录的公开约定单独写一节。

## 怎么算做完

- SessionStart 钩子给了 `additionalContext`：模型在这一段第一次请求时收到这段文字，排在用户输入前面；钩子还在跑时第一次请求等它，最多等到钩子自己的超时；第一次请求已发出后才到的，放进下一次请求。新建、打开存盘会话这两种 SessionStart 算；客户端离开后重新连上发的那次不注入（钩子照旧运行），重连几次会话里都不多出注入；`/new`、`/handoff`、计划清空后实施、`canter exec` 这些走创建接口的入口照样生效。
- UserPromptSubmit 钩子放行并给了 `additionalContext`：这段文字和这条输入一起交给模型，在用户的话前面；普通输入、排队、插话都一样；被拦下的输入不注入；不触发 UserPromptSubmit 的自动轮（目标续跑、后台叫醒、子会话的初始任务）不注入。
- 注入只往后加：已经发出的请求前缀一个字节都不变；重开、分叉、回退、撤回后，模型看到的和原来一致，回退、撤回掉的那一轮的注入跟着去掉。压缩时注入的文字不算用户原话。
- 只认 JSON：纯文字 stdout、空的 `additionalContext`、不是字符串、JSON 坏了，都不注入，照旧放行；坏 JSON 照旧给英文警告。同一事件几条命令都给了文字，按配置顺序拼起来。受限会话照旧不跑钩子；子会话照旧不发 SessionStart。
- 终端对话里注入处显示一行灰字，写哪个事件注入了多少字（英文，如 `SessionStart hook added context (1.2k chars)`），不显示正文；导出里同样一行。
- 所有事件的钩子 stdin 都带 `transcript_path`：这个会话 `events.jsonl` 的绝对路径，子会话给它自己的。
- DESIGN 写明 `events.jsonl` 对外公开、只加不改的部分：文件只往后加行；完成的用户消息、完成的模型回复各是哪种行、文字在哪个字段；回退、撤回去掉的轮靠哪种后加的行认出来；其余内容不算公开约定。「钩子（P2-153）」一节和事件表照新规则改，删掉「没有 transcript_path 等数据的字段不硬造」里 transcript_path 那部分。
