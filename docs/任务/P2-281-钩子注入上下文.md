# 任务：SessionStart、UserPromptSubmit 钩子能往会话里注入上下文

依据：用户的项目都由 cairn 管跨会话记忆，cairn 在 Claude Code、Codex 里靠 SessionStart 钩子在开局注入「上次做到哪」。canter 的钩子（P2-153）只发通知，DESIGN 写明「没有实现 SessionStart / UserPromptSubmit 注入上下文」，所以 cairn 接不上 canter。本件给 canter 加通用的钩子注入能力，照 Claude Code 钩子文档的字段；不为 cairn 写特例，cairn 那边怎么接是 cairn 的活。
依赖：P2-280

## 用户原话

- 11-11：「关于canter在canter-desktop的记忆问题，现在基本上我的项目都是cairn在管记忆，所以我压根不关心记忆。但是cairn没有接入canter。我应该怎么做？」
- 11-11：「关于记忆我的理解是canter本身的记忆该记还是记。只是canter-desktop中工作的canter能够接入cairn就是了。」（主控确认）
- 11-11：「cairn是一个独立的记忆服务。不能因为机器上没有canter就失败」
- 11-11（主控列了计划：P2-279 → P2-280 → 本件 → 交 cairn 需求）：「写吧」

## 要做的

1. **SessionStart**：钩子成功退出、stdout 是 JSON 且带 `hookSpecificOutput.additionalContext`（字符串，非空）时，这段文字交给模型。
   - 会话打开不等钩子，界面照常打开。
   - 会话这一段第一次向模型发请求前，等还在跑的 SessionStart 钩子出结果，最多等到钩子自己的 timeout；拿到的文字放在这次请求的用户输入前面。
   - 第一次请求已经发出后才到的，放在下一次请求前面，不叫醒、不另开一轮。
   - `startup`、`resume` 两种 source 都注入。
2. **UserPromptSubmit**：钩子放行时，同样识别 `additionalContext`，这段文字和这条输入一起交给模型，放在用户的话前面。排队输入、插话都一样。被拦下的输入不注入。
3. **放在哪、怎么存**：
   - 照 DESIGN 第 17 条只往后加，不改已经发出的内容，不进系统提示词和环境段。
   - 写进模型历史，标明来自哪个钩子事件，是内部上下文，不是用户原话。压缩时按内部上下文处理，不算用户原话。
   - 重开、分叉、回退、撤回照原样重放或随所属轮去掉。
   - 同一事件有几条命令都给了文字的，按配置顺序拼起来。
4. **不变的**：
   - 受限会话照旧不跑钩子；
   - 子 agent 照旧不发 SessionStart，SubagentStart 照旧不注入；
   - 钩子起不来、超时、出错、输出不是合法 JSON，照旧放行加英文警告，会话照常跑；
   - stdout 32 KiB 的上限不变；
   - 别的事件的输出照旧不进模型；
   - 钩子的配置格式不变（还是只在全局 `~/.canter/config.json`）。
5. **DESIGN**：「钩子（P2-153）」一节改成新的规则，事件表里 SessionStart、UserPromptSubmit 的「作用」一栏跟着改；写明参照 Claude Code 钩子文档的 `additionalContext`。

## 用户定的（11-11：「都按你的建议来」，两条都选 A）

1. **只认 JSON，还是也认纯文字**：Claude Code 对这两个事件也把纯文字 stdout 当成上下文。
   - **选 A**（主控建议）：只认 JSON 的 `additionalContext`，纯文字 stdout 照旧只记警告。好处是钩子顺手打的日志不会意外进模型；cairn 适配 canter 时照这个格式输出就行。
   - B：纯文字也注入，和 Claude Code 一样，现成为 Claude Code 写的钩子不用改就能用。代价是打日志的钩子会把日志塞给模型。
2. **界面上显示不显示**：注入的文字会影响模型怎么做，用户应该看得到。
   - **选 A**（主控建议）：对话里加一行灰字，写哪个事件注入了多少字（英文，比如 `SessionStart hook added context (1.2k chars)`），不显示正文；导出里同样一行。
   - B：不显示，只进模型历史。

## 不要做

- 不为 cairn 写特例，不在代码和文档里提 cairn；canter 不依赖 cairn，机器上没有 cairn 时什么都不变。
- 不加其它事件的注入（Stop、PreCompact 等），不加 prompt / agent / http 类型的钩子，不加项目钩子。
- 不改钩子的环境变量、超时、进程组、并行和停机预算规则。
- 不按模型或服务商分支。
