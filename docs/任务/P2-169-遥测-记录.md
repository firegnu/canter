## 要做的

1. **压缩前后各多大**：每次压缩（自动、手动 `/compact`）记下压缩前和压缩后的上下文 token、压掉了多少条消息。
2. **上下文里各部分占多少**：每次模型请求按估算记下系统提示词（含 AGENTS.md 等固定前缀）、工具说明、对话、工具结果各占多少 token。估算沿用 `compaction.rs` 的 `estimate`，不另引分词器；和服务商回报的实际输入 token 对不上没关系，标明是估算。
3. **每次请求的用时**：每次模型请求从发出到收完的时间（毫秒），和首个回复片段到达的时间（如果拿得到）。重试本来就有 `ModelRetry` 记录，不重复记。
4. **每次工具调用的结果大小**：交给模型的结果按估算多少 token、有没有被截断（截断前多大）。工具名和成功失败本来就有，不重复记。
5. **等人批准的时间**：每次批准框从弹出到用户回答等了多久、结果是批准、拒绝还是取消。
6. **每次请求当时的设置**：模型、思考档位、权限模式、是否计划模式。会话中途会换，要按请求记。
7. **会话标签**：启动时能给会话带几个 `键=值` 标签（比如任务编号、派活的名字），存进会话，以后外部工具和 eval 按标签把会话和自己的记录对上。终端用命令行参数传（照现有 `--add-dir` 那样，可写几次），服务端在新建会话的协议里收；是通用接口，代码和文档里不为 corral 写特例（CLAUDE.md「独立」一条）。标签不进模型请求。开关关掉时标签照样存（它是用户主动给的，不算遥测）。
8. **开关**：`config.json` 加 `telemetry`，缺省为开，`false` 关；和 `auto_compact_tokens` 一样服务端启动时读。关掉时 1～6 都不记，现有的 `SessionUsage`（token、缓存、花费、上下文占用）、压缩摘要、重试、工具调用照旧记，`/usage`、状态栏、`/context` 行为不变。
9. **存在哪**：并进会话存盘（`events.jsonl`），跟着会话走、删会话一起删。新字段全部可省略，旧会话照常打开，旧版本打开新会话不坏。具体是加在现有事件上还是新增事件由你定，写进 DESIGN。字段名和含义写清楚、保持稳定：下一件 P2-170 要据此出 JSON 给以后的 eval 用。
10. **不给模型看**：这些数据不进模型请求、不进提示词，不改变模型看到的内容，不让缓存变冷。
11. **不能让 agent 变慢**：记录不能拖慢请求、工具调用和界面。估算、统计不放在发请求和收回复的关键路径上拖时间，写盘沿用现有的事件写入，不另加每次请求的同步读写。完成记录里写清楚怎么保证的，并给一次开关开和关的对比（假服务端、长历史会话，同样的请求，各自用时）。
12. **文档**：DESIGN 补一节「遥测记录」，写字段、开关、和 Codex 的差别（如有）。界面文字（如果有）一律英文。
