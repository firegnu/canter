## 重点看

1. 挂载有没有漏：macOS 墙里读不到、写不了的东西（`~/.ssh`、`~/.aws`、`~/.gnupg`、canter 状态目录和控制 socket、`/run` 下的 docker.sock、cwd 外的文件），在 Linux 墙里有没有哪条路径能读到或写到——包括可写根、只读挂回、缓存符号链接、记忆目录例外、`writePaths` 申请、后台命令。挂载冲突时是不是失败而不是悄悄放宽。
2. Git 锁和占位：已有仓库（含嵌套、worktree、子模块、`.git` 文件指针）的 config、hooks 等能不能在墙里被改。占位建在用户真实的 `.git` 里：会不会弄坏用户在墙外同时跑的 git、并发和后台命令下引用计数对不对、会不会删掉不是自己建的文件。
3. 每条命令启动前 `find_git` 把 cwd、新增目录、`writePaths` 整棵树走一遍：碰到读不了的子目录（比如 Docker 建的属主别人、权限 700 的数据目录）或走的时候被删掉的目录（后台 `cargo build` 正在改 target），是不是让命令直接失败；正常项目里会不会碰到；如果改成跳过，会不会让墙里能改到某个已有仓库的 config／hooks。
4. seccomp、Landlock、`pre_exec`：BPF 跳转和参数偏移对不对；不联网时 IP 网络是不是真不通；联网时挡 netlink、挡硬链接会不会让常见工具（git、cargo、npm、node）在正常用法下失败；`PR_SET_NO_NEW_PRIVS` 加在 bwrap 自己身上有没有问题。
5. macOS 行为有没有变：`sandbox.rs`、`shell.rs`、`executor.rs`、`doctor.rs` 的改动在 macOS 上是不是一条不变；测试有没有为在 Linux 上过而删测试、放宽断言，macOS 上的沙箱覆盖有没有变少。
