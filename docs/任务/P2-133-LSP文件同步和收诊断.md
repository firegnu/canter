## 要做的

1. **write / edit / 回退之后**：成功写入（含回退恢复和删除）后通知语言服务器（`didOpen` / `didChange` / `didSave` / `didClose`），版本按实例内同一文件全局递增，记内容摘要；第一次成功写入匹配的文件才起服务器（懒启动）；写失败、被拒绝的不通知。
2. **shell 和外部改动**：服务器起来以后，监视项目根下匹配的源码和项目配置文件（合并约 200 ms 一批），已打开的文件重读后发 `didChange`，没打开的发 `didChangeWatchedFiles`，需要诊断时有限地打开（每个实例最多 64 个，超了按最近使用回收）；shell 前台结束、后台命令结束时核对一次；`Cargo.toml`、`pyproject`、`tsconfig` 这类配置变了让服务器重载，不确定能重载就重起实例。不监视 `.git` 内部、`target`、`node_modules`、虚拟环境；不跟符号链接跑出授权目录或进受保护路径；监视失败就标「可能过期」并重建。只用 shell、从没用过 write / edit 的会话不起服务器（用户 10-29 定）。
3. **收诊断**：支持服务器主动推（带版本、不带版本）和 canter 去拉；按版本、实例代数、磁盘内容摘要判断是不是针对当前内容，旧的丢掉；空列表表示这个来源清掉了这个文件的诊断；不带版本的标「版本未确认」，不当成已修好；文件又变了就取消旧的拉取。缓存只存本会话关注的文件，帧、stderr、缓存都有字节上限，超了报告不完整。
4. 报给用户和客户端的原因、错误一律写英文（canter 界面都是英文）。
5. 给 P2-134 一个窄接口：「这次修改的诊断」（能等一会儿）和「之后到的诊断批次」订阅。不在本件里定等多久。

- 做了什么：在 `canter-tools::lsp` 增加会话同步、原生文件监视、诊断收集和有界交付。write/edit 仅在实际写入成功后发出修改票据，回退恢复/删除后通知；失败及拒绝结果没有票据。服务端把共享池传给核心，由会话持有 `LspSession`；关闭会话释放订阅。普通修改轮才能主动同步，计划/审查期间暂停，恢复后有界核对；同一轮批准计划后转实施也及时更新状态。未改变文件批准和原子写入逻辑，没有添加模型内容或客户端协议。
- 同步和监视：实例内串行同步文档，使用实例代数、单调递增版本和内容摘要；支持 Full/Incremental（UTF-16 整篇替换范围）、open/close 和按能力发 save/includeText。每实例最多 64 个打开文档，按最近同步使用回收，重新打开继续递增版本。notify 原生事件在 Tokio 合并约 200 ms；同步已打开文件，向未打开文件发 watchedFiles 并有限打开；支持作用域内的动态监视注册。shell 的共同完成路径覆盖前台、后台和用户命令，核对打开文件和已知配置；纯 shell 不激活实例。删除、改名清除旧 URI 的结果；项目配置变化和运行中监视失败标记 stale 后重建。监视初建失败重建一次，仍失败明确报错，后续修改可再试。
- 路径与资源：排除 `.git`、`target`、`node_modules`、虚拟环境和受保护目录；不遍历符号链接，读取使用逐级目录描述符和 O_NOFOLLOW，防止检查后路径替换把读取带出范围。关注文件最多 1,024 个、路径元数据最多 1 MiB；监视最多 4,096 个目录/配置，初建扫描最多 100,000 个目录项，事件队列最多 1 MiB / 4,096 路径，超限明确降级。按主控决定，诊断缓存与待交付队列各 1 MiB、单文件 256 KiB，均为内部常量，按序列化字节加元数据计费。stderr 继续排空但不存储。发出超过 16 MiB 的消息仅该条报 Protocol 错误，连接和实例保留；没有放宽原有 3 秒传输写超时。
- 诊断和后续接口：按实例/URI 整表替换 push，pull 按 provider 分开；空表清除该来源。接收和交付时核对代数、版本及磁盘摘要，丢弃旧结果；无版本推送标 `VersionUnconfirmed`，空表也不能解释为修好。支持文档 pull 的 full/unchanged、resultId、refresh，文件变化取消旧请求并忽略迟到回复。`LspSession::changed` 返回 `ChangeTicket`，`wait(Duration)` 由调用方定预算；取消等待不取消启动。write/edit 票据通过内部 `ToolOutput.change_ticket` 返回；`subscribe().recv()` 提供后续批次，`diagnostics().await` 提供重新校验后的缓存。批次含 id、文件、服务器、代数、版本、摘要、来源、freshness、不完整标记和英文原因，供 P2-134 使用；没有在本件定 500 ms 等待或模型交付策略。接口说明已更新 `crates/canter-tools/README.md`。
