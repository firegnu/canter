## 要做成什么

1. **记账时标计费方式**：每次模型请求（主线、压缩、`/btw`、交接、下一句建议、子 agent 都算）的用量记录带上这次怎么计费：按价表算美元，还是用 ChatGPT 套餐。按哪种由这家的配置决定（`auth: "chatgpt"` 的家是套餐），不按家名、模型名或地址判断。套餐请求不算美元、也不记成未知金额，token 照常记。
2. **合计分开**：会话、每轮、按天按模型的合计里，别家的美元照原来的规则加，套餐请求只加 token，并标出「有套餐用量」；套餐请求不让别家已知的金额变成未知。
3. **各处显示**（用户 11-05 定的字）：
   - 状态栏 Cost 项：只用 GPT 时 `ChatGPT plan`，混着用时 `$0.12 + ChatGPT plan`，别家还有未知金额时 `$0.12+? + ChatGPT plan`。
   - `/usage`、`canter usage`、`canter stats` 的表：GPT 那几行的 Cost 列写 `ChatGPT plan`，token 列照常；合计行照第 2 条写。表里有套餐用量时，下面加一行 `ChatGPT plan usage: https://chatgpt.com/settings/usage`。
   - `statusLine` 脚本收到的 JSON：加一个可省略的字段说明有套餐用量，原有的花费字段含义不变（只是不再因为套餐请求带上未知）。
4. **`/goal` 预算**：套餐请求不计入美元预算，也不当成「未知金额」去停目标；目标照常按别家的美元算（用户 11-05 选「不计入预算」）。
5. **以前的记录**：已经记成未知金额的旧 GPT 请求照旧当未知，不回头改、读的时候也不补认；只有以后的请求标套餐（用户 11-05 选「照旧当未知」）。
6. **协议**：用量记录和合计加的字段都可省略；旧客户端读新服务端照常显示（套餐部分它不认识，按原样只显示美元），新客户端读旧服务端和旧存盘照原样显示。
