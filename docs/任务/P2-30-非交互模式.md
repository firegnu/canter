## 要做的

1. **`canter exec "<任务>"`**：在当前目录新建一个会话，跑一轮，做完就退出。和交互界面一样连常驻服务端（没有就在后台起一个），会话由服务端跑，`exec` 只是另一种客户端。
   - 任务文字也能从标准输入读：不给任务文字或给 `-` 时读标准输入；既给了文字、标准输入又是管道时，把标准输入的内容附在后面。
   - 交互界面已有的 `--model`、`--tag key=value`、`--add-dir` 照样能用。
2. **权限**（用户：「照 Codex，要批准的都拒」）：
   - 默认用「只问执行」档加沙箱：工作目录里读写、沙箱里的命令照常跑。
   - 碰到要批准的事（写沙箱外、联网、MCP、`web_fetch`、文件规则里要问的、计划模式的计划批准等），一律自动拒绝，告诉模型「没人批准」，不卡住。
   - 加 `--yolo` 换成「全部允许」：沙箱照旧，能联网；内置的危险命令检查和文件规则里的禁止照旧拦。
3. **输出**（用户：「文字 + --json 两种」）：
   - 默认把模型最后的回答打到标准输出；过程（调了什么工具、被拒的批准、重试、出错）简要打到标准错误。
   - `--json`：标准输出每个事件一行 JSON，最后一行写结局、用量、花费和会话 ID，给 eval 和脚本解析。事件名和字段写进 DESIGN，以后只加不改。
4. **中途提问和退出**（用户：「问题自动答没人，出错非 0 退出」）：
   - 模型用 `ask_user` 时，自动回答「没人在，按你自己的判断继续」，不卡住。
   - 正常做完退出码 0。模型请求最终失败、这一轮被打断（Ctrl+C）、花费到上限、有批准被自动拒绝时，退出码非 0，并在标准错误写原因。不同原因用不同的退出码，写进 DESIGN。
   - Ctrl+C 打断这一轮再退出，不留下还在跑的轮。
5. **会话**（用户：「会话照常留下」「支持接着上次的跑」）：
   - 跑完的会话照常存盘，`canter stats` 能看，`canter -r` 能打开。
   - `canter exec --resume <会话 ID> "<任务>"` 或 `canter exec --last "<任务>"` 在已有会话上再跑一轮。`--last` 只找当前目录的会话（和交互界面的 `-c` 一样）。
6. **服务端为主**：不让模型等批准、自动回答提问这些行为放在服务端，按会话设置，由 `exec` 这个客户端开；以后网页、GPUI 客户端也能用。协议加的东西照 Codex v2 的风格，和 Codex 不同的地方写进 DESIGN。新客户端连不支持的旧服务端时报错，提示运行 `canter serve --replace`，不发请求。
7. **不改交互界面的行为**：交互界面打开的会话照旧弹批准框、照旧问用户。
