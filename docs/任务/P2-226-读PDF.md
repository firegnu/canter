## 要做的

1. **读文字**：read 遇到 PDF（按内容认，不只看扩展名）时，用 `pdf-inspector` 转成带页码的文字，`startLine`、`lineCount` 和现有的行数、字节上限、「从哪行接着读」都作用在转出来的文字上，模型能看出每段在第几页。
2. **扫描页**：抽不出文字的页（库报的需要 OCR 的页），在这次读取的结果末尾加一句英文说明，列出页码；当前模型能看图时，告诉它怎么要某一页的图片；不能看图时只说这些页没有能抽出的文字。不自动附图。
3. **要页面图**：read 新加一个可选参数（名字你定，比如 `page`），只对 PDF 有效：用本机 `pdftoppm` 把那一页转成 PNG，走现有的工具看图那条路（`ToolImage`、会话副本、8 MiB、请求预算）交给模型。模型可以要任何一页（看图表、版面），不只扫描页。
   - 当前模型不能看图时不转图，回一句英文说明。
   - 没装 `pdftoppm` 时回一句英文说明怎么装（`brew install poppler`）；读文字不受影响。
   - 页码超出范围、参数用在非 PDF 上，给英文说明。
4. **上限和不卡住**：
   - PDF 超过 50 MiB 不读，给英文说明。
   - 加密、损坏、转不出来的 PDF 只让这次读取失败，给英文说明，不影响会话和服务端。
   - 文字转换和转图都有超时；超时或 read 被取消后，不能留下一直占着 CPU 或内存的转换（库在本进程里跑不能中途停的话，想办法让它可以被停掉，办法你定，写进完成记录）。
   - 转出来的 PNG 大小也要守 8 MiB，分辨率你定，能看清正文即可。
5. **权限**：读 PDF 和转图都照 read 现有的读文件权限和状态目录拒读走，不另加批准；转图读到的必须是通过 read 检查的同一份内容，不能另开一条按路径读文件、绕过检查的路。
6. **工具说明**：read 的说明里写上能读 PDF、按页文字、扫描页、怎么要页面图。改工具说明会让升级后第一次请求的前缀变一次，这是可以接受的；没有 PDF 时请求里其他东西不变。
7. **依赖**：`pdf-inspector` 用当前最新的 1.x，不开 python 这类用不到的功能。只用库、不搬代码；参考了 omp 的哪里写进完成记录。
8. **DESIGN** 第 8 条写清：read 读 PDF 的做法、扫描页提示、页面图参数、上限、要本机 `pdftoppm` 才能转图、和 Codex、Claude Code、omp 不同的地方。
