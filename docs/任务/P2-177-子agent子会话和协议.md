## 要做的

子 agent 就是一个普通的 canter 会话，只多记「父会话是谁」。存法、打开、压缩、遥测和普通会话一样，能复用的都复用。

1. **子会话**：
   - 和普通会话放在一起（`<CANTER_HOME>/sessions/<id>/`）。
   - 快照多一个 `parent`，记父会话 ID 和开它时父会话所在的轮 ID（回退要用），再记开它时给的任务文字。
   - 旧存盘没有这些字段，照普通会话读。
2. **核心接口**：给下一件 P2-178 用。
   - 能从一个父会话开子会话，并用任务文字开第一轮。
   - 能对子会话再开一轮（P2-178 的 `send_input` 要用）。
   - 能关掉子会话：在跑的轮取消。
3. **继承**：开的那一刻照父会话当下的值：模型、思考档位、权限档位、沙箱、工作目录、新增目录，以及父会话内存里的环境变量。放行规则是全局的 `rules.json`，和普通会话一样每次检查实时读（11-02 主控决定，见主控审查）。
4. **状态**：
   - 子会话有五种状态：在跑、做完、失败、被关、中断，跟着最近一轮变。
   - 「做完」时记下这一轮最终那条回复，作为交给父会话的结果。
   - 状态和结果存盘，重开后一致。
5. **协议**：
   - 子会话用现有的会话接口就能看、能订阅事件，不另造。
   - 新加 `GET /v1/sessions/{id}/agents`，列出该会话的子会话：ID、任务、状态、最终回复、开始和更新时间。
   - `features` 加一项。
   - 和 Codex 不一样的地方写进 DESIGN：Codex 用 `SessionSource::SubAgent(ThreadSpawn { parent_thread_id, .. })` 标来源，canter 用 `parent` 字段。
6. **会话列表**：会话列表（`--resume` 选择列表）、`canter stats` 列表、`canter -c` 和 `canter exec --last` 找「这个目录最近的会话」时，都不算子会话。按 ID 直接打开子会话照常允许。
7. **父会话进回收站**：
   - 子会话跟着一起进回收站。
   - 有子会话在跑就拒绝，和现在「有活在跑就不让删」一样。
   - 直接删某个子会话照现有规则，不另加限制。
8. **父会话分叉**：子会话不复制，新会话没有子会话。分叉一个子会话得到的新会话不带 `parent`。
9. **父会话回退**：
   - 有子会话在跑就拒绝回退。
   - 被回退掉的那几轮里开过的子会话，跟着进回收站。
10. **服务端重启**：没做完的子会话标成「中断」，不自动接着跑。
11. **DESIGN**：新增一条「子 agent 的子会话（P2-177）」，写上面这些规则和理由；协议差异写进第 8 条的扩展列表。
