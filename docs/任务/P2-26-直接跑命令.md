## 要做的

1. **终端**：输入框里以 `!` 开头、后面有命令的（去掉 `!` 和前后空白），按 Enter 不发给模型，发「跑这条命令」的请求。只有 `!` 没有命令的不发。会话在干活、等批准、等回答、压缩时不跑：草稿留着，状态栏提示一句要等这一轮结束。`!` 命令照 P2-25 记进输入历史。
2. **协议**：照 Codex `thread/shellCommand` 加一个会话请求（字段照 Codex：`command`，可选 `timeoutMs`），会话不空闲时返回明确的错误。`commandExecution` 项目加可选的 `source`（`agent` / `userShell`，照 Codex 的 `ExecCommandSource`），省略按 `agent` 读，旧终端忽略这个字段照常显示。DESIGN 第 8 条写明加了什么、和 Codex 不一样的地方和理由。
3. **核心**：空闲时作为单独的一轮（照 Codex `StandaloneTurn`）：在会话的工作目录和环境里用 shell 跑整条命令，复用 `shell` 工具那一套（输出上限、进程组、Esc 停下、超时；不给 `timeoutMs` 时照 `shell` 工具的默认）。不经批准，任何权限模式都直接跑（用户自己敲的）。不调模型。
4. **放进模型历史**：跑完把命令、退出码、用时、输出（按给模型的输出上限截断）照 Codex 的格式包成一段用户角色的内容，追加到模型历史末尾；模型这次不回答，用户下次发消息时一起带上。只往后加，不改前面的内容。
5. **存盘和老功能**：这一轮和它的项目照常存盘、`/resume` 后照样显示；`/rewind` 能退回它（它没有改文件，只退回对话）；压缩把它算进去；`/export` 照命令写一行摘要并标明是用户跑的；`/btw`、`/review` 不受影响。旧版本 canter 打开带这种轮的会话不能读坏（照 DESIGN 第 8 条的兼容规矩，写清旧版会看到什么）。
