# 任务：远程连接端到端加密，中转 VPS 看不到令牌和内容

依据：从 P2-300 第 2 条拆出。现在两段 SSH 隧道在 VPS 上解开，经过的内容和令牌在 VPS 上是明文；P2-302 后隧道一直开着，VPS 被攻破的人截到令牌，随时能借隧道让服务端机器上的 agent 以用户身份干活（拿不到那台的 shell：`-R` 只转发 canter 那一个端口；VPS 上只有两边的公钥）。
依赖：P2-302
执行：主控（先试的办法只改两边的隧道服务和文档，用户在场时做）
待用户：什么时候做
优先：低（iPad 要走 HTTPS 时变高，见 P2-306）

## 要做的（开工时补全）

1. **先试不改代码的办法**：服务端机器把自己的 sshd 也用 `-R` 挂到 VPS 回环地址；客户端 `ssh -J <中转>` 直接和服务端机器建 SSH，在这条连接里 `-L` 转 canter 端口。VPS 只转发加密的 SSH。改 P2-302 的隧道服务和 `docs/remote.md`。
2. 不行（或者给 iPad、网页用，客户端开不了 SSH）再做 HTTPS 在服务端机器上解密、VPS 只按 TCP 原样转发（要改代码，先改 DESIGN）。
3. 顺手：VPS `authorized_keys` 给两把公钥加 `restrict` 和 `permitlisten`／`permitopen`，只许挂、连 canter 那个端口（防两边私钥被偷后登 VPS 的 shell，不防 VPS 被攻破）。

## 不要做

- 不改「一台服务端只服务一个人」。
- 改 VPS 的 sshd、`authorized_keys` 先问用户。
- 文档和测试里不写真实的 IP、主机名、用户名。
