## 要做的

1. **配置**：内置服务器表（随 canter 发布的数据文件，本件里可以是空表或只有测试用的项，具体语言 P2-136 加）加 `config.json` 的 `lsp` 段覆盖；`lsp.enabled` 默认 false，关着时不起进程、不监视、不加任何东西。每份配置至少有服务器 id、命令和参数、扩展名到 languageId、项目根的标记、initializationOptions、回答 `workspace/configuration` 用的 settings。命令按参数直接起，用会话环境的 `PATH` 找程序，不经 shell、不用 `npx` 这类会临时联网装的；不读仓库里自带的 LSP 启动配置。改配置照旧 `canter serve --replace` 生效。
2. **通信**：专门的「参数启动 + 双向 stdio」，不借 shell 后台命令、不借 MCP 的 `rmcp`。处理 `Content-Length` 帧、请求 id 对应、错误、取消、服务器反过来问的请求（`workspace/configuration` 回 settings；`workspace/applyEdit`、执行命令这类回明确不支持）、`initialize` / `initialized` / `shutdown` / `exit`。
3. **实例管理**：服务端持有一份；同一项目根、同一服务器配置、同一完整启动环境才共用一个实例，环境只在内存里比、不进日志和事件；给后面几件一个「为这个文件拿实例（没有就起）」的窄接口。照方案 4.3 和用户 10-29 的选择：最多 2 个实例；每 5 秒采样进程树内存，单个 4 GiB、合计 8 GiB 软上限，超了先回收空闲的、再停超限的并报原因；10 分钟没有真实同步或诊断请求就回收；`initialize` 最多 30 秒；没装或起不来报原因、60 秒退避；崩溃 5 分钟内最多自动重起 2 次，再不行就停住，等用户重试。
4. **不留进程**：复用 P2-28 的进程组和看护。正常停是 `shutdown` → `exit`，超时杀进程组；服务端停止和 `serve --replace` 时关掉所有实例；服务端被强杀时语言服务器进程组也被清掉。
5. **项目根**：按配置里的根标记找，限制在会话工作目录和加进来的目录里，规范化实际路径；同一个仓库的不同 worktree 不合并；找不到就报不支持，不拿整台机器当项目。
6. **计划和审查轮不起服务器**。
7. 报给用户和客户端的原因、错误一律写英文（canter 界面都是英文）。
