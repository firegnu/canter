### 意见

1. **建议改：受限模式下也自动跑 `git log`，而且没用现有的 git 加固。**
   - 位置：`crates/canter-core/src/suggestions.rs` `suggest_example`（153 行起）和 `git_example`（204 行起）。
   - 问题：用户在信任提示里选了受限模式，会话打开时服务端照样在这个目录里跑 `git log`。受限模式下钩子、LSP、记忆都关了（`hooks.rs:169`、`session.rs:2067` 等），这里是新增的一处在项目目录自动执行的程序。`git log` 会读项目自己的 `.git/config`；按 git 的行为，`log.showSignature` 打开时会调用 `gpg.program` 验签，也就是项目配置能让打开会话时跑一个程序。另外它用会话的完整环境，会读用户全局 git 配置；用户全局开了 `log.showSignature` 时，每次开空会话都会在后台调最多 30 次 gpg，靠 2 秒超时兜底。终端里现有的自动 git（状态栏行数、`/files`）走 `crates/canter-tui/src/git.rs` 的 `command()`，设了 `GIT_CONFIG_GLOBAL=/dev/null`、`GIT_CONFIG_NOSYSTEM=1`、`core.fsmonitor=false`、`core.hooksPath=/dev/null`、`--no-pager`；这里没照做。只读代码，没有构造仓库去验证。
   - 改法：不依赖 git 配置检查做得完美。`suggest_example` 开头加 `self.shared.runtime().context.restricted_mode` 为真就不出示例；`git_example` 照 `git.rs` 的 `command()` 设同样的环境和 `-c`，再加 `--no-show-signature`。
2. **建议改：没有客户端连着时也生成建议。**
   - 位置：`crates/canter-core/src/suggestions.rs` `start`（53 行起）。
   - 问题：用户在一轮跑着时关了终端，这一轮结束仍发一次建议请求，花钱但没人收到；`unused` 照样加一，会提前进入少出。
   - 改法：`start` 里没有订阅者就不出，比如 `state.journal.events` 的 `receiver_count() == 0`，或 `shared.clients` 的连接数为 0（后者要让核心测试先 `attach_client`）。
3. **可以不改：`fromSuggestion` 标记有边角。** 位置：`crates/canter-tui/src/app.rs` `key_on`、`take_suggestion_origin`。接受建议后把整段删掉重打，仍记「用了」（任务说改过也算，可以接受）；接受后按 Shift+Tab 切模式再发，标记被清掉，用了也不算。只影响少出计数。
4. **可以不改：`canter exec` 打开空会话也会起 git 示例。** 位置：`Session::subscribe` → `suggest_example`；`crates/canter/src/exec.rs` 先订阅后发输入。输入一到就取消、git 被杀；极少数情况下 git 先跑完，`--json` 输出会多一行 `seq: 0` 的 `session.promptSuggestion`。要处理的话，exec 输出时跳过 `is_ephemeral()` 的事件。
5. **可以不改：别的客户端 rewind 以后，本终端已显示的灰字不会清掉。** 位置：`app.rs` `apply_event` 只在收到建议时比对轮 id，`visible_suggestion` 不再比对。本机的按键（打字、Esc、`/rewind`）都会先清掉灰字，只有多个客户端时才会遇到。改法：`SessionRewound`、`TurnRetracted` 时清掉 `suggestion`。
6. **可以不改：进入计划模式、rewind、切模型时不取消在跑的建议请求。** 回来时不会发出去，只是多花一次请求的钱。建议请求自己因长度停下（`Finished(Length)`）时没单独判断，可能发出半句；主线 `max_output_tokens` 很大，基本遇不到。
