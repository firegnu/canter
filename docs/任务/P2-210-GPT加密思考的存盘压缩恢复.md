## 要做成什么

用 GPT（`"api": "responses"`）的会话：

1. **跨轮、重启、`--resume`**：历史里某条 GPT 输出带着存盘的 replay，只有当这次请求发给**同一个模型、同一个 ChatGPT 账号**时，才原样发回它的输出项（含加密思考）；否则照现在用普通文字。replay 要记下是哪个账号生成的；会话文件里不存账号原文 id，存一个推不出原文的标识。P2-210 之前存下的、没有账号标识的 replay 当作「不同账号」，用普通文字。
2. **压缩**：发去做总结的请求（`prefix` 和 `transcript` 两种）按第 1 条的规则带上 replay，开头和上一次对话请求尽量逐字节一样，能命中缓存。压缩完成后，被压掉那段历史里的 replay 跟着一起丢掉，之后只剩总结。
3. **辅助请求**（下一句建议、顺口问 `/btw`、交接）：发给同一个模型、用的是同一段会话历史的，按第 1 条的规则带上；发给别的模型的照现在不带。子 agent 和 fork 不另立规则，各自的请求同样按第 1 条判断。
4. **被拒收**：GPT 因为发回的加密内容不认（解不开、过期、不属于这个账号这一类）拒绝请求时，同一个请求去掉 replay、换成普通文字自动再发一次，服务端日志写一行英文原因（不写密文和错误原文），用户不用管；之后这个会话不要每次请求都再被同一批密文拒一次。「被拒」要按服务器给的错误类型认，依据写进完成记录（比如 Codex 源码里怎么认）；认不准就停下问主控，不要按错误文字猜。
5. 回传白名单：用户 11-04、11-05 真调的日志里，公开接口只在 reasoning 项上给过 `encrypted_content`，message、function_call 项上没有、也没有 `encrypted_function_args`。核对 Codex 源码，结论写进完成记录；只有确认公开接口会返回、也支持回传时才加进白名单。
6. 上下文估算和 `/context` 照现在只算普通内容：密文不按字符长度算成 token，同一段内容不重复计。
7. 旧版 canter 读到新版存的会话不出错（新加的字段旧版忽略也能用）。
