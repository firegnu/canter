1. **`context` 改成进度条**：写成 `█████░░░░░ 186k/400k (46%)`。
   - 10 格，满 = 压缩线（服务端发的 `autoCompactTokens`）；拿不到压缩线时（旧服务端）满 = 窗口。

   - 已用的格 `█` 和百分比按离满还剩多少变色，照 P2-113 的 `bar_room`（剩 ≥50% 绿、20%～50% 黄、<20% 红）；空格 `░` 和 `186k/400k` 灰。不带颜色时照旧能从 `█`/`░` 看出多少。
2. **去掉 `compact` 项**：`/statusline` 列表里没有它了；`tui.json` 里存着的 `compact` 照「不认识的项跳过」处理，不报错。
3. **git 改动行数**：新项 `diff`，默认显示，放在 `branch` 后面（旧 `tui.json` 里没有时照 P2-113 补 `compact` 的办法补在 `branch` 后面、勾着）。
   - 写成 `(+120,-8)`：`+120` 绿、`-8` 红、括号和逗号灰；干净时 `(+0,-0)`。
   - 数的是工作区和暂存区相对 HEAD 加删的行数（`git diff HEAD --numstat` 那种），二进制文件不计行，未跟踪的文件不算；还没有提交的新仓库照暂存区算。
   - 不在 git 仓库里、git 出错或超时时这项不显示。
   - 照 `git.rs` 现成的办法跑：只读、关掉外部 diff、textconv 和会起程序的过滤器、有时间上限，不在画面线程里等，不会卡住打字和画面。
   - 什么时候重算：打开会话、换工作目录、每轮结束、`!` 命令跑完、每次工具调用结束；空闲时每 5 秒一次（接住在编辑器里改的）。上一次还没跑完不再起新的。
4. **状态栏脚本的 JSON**：加 `gitDiff: {"added": N, "removed": M}`，拿不到时 `null`；`context` 里已有的字段不动。
