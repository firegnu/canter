### 对完成记录里取舍的表态

- 显式 `timeoutMs: 0` 立即超时：同意。Codex `ThreadShellCommandParams.timeout_ms` 注释原话是「zero requests an immediate timeout, not unlimited execution」；终端不传 `timeoutMs`，只影响别的客户端。显式值没有上限，tokio 的 `sleep` 对超大值封顶，不会 panic，Codex 也不设上限。建议 DESIGN 写一句（第 3 条）。
- `agent` 不写出：同意。已有命令项目的序列化逐字节不变，旧读者本来就不认这个字段，新读者省略按 agent；Schema 里 `source` 不在 required，TS 是 `source?:`，DESIGN 写了「省略按 agent 读」。
- 命令轮不参与「模型没开口就撤回」：同意。撤回把这一轮从快照里整个拿掉、不留记录，而命令已经真跑过、可能改了文件，拿掉会让人看不出跑过什么；要退对话用 `/rewind`，它留记录轮。服务端在同一把锁里判断，终端照普通打断处理，测试覆盖了。
- 命令跑着时的普通插话排到下一轮：同意，和压缩轮一致，命令轮没有模型循环来吃插话。问题只在 Esc 停命令时这些排队消息会丢，见第 1 条。
