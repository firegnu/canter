# 任务：去掉输入框上方的常驻任务清单

依据：模型用 `update_plan` 列了清单后，终端在状态行下面、输入框上面常驻最多五行没做完的步骤（P2-34）。用户觉得不需要，清单给模型自己用就够了。Codex 只在对话里出「Updated Plan」卡片，输入框上面没有常驻清单。本轮只去掉常驻显示，`update_plan` 工具、提醒、压缩时带清单、对话里的进度卡片都不变。
依赖：P2-279

## 用户原话

- 11-11：「canter tui现在做什么任务喜欢再最下面加一个任务todo list。我理解这个不需要，canter自己知道就行了。我记得codex和claude code都没有这个玩意。你觉得呢？」
- 主控答：Codex 有同样的工具，只在对话里出卡片；Claude Code 据主控所知干活时也显示清单。建议工具留着（对模型有用），只去掉输入框上面常驻的那几行。用户：「写个任务单，等279做完再派」

## 要做的

1. 终端界面不再在状态行下面、输入框上面显示常驻的未完成步骤（包括 `… and N more`、` (+N more)` 那两种写法）。那几行空出来还给对话。
2. 对话里每次成功更新出的进度卡片照旧，往上翻能看到；导出照旧保留每次的清单卡片。
3. `update_plan` 工具、工具说明、十次提醒、Stop 时的待办提醒、压缩时附 `[Current plan]`、`plan_enabled` 开关、协议和服务端都不变。
4. DESIGN 第 8 条 P2-34 那句「状态行下面、输入框上面最多五行未完成步骤…」改成现在的样子，写明 11-11 用户去掉了常驻显示。

## 不要做

- 不改模型能看到的任何东西（工具、说明、提醒、压缩），不改服务端和协议。
- 不另加开关，不把常驻清单挪到别处（比如状态栏、底部活动行）。
- 不改进度卡片的样子。
