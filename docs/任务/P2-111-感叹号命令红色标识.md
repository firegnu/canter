- 做了什么：`theme.rs` 加 `shell()`（终端 16 色里的红色，`Color::Red`）。输入框按 Enter 跑命令的同一个规则（`full_text()` 去掉开头空白后以 `!` 开头）判断，是 `!` 命令时边框用 `shell()`、草稿里开头那个 `!` 也用 `shell()`，其余字照旧；搜索框开着时不算。对话里用户跑的命令卡片，`!` 不再和命令一起交给 Bash 语法上色（原来被上成品红），改成单独一个红色 `!` 加空格放在命令前面，命令照旧上色；模型跑的卡片、等批准的卡片不动。从历史画卡片走同一段代码。`/export`、协议、存盘、`!` 的发送和运行都没动。
- 验证了什么：`tests/user_shell.rs` 加两个 `TestBackend` 画面测试——输入 `!ls` 边框角和 `!` 是红色、`l` 不是，Home + Delete 删掉 `!` 后都变回；输入 `ls` 都不是红色；会话里一张模型跑的、一张用户跑的 `git status` 卡片，用户的 `!` 是红色，两张卡片上 `git status` 每格的字和样式一样，模型那张没有 `!`。两个测试先跑确认失败（边框 Reset、`!` 是 Magenta），实现后通过。`cargo nextest run -p canter-tui`（494 个全过）、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`、`git diff --check` 都过。
