### 重点逐条

- **重点 1（能不能写文件、起程序）**：没发现漏洞。
  - GNU 和 BSD 都对过了。GNU 源码的短选项串：sort 是 `-bcCdfghik:mMno:rRsS:t:T:uVy:z`，uniq 是 `-0123456789Dcdf:is:uw:z`；macOS 的 sort（2.3-Apple）、uniq 看 man 和实际运行结果。放行的短选项 `bcCdfghiMmnrsuVz`、`cdiu` 在两种实现里都不带值，`k`、`t`、`f`、`s` 都带值，和解析器一致。会写文件或起程序的只有 `-o/--output`、`--compress-program`、`-T/--temporary-directory`；会读别的文件的只有 `--files0-from`、`--random-source`。这些都不在白名单里，在组合短选项里（`-uo`、`-cfo`、`-mo`、`-nroout`）、写在文件后面（`sort file -o out`）、写成 `=` 形式或长选项缩写（`--out=`、`--o=`、`--comp=`、`--files0=`），都要问。
  - 长选项缩写：解析器只认完整的名字，而 getopt_long 遇到完整名字时优先精确匹配，所以缩写不可能落到危险选项上。放行的每个长选项名在 GNU 和 BSD 两边都真实存在，参数类型也一致（`check` 可带可不带值，`key`、`field-separator`、`skip-fields`、`skip-chars` 必须带值），不会出现「这边不认、被当成另一个选项缩写」的情况。
  - 值吞掉下一个参数：`sort -t -o out` 会放行，但 getopt 同样把 `-o` 当成 `-t` 的值。本机实测报错 `-o: Invalid argument`，GNU 会报 multi-character tab，都不写文件。`uniq -f -c out` 同理，报数字无效，`out` 也只会被当成输入。
  - uniq 的输出文件：本机实测 `/usr/bin/uniq in.txt -c` 和 `/usr/bin/uniq in.txt --` 真的分别写出了名为 `-c`、`--` 的文件。GNU 在设了 `POSIXLY_CORRECT` 时也一样（`uniq.c` 里的 `posixly_correct && nfiles != 0`）。代码要求唯一的输入文件必须是最后一个参数，这类写法都要问；`uniq a b`、`uniq -- -- file`、`uniq file ''`、`uniq file -` 也都要问。
  - 环境变量：两种实现都没有能让 sort/uniq 起别的程序的环境变量。macOS man 里只有 locale、`TMPDIR` 和两个 `GNUSORT_*` 兼容开关。
  - 管道、重定向、`&`、`env sort`、`command sort`、`/usr/bin/sort`、`TMPDIR=x sort`、`| tee`、`| xargs` 都要问，和 P1-9 一样。
- **重点 2（受保护路径）**：挡住了。sort/uniq 用的是和 cat 相同的参数解析，每个参数和选项值都按当前可能的 cwd 查。实测这些都要问：`~/.CANTER/…`、`../.canter/…`、`cd .. && sort .canter/…`、`cd ~ && uniq .Canter/…`、`cd sub && sort ../../.canter/…`、`--` 后面的路径、`--key=1 ~/.canter/…`、`-s1 ../.canter/…`、反斜杠写法 `~/.c\anter/…`、`"$HOME/…"`、引号里的 `~`、`~/repo/../.canter/…`、目录本身 `~/.canter`、`cd ~/.canter && sort config.json`、`sort -m a <受保护文件>`。P1-9 审查抓到的几类（大小写、cd 用字面路径、递归读父目录、git 配置）这次都没有重新打开：sort/uniq 不递归，不走 git 分支，路径和 cd 的检查都是共用的原代码，这次没改。`find .. \( -name config.json \) | sort` 会放行，但只列出文件名，和 P1-9 定下的 `find ~` 放行一致，不是新问题。
