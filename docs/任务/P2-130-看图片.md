## 要做的

1. **`read` 读图片**：读到 JPEG、PNG、GIF、WebP（按内容识别，和 P2-5 一样）时，不报错，把图交给模型；别的二进制文件照旧报错。`read` 的工具说明加一句能看图片。批准和受保护路径照 `read` 现在的规矩。
2. **MCP 图片**：MCP 返回的图片交给模型。同一个结果里的文字照旧。MCP 的其它内容：内嵌资源是文字的照文字交给模型；服务只给 `structuredContent`、不给文字时，把它当 JSON 文字交给模型；音频等照旧占位（这几样做的时候查清，写进完成记录）。
3. **怎么交给模型**：DeepSeek 只收 user 消息里的图片，所以工具结果里写一句英文说明（比如图片在下一条消息里，带图片名），这批工具结果后面紧接着补一条带图的 user 消息。照第 17 条只往后加。具体写法你定，写进完成记录和 DESIGN。
4. **存和上限**：走 P2-5 那套：图片存进会话目录（0600），每张 8 MiB 上限，超了不交图、结果里写明；历史里图片的 40 MiB 预算、换到不收图片的模型时的文字占位、估上下文每张 1024 token，都照旧。压缩、回退、撤回、从历史打开会话、导出都照 P2-5 对用户图片的处理。
5. **界面**：工具卡片上一行写图片名、格式、大小，终端里不画图；从历史打开会话、另一个终端打开同一个会话看到的一样。
6. **协议和文档**：工具结果带图怎么给客户端照 Codex app-server 的结构定，和 Codex 不同的写进 DESIGN 第 8 条；`crates/canter-tools/README.md` 跟着改。旧客户端、旧会话照旧能用。
