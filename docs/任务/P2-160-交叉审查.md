### 五个重点

1. **文件锁：没问题。**
   - `SessionWriter` 的 `unlock` 只在 Drop 里；写入是无缓冲的 `write_all` 加 sync，放锁时没有没落盘的数据。`SessionWriter`、`Lease` 都不能 Clone，代码里没有 `try_clone`、`mem::forget` 或取走 fd 的地方，不会在拥有者还要用时放锁。flock 的解锁只作用于本进程这一个打开的文件描述，放不掉别的写者或别的服务端的锁，所以也不会让两个同时拿到。
   - `Lease` 的 Drop 仍是先删 `server.json` / `server.sock` / `replace.json` 再放锁，和原来关文件放锁的顺序一样，后来的服务端拿到锁时这些文件已经删了。`server_running` 只在拿到共享锁（说明没有服务端）之后放自己的探测锁。
   - macOS：flock 语义一样，没有并发 fork 时和原来"关文件即放锁"效果相同，只是去掉了 fork 竞争那个窗口。
   - 继承的来源核对过：`guardian.rs` 的中间进程在两次 fork 之间、`wait_ready` 期间不 exec，会短暂持有服务端全部 fd；显式解锁是对的修法。
2. **杀进程组：没问题。** dash 的 kill 解析完 `-KILL` 后把下一个参数直接当 pid，`--` 会报非法数字，所以原写法在 dash 上杀不了；bash 的 kill 只把第一个 `-xxx` 当信号，后面的 `-<pgid>` 当进程组（bash 源码注释明说）。`$1` 是命令进程自己的 pid（`process_group(0)` 后就是 pgid），看护进程自己 `setpgid(0,0)` 另成一组，杀不到自己。实测见上。没验 Alpine 的 busybox ash（不在本次重点；P2-260 若在 Alpine 题目容器里跑，可以在那边顺手看一眼）。
3. **Linux 沙箱开着时：没有悄悄不隔离的路径。** 沙箱开着时 `LocalExecutor.sandbox` 是 `Some(Err(提示))`：
   - 模型 shell 的前台、后台、转后台、带 `sandboxRequest` 的，都走 `launch(sandboxed = true)` → 失败；`check_sandbox_request` 也失败。
   - read / write / edit / apply_patch / 删除走 `resolve_path` / `resolve_write_path` → 失败；ast_grep 不给 path 时先把 cwd 补成 path 走 `resolve_path`，每个文件再过一次；图片和 PDF 先 `resolve_path`；记忆的写和改走同一套。
   - 子 agent 的执行器在 `canter-core/src/session.rs:2298`、`configuration.rs:412` 同样用 `with_sandbox(...)` 建，和父会话一样被拦。doctor 报 Fail。
   - 不在沙箱里的：用户 `!`（只有 `ExecCommandSource::UserShell` 走 `spawn_user`）、MCP、web_fetch、LSP、钩子、提示建议里那条固定的 `git diff`。这些在 macOS 上也是设计上就在墙外（DESIGN 沙箱一节），不是 Linux 特有。
4. **缺 CA：没问题。**
   - 按文字识别：核对过锁定版本的源码。rustls-platform-verifier 0.7.1 `src/verification/others.rs:106` 返回 `rustls::Error::General("No CA certificates were loaded from the system")`，rustls 0.23.46 `src/error.rs:1010` 显示为 `unexpected error: {err}`，和代码里比对的字符串一致；这段只在非 Apple 的 unix 上编译，macOS 走不到。认不出时退回 `cannot initialize catalog HTTP client: …`，同样退出 1、不 panic。
   - `http.rs` router 新加的 `expect`：只有 `App.reload` 是 None 时才走到。生产里唯一构造 `App` 的地方是 `lib.rs:133`，`reload: Some(...)`，所以生产走不到，只有测试的 App 会走。
   - `serve --replace`：`lifecycle.rs:146-148` 的预检在写 `replace.json` 之前，失败用 `?` 直接返回；上面实测确认旧服务端不受影响。
5. **测试：没有为了过而放宽。** diff 里去掉的测试属性 0 个、新增 4 个；没改超时（shell 测试的 `timeoutMs` 600 / 300 原样）。新加的 macOS 限定都是测 Seatbelt 探测、Seatbelt 下的记忆目录、`sandboxRequest`、launchd 本身的。macOS 上原来开沙箱跑的测试仍开着跑。`/bin/bash -c` 包一层：macOS 的 `/bin/sh` 本来就是 bash，语义不变；dash 没有终端时 `set -m` 不开作业控制，是测试脚本的真实平台差异。两处把屏幕文字合并空白再比，是终端折行位置随临时路径长度变，比的整句没变。macOS 覆盖唯一的减少见建议改 1；Linux 上有一条变得测不到要测的东西，见建议改 2。
