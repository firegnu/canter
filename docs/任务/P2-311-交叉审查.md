### 四个重点的结论

1. **安全**：没找到能读到仓库外内容或让读取卡住的路子。
   - 根目录从 `/` 起逐级 `openat(O_DIRECTORY|O_NOFOLLOW)`，每个文件的父目录也逐级这样打开，只接受 `Component::Normal`，遇到 `..`、`.`、绝对路径都报错。git 给的根是物理路径：测试目录在 `/var/folders` 下（`/var` 是符号链接），测试照样过。万一给的不是物理路径，结果是全部打不开、按读不了处理，也不会跟着链接走。
   - 最后一级先 `statat(SYMLINK_NOFOLLOW)`。符号链接只做 `readlinkat`；普通文件才 `openat(NOFOLLOW|NONBLOCK)`，打开后再 `fstat` 确认一次是普通文件。如果 stat 和 open 之间被换成符号链接，open 会报 ELOOP；换成 FIFO，因为带 NONBLOCK 不会卡，随后被 fstat 拒掉。git 本来也不列 FIFO（临时仓库里试过）。
   - 引号路径：`unquote` 照 git 的 C 风格转义还原；碰到认不出的转义就退回原串，结果只是找不到文件。还原出的路径照样要过上面的逐级检查。
   - 测试里 `link -> ../outside` 只输出 `+../outside`，没有 outside 的内容。
   - 能读到仓库外文件的情况只有两种：仓库里有指向外面的硬链接，或者 `.git/config` 用 `core.worktree` 把工作区指到别处。这两种 git 自己也一样会读。要做到这两点，得先能写仓库或 `.git`；远程令牌本来就能让 agent 跑命令。所以不算新增的泄露途径，不单列意见。
2. **兼容**：
   - 不带参数或传 false 时，diff 仍走 `git::local`。改动只是把取根目录和取列表拆成了两个小函数，git 命令、执行顺序、错误文本都没变。
   - summary 的新分支直接返回 None，新键被 `skip_serializing_if` 去掉，JSON 和改前一致。
   - `WorkspaceDiff` 原有的四个字段都是单个小写词，加了 `rename_all = "camelCase"` 后名字不变。
   - 终端只用路由常量，不发新参数；`/review` 仍调 `git::local`。protocol 的往返测试覆盖了缺省、null、0 三种情况。
   - 唯一的新行为：`/diff?untrackedContent=<不是布尔值>` 现在返回 400，和 summary 现有参数的处理一样。旧客户端不发这个参数，不受影响。
3. **预算和超时**：
   - 计数时每次最多读剩余预算那么多（`limit.min(*remaining)`），缓冲 16 KiB，只为 diff 留不超过剩余 256 KiB 的前缀，不会把整个文件读进内存。正好读满预算时，用 fstat 拿到的长度判断有没有读完，不多读一个字节。
   - 超时后外层 future 被丢掉，`drop_guard` 取消令牌，阻塞线程在处理下一个文件之前退出；最坏把手上这一个文件读完，总量不超过剩余预算（≤ 8 MiB）。summary 的 2 秒超时也是这样。
   - summary 里两种行数并行算，总时长仍在 2 秒左右。git 子进程照旧 `kill_on_drop`。
4. **正确性**：
   - 在临时仓库里和 `git diff --no-index /dev/null`、`--numstat` 逐项对照，形状和行数都一致（只少了 `index` 行，任务书要求不写）。对照的情况有：带空格的路径（git 在 `+++ b/sp ace` 后加一个 tab，代码也加）、要加引号的路径 `diff --git "a/…" "b/…"`、非 ASCII 文件名的八进制转义、单行的 `@@ -0,0 +1 @@`、两行且末尾无换行、符号链接（`120000` 加无换行标记）、空文件只有两行头。
   - 二进制只看前 8000 字节里有没有 NUL，和 git 一样。
   - diff 截断时，前缀可能断在一行中间。但渲染出来的字节一定多于剩余预算，会先触发截断，不会补出一个假的「No newline」标记。
   - `untrackedFiles` 只取列表里带换行的完整行；列表被截断时 summary 返回 null。这两点都有测试。

### 意见

1. **建议改**：`crates/canter-server/src/workspace/untracked.rs:88-95`，还有协议 README「会话工作区只读查询」一节新加的第三条。
   - 问题：只要有一项读不了（`read_file` 出错），diff 就直接置 `truncated: true`，这一项和它后面的所有项都不再出现在 `untrackedDiff` 里，哪怕预算还剩很多。git 会把嵌套仓库列成 `nested/`：临时仓库里列出来的是 `a.txt`、`nested/`、`z.txt`。它是目录，一定读不了，于是 `z.txt` 不在 diff 里。没有读权限的文件（git 照样列出）、列出后被删掉的临时文件，也会这样。结果是：工作区里只要有一个没被忽略的嵌套仓库，`untrackedDiff` 每次都断在它那里，`untrackedLines` 每次都是 null。README 只写了「读不了时 lines 为 null」和「计数超预算时截断」，没写读不了也会让 diff 截断，rein 会当成预算用完了。
   - 改法（交主控定）：diff 里跳过读不了的项，接着处理后面的文件，`truncated` 只表示预算用完；这一项的逐文件记录照旧 `lines: null`。summary 维持任务书写的「读不了给 null」。如果希望有嵌套仓库时也能拿到总数，得另外定一条「以 `/` 结尾的目录项不计入」，这算改需求，要问用户。最少也要把现在的行为写进 README。
