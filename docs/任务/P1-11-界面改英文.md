# 任务：canter 自己写的字改成英文

依据：用户 10-24 用了装好的 P1-9 版本后提的。终端界面、命令行、服务端和核心里 canter 自己写给人看、写给模型看的中文都改成英文；模型的回答不管，代码注释和 `docs/` 里的文档不改。
依赖：P1-9
执行：派出

## 用户原话

- 「还有一个问题，不需要中文，改成英文（我说的是类似 “工作中” 这种，而不是输出）。理解我意思吧？」（附截图：`等你批准`、`跑`、`思考：`、批准框「要跑这条命令吗？」、四个选项和说明、`目录：`、底下的操作提示、状态栏的「每次问」）
- 主控问范围，用户 10-24 选：「用户看得到的都改」（终端界面、`canter --help` 和命令行报错、服务端发到界面上的错误和提示、核心发的 warning）；给模型看的内部提示「也改英文」（如「[本轮被打断；尚未完成的操作没有继续执行。]」「[上下文摘要]」、工具结果里的「没有结果：被打断」）。

## 在哪里干活

- worktree：`../canter-worktrees/p1-11-english`，分支 `p1-11-english`（派的时候从 main 建）。

## 现在怎样

带中文字符串的源文件（`grep -rlP '[\x{4e00}-\x{9fff}]' crates/*/src`）：`canter-tui`（约 90 行）、`canter-server`（约 60 行）、`canter`（约 10 行）、`canter-core`（约 13 行）、`canter-tools`、`canter-model` 各 1 行。系统提示词和工具说明已经是英文。

## 要做的

- 上面这些地方给人看和给模型看的字都改成英文：短、直白，和常见 coding agent 的说法一致（例如 Working、Waiting for approval、Run、Thinking）。
- 界面排版、按键、行为都不变；英文变长的地方照现有的截断和换行规则走。
- 测试里断言中文文字的、`crates/canter-tui/tests/expected/replay.txt` 这类期望输出，跟着改成新文字，断言的意思不变、不删。
- 代码注释、README、`docs/` 不改；测试里模拟用户或模型说中文的输入不改（那是「输出」，不是 canter 的字）。

## 怎么算做完

- （待用户给验收原话。主控建议：在 `ink-sample` 里开 `canter`，界面上、批准框、状态栏、`canter --help` 看不到中文，模型的回答照常。）
