P2-180 子 agent 的钩子和统计

3 个问题，橙框是主控的推荐。钩子是 P2-153 做的全局钩子（~/.canter/config.json 的 hooks）；统计是 canter stats <会话 ID>。

主控的推荐，一句话版
  1. 子 agent 里干的活照常触发工具类钩子，并标明「这是哪个子 agent」；子 agent 的一轮结束发 SubagentStop，不发 Stop。
  2. 新加的 SubagentStart、SubagentStop 只通知，不能拦、不能改子 agent 的行为（和现在的 Stop 一样）。
  3. canter stats <主会话> 的总花费把子 agent 算进去，下面加一节 Sub-agents，每个子 agent 一行。

1. 子 agent 里干活时，现有的钩子怎么触发

子 agent 是带父会话标记的普通会话。现有 9 个钩子事件在它身上怎么发？

A. 照 Claude Code：工具类照发并标来源，结束换成 SubagentStop推荐

事件在子 agent 里
PreToolUse / PermissionRequest / PostToolUse照常发；stdin 多 agent_id、agent_type（explorer / general）、parent_session_id。比如「改完文件跑 cargo fmt」对子 agent 改的文件也生效。
UserPromptSubmit只在你自己在子会话一屏里打字时发；主 agent 交给它的任务、send_input 不发（属于自动输入，和现在目标续跑、后台叫醒一样）。
Stop / StopFailure / Interrupt不发，换成 SubagentStop（见下）。所以「每轮结束响一声」的 Stop 钩子不会因为子 agent 响一堆。
SessionStart / SessionEnd不发：子 agent 不算一个会话的开始和结束，换成 SubagentStart / SubagentStop。

新增两个事件：

事件什么时候stdin 多的字段
SubagentStart主 agent 开出一个子 agent，它开始第一轮前agent_id、agent_type、task
SubagentStop子 agent 的一轮结束（做完、失败、中断、被停掉）agent_id、agent_type、status、last_assistant_message

B. 子 agent 当普通会话，全部照发

  • 9 个事件在子会话里全部照普通会话发，只加 SubagentStart / SubagentStop 两个新事件。
  • 改动最少；但 Stop、SessionStart/End 会因为子 agent 多发很多次，钩子脚本分不清是主会话还是子 agent，除非自己去读会话文件。

2. SubagentStart、SubagentStop 能做什么

A. 只通知推荐

  • 和现在的 Stop、SessionStart 一样：异步跑，不让子 agent 等，结果不影响它。
  • 够用来记日志、发提醒、统计子 agent 开了几个。

B. 照 Claude Code 能改行为

  • SubagentStart 的输出可以往子 agent 的上下文里加一段话。
  • SubagentStop 可以拦下，让子 agent 不许停、接着干（附原因）。
  • canter 现在的 Stop 也不支持拦下接着干（P2-153 没做），只给子 agent 做会不一致；要做得同时想清楚和 wait_agent、叫醒、花费上限怎么配合。
