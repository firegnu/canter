## 要做的

1. **监听**：
   - `config.json` 加 `remote.listen`（地址列表）。不写就不开 TCP，和现在一样。
   - 第一版只允许回环地址（`127.0.0.1`、`::1`），别的地址一律拒绝，提示写 "remote.listen accepts loopback addresses only; put an HTTPS proxy such as Caddy in front of it"。
   - 不放 Tailscale 地址（用户 11-14 改了调研第 6 节第 2 件）。
2. **同一套接口**：TCP 挂同一个 `router`。认证只套在 TCP 那一路上，unix socket 照旧不要令牌。
3. **认证是所有 TCP 请求的第一关**：
   - 用 `Authorization: Bearer <令牌>`。
   - 没带令牌或令牌不对，直接回 401，错误码 `unauthorized`，不做别的任何处理。
   - 令牌不放网址里。日志只记客户端名，不记令牌。
4. **令牌**：
   - 在服务端机器上跑 `canter remote token add <客户端名>`，打印一次随机 256 位令牌；另有 `canter remote token list`、`canter remote token remove <名>`。
   - 不提供协议接口来发令牌。
   - 存 `<CANTER_HOME>/remote-tokens.json`，权限 0600，每条 `{name, sha256, created}`，不存明文，比对用常量时间。
5. **撤销**：
   - 令牌文件变了，服务端在下一个请求时重读。
   - 撤掉的令牌，新请求立刻被拒；它已经开着的 SSE 流主动断开。
6. **断线**：给 TCP 连接开 keepalive。
7. **换进程**：`canter serve --replace` 换进程时，新进程要能接上同一个端口，不因为端口冲突起不来。
8. **判断不了的时候**（主控提议，用户 11-14 同意）：
   - 包括令牌文件坏了或读不了、`remote.listen` 写错、端口被占这类情况；
   - 处理办法：TCP 那一路全部拒绝或者干脆不开；unix socket 和服务端照常起来，本机照常用；
   - 原因写进日志，`canter doctor` 里显示 TCP 监听状态（开没开、为什么）和令牌条数。
9. **文档**：
   - DESIGN 第 2 条（一台服务端只服务一个人）、第 15 条（本机 TCP 端口加令牌、不做 TLS、经自建中转）主控 11-16 已改好。实现和它对不上的，按实现补准细节；要改意思的，停下来问主控。
   - 协议 README 加 TCP 和认证一节，写上错误码 `unauthorized`。
