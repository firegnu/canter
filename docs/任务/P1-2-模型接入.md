## 要做的

### 各家通用的一层

以后加 OpenAI Responses 接口时，这一层不用改。

- **消息类型**：系统提示词、用户的话、模型的回复（文字、思考内容、工具调用）、工具结果（对应哪个工具调用 id、回给模型的文字）。工具调用的参数原样保留成字符串，不在这一层解析，参数不是合法 JSON 也照样保留。
- **这些消息类型要能存盘**：第 4 件会把它们原样写进模型历史（DESIGN 第 13 条）。所以要能序列化、反序列化；以后新增的消息种类，旧版本读到要能跳过，不能整个读失败（`#[serde(other)]` 兜底或带版本，你定）。
- **工具清单**：每个工具有名字、说明、参数的 JSON Schema（`serde_json::Value`）。本包不依赖 `canter-tools`。
- **请求**：模型名、消息、工具清单，加上第一期用得到的少量选项（比如思考开不开，照 DeepSeek 文档定）。
- **流式收回**：文字增量、思考内容增量、一个完整的工具调用（id、名字、原样参数）、用量、结束原因（正常结束、要调工具、被截断、其他）。
- **错误分类**：能重试的（限流、服务端错误、网络、超时）、上下文超长（第 4 件靠它触发压缩）、认证失败、请求不对、其他。
- **取消**：调用方给一个取消信号（用 `tokio-util` 的 `CancellationToken`，P1-3 也用它），取消后立刻停下，不再往外吐东西。
- **重试**：能重试的错误自动重试，退避加上限，有 `Retry-After` 就照它。**只在还没往外吐任何东西时重试**；流到一半断了，返回错误，由调用方决定。

### Chat Completions 接口（DeepSeek）

- `POST {base_url}/chat/completions`，`stream: true`，带上取用量的选项。
- 流里的工具调用是一段一段来的，按序号拼成完整的工具调用。
- 思考内容走 `reasoning_content`；思考模式下带工具调用时，思考内容要不要回传、怎么回传，照 DeepSeek 文档做，写进完成记录。
- base_url、API key、模型名由调用方传进来，本包不读配置文件、不读环境变量（配置是第 5 件）。所以别家的兼容接口也能接，但第一期只对 DeepSeek 负责。
- **API key 不外泄**：放在不会被 Debug、Display 打印出来的类型里；错误信息、日志、测试快照里不带 key，也不带请求头。

### 拿主意的地方

- 对外接口：`Model: Send + Sync`，`stream(Request, CancellationToken) -> ModelStream<'_>`；流是 `Send` 的 `Stream<Item = Result<ModelEvent, ModelError>>`，可以用 `dyn Model` 注入假模型。`ChatCompletions::new(&str, ApiKey)` 建客户端；`Request` 只有模型、历史消息、工具和选项，选项为 `thinking: Option<bool>`、`max_output_tokens: Option<u32>`。HTTP/wire 类型全部私有；第 4 件接入细节见 `crates/canter-model/README.md`。
- 存盘类型：`Message::{System, User, Assistant, ToolResult, Unknown}`；助手内容为 `AssistantContent::{Text, Reasoning, ToolCall, Unknown}`。两者都用 `type` 标签、snake_case 和 `#[serde(other)]`，未知种类读成 Unknown 并在发请求时跳过，不保留未知字段。工具参数使用 `String`。核心须保存原始思考内容，等到 `Finished(ToolCalls)` 再执行工具；流中错误或取消时不得执行这一批工具。
- DeepSeek 思考内容：按 2026-10-24 阅读的[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，带 `tools` 的后续请求必须回传所有历史助手消息的完整 `reasoning_content`，包括没有调工具的轮次。适配器原样串接 `Reasoning` 片段并回传，不删除旧轮次；没有工具时仍保留字段，由服务端忽略。开关映射为 `thinking.type = enabled/disabled`，不自行覆盖模型或设置采样参数。
- 用量按当前[官方流式接口](https://api-docs.deepseek.com/api/create-chat-completion/)处理：与最后一个非空 choices、带结束原因的 chunk 同帧到达；同时可读取兼容接口单独的 usage-only chunk。[错误码](https://api-docs.deepseek.com/quick_start/error_codes/)据 HTTP 状态分类；400/422 的上下文超长另识别 `context_length_exceeded` 等代码及 maximum context length 等说明，不把原文放进错误。连接超时 30 s、每次网络读取超时 300 s。
