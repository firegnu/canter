### 核过的（已查证，附依据）

1. **令牌和密钥不外泄**：没找到正常使用下会外泄的路径。
   - canter 出错时一律给固定文字（`map_err(|_| …)`），rmcp 的报错原文进不了日志、`/v1/mcp` 和命令行输出。
   - canter 没装 tracing 订阅者（全仓库搜不到 `tracing_subscriber`），rmcp 里打印授权码和换令牌结果的 `debug!` 不会落地。
   - 脱敏名单和服务端共用：读令牌文件、存新令牌时把 access/refresh token 和客户端密钥加进去，在请求发出前生效。工具结果、structuredContent、工具说明、schema（键和值）、`/v1/mcp` 的工具名都过 `public()`。
   - 现有测试 `oauth_runtime_refreshes_redacts_and_logout_stops_authentication` 断言事件、模型请求、`/v1/mcp`、会话目录、`server.log` 里都没有测试令牌。
   - 权限：`mcp-auth/` 是 0700，令牌文件和锁文件是 0600（本机实测 `mcp-auth` 是 `drwx------`）。`mcp-auth/` 在状态目录里，shell 碰它要批准的规矩和 `config.json` 一样。
2. **配置文件不写坏**：在隔离目录用编出来的程序实测过。
   - 现有 `config.json` 带 `api_key`、0644 权限、没有 `mcp_servers`：`add` 之后别的字段一个字节没变，文件变成 0600；重名报错，文件不变。`remove` 之后变成 `"mcp_servers": {}`。
   - 新插进去的那段缩进不整齐（`"api_key": …\n,\n  "mcp_servers"`），但 JSON 是合法的。
   - 服务端只读 `config.json`（全仓库查过写它的地方），命令之间靠 `config.lock` 排队，所以不会丢内容。
3. **登录流程安全**：
   - 回调只绑 `127.0.0.1:0`，在动态注册之前就绑好。
   - 回调里 `state` 只能出现一次，而且要和授权网址里的一致；不对的回 400 接着等，本机别的进程没法打断登录。
   - PKCE 用 S256，测试核了 challenge 和 verifier；服务器声明了 RFC 9207 时会核 `iss`。
   - 浏览器里点拒绝、超时、没有 `registration_endpoint`，都报固定文字退出，不写令牌。
   - 令牌按 URL 原串绑定，地址变了 `read()` 就返回空。
4. **服务端连接**：
   - 有令牌时带上，过期前 30 秒内会主动续（rmcp 的 `REFRESH_BUFFER_SECS`）。
   - 续被拒（`invalid_grant`）时，rmcp 改成不带令牌发出去，收到 401 后走 `AuthRequired`，只标这一个服务要登录。
   - 没令牌、不要认证的 HTTP 服务：读令牌文件得到 NotFound，请求不带令牌，和以前一样（`oauth_failed_refresh_only_disconnects_that_service` 里的 `healthy` 服务验证了）。
   - 配了 Authorization 头的服务 `use_oauth=false`，不装令牌存储，照旧带静态头（老测试 `redaction_removes_bearer_token_echoed_without_prefix` 仍通过）。
   - stdio 只是多传了一个 `home` 参数。

### 意见

1. **建议改**：续期时临时出错也会把服务标成「要登录」，而且到重启前都不恢复。
   - 位置：`crates/canter-tools/src/mcp/http.rs:33-43`（`observe`），`crates/canter-tools/src/mcp.rs:446-451`。
   - 问题：`observe` 碰到 `Error::Auth(_)` 就设 `needs_login`，而这个标志设了就不会清。rmcp 把续期失败分成两种：
     - 被授权服务器拒绝的，它自己已经转成了 401 → `AuthRequired`；
     - 网络断、令牌端点 5xx、读凭证文件出错，报 `TokenRefreshFailed` / `CredentialStoreError`，rmcp 注释写明是「可以重试」的。

     canter 把后一种也当成要登录。启动时 `authorized_client` 的任何失败（包括发现授权服务器时网络不通）同样标成要登录。`InsufficientScope`（某一个工具缺权限）也会让整个服务停掉。
   - 已查证：我临时加了一个测试（跑完已删）。服务端在跑、令牌过期，令牌端点只回了一次 503，`/v1/mcp` 就变成「Login required」；令牌端点恢复以后，下一次调用仍然是「MCP service disconnected」，状态还是要登录，令牌文件和刷新令牌都还能用（`refreshes` 计数是 1，没有再试）。
   - 什么时候会碰到：电脑睡醒、网络还没连上，正好赶上令牌过期（GitLab 的访问令牌大约两小时过期）。用户会被叫去重新登录，其实重启服务端就够了。这需要两件事凑在一起，所以记「建议改」。
   - 改法：`observe` 只对 `AuthRequired`、`InsufficientScope` 和 `Auth(AuthorizationRequired | TokenRefreshRejected)` 设标志，别的认证错误按普通调用失败处理，下次调用会重试。启动时只有 `authorized_client` 返回 `AuthorizationRequired` 才标要登录，别的失败用普通连接错误的文字。`InsufficientScope` 要不要整个服务停掉，可以再定。
2. **建议改**：授权服务器给的网址没有核对协议，也丢了 rmcp 自带的地址过滤。
   - 位置：`crates/canter-tools/src/mcp/oauth.rs:139-150`（`with_client`），`233-248`（打开浏览器）。
   - 问题：
     - rmcp 只核对 issuer，不管 `authorization_endpoint`、`token_endpoint`、`registration_endpoint` 是不是 https。`with_client` 换成 canter 自己的 reqwest 客户端，按 rmcp 文档会去掉它对内网和链路本地地址（含云主机元数据地址）的过滤。
     - 所以服务器给出 `http://远端/token` 时，授权码、PKCE verifier 和以后的刷新令牌都会明文发出去，这和 DESIGN「非本机必须 HTTPS」的意思不一致。
     - 授权网址不管是什么协议都会交给 `open`。
   - 什么时候会碰到：只在 MCP 服务或授权服务器配置错了、或者有恶意时（推测，没构造输入去试）。
   - 改法：`resolve_metadata` 之后、服务端 `initialize_from_store` 之后，要求这三个端点是 https；只有 MCP URL 本身是本机地址时，才允许本机 http。`open` 之前确认授权网址是 http(s)。不想自己做地址过滤的话，可以用 `new_with_oauth_http_client` 包一个 `no_proxy` 的客户端，保留 rmcp 的检查。
3. **可以不改**：登录全程拿着凭证锁，第二个登录会没有任何提示地等着。
   - 位置：`oauth.rs:85-106`、`192-195`。
   - 问题：`canter mcp login` 从发现到等浏览器（最多 5 分钟）一直拿着这个服务的凭证锁，`lock()` 只会每 25ms 重试一次，没有上限，也不打印东西。同名的第二个 `login` 或 `logout` 会一直卡着，直到第一个超时。这期间服务端要给这个服务续期也会卡住，那次调用按工具超时失败。
   - 改法：命令行拿锁改成 `try_lock`，拿不到就报「another login for this service is in progress」。或者只在保存令牌时拿锁。
4. **可以不改**：回调成功页的 `Content-Length` 写错了一个字节。
   - 位置：`oauth.rs:303`。
   - 问题：写的是 `Content-Length: 22`，正文「You may close this tab.」实际 23 字节（`wc -c` 核过），浏览器显示出来少一个句号。
   - 改法：改成 23，或者按正文长度算。
5. **可以不改，用户真连 GitLab 时注意**：发现授权服务器的方式在 GitLab 上能不能用，还不知道。
   - 位置：`oauth.rs:205-216`、`139-146`。
   - 问题：
     - 登录用 `resolve_metadata()`，按 MCP URL 推出 well-known 路径。它不先发一次请求，从 401 的 `WWW-Authenticate` 里拿 `resource_metadata`，而 MCP 规范要求有这个值时要用它。
     - OAuth 请求一律不跟随重定向：`Policy::none` 盖掉了 rmcp 对注册等请求的 Follow。

     本机假服务覆盖不到这两点。GitLab 的授权服务器和 MCP 在同一个域名下，多半没事，但没法确认。
   - 改法：如果用户实测时报「cannot discover MCP authorization server」或「OAuth dynamic client registration failed」，先查这两处。可以改成先发一次不带令牌的请求，再用 `resolve_metadata_from_challenge`，或者对发现和注册请求放开同域名内的重定向。
6. **可以不改**：`config.json` 是符号链接时，写配置会把链接换成普通文件。
   - 位置：`crates/canter/src/mcp.rs:198-204`。
   - 问题：原子替换用的是 rename，会把链接本身换掉。链接断了，内容不丢，只在用户自己把它链到 dotfiles 时会碰到。
   - 改法：要支持的话，先用 `canonicalize` 拿到真实路径，在真实路径那个目录里替换。
