# 任务：第四期 - 将canter coding agent扩展成personal agent

2026-10-27，用户在看板上新建。
待用户：看下面的方案，定「要用户定的」几点；定了再拆成小任务

## 用户原话

- 11-11：「canter自身的开发有这么几个方向。……3: 在现在coding agent的基础之上演化出personal agent甚至现在类似muse或者dots这种类似贴身助理」
- 11-11：「另外贴身助理也按照你的建议先写一份方案附加到那个任务上。另外垂直领域那个暂时不做。」

## 方案（11-11 主控草稿，没定）

### 要做成什么

一句话：**一直在、记得你、你不在电脑前也能替你做事，做完或卡住告诉你，对外的事先问你。**

参照（主控 11-11 前查的公开介绍，细节以官方为准）：

- Muse（Meta，9-08）：跑在云端虚拟机里，能跨多个服务替人做事；动手前走批准流程，另有一层审查盯着它做的事。
- dots（OpenAI，9-29）：一直开着，记用户的目标和偏好；没人时会自己在后台查资料，后台只用只读工具；什么事要先问，由用户定的规则管。

两家的共同点：一直在线、能主动、对外的动作分级批准。canter 和它们最大的不同是 canter 跑在用户自己的机器上，凭证只放本机。

### canter 已经有的

- 常驻服务端，能装成登录时启动的用户服务（P2-14）。
- `/goal` 目标加美元预算，没人时自己续跑（P2-109）。
- 后台命令和叫醒：命令跑完或输出出现条件时，服务端自己开一轮（P2-28、P2-101）。
- 全局记忆和项目记忆（P2-22）。
- 子 agent 和自定义角色（P2-178、P2-223）。
- MCP（含 OAuth 登录，P2-12、P2-131），能接邮件、日历、笔记这类服务。
- 技能（含 docx、pptx、xlsx、网页测试）、网页搜索和抓取。
- 三档权限、命令放行规则、沙箱（macOS、Linux）。
- Linux 上能跑（P2-160、P2-272）。

coding agent 的底子大部分能直接用。缺的主要是「人不在电脑前」那一块。

### 缺的，按先后

1. **定时和周期任务（新）**：比如每天早上 8 点查几个仓库的 CI 和 issue，汇总成一段话。现在只有用户开口或后台事件才开一轮，没有按时间开的。做在服务端，经协议暴露，终端、网页、桌面共用。服务端重启后要能接上。
2. **推到手机**：P2-149 外部通知。目标完成、卡住、等批准、出错时推一条，内容不带密钥和私人数据。
3. **没人时不卡死**：
   - P2-147：批准框没人答，超时后当作拒绝；
   - P2-148：断网久了接着重试；
   - P2-119：服务端重启后自动接着做。
4. **人不在电脑前也能看、能回**：现在服务端只听本机 Unix socket，别的机器连不上。要有网页客户端（P2-84，网页优先，手机能打开），再加一个远程入口和登录校验。远程入口建议走 Tailscale 这类私有网络，不开公网端口。
5. **替人做对外的事，分级授权（新）**：发邮件、改日历、下单、付钱这类事做错了收不回来。第一版只做到「起草、列出来等用户点」，不自动发、不自动付。以后再按动作种类分「直接做 / 先问 / 不许」，规则由用户定，照现在命令放行规则的样子做。
6. **主动提醒**：P2-139 实时提醒管会话里的，dots 那种「没人时自己去查」可以用第 1 条的定时加只读工具实现，不另做一套。

### 第一块做什么（建议）

**定时任务加推到手机（上面第 1、2 条）**，例子：每天早上跑一个只读目标，跑完把结论推到手机。

理由：

- 全在服务端，不碰界面，不需要远程入口；
- 只读的活不涉及对外动作，现有权限规则就够；
- 做完马上能天天用，能看出「助理」这条路值不值得往下走。

第二块是网页客户端加远程入口（第 4 条）。它和用户打算让 canter 自己做的 P2-84 是同一件，那件做完这块就有了一大半。第三块是从手机批准，加上对外动作分级（第 3、5 条）。

### 跑在哪台机器

Mac 合盖会睡，定时任务和夜里的活会停。可选：

- **Mac**：用户在用时能跑；要夜里跑就设成接电源时不睡。
- **5090（Linux，一直开着）**：canter 已能在上面跑，有沙箱。问题是 P2-80 定过 GPT 订阅凭证「只支持本机 canter 服务端」，5090 算不算本机要用户定。DeepSeek key 没有这个限制。
- **云虚拟机**：和「凭证只放本机」冲突，主控不推荐。

主控建议：第一块先在 Mac 上做、上面验证；常驻机到第二块（远程入口）时再定。

### 和别的任务的关系

- **P2-273 垂直领域 agent（暂时不做）**：垂直 agent 可以看成「canter 加一组领域技能、MCP 和记忆」。定时、推送、分级授权这些机制贴身助理和它共用，先做贴身助理这边，P2-273 以后就是在上面配一套东西。
- **P2-84 网页或桌面客户端**：第二块靠它。
- **P2-248 精调和 DESIGN 里「用 eval 来改」**：助理改模型行为（主动提醒说什么、定时任务的提示词）同样先跑基线再比。真实使用里的失败攒成 eval 题。
- **DESIGN 第 23 条**：不绑定 DeepSeek，助理功能各家模型通用。

### 先不做

- 不上云、不把凭证交给第三方保管。
- 不自动发信、不自动付款、不自动对外提交。
- 不做语音和手机原生应用。
- 不做后台提炼记忆、向量检索（P2-22 定的记忆规矩不变）。

### 要用户定的

1. 方向：同不同意「第一块做定时任务加推到手机，第二块网页客户端加远程入口，第三块手机批准和对外动作分级」。
2. 推送用哪家：ntfy、Bark（iPhone），还是只给一个通用的命令钩子，用户自己接。主控建议通用命令钩子，再附一个 ntfy 的例子。
3. 常驻机：先 Mac，还是现在就定 5090；5090 能不能放 GPT 订阅凭证。
4. 远程入口（第二块时定）：Tailscale 这类私有网络，还是只在局域网里用。
