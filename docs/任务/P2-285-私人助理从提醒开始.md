### Claude Duet 是什么

Anthropic 2026-10 发布的主动型 agent，研究预览，美国 Pro、Max 用户排队开通：

- 设备：iPhone、iPad 是单独的 App（iPad 要 iPadOS 26）；Mac 上没有原生 App，走 claude.ai 网页；有的报道说也有 Android。

### 对用户思路的看法

大方向对：Duet 也是下面一层 agent 能力（模型、记忆、技能、连接的应用），上面一层负责主动找人、通知、等批准。和用户说的「canter 当 agent，上面做一层 assistant」是同一个结构。

主控建议调整三处：

1. **assistant 这一层放在服务端，不另做一个程序去调 canter。** 提醒、早报要在没开任何窗口时到点自己跑，只有常驻服务端做得到；也合 DESIGN 第 2 条（一台机器一个常驻服务端、多个客户端）和用户定的「行为放服务端、客户端只管显示」。手机、iPad、Mac 都只是客户端，看同一份提醒和结果。服务端要加的是三样：定时触发、通知出口、要用户同意的操作先挂起等批准（批准 canter 已有）。
2. **最难的是手机怎么连上服务端，不是 App。**
   - 现在服务端只在本机监听；手机要连，得解决远程访问（比如 Tailscale）和登录鉴权。
   - Mac 合盖睡着时提醒不会响：要么服务端放在一直开着的机器上（比如跑 Terminal-Bench 的那台 5090），要么接受睡眠时不准。
   - 原生 iOS 推送要 Apple 开发者账号，还要一个转发推送的服务。
3. **手机端先用网页，原生 App 往后放。** Duet 在 Mac 上也只给网页；canter 的网页客户端本来就在 DESIGN 计划里。iPhone、iPad 把网页加到主屏幕后能收网页推送，一份代码三个设备。原生 iOS App 要写 Swift，和 CLAUDE.md「语言与依赖」只用 Rust 的规矩冲突，要用户单独定。更省事的第一步：提醒先发到已经接好的 Slack 私有频道，手机马上能收到，不用写客户端。

### 建议的第一版

只做提醒，用来验证这一层：用户在对话里说一句（比如「明天 9 点提醒我交报销」），模型记成一条提醒；服务端到点通过 Slack 或桌面通知告诉用户。网页、iOS 客户端放后面的任务。

## 待定

开写需求前要用户定：

- 服务端跑在哪：Mac（睡眠时提醒不准），还是一直开着的那台机器。
- 第一版的通知出口：Slack、macOS 系统通知、网页推送，还是几种都要。
- 手机端：走网页客户端，还是要原生 iOS App（要写 Swift，规矩要破例）。
- 「canter 从 coding agent 扩成私人助理」这个方向：同意的话先写进 DESIGN（CLAUDE.md 开头也说 canter 是 coding agent），再写任务单。

- 只是到点提醒一句，还是到点让 canter 做一件事（比如到点去查一下某个东西再告诉用户）。
- 重复提醒（每天、每周）要不要第一版就做。
