### 必须改

1. **【必须改】会话里存的档位，打开、恢复和热重载时都不按模型当前能力重新核对，不支持的档位照发**
   - 位置：`crates/canter-core/src/context.rs:535-547`（请求直接用存的档位，只把 Unknown 当 high）；`crates/canter-core/src/session.rs:848` `open_inner`（打开、恢复、分叉都不核对）；`crates/canter-core/src/configuration.rs:285-293` `apply_configuration`（热重载只刷新 plan/sandbox）。只有新建（`session.rs:1103-1105`）和 PATCH 带档位或换模型（`session.rs:1756-1771`）时才校验。
   - 已查证（读代码）：存的档位不在模型当前支持列表里时，主请求、顺口问（`suggestions.rs:74`）、btw（`btw.rs:104`）都照原值发。Responses 适配器对任何档位都写 `reasoning.effort`（`responses/wire.rs:58`），档位是 none 就发 `"effort":"none"`。前提相同时，派子 agent（`agents.rs:608-633` 复制父会话设置后走 `create_inner` 校验）会被拒；TUI `/new` 和「在新会话里实现计划」（`canter-tui/src/run.rs:1786`、`1712`）带原档位新建，也会被拒。
   - 这个前提怎么出现（代码路径已查证；用户数据里现在有没有这样的会话，未知，没去看）：① P2-206 之前 GPT 走旧四档，`/think none` 合法，而且那时不发 effort，存着 none 也没事；装上本件后，同一个会话每轮发 `effort:"none"`。② 用户现在的配置里 gpt-6.1-sol 没写档位，从装好到主控改配置这段时间，GPT 照样列出 none、也接受 none；改完配置热重载后，这些会话不会被纠正。③ 以后热重载从某个模型的列表里删掉一档（比如 max），存着这一档的会话照发。exec 没有设档位的参数，只能先换到别的模型再换回来绕过去。
   - 推测（没真调，未证实）：gpt-6.1-sol 模型页没有 none，发 `effort:"none"` 多半每轮 400（OpenAI 对不支持的 effort 一般回 unsupported_value）。会话不会永久卡死，TUI 里 `/think <支持的档>` 能恢复，但出错原因得用户自己猜。
   - 不影响别家（已查证）：没写档位的模型支持旧四档，别家会话里只可能存这四档或 Unknown，核对不会触发。改的时候 Unknown 照旧当 high，就能保持原样。
   - 改法（建议，细节开发定）：会话打开后、应用新配置时，按换模型那条规则处理（放在 `apply_configuration` 刷新 plan/sandbox 的那段，或者别的打开、热重载、开轮前都会经过的地方）：有效档位（Unknown 当 high）不在当前模型支持列表里，就改成模型默认档，写 `session.updated`，再发一条同样格式的 warning。不建议只在 `context::request` 里悄悄换，那样状态栏显示的就不是实际发出去的档位。补测试：GPT 型配置下打开存着 none 的旧会话（或者热重载把当前档移出列表），下一次请求的 `reasoning.effort` 是默认档，并且有提示；再跑现有逐字节比对，确认别家不变。DESIGN 第 6 条补上这条规则。

### 建议改

2. **【建议改】TUI `/new` 发现原模型已不在配置里、改用默认模型时，仍带着原档位**（`crates/canter-tui/src/run.rs:1802`）。例：GPT 会话是 xhigh，配置里删掉 GPT 后 `/new`，退到默认的 DeepSeek 并带上 xhigh，被拒「Could not start a new session: Thinking effort 'xhigh' is not supported…」。改法：退到默认模型重试时，把 `params.reasoning_effort` 一并置 None，由服务端用默认模型的默认档。只牵涉用过 GPT 的会话，别家不变。
3. **【建议改】存的档位是 Unknown 时换模型，会提示「Thinking effort changed from unknown to high for …」**（`crates/canter-core/src/session.rs:1762`，`supported.contains(&Unknown)` 永远为假）。运行时和状态栏本来都把 Unknown 当 high，目标默认也是 high 时其实没换档，这条提示是多余的；别家之间换模型也会出这条（以前是静默写 high）。Unknown 只在降级或手改存盘时出现，影响很小。改法：判断之前先把 Unknown 当 high，和 `context::request`、状态栏保持一致；`crates/canter-protocol/README.md:290`「PATCH 没带档位时也写成 high」那句，顺带补一句换模型时按目标模型的规则走。
