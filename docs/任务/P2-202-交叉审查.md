## 重点看

1. **令牌不外流**：access、refresh、ID token、授权 `code`、`state`、完整授权网址，会不会经 `Debug`/`Display`/`Serialize`、错误链、日志、回调网页、HTTP 跳转、panic 信息漏出去；带令牌的请求头是不是 sensitive、会不会被发到 OpenAI 以外的地址（discovery 给的地址怎么校验）。
2. **ID token 校验对不对**：签名算法有没有限死（不接受 `none`、不能拿公钥当 HMAC 密钥这类混淆），issuer、audience、过期、`nonce` 都查了；再登录时 client id 和 `sub` 不一致确实拒绝、不覆盖旧记录；缺 `chatgpt.tokens.use.direct` 时取不到推理令牌。
3. **刷新和退出的并发**：同一条记录同时要令牌只刷一次、失败共享；刷新回来整组原子保存，中途崩了不会丢掉新的 refresh token 或留下半新半旧；退出和刷新同时发生时令牌不会复活、撤销的是最新的 refresh token；调用方放弃等待不会弄丢正在轮换的令牌。
4. **本机存储**：目录 0700、文件创建时就是 0600（不是先写后 chmod）；临时文件同目录、原子替换、落盘顺序对；拒绝符号链接和所有者不对；锁能挡住同一状态目录的第二个服务端；同邮箱两条记录不串。
5. **登录事务**：先监听再生成 state/nonce/PKCE；`state` 不对、用户拒绝时不换令牌；取消、超时后监听关掉；首次用 `dynamic_agent_client`、换令牌用签下来的 client id，绝不用 `dynamic_agent_client` 换令牌；没有借 Codex 的 client id 和接口。
