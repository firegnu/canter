## 要做的

### 执行器

真正读写文件、跑命令的一层。第一期在服务端进程里；接口要留好，第二期能换成单独的子进程。

- 读文件、写文件、起命令（拿到输出流、等结束、杀掉）。
- 每个会话一个执行器，带这个会话的工作目录和环境变量。命令用的就是客户端交来的那份环境，不混进服务端自己的环境。
- 相对路径按会话的工作目录解析。

### 工具

每个工具都有：名字、说明、参数的 JSON Schema（`serde_json::Value`，第 4 件交给模型）、风险档（读 / 写 / 执行）。调用时拿到模型给的**原样参数字符串**。参数不是合法 JSON 或缺字段时，返回一段给模型看的错误说明，不 panic，也不改任何文件。

每次调用交回两样东西：
- 回给模型的文字；
- 给客户端显示的最终项目，用 `canter-protocol` 的 `Item`：读文件是 `fileRead`，写和改是 `fileChange`（带 diff），shell 是 `commandExecution`。

shell 的输出还要能边跑边交出去，第 4 件转成 `item.delta` 事件。

- **read**：带行号读，能从第几行读、读几行；一次读的行数和字节数有上限，超了告诉模型怎么往下读；二进制文件不硬读。
- **write**：整文件写，没有的上级目录自动建；diff 用 `similar` 算。
- **edit**：按文字替换。一次可以给好几处「旧的一段 → 新的一段」，每段旧文字在文件里必须正好出现一次。**全部能改才一起改，有一处不行就一处都不改**；找不到、找到多处，都要说清是哪一处、什么问题。
- **shell**：有超时（默认值和上限你定，写进完成记录）；回给模型的输出太长就截断，留头留尾，并注明截了多少；给客户端显示的是完整输出。超时或被取消时，杀掉整个进程组，不留下还在跑的子进程。用哪个 shell 你定，写进完成记录。
- **取消**：每个工具都能被取消，用 `tokio-util` 的 `CancellationToken`（P1-2 也用它）。

### 权限闸门

只做判断，不弹框、不发事件（批准框是第 4、7 件的事）。给它工具、参数、风险档、会话的权限模式，它答三种之一：直接执行、要先问人（附上批准请求的内容）、拒绝。

- **三种模式**：
  - `alwaysAsk`（每次问）：写和执行都问，读不问；
  - `askForExecution`（只问执行）：只有执行问；
  - `allowAll`（全放行）：都不问。
- **四种回答**：`accept`（允许这一次）、`acceptForSession`（本会话都允许）、`decline`（拒绝）、`cancel`（拒绝并停下）。「本会话都允许」的意思是：这个会话里同一个工具以后不再问（主控定）。这份记忆跟着会话，不跨会话，服务端重启后不保留。
- **批准请求的内容**：工具名、完整参数（完整命令、要改的 diff）、可选的四种回答。
- 存盘重放出 `PermissionMode::Unknown` 时（退回旧版会遇到），一律按 `alwaysAsk` 处理，不能用兜底分支放行（第 1 件审查带过来的）。
