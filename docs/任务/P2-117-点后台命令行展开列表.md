## 完成记录

- **做了什么**：输入框上方那一行改成 `▸ N background commands`（去掉 `· /ps`），`/ps` 列表或某条的日志开着时写 `▾`。鼠标左键按下时，按按下那一帧画出来的位置判断：点这一行（收着时）返回和 `/ps` 一样的 `BackgroundList`；开着时点它收起列表或日志页；点列表里某一条返回 `BackgroundOutput(id)`，和选中按 Enter 一样。为此每一帧在 `Shown` 里记下这一行的屏幕行、开没开、列表里每条命令的屏幕行和编号；`handle_mouse*` 改成返回 `Option<Action>`，`run.rs` 把它交给原来处理 `/ps`、Enter 的那套。`commands.rs` 把列表从第几条开始画抽成 `first_shown`，点击和画法用同一个算法。`?` 帮助加一条，README 加「后台命令」一节，DESIGN 第 22 条那句跟着改。
- **验证了什么**：新加画面测试 `user_shell.rs::clicking_the_background_row_opens_the_list_a_command_its_log_and_closes_it`（点那一行出 `BackgroundList`、开着时行首 `▾`、点 `#1` 出它的日志、再点那一行收起回到 `▸`）；`cargo nextest run --all-targets` 901 个全过（含 `crates/canter/tests/tui.rs`，里面等 `1 background commands · /ps` 的三处改成等 `▸ 1 background commands`），`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`、`git diff --check` 都过。没起真实服务端、没调模型。
- **拿主意的地方**：
  - 某条的日志页开着时也算「展开」：行首 `▾`，点这一行收起日志页（不是回到列表）。
  - 整行都能点，不只是字。
  - 批准框、提问框、搜索框开着时点这一行不打开（`/ps` 那时也输不进去）；别的弹框（`?`、`/mode` 等）开着时点它，换成后台列表，和 `/ps` 一样。
  - 命令都已退出、没有这一行时，用 `/ps` 打开的列表里照样能点某一条看日志。
  - 点了某一条、日志还没从服务端回来那一下，行首短暂是 `▸`（列表已收起，和按 Enter 一样）。
- **没做的事**：没把后台命令放进状态栏；没改服务端、协议、状态栏 JSON；没加任务要求以外的测试。
- **踩过的坑**：列表展开时插在这一行和输入框之间，这一行会往上挪；测试一开始拿展开前的行号去点「收起」，点空了。点击按当帧画的位置判断本来就对，改的是测试。
