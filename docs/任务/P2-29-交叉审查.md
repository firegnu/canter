## 重点看

1. 单实例还保不保证：一个服务端已在跑时，新服务端是否一定被拒；两个服务端同时启动，会不会两个都拿到锁，或都被拒。
2. `acquire` 的重试循环没有上限：一直有客户端在检查（几个终端在重连）时，会不会一直转、占 CPU、启动迟迟不成功；要不要上限、上限到了该怎么报。
3. `serve --replace`：等旧服务端退出的那段，以及 `WouldBlock if replace` 分支，在有检查者时是否仍对。
4. 锁的语义：`flock` 共享 / 独占锁在同一文件不同 fd、同一进程多线程、macOS 和 Linux 上的行为，和代码的假设对不对得上；有没有别处还拿 `server.lock` 的独占锁做检查。
5. 新加的回归测试：在原代码上是否真因为这个原因失败，修完后会不会在机器忙时自己变成偶发。
