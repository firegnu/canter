## 要做成什么

1. **协议**：`/v1` 加账号相关的接口，结构照 Codex app-server v2 的 `account/*`（`account/login/start`、`account/login/cancel`、登录完成的通知、`account/read`、`account/logout`）：发起登录、等登录结果、取消、列账号、选当前账号、改后台运行同意、退出。每个接口带 `provider` 字段，这次只认 `chatgpt`，写别的报错并列出支持哪些。和 Codex 不一样的地方（包括加了 `provider`）写进 DESIGN 第 8 条并说明为什么。
   - 授权网址只回给发起登录的那个客户端，不进会话事件、SSE 重放文件和日志。
   - 回给客户端的账号信息只有记录 ID、email、状态、有没有套餐权限、后台运行同意、有没有待作废的令牌；任何令牌、`code`、`state` 都不出服务端。
2. **命令**：`canter auth login <家名>`、`canter auth status [<家名>]`、`canter auth use <家名> <账号>`、`canter auth background <家名> on|off`、`canter auth logout <家名> [<账号>]`，都经 socket 让服务端做（凭证只由服务端管，CLI 不碰凭证文件）。`<账号>` 可以写 email 或 `status` 里列的序号。这次只实现 `chatgpt`；`login` 不带家名时打用法和能登录的家，家名不认得时报错并列出能登录的家。
   - 11-04 用户问「canter auth login这个只是针对gpt吗？如果以后还有其他的这种providor呢？」，主控建议命令和协议都带家名、只实现 `chatgpt`、不做通用登录框架，用户：「可以，照这个改任务文件」。只留家名这一位：不为以后的家预先抽象登录流程，凭证照 P2-202 放 `auth/chatgpt/`（以后别家放 `auth/<家名>/`）。填 key 的家照旧写 `config.json`，`canter auth` 只管要浏览器登录的家。
3. **登录**（样子见下面的示意，文字照抄，细节可以调，调了写进完成记录）：
   - 先打隐私说明：凭证只存在这台机器的哪里、只有本人能读；用 ChatGPT 模型时会把提示、读到的项目文件和工具结果发给 OpenAI；怎么退出和清除。
   - 问后台运行同意，默认「不」。同意单独记在这条账号记录上，不和 OAuth 授权范围、`--yolo` 混在一起。不在终端里（stdin 不是终端）时不问，记成不同意。
   - CLI 在本机用系统浏览器打开授权网址（macOS `open`）；打不开就打出网址，提示粘到这台机器的浏览器里。Ctrl+C 取消登录。
   - 成功后打出登录的 email；这是这台机器第一次有授权了套餐的账号时，再打一次 `You're using your ChatGPT plan` 和 Manage usage 链接 `https://chatgpt.com/settings/usage`（OpenAI 的 UI/UX 规范要求，只第一次打）。授权里没有套餐权限时说明「已登录、没授权用套餐」。
   - 新登录的账号成为当前账号。
4. **状态**：`canter auth status` 按家分组列所有账号（这次只有 `chatgpt` 一组）：当前的加标记，状态（已登录 / 要重新登录 / 没授权套餐 / 已退出）、后台运行同意、有没有待作废的令牌。没有账号时说怎么登录。
5. **退出**：照 P2-202 的 `logout`。远程作废确认了、没确认、本来就没有可作废的令牌（比如要重新登录的记录），三种提示分开；没确认时说可以再跑一次 `canter auth logout chatgpt` 重试。
6. **P2-202 留下的两条**（见下面「P2-202 留给本件的」）一起做掉：待作废的令牌在 `status` 里看得出来，再跑 `logout` 会重试作废；复登覆盖这条记录前先尽力作废一次旧的待作废令牌。
7. **后台运行同意给模型层留口子**：服务端能按账号记录查到同意没有，P2-204 发 GPT 请求时据此决定「最后一个界面离开后还发不发新请求」。本件只存、只查，不做这个判断。
