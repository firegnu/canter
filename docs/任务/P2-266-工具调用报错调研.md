# 任务：日常会话的工具调用报错调研

执行：主控
类型：调研
依据：查日常会话里有哪些和 P2-265（读文件不认 `limit`、`offset`）同类的工具调用错误，给结论和建议；本轮不改代码。

## 用户原话

- 11-09（看到 eval 会话里 `Read src/cli.ts · failed`）：「我发现委派出去的agent这种错误有点多。虽然最后也能纠正过来。只调查给结论即可」
- 11-09（P2-265 派出后）：「能不能查一下之前canter的做任务的遥测，看看还有哪些工具调用之类的类似265的这种错误。」
- 「合并推送吧， 然后把你调研的结果结论和你的建议写一下」

## 怎么查的

- 范围：`~/.canter/sessions` 下 304 个会话（截至 11-09 晚），共 10343 次工具调用；只读会话记录，没碰配置。
- `private-telemetry.jsonl` 只记每次模型请求，没有工具结果，所以改从 `model-history.jsonl` 把每次工具调用（名字、参数）和返回的文字配对，再按工具和报错归类。`events.jsonl` 里失败的工具条目大多不带报错原文，只用来数失败条目：449 条（shell 失败 185、被拦 106、拒绝 15；edit/write 77；read 37；ast_grep 17；其他 12）。
- 是不是失败按返回文字判断，各类数字是这些文字归类后的个数。shell 正常的非零退出（编译、测试失败）不算在这份调研里。

## 结论

### 1. 参数名写错（和 P2-265 同类）

| 工具 | 次数 | 模型写的 | canter 要的 |
|---|---|---|---|
| `read` | 26（`limit` 18、`offset` 8） | `limit` / `offset` | `lineCount` / `startLine`，P2-265 已修 |
| `update_plan` | 5 | 每一步 `{"description", "status"}` | `{"step", "status"}`；其余 219 次写对了 |
| `shell` | 1 | 多带 `description` | 没有这个参数 |
| `edit` | 5 | 某一条缺 `oldText` 或 `newText`，或写成 `oldText2`、`oldTextPlaceholder` | 模型写乱了，不是别家参数名的习惯 |

报错来自好几家模型（调用 ID 格式不同），不是一个模型独有。

### 2. 只读子 agent 的 shell 被拦

- 87 次被拦（「This shell command is not read-only, so it did not run」），全在只读子 agent 里。
- 11-08 两次放宽（`4f7ef07` 改提示、`c06d149` 允许丢到 `/dev/null`、末段通配符、`git -C`）之后还剩 36 次：`cd <目录> && …` 27 次（其中 7 次还带 `;`），用 `;` 串几条只读命令 5 次，其他 4 次（`rg -rn` 的 `-r` 是替换、`git status` 等）。
- 每次被拦，模型要换一种写法重试，是现在剩下最多的一类无效调用。

### 3. `edit` 里夹着「什么都不改」的修改

- 42 次 `edit` 调用里有一条修改原文、新文一字不差，后面跟着真正的修改。看样子模型把它当「定位锚点」用。其中 11 次因为锚点和真修改叠在同一段，被报 `edit N overlaps edit N`。
- 另有 1 次整次调用都是这种空修改，canter 照样回「Updated …: 0 lines added, 0 lines removed」，看起来像改成功了（eval 里 `mg-keep-3` 第 4 个会话也有一次，模型下一步自己发现了）。

### 4. 正常的保护或模型自己的失误（不建议改）

- `rm` 碰到写成变量的路径（`"$tmp"`、`$D` 等）被拦 12 次：安全保护，照旧。
- `edit` 找不到原文 37 次、原文匹配到多处 8 次、原文为空 3 次：报错已经说清楚了，模型下一步都改对了。
- `ast_grep` 写法不合法 15 次：同上。
- 读不存在的文件 7 次、读目录 2 次、读二进制 2 次：正常。

## 建议

按值得做的程度排：

1. **`update_plan` 收下 `description` 当 `step`**（照 P2-265 的做法：工具说明不改，写两遍报错）。改动小，和 P2-265 同一类。次数少（5 次），但每次都要重发整份计划。
2. **`edit` 的空修改**：原文和新文一样的那条直接跳过，不参与重叠检查；整次调用都是空修改时明说「nothing changed」，不报「Updated」。能消掉 11 次 overlaps 报错，也不会再让模型以为改成功了。要先看清模型拿锚点想干什么，跳过以后它要的修改会不会落空。
3. **只读 shell 收下 `cd <目录> && <只读命令>`**：次数最多（11-08 以后 27 次），但碰的是只读安全检查。要做就单独出设计，比如只认开头一个 `cd`、后面整条照原规则检查，交叉审查要做。不建议顺手放宽 `;`、`&&` 串任意命令。
4. 其余（第 4 节）不改。

数字是 11-09 一次的截面。P2-265 合并后过一段时间再数一次，可以顺带看看这几类有没有变。

## 更正（11-09，主控）

第 2 节「11-08 以后还剩 36 次：`cd <目录> && …` 27 次」和建议 3 是按命令的样子分的，不是按被拦的原因。读了 `crates/canter-tools/src/readonly.rs` 再逐条看命令全文：检查器本来就认 `cd 目录`、`&&`、`;` 并跟踪 `cd` 后的目录，这些命令被拦是因为 `cd` 后面那段本身不是只读。按原因重数这 36 次：

- `rg -rn …`（照 `grep -rn` 的习惯；rg 默认递归，`-r` 是 `--replace`）21 次，分在 9 个子 agent 会话，每个 2～3 次，被拦后都改了；
- 通配没匹配上、写在中间段或写成 `**` 约 11 次；
- `git status` 2 次（会刷新 index）；
- 直接跑程序、带反引号 2 次（该拦）。

建议 3（收下 `cd <目录> && <只读命令>`）作废：照那样做一次也消不掉。能减少的只有 `rg -r` 这一类，见 P2-268。
