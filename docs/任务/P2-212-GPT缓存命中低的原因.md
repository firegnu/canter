## 现场

- 用户装的是 main `d7171bc`，配置 `chatgpt/gpt-6.1-sol`（`"api": "responses"`、`"auth": "chatgpt"`），在 `canter-test-rust` 里真用。
- 第 1 轮只问一句：↑8.71k、0% cached。第 2 轮读 README.md（一次工具调用，两次请求）：↑17.9k、0% cached。第 3 轮读 TODO.md，一次工具调用。
- 第 4 轮让它实现一个功能：2 分 53 秒、多次工具调用（读文件、改文件、跑 `cargo test` 等）、还用了计划（屏幕上有 `Plan 3/3 complete`）。这一轮 ↑387k、5% cached、↓4.13k。状态栏：`30k/190k`，`cache 8% (last 36%)`。
- 对照：用户接着在同一个仓库换 `opencode-go/deepseek-v4.1-flash`（Chat Completions）让它实现另一个功能，同样多步工具调用、改多个文件、跑测试：这一轮 ↑1.61M、93% cached，状态栏 `cache 74% (last 99%)`（74% 里含前面 GPT 几轮）。所以核心拼历史在 Chat Completions 这条路上是稳的，问题多半在 GPT 适配器这一层（转换、replay 条目）或服务端（缓存键、对加密思考条目的处理）。「要查清的」第 2 条仍要用假服务端证实，不只凭这个数字。
- 主控按数字推测（没证实）：最后一次请求约 30k，命中 36% 约 11k，差不多是系统提示加工具列表（约 8.7k）再加前两三轮的普通历史，也就是命中停在本轮开始的地方，本轮工具循环往后加的部分没有接上前一次请求。
- 主控已看过、没发现问题的（请再核实）：`crates/canter-core/src/prompt.rs` 只出一条系统消息；`crates/canter-model/src/responses/wire.rs` 的工具列表分组和顺序固定；`crates/canter-core/src/telemetry.rs` 只给本轮（同一个 turn id）的助手消息留 `replay`，`runner.rs` 每次请求成功结束时给助手消息挂上本轮 scope 的 replay。
- canter 发给 GPT 的请求里没有 `prompt_cache_key`。OpenAI Prompt caching 指南（`https://developers.openai.com/api/docs/guides/prompt-caching`）说缓存默认开，GPT-5.6 起这个键「not needed to optimize caching」，路由看开头 token 的哈希和这个键，超过每分钟 15 次请求可能分流；SIWC Preview limitations 的禁用字段里有 `prompt_cache_retention`，没有 `prompt_cache_key`。Codex 会发这个键。

## 要查清的

1. 同一轮多步工具循环里，canter 发给 GPT 的连续几次请求，后一次的开头是不是逐字节包含前一次的全部输入（加上前一次的输出和工具结果）？不包含的话，从哪一项开始不同、是什么内容、在哪段代码里产生的。场景要像现场：多次工具调用、中间用计划（todo/plan 工具），有前几轮普通历史；必要时也看压缩、图片、批准、子 agent 这类会在轮中插东西的情况会不会出现。
2. 同样的场景换成 Chat Completions 的家（DeepSeek 那种），连续请求的前缀是否稳定。用来分清是核心拼历史的问题（别家也受影响），还是只在 GPT 适配器里。
3. 跨轮：下一轮第一次请求和上一轮最后一次请求比，前缀在哪里断（上一轮的 replay 在下一轮不再发，这一点 P2-210 会处理，这里只要说清它占多少影响）。
4. 用量映射：`crates/canter-model/src/responses/sse.rs` 读 `input_tokens_details.cached_tokens`，状态栏和每轮那行的百分比怎么从它算出来，有没有算错、漏算或被别的请求（顺口问、建议、标题这类辅助请求，如果有）拉低的可能。
5. 对照 Codex `rust-v0.163.0`（`/tmp/canter-p2-202-codex-reference`，只读）：它发 Responses 时和缓存有关的字段（`prompt_cache_key` 取什么值、别的会影响前缀或路由的东西），和 canter 的差别。
6. 前缀如果确实稳定，列出剩下的可能（缓存键、服务端对加密思考条目的处理、请求太密分流等），说明哪几条要用户在场真调才能分清、每条怎么试、要真调几次。
