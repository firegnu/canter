### 意见

1. **建议改**：`crates/canter-tools/src/sandbox.rs:170`。
   问题：申请的写路径和 cwd 放在同一个循环里，除了 `allow file-write*`，还会一起放开这些路径下 Unix socket 的 `network-bind` 和 `network-outbound`。批准框只写了 `Write access for this command: <paths>`。如果用户批准写一个目录，比如 `/private/tmp`，这条命令也能连上这个目录里别的程序的 socket：比如 tmux 的 `/private/tmp/tmux-<uid>/default`，借它往用户的终端会话里输入命令，在墙外执行；Docker 的 socket 也一样。这不在任务定义的硬边界里（状态目录的 socket 仍然被后面的拒绝规则挡住），所以不算必须改；但批准框没写清这次放开了什么。
   改法：申请的写路径只加 `allow file-write*`，不加那两条 Unix socket 放行；cwd、新增目录和临时目录照 P2-163 不变。如果确实要连申请目录里的 socket，再在批准框里写明。建议用前一种。

2. **建议改**：`crates/canter-tools/src/lib.rs:1179–1186`、`crates/canter-tools/src/shell.rs:17–28`。
   问题：`ShellArgs` 用的是 `deny_unknown_fields`，现在多了两个字段，所以沙箱关闭时，模型带了任何未知参数，serde 的报错都会从 ``expected one of `command`, `timeoutMs`, `background` `` 变成连 `sandboxRequest`、`justification` 一起列出来，参数名会出现在下一轮发给模型的工具结果里；带 `sandboxRequest` 时，报错从 unknown field 变成 `sandboxRequest and justification require an enabled sandbox`。只在模型传错参数时才会发生，拒绝、不执行这一点没变，正常请求也没变，所以算建议改。
   改法：沙箱关闭时用不含这两个字段的旧结构体解析（或者只在沙箱开着时用新结构体），让报错和改动前逐字节一样；补一条「关闭时带未知参数，报错文字不变」的测试。

3. **可以不改**：`crates/canter-tools/src/lib.rs:1187–1199`、`permission.rs:316`。
   问题：空申请 `sandboxRequest: {}`（network 为 false、writePaths 为空）加上理由也会被当成申请：询问档会强制弹一个只有 `Reason:` 的 sandboxApproval 框，本来墙内免问的命令反而要问。不放宽任何东西。
   改法：准备阶段拒绝空申请，或者把空申请当成没有申请。

4. **可以不改**：`crates/canter-core/src/runner.rs:1079`。
   问题：请求类型是按 `approval.tool == "shell"` 这个字符串，加上 arguments 里有没有 `sandboxRequest` 来决定的。现在不会判错：MCP 工具的名字都带 `mcp__` 前缀；准备阶段保证只有真有申请时 arguments 里才有这个键。
   改法：以后可以改成看 `call.tool() == Tool::Shell` 和解析后的 `args.sandbox_request`，少依赖一层约定。
