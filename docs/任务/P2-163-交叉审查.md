### 必须改

1. **必须改：「全部允许」下域名解析不通。**
   - 位置：`crates/canter-tools/src/sandbox.rs:162` 联网段。
   - 问题：只放了 `(remote ip "*:*")`，Unix socket 只放可写范围；macOS 的域名解析要连 `/private/var/run/mDNSResponder`。复刻规则下连这个 socket 失败（墙外能连），加一条放行后能连。苹果 App Sandbox（`/System/Library/Sandbox/Profiles/application.sb:783`）就是把这个 socket 和联网权限绑在一起；Codex 全联网用不加限定的 `(allow network-outbound)`，srt 用 `(allow network*)`，都包含它。结果是 `git push`、cargo 下依赖、`npm install` 只要用域名就解析失败（除非用户设了本机代理的环境变量）。测试只用 IP 连本机，所以没发现。「怎么算做完」没达到。
   - 改法：联网档加 `(allow network-outbound (remote unix-socket (path-literal "/private/var/run/mDNSResponder")))`，留在状态目录拒绝规则之前（现在的顺序已满足）；可参考苹果 `system.sb` 的 `system-network` 顺带加 `com.apple.dnssd.service`。补一条回归：「全部允许」能连上这个 socket（只建连接、不发查询），两个询问档连不上。

2. **必须改：新建仓库的 `.git/config`、`.git/hooks` 在所有可写位置都被拒，挡掉了 cargo 的 git 依赖和 `git clone`。**
   - 位置：`sandbox.rs:152-156` 两条不限范围的正则。
   - 问题：CARGO_HOME、TMPDIR、npm 缓存里新建 `.git/config`、`.git/hooks` 也被拒。cargo 检出 git 依赖时会在 `$CARGO_HOME/git/checkouts/<名>/<版本>/.git` 建工作区：复刻规则下用本机 file:// 仓库做 git 依赖，`cargo run` 失败（只建出 `.git/objects`、`.git/refs`），墙外同一命令成功；`git clone` 到 `$TMPDIR` 报 `.git/hooks/: Operation not permitted`。新 CARGO_HOME 是空的，带 git 依赖的项目第一次 `cargo test` 必定失败（用户本机 `~/.cargo/git/checkouts` 里就有这类依赖，`grok-build` 也用）；npm 的 git 依赖同理。不符合「cargo、npm 在墙里能下依赖、能编译」。
   - 改法：这两条只套在 cwd 和新增目录上，例如 `(deny file-write* (require-all (subpath <cwd 参数>) (regex ...)))`；TMPDIR 和两个缓存不加。缓存里的检出用户不会进去跑 git，不用锁。

3. **必须改：子模块的 config、hooks 没锁。**（读规则得出，没实测）
   - 位置：`sandbox.rs:221` `git_protected_paths`，以及 `:148`、`:155` 两条正则。
   - 问题：只覆盖元数据目录自己和 `worktrees/*` 下的 config、hooks。子模块的元数据在 `.git/modules/<名>/`（名字可带斜杠、可嵌套），里面的 `config`、`hooks` 两条正则都匹配不上，而 `.git` 整体可写。模型往子模块配置里写 `core.fsmonitor` 或写 hook，用户在墙外对父仓库跑 `git status`（终端提示符经常在跑）时，git 会进子模块起子进程、读这份配置并执行。属于「`.git` 配置或 hooks 能改」。
   - 改法：在每个 git 元数据目录上照 `:148` 的写法再加一条，覆盖 `modules/` 下任意层的 `config`、`config.worktree`、`hooks`、`commondir`、`gitdir`，例如 `(require-all (subpath <gitdir>) (regex #"/modules/.+/(config(\.worktree)?|hooks|commondir|gitdir)(/|$)"))`；代价是子模块里名叫 config/hooks 的分支引用写不了，可以接受。也可以启动时像 `worktrees` 那样枚举。补普通回归：子模块的 config、hooks 写不了，在子模块里提交能成功。

### 建议改

4. **建议改：只要非零退出就附沙箱说明，范围太宽。**
   - 位置：`crates/canter-tools/src/shell.rs:359`。
   - 问题：grep 没匹配、`cargo test` 失败、diff 有差异、`test` 为假，都会附「The sandbox blocks ... they can run it themselves with !.」。这些是模型最常见的非零退出，每次都附，模型容易把普通失败归给沙箱、叫用户用 `!` 重跑。任务写的是「命令被墙挡住时」才加。
   - 改法：只在看到拒绝特征时附（现有的 `mentions_denial`；询问档下可再认 `Could not resolve host`、`Network is unreachable` 这类网络错误）。或者改成条件句：「If this failed with "Operation not permitted" or a network error, ...」。前一种更干净。

5. **建议改（要不要做、要不要升为必须改，主控定）：两类路径别名没处理，没确认。**
   - 硬链接：规则里没有 `file-link`。复刻实测，项目内硬链接能建，而没有任何一条规则放行 `file-link`，说明它不归可写规则管。Codex 对拒绝目录也用 `(deny file-read* file-write* (subpath ...))`，并有回归测试证明从拒绝目录硬链接到工作区会失败（`seatbelt_daemon_socket_tests.rs`），所以 `.ssh`、状态目录大概率没事。没把握的是「可读不可写」的文件（如 `~/.zshrc`、`.git/config`）：能不能硬链接进 cwd，再从新路径改写。苹果 App Sandbox 在 `(deny default)` 之后又单写了一条 `(deny file-link)`。
   - 大小写：APFS 默认不区分大小写，规则按区分大小写的路径匹配。已有的目录，内核多半给出磁盘上的真名；新建 `.GIT` 这种就不在正则里。Codex 为这类问题专门有测试（`seatbelt_protects_case_variants_of_metadata`，注释写的是 "reported aliases"）。
   - 按 CLAUDE.md 我没去试。不依赖弄清 Seatbelt 细节的改法：全局加 `(deny file-link)`（git 写对象时链接失败会退回 rename，cargo 退回复制，用普通回归确认提交和编译照常）；受保护的名字生成不分大小写的正则（如 `[sS][sS][hH]`）。

6. **建议改：`> /dev/stderr`、`> /dev/stdout` 写不了。**
   - 位置：`sandbox.rs:117` 只放了 `/dev/null`。
   - 问题：复刻规则下 `printf x > /dev/stderr` 报 Operation not permitted。这是脚本里的常见写法，失败了还会带出沙箱说明。
   - 改法：加 `(allow file-write-data (literal "/dev/stdout") (literal "/dev/stderr") (regex #"^/dev/fd/[0-9]+$"))`，打开它们只是复制已有的文件描述符。`/dev/tty` 可以不管。

7. **建议改：新增目录里有一个不存在，所有模型命令都起不来。**
   - 位置：`sandbox.rs:96` 的 `directory.canonicalize()?`。
   - 问题：P2-118 的目录会持久保存。用户加过的目录被删掉以后（比如临时编译目录），这个会话里每条模型命令都报 `Could not start sandbox: No such file or directory`，也不说是哪个目录。
   - 改法：不存在的新增目录直接跳过（少一条放行只会更窄，不会放开）；或者至少在错误里写出路径。`sandbox_setup_and_policy_failures_never_run_the_command` 第二段要跟着改。

8. **建议改：说明里「原 cargo 配置不生效」不对。**
   - 位置：`crates/canter-server/README.md:82-83`，完成记录「主控决定及兼容说明」第一条。
   - 问题：cargo 会从 cwd 一路往上找 `.cargo/config.toml`，项目在家目录下时会读到 `~/.cargo/config.toml`（复刻实测：家目录下的项目能用 `~/.cargo/config.toml` 里的 alias）。真正不生效的是 `credentials.toml` 和 CARGO_HOME 下的 bin；只有项目不在家目录下时，整份配置才不生效。
   - 改法：改成准确的说法，免得用户装好后核对镜像、私有仓库时被误导。

9. **建议改（设计问题，交主控问用户）：cwd 是家目录时 `~/.zshrc` 可写。**
