### 意见

1. **建议改**：清单简介取的是说明的第一行，第一行为空时简介就是空的。
   - 位置：`crates/canter-tools/src/mcp/search.rs:9`。
   - 问题（读代码）：用的是 `lines().next()`。说明以换行开头时（比如 Python 文档字符串写成 `"""` 换行再写正文），清单里这一行只剩 `mcp__服务__工具: `，模型只能看名字猜。
   - 推测：官方 Python SDK 直接拿函数的 `__doc__` 当说明，这种写法不少见；没实测。
   - 改法：取第一个去掉空白后不为空的行；全空时不写冒号。
2. **建议改**：schema 本身编不过时，这个工具在按需模式下永远调不了。
   - 位置：`crates/canter-tools/src/mcp.rs:526-534`。
   - 问题：完成记录里定的是「schema 无效或引用解析不了也不调用」。参数不对就不调，这一点没问题；但 schema 本身编不过时，没有办法判断参数对不对，结果这个工具在按需模式下怎么也调不了。全量模式下同一个工具照常能调（批准照旧）。
   - 推测：会触发的情况有外部 `$ref`、jsonschema 认不出的 `$schema`、不合元 schema 的旧写法，真实服务里有多常见不知道；能退回的办法只有整体关掉 `mcp_tool_search`。
   - 改法（交主控定）：区分「schema 编不过」和「参数校验不过」。前者只检查参数是不是对象，然后照常走批准和调用；同时在结果或者 warning 里说一句没能校验。批准不受影响，所以不会开后门。
3. **建议改**：模型照清单里的全名直接调（不经过 `mcp_call`）时，只拿到 `Unknown tool`，界面还会出一条 warning。
   - 位置：`crates/canter-core/src/runner.rs:747-763`。
   - 问题：清单里列的 `mcp__服务__工具` 长得像函数名，DeepSeek 有可能直接按这个名字调（推测）。结果文字不提示改用 `mcp_call`，模型不一定知道该怎么改。
   - 改法：开了按需、名字又在清单里时，结果写成类似 `Call MCP tools through mcp_call {name, arguments}`。只影响出错时的结果文字，不影响前缀。
