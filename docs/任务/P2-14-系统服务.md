## 要做的

1. **`canter service install`**：装成 launchd 用户服务（`~/Library/LaunchAgents` 下一份配置），登录时起一次服务端；崩了、正常退出都不重启。把运行 install 那个终端的 PATH 写进服务配置；服务端的日志写到 canter 现有的日志位置。已经装过的再 install 就是更新配置（换 PATH 用这个）。install 时机器上已有服务端在跑，不打断它，也不报吓人的错。屏幕上说清楚装了什么、写在哪、下次登录生效。
2. **`canter service uninstall`**：卸掉服务配置，下次登录不再自起；不停正在跑的服务端，不删 `~/.canter` 里的任何东西（会话、key、备份）。没装过就说没装过。
3. **`canter upgrade`**：
   - 到编译当前程序的那个仓库目录（编译时记下来）编译安装当前代码；`canter upgrade <目录>` 指定别的目录。目录不是 canter 仓库、编译失败，就停下、旧程序和服务端都不动。
   - 安装前把当前程序备份到 `~/.canter` 下，文件名带上它的提交（`canter --version` 里那个）。只留最近 5 份，更早的自动删掉。
   - 换服务端前先查哪些会话在跑一轮，有就列出来（名字或 id，在跑什么），等它们都跑完再换，不设上限；等的时候新开始的轮也要等。Ctrl-C 取消：新程序已经装上，但服务端不换，屏幕上说清楚现在是什么状态、之后怎么换。`--now` 不等，照现在的 `--replace`（最多等 60 秒，到点打断）。
   - 换完打出新旧版本（和 `canter --version` 一样的格式）。
4. **`canter rollback`**：把最近一份备份换回来（当前的那份也先备份，这样能再换回去），然后照 upgrade 一样等在跑的轮、换服务端；`--now` 也一样。没有备份就说没有。
5. **修 `--replace` 的已知问题**：旧服务端停止接受连接到真正退出之间（HTTP 收尾最多 5 秒），父命令探测到连接被拒就报错退出，刚等到锁的新服务端被杀，旧的随后也退出，机器上没有服务端。改成这段时间「连接被拒但锁还在」当成旧的还在退出，接着等，不当出错；总期限不变（DESIGN 第 11 条的 105 秒）。
6. **文档**：DESIGN 第 11、16 条改成新的做法（服务、upgrade、rollback、备份留几份、`--replace` 的修法），写明用户 11-01 定的四条。`canter --help` 里有这几个命令。

屏幕上的字（命令说明、提示、报错）一律英文。

## 怎么算做完

- `--replace` 遇到「旧服务端停止接连接但还没退出」时接着等，最后机器上有新服务端在跑。

### 给用户在场实测的步骤

1. 合并、安装本分支后先记下 `canter --version` 和当前服务端登记 PID。在平常使用的终端运行 `canter service install`；应显示 plist 路径及下次登录生效。用 `plutil -p ~/Library/LaunchAgents/com.canter.server.plist` 查看 RunAtLoad=true、KeepAlive=false、PATH 与该终端一致、日志路径正确。再 install 一次后当前服务端 PID 应不变；修改终端 PATH 后重新 install，plist 应更新。
2. 重新登录后用 `launchctl print gui/$(id -u)/com.canter.server` 查看 job，检查 `~/.canter/server.json` 与 `server.log` 中的就绪信息。若不想重新登录，可在确认所有任务结束后按登记的确切 PID 停旧服务端，再用 `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.canter.server.plist` 手动加载验证（已经加载的 job 不重复 bootstrap）。检查已有的、依赖终端 PATH 的 stdio MCP 在 `/mcp` 中正常连接；不必发模型请求。
3. 在无任务运行时，按该服务的确切 PID 发 SIGTERM，观察 launchd 不重启；需要验证崩溃时先 `launchctl kickstart gui/$(id -u)/com.canter.server`，记录这次 PID，再对这个 PID 发 SIGKILL，观察仍不重启。随后打开 `canter`，应照旧自动启动一个后台服务端。不要按项目名或路径批量杀进程。
4. 有会话在执行、等批准/回答、目标续跑或运行后台命令时运行 `canter upgrade <仓库目录>`：编译成功后应列出运行会话并等待，等待期间另开一轮也应继续等，目标两轮之间不应换服务端。先试 Ctrl-C：程序版本已更新、旧服务端 PID 不变，提示用 `canter serve --replace` 完成切换（最多等轮 60 秒后打断）。旧版没有 `runningTurns` 时也应给这条提示，不自行换服务端、不提示重新 upgrade / rollback；在合适时机执行它。长期后台命令可以取消等待，或一开始就用 `--now`。
5. **upgrade 换好服务端后，打开 `/mcp`，确认依赖 PATH 的 stdio MCP 仍能连接。** 用与 install 时不同的终端 PATH 做一次替换，再检查仍使用服务配置保存的 PATH；没有运行任务时也可停服务端、让终端自动启动后复查。前台 `canter serve` 同样使用保存的 PATH 和 HOME。
6. 用 `canter rollback` 检查旧/新版本输出及服务端更换，再 rollback 可切回。累计超过 5 次操作后，`~/.canter/backups` 中只应有最近 5 份命令管理的备份。rollback 始终选最近一份，不跳过与当前程序相同的备份。指定非 canter 目录或编译失败时，原程序和服务端应不变。
7. 服务端在运行时执行 `canter service uninstall`：plist 消失，当前 PID 和 canter 数据仍在；再执行一次应显示未安装。下次登录不再由这个 job 自起，终端的自动启动行为仍保留。
