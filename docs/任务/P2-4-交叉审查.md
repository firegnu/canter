### 建议改

1. **「自己写」时粘贴进了看不见的输入框**
   - 位置：`crates/canter-tui/src/app.rs:601`（`handle_paste`），`crates/canter-tui/src/run.rs:480`。
   - 问题：开着括号粘贴模式，问题框在「自己写」状态时粘贴，文字进的是被问题框挡住的消息草稿，不进回答；答完换回输入框才看到。粘贴一段话当回答很常见。没列为必须改，是因为它不会回答问题、不会发送，草稿回来时看得见，而且批准框开着时本来就是这样（旧行为）。
   - 改法：当前请求在「自己写」状态时，`handle_paste` 把文字追加到 `approval.custom`（换行换成空格，或者拒收并提示），其余时候照旧；加一条 TestBackend 测试。
2. **进了「自己写」就回不到选项**
   - 位置：`crates/canter-tui/src/app.rs:1076` 起（`question_key` 里「自己写」那一支）。
   - 问题：文字为空时按 Backspace 或 ↑ 都没反应，只能按 Esc，而 Esc 会打断整轮；PgUp/PgDn 在这个状态下也滚不了问题正文。另外 Ctrl+C（`app.rs:983`）直接退出终端，输入框里的 Ctrl+C 是先清空，这里打的字会丢掉（这是批准框原有的行为，可以不动）。
   - 改法：文字为空时 Backspace（或 ↑）回到选项列表；PgUp/PgDn 照选项状态处理。Esc 仍然是打断，和批准框一致。
3. **「自己写」里数字键和 Enter 不当选项，这一点没有测试**
   - 位置：`crates/canter-tui/tests/approval_box.rs:173`。
   - 问题：本轮重点第 4 条要求的行为，代码是对的（试验代码验证过），但没有测试固定下来，以后改按键时容易改坏。
   - 改法：在现有问题框测试后面加几行：选「自己写」，同一帧里按 `1`、Enter 都返回 None；换帧后打「2 x」再按 Enter，得到 `Text { text: "2 x" }`。
4. **参数不合格时对话里显示「Question cancelled」**
   - 位置：`crates/canter-tools/src/lib.rs:779`（`tool_error` 的 AskUser 项目），`crates/canter-tui/src/cells.rs:113`。
   - 问题：模型给的参数不合格时，没有开请求，用户也没见过这道题，对话里却多一行「? 问题 → Question cancelled」（缺 question 时是「?  → Question cancelled」）。模型多半会改了参数重问，用户会先看到一条莫名其妙的「已取消」。
   - 改法：最省事的是把没有回答时的文案改成中性的「No answer」；想分清楚，可以在参数错误时不发 `userInput` 项目，只把错误交回模型。

### 可以不改

1. **崩溃窗口里显示和事件对不上**：`crates/canter-core/src/session.rs:300` 一带。服务端在写下带回答的 `request.resolved` 之后、写工具结果之前被 SIGKILL，重开后模型拿到「No result: the server stopped…」，项目显示「Question cancelled」，事件里却留着那次回答。模型那边是一致的，因为只看模型历史；批准请求在同一窗口也一样，窗口极小。
2. **已处理的请求先按重复处理**：`crates/canter-core/src/session.rs:563`。对已处理的请求再送格式不对的回答（比如对已答的问题送 `decision`，或者两个都不带），返回 200 和 `alreadyResolved`，不是 400。这是原来就有的「先查重复」顺序，和 README「已处理请求沿用重复处理规则」一致。
3. **真服务端测试更多了**：`crates/canter/tests/tui.rs` 从 27 个测试增到 33 个（重启那条要起 4 次服务端），全套并行跑时负载更高。主控遇到的 `tests/tui.rs:122` 起服务端超时（`WAIT` 20 秒）不是本件代码的问题，但新测试会加重负载。这次在审查 worktree 跑全套一次通过。真要稳，以后可以单独给真服务端测试限并发，不放在本件做。
