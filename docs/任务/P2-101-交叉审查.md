## 重点看

1. **叫醒和别的事撞在一起**：叫醒正好碰上用户发消息、按 Esc、批准框弹出、压缩、服务端关闭时，会不会抢掉用户的输入、开出两轮、或者卡住不再叫醒。
2. **事件不丢不重**：压缩、回退、重开会话之后，没送到模型的事件还在、只送一次；补记的事件不会再触发叫醒。
3. **不会一直花钱**：连续叫醒的计数在所有路径上都对（用户输入清零、上限后不再开轮、`auto_wake_limit` 为 0 不叫醒）；`monitor` 匹配得很频繁时，叫醒的次数被 2 秒合并和上限挡住。
4. **谁的命令叫醒谁**：模型的命令结束叫醒；用户的 `!cmd &` 不叫醒，挂了 `monitor` 才叫醒；`shell_stop`、`/ps`、`/stop` 停掉的不叫醒；Ctrl+B 转后台后来源不变。
