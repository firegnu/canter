## 重点看

1. **不会误删、不会删一半、删完不会复活**：删除和恢复、挂上终端、发输入、自动叫醒、目标续跑、服务端停机同时发生时，只有一边成功。已经拿到 `Session` 引用的迟到请求不能再往被移走的目录写，也不能在 `sessions/` 里重新建出这个会话（比如往旧路径追加事件、model history、遥测、临时目录、rewind 文件）。关掉之后移目录失败时，会话处在什么状态，能不能再删或再打开。
2. **「能不能删」的判定**：有终端挂着、在跑一轮、等批准或回答、排队输入、`/btw`、目标续跑、后台会叫醒，这些都拒绝；没人挂着、已停下的会话能正常关掉再移走。注意没加载的会话（不在登记表里）被一个只读事件流看着时怎么算。
3. **登记表锁**：`resume` 和 `EventReader` 现在锁住的时间更长（包括查文件夹信任、订阅、挂接）。看有没有死锁或锁顺序反过来（登记表锁 → 会话状态锁 → clients 锁），有没有在持锁时等可能很久的东西。
4. **条件改名**：`expectedName` 的比较在状态锁内；自动起名、自动撤销都带条件，手动不带；不相等时不追加事件。旧服务端（没有 `conditionalName`）时退回原行为。手动改过名的会话，别的终端打开它也不会自动起名覆盖。
5. **范围和兼容**：没改存盘格式；旧终端连新服务端、新终端连旧服务端都能用（旧服务端删时提示 `canter serve --replace`）；屏幕上的字都是英文；原 `DELETE /v1/sessions/{id}` 仍只是关会话。
