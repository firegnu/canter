## 要点（转述，待核原文）

- 四层：对话记录（可搜索的事件日志）、记忆笔记（模型自己写的要点）、整理出的表示（模型维护的 wiki 页）、每次都注入的上下文（要短：占 token，错的笔记会带进每个会话）。
- 「做梦」（dreaming）：会话之外另跑一遍，拿过去的对话记录核对、改正笔记，或新写笔记和 wiki。
- 实验：CL-Bench 1.0 上开记忆后 Opus 5.5 0.655 → 0.838、Sonnet 5.5 0.644 → 0.833；Sonnet 4.6 常不读记忆文件，提示它先读再验证后 0.330 → 0.641。
- 规定「只记失败」反而让 Opus 5、Opus 4.7 丢掉大半收益：说清记忆是干什么用的，比规定怎么记、记什么好；强模型让它自己判断什么值得记。
- 建议：常驻注入的那层要短；说用途、不定死规则；确认模型真的读了笔记；拿实际发生的事核对、改正笔记；整理（做梦）对准会变的信息，频率要调；记忆提示要在自己的任务上测，不照抄。

## 11-09 读原文后结掉

用户给了原文 PDF（`~/Desktop/The components of agent memory \ Anthropic.pdf`），主控用 pdftotext 读了全文。PDF 里的图是空白的，上面「实验」一条的分数（0.655 → 0.838 等）核不了；正文能核的：Sonnet 4.6 提示「先读记忆、再验证猜测」后分数「接近翻倍」，「只记失败」让 Opus 5、Opus 4.7 丢掉大半收益，合并案问题用 wiki 87%、只用搜索 73%，Stainless 语料上做梦从 2 次到 128 次、得分 13% → 48%。转述漏了两点：只记环境里看不到的东西（Pokémon：Sonnet 3.7 写 413 个文件、Fable 5 写 9 个加一个 `global.md`）；wiki 只在资料多、要跨文档时有用，单文档能答的没提升，还可能写得比原文大。
