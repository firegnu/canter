### 意见

1. **必须改**｜`crates/canter-tui/src/run.rs:802`（`resume`）、`crates/canter/src/exec.rs:185`
   - 问题：终端开着的会话被 `exec --resume` / `--last` 接管后，这个终端里之后的批准全被自动拒、提问被自动回答，直到重新打开会话。`nonInteractive` 只在终端「恢复」时清掉；已经开着这个会话的终端不会再恢复，也不理 `session.updated` 里这个字段；`exec` 结束时也不清。`--last` 选当前目录最近的会话，终端开着时多半就是它，所以「终端开着，另一个窗口跑 `canter exec --last …`」就会触发。违反「要做的」第 7 条、「不要做」第 1 条（交互界面打开的会话照旧弹批准框、照旧问用户）。复现见验证第 1 条。
   - 改法（二选一，建议前者）：
     - 小改：终端在空闲时发送输入前，若当前设置 `nonInteractive` 为真，先发和 `resume` 里一样的 PATCH `nonInteractive:false`，再发输入（可顺带在这个设置变真时提示一行）。补一条终端测试：终端开着 → `exec --resume` → 终端里 `ask_user` 照旧弹框。
     - 大改（要改 DESIGN，主控定）：把「非交互」从存盘的会话设置改成这一次输入/这一轮的属性，只有 exec 发起的那一轮自动拒。

2. **建议改**｜`crates/canter-tui/src/run.rs:818`、`crates/canter-core/src/session.rs:1259`
   - 问题：非交互会话有轮在跑时，终端打不开它：`canter -r/-c` 报 409 直接退出，`/resume` 只给一行警告。以前终端可以接上正在跑的会话看着、按 Esc 打断；现在 exec 被杀后留下的那一轮（见第 3 条）只能等它自己跑完，或者 `canter serve --replace`。

3. **建议改**｜`crates/canter/src/exec.rs:139`

### 重点逐项

1. 不越权、不卡住：core 里只有三处开待答请求（`runner.rs` 的 `permission`、`ask_user`，`plan_mode.rs` 的 `submit`），三处都在同一把锁里先判 `nonInteractive`，一次写入 opened/resolved，不注册等待通道。shell、沙箱申请、写墙外、联网、MCP、`web_fetch`、文件规则 prompt 都走 `permission`，拒绝走 `declined_output`，不执行；没找到别的等人的地方。`--yolo` 下危险命令和文件规则 forbidden 在 `Gate::evaluate` 里先于档位判断，这次没动；测试覆盖了 forbidden。
2. 交互会话：交互界面新建、`/new`、`/handoff`、Clear context 都显式 `nonInteractive:false`；交互恢复会清（有测试）。exec 在跑时终端打开 → 409（第 2 条）；终端开着时被 exec 接管 → 第 1 条。设置的修改、空闲判断和输入的忙判断都在同一把锁里，单个请求之间没有竞态；跨两次请求的窗口见第 6 条。
3. 留在存盘里：exec 被 SIGKILL/断开后，服务端那一轮照样跑完（批准都由服务端自动处理，不会卡住）；跑完之前新终端打不开（第 2 条），跑完后用 `-r`/`-c` 打开会清掉。`SessionSettings` 没有 `deny_unknown_fields`，退回旧服务端会忽略这个字段（按交互跑）；旧会话缺这个字段按 false。旧版终端打开这种会话不会清它，只在新旧程序混用时出现，可以不管。
4. 结局和退出码：做完 0、模型最终失败 2、有批准被自动拒 3、预算到上限 4、Ctrl+C 130，与 DESIGN 一致，同时发生按 130、2、4、3、0。Ctrl+C 走服务端 interrupt，它等这一轮 done 才返回；测试确认轮为 interrupted、会话 idle、命令进程已退出。`--json` 末行的 usage/cost 取 `turn.usage`，是这一轮的量（续跑时不含以前的轮），会话 ID、turn ID 正确。
5. 只跑一轮：目标续跑（`schedule_goal`、`next_goal`）和后台叫醒两处都先判 `nonInteractive`；同一轮里的预算收尾照旧（有测试）；交互恢复后后台叫醒照常，目标要等下一条用户消息才续跑（有测试），和 DESIGN 里服务端重开后的语义一致。
