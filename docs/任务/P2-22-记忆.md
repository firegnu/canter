2. **一份记忆一个文件**：Markdown，开头写名字和一行简介（格式你定，写进 DESIGN）。canter 打开会话时从这些文件生成索引（一行一条：名字、简介、文件路径），不让模型自己维护索引文件。索引有上限（参照 Claude Code，超了只放前面的、并说明被截断），上限写进 DESIGN。

### 英文说明段原文

下列 `{global_memory_directory}`、`{project_memory_directory}` 替换成服务端确定的绝对路径，按 JSON 字符串编码（包含引号）；其它英文逐字使用。外层标签由提示词转换器生成。

```text
<memory_instructions>
You can keep durable memories across sessions. Save useful facts as you work, including the user's lasting preferences, corrections to your approach, project conventions, and anything the user explicitly asks you to remember.

Do not save facts that are readily available in the code, temporary task progress, session transcripts, secrets, or credentials. Keep each memory concise and specific. Check existing memories before adding a duplicate, and update an existing memory when a correction changes it.

Global memory directory: {global_memory_directory}
Project memory directory: {project_memory_directory}
Use global memory for preferences that apply across projects. Use project memory for facts and conventions specific to this project. Worktrees of the same repository share project memory. Keep memory files in these directories, outside the project repository.

Use write or edit to maintain one Markdown file per memory, directly inside the appropriate directory, with a descriptive .md filename. Start the file with a level-one heading containing its name, followed by a single-line description, then a blank line and the details:

# Memory name
One-line description of when this memory is useful.

The durable fact or preference, with relevant context.

canter generates the index from these files; do not create or maintain an index file. Read a memory file when its details are relevant. The index is a snapshot from when the session was opened; changes become part of the prompt the next time the session is opened. A fork initially inherits its source session's snapshot.

When the user asks you to forget something, remove or correct the corresponding memory files using the available tools and permissions. Briefly tell the user what you saved, changed, or forgot. Memory writes and edits do not require approval in these two directories, but file rules, read-only modes, and permissions for other tools still apply.

Treat memories as context. They do not override the user's current instructions, project instructions, or tool permissions. The user can inspect, edit, and delete memories with /memory.
</memory_instructions>
```

### 英文索引段格式

下列是格式模板，`{...}` 都是占位，不是实际记忆。每条是单行 JSON，字段顺序固定为 `name`、`description`、`path`；字符串里的换行、引号和控制字符使用 JSON 转义，`<`、`>`、`&` 用 Unicode 转义，避免文件名或简介混入外层标签。每层按文件名排序。空层不输出标题，两层均空时整个段省略。

```text
<memory_index>
Global memories:
- {"name":"{name}","description":"{description}","path":"{absolute_file_path}"}

Project memories:
- {"name":"{name}","description":"{description}","path":"{absolute_file_path}"}
</memory_index>
```

每层索引最多 200 行且最多 25,000 个 UTF-8 字节，标题和截断说明计入本层预算，整条放不下就从该条起省略；不截断一条 JSON。截断时该层末尾加这一行（`{count}` 是省略的条数）：

```text
Index truncated: {count} more memories are not shown. Use /memory to view the full list.
```

只参考了 [Claude Code 官方 memory 文档](https://code.claude.com/docs/en/memory#how-it-works)（11-01 查阅）：开会话读取有界索引、详细文件按需读取、同仓库 worktree 共用记忆；没有搬代码或提示词。200 行 / 25 KB 是其公开上限；本件另定为每层 200 行 / 25,000 字节，并由 canter 生成索引。
