## 要做的

- **什么时候算撤回**：这一轮模型还没有任何输出（没有思考、回答、调工具的项目）时，在终端按 Esc（就是现在打断用的那个 Esc，有选区、搜索、弹框时先关它们照旧）。模型已经开口就是普通打断，照现在。判断在服务端、和取消请求在同一把锁里做，终端只管发 `retract: true`。
- **协议**（照 DESIGN）：`SessionInterruptParams` 加可选 `retract`，回复加可选 `retracted`；新事件 `turn.retracted { turnId }`，归并时把这一轮从快照里整个拿掉，不留 P2-23 那种「Rewind before …」记录轮。TypeScript 导出跟着更新。
- **模型那边**：撤回的那条用户消息以后不再发给模型。模型历史照第 17 条只往后加（追加一条过滤记录，借 P2-23 的办法），不改已有的行；恢复会话、服务端重启后重放，结果一样。撤回之前已经在那一轮之前的对话不受影响。
- **终端**：
  - 撤回成功：对话里这一轮没了；消息全文（多行原样、图片附件一起）回到输入框，光标在末尾。输入框里已经有草稿时，撤回的放前面，草稿接在后面，中间换一行，两样都不丢。
  - 回复 `retracted: false`：照现在的打断显示，消息留在对话里。
  - 同一会话开着的别的终端：这一轮直接消失，不加提示；全文只回到按 Esc 的那个终端。
- **排队的消息**（10-26 用户指出照打断处理会被丢掉）：撤回时还排着的消息也一起回到这个终端的输入框，不丢。服务端照普通打断把它们移出（`input.removed`），终端用它手上的全文和图片附件放回去。输入框里的顺序：撤回的那条、排队的（按发出的顺序）、原来的草稿，中间各换一行。普通打断（不带 `retract`）照现在，不改。
- 相关 README（协议包、终端）写上撤回。
