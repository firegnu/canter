## 要做成什么

照方案 §2「推荐流程」「凭证位置、并发、刷新和退出」「不进入日志、事件、错误和快照的具体办法」做，接口和字段以官方开发文档为准（见「先读」）。

1. **安装实例身份**：每个 canter 状态目录第一次用到时生成一个 `urn:uuid:<UUIDv4>` 作为 host ID，存下来，以后一直用它（`ext_agent_host_id`）。
2. **登录事务**：服务端发起一次登录，得到登录事务 ID 和授权网址。
   - 先在 `127.0.0.1` 上监听回调（路径 `/auth/callback`），再生成本次独有的 `state`、`nonce`、PKCE（S256）。
   - 首次登录用 `client_id=dynamic_agent_client`、`agent_name_hint=canter`；以后再登录用上次签下来的 client id，不带 `agent_name_hint`。scopes、`resource` 照文档。
   - 能取消，有超时；取消、超时、完成后都关掉监听、清掉事务。回调网页不回显查询参数，不加载任何外部资源。
3. **回调和换令牌**：
   - 核对 `state`；用户拒绝（`access_denied`）就停，不换令牌。
   - 首次登录必须拿到签下来的 client id；再登录时回来的 client id 和存的不一样就拒绝。
   - 用签下来的 client id（绝不能用 `dynamic_agent_client`）、同一个 `redirect_uri`、PKCE verifier、`resource` 去换令牌。
4. **校验 ID token**：按 OpenAI 公布的 JWKS 验签名，再查 issuer、audience（签下来的 client id）、过期时间、`nonce`；只解码不验签不算。再登录时 `sub` 要和这条记录的一样，不一样就拒绝、不覆盖。
5. **套餐权限**：授权范围里没有 `chatgpt.tokens.use.direct` 时，记成「已登录、没授权用套餐」，取令牌接口不给推理用的令牌。
6. **存在本机**：
   - 放 `CANTER_HOME/auth/chatgpt/` 下，目录 0700。
   - 每条登录记录一个文件，0600，文件名用本地随机 ID，不用 email。
   - 新建时就是 0600，同目录写临时文件再原子替换、落盘，之后才换内存里的凭证；不要先宽权限写完再 chmod。
   - 拒绝符号链接和所有者不对的文件。
   - 能存几条记录（不同账号、同邮箱不同 workspace 不互相覆盖）；选哪条当前用由 P2-203 做，本件只要存储和接口支持。
7. **刷新**：
   - 只由服务端刷新；同一条记录的刷新串行，两个请求同时要令牌也只刷一次。
   - 按保存的过期时间在要用之前刷新，遵守 `earliest_refresh_at`；没活的时候不刷。
   - 刷新回来的 access token、新 refresh token、过期时间、授权范围一起换、一起存，不能只换 access token。
   - 出错分开处理：`invalid_grant`、`refresh_token_reused`、`refresh_token_invalidated` 这类刷新不了的，清掉令牌、保留记录和 host ID，标成要重新登录；网络错、503 保留凭证；`invalid_client` 报成客户端配置问题。一次 401 最多刷新一次，不循环。
8. **退出**：先挡住这条记录的新请求，并且不让正在进行的刷新再把令牌写回来；按 discovery 里的 `revocation_endpoint` 作废 refresh token，有限次重试；不管远程确认没有，本地都清掉 access、refresh、ID token，保留 host ID 和记录绑定。远程没确认时，结果里要能看出来（P2-203 据此提示用户）。
9. **给模型层的取令牌接口**：一个窄接口：给一条记录 ID，拿当前可用的 access token（需要就先刷新），或者拿到明确的错误类别（没登录、要重新登录、没授权套餐、暂时连不上等）。P2-204 的 Responses 适配器会用它。本件不把它接进 `Router`，也不加 `api: "responses"`。
10. **不外流**：
    - 令牌类型不派生、不实现 Debug、Display 和通用 Serialize，只有存储模块显式读写。
    - 令牌不进 `SessionSettings`、消息、工具定义、命令行参数、shell 和 MCP 子进程的环境变量。
    - 带令牌的 HTTP 头标成 sensitive，关掉自动跟随跳转；正式的授权地址和 API 地址写死，只有测试能换成本机地址；discovery 给的地址也要校验是可信的 HTTPS 地址。
    - `state`、`code`、完整授权网址不记日志、不进错误链。错误照 `ModelError` 现在的脱敏办法，只留状态码和认得的错误码，不留服务器原文。
