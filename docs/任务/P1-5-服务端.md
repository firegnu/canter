## 要做的

### 一台机器一个

- `canter serve`：起来先拿状态目录下的一把文件锁，拿不到说明已经有一个在跑，报一句清楚的话后退出。
- 写登记文件（目录 0700、文件 0600）：pid、版本、协议版本、socket 路径。
- 给客户端用的「找服务端，没有就在后台起一个」：读登记文件，找到了、进程在、协议版本对得上，就连；找不到就在后台起 `canter serve`，等它写好登记文件再连。放在哪个包由你定，P1-7 要用。
- 启动时清理建会话中途留下的 `.creating-*` 临时目录：拿得到其中事件文件的锁才删（第 1 件审查带过来的）。

### HTTP + SSE

- 只听本机 unix socket，不开 TCP。认证靠目录权限（0700）。
- 协议 README「HTTP 对照」里的每条命令都接上 P1-4 的会话接口；出错照「错误与 SSE」回 `{ code, message }`，HTTP 状态照那张表。
- `GET /v1/events`：SSE，帧格式和续传规则照协议 README（`sse_frame`、`resume_after`，`Last-Event-ID` 优先）。断线后从序号接着收，不漏不重。空闲时发心跳注释。
- 几个客户端能同看一个会话；批准请求先到先得，后到的回 `alreadyResolved`。
- 会话里的命令用建会话时客户端交来的工作目录和环境；环境变量不进事件流、不进日志。
- **加一条「接着聊」命令**（主控定，照 Codex 的 `thread/resume`）：环境不存盘（DESIGN 第 14 条），服务端重启后会话不在内存里，客户端要靠这条命令把环境重新交上来，服务端用它 `Session::open`。会话已经打开时不换环境，照常返回快照。没打开的会话：看快照、订事件直接从盘上读；送话、打断、回答批准、压缩、改设置回错误，提示先接着聊。命令的路径、参数名、错误码你定，改协议包（类型、测试、生成产物、README），DESIGN 第 8 条「和 Codex 不一样的地方」补一句。P1-7 的 `--resume` 用它。

### 配置

- 配置文件放状态目录下：DeepSeek 的 base_url、模型名、上下文窗口、API key。文件 0600。
- 受保护路径：建会话时把状态目录和配置文件作为 `protected_paths` 交给执行器（照 `crates/canter-tools/README.md`「第 4 件接入」第 1 条，经 P1-4 的接口传）。
- 日志不带 API key、环境变量的值、请求体里的私有内容。

- P1-2 审查带过来的：DeepSeek 客户端不走代理；base_url 是非本机地址又用 `http://` 时 key 会明文传出去，配置里要么拒绝、要么提示。

### 做了什么

- 新建 `canter-server` 和可执行包 `canter`，入口为 `canter serve [--replace]`。只监听 Unix socket；启动先拿状态目录的文件锁，重复启动清楚报错，登记发布采用临时文件加 rename，目录 0700、文件及 socket 0600。启动按事件文件锁清理 `.creating-*`，未取得锁或没有普通事件文件的目录保留。
- 接通协议 README 的全部 HTTP 命令，统一返回 `{ code, message }`；请求体、查询和路径解析错误也转换为安全的 JSON 错误。每个已打开会话共享一个 Session，创建、恢复、关闭在调用者断线后仍完整完成登记变更；批准沿用核心的先到先得语义。
- SSE 使用 `sse_frame`、`resume_after`，Last-Event-ID 优先，每 15 秒发空闲注释；心跳期间保留正在等待的接收操作。未打开会话从盘读取快照和事件，订阅在 resume 后衔接核心事件，不丢序号，也不在空闲时反复轮询整份事件文件。
- 新增 `POST /v1/sessions/{id}/resume { env }` 和 `session_not_resumed`（409），同步类型、导出测试、Schema/TypeScript、协议 README、DESIGN 第 8 条。已打开时保留原环境，未打开时变更命令提示先接着聊。创建和恢复均传入完整客户端环境及状态目录、配置文件两个受保护路径。
- 配置只从状态目录的 JSON 文件读取，错误和日志不回显配置或私有请求内容；拒绝非本机 HTTP base_url。显式替换通过私有交接文件通知旧服务端，等待工作结束后关闭所有会话、交出锁，不新增升级 HTTP 命令。

### 拿主意的地方

- **状态布局**：`~/.canter/`（或绝对路径 CANTER_HOME）下放 `config.json`、`server.lock`、`server.json`、`server.sock`、自动启动的 `server.log`、显式替换用的 `replace.lock` / `replace.json`，会话放 `sessions/<id>/`。锁文件保留，登记和 socket 正常退出时移除，崩溃残留在下次持锁启动时清理。状态目录的 DESIGN 正式记录按任务约定留给主控合并时补。
- **配置格式**：JSON，必填 `base_url`、`model`、`context_window`、`api_key`，配置读取前收紧为 0600，不从环境变量找 key。沿用核心的输出预留 65,536，窗口须大于 81,920；创建请求 model 为空字符串时用配置默认模型。客户端和模型 HTTP 均禁用代理；非本机地址必须 HTTPS。
- **客户端发现/启动**：放在 `canter-server` 公共 API：`state_directory`、`discover`、`ensure_server`。检查登记 PID、协议和 `/v1/info`；返回固定 Unix socket 的 reqwest Client，以及版本不同时供 P1-7 显示的提示。没有服务端时用独立 Unix session 拉起指定可执行文件，最多等 15 秒；协议不兼容或活进程无响应则报错，不自动替换。
- **升级**：显式 `canter serve --replace`，新进程先验证配置，通过含旧 instance 的私有文件请求交接，避免向复用 PID 发退出信号。旧服务拒绝新增工作，允许已有批准、打断和关闭；默认最多等 **60 秒**，随后并发 await 所有会话 close，未完成轮记为 interrupted。HTTP 另给 5 秒收尾；新进程等服务端锁最多 75 秒，超时不强杀。Ctrl-C / SIGTERM 直接关闭会话，不等待升级窗口。未加入额外配置选项或 HTTP 命令。
