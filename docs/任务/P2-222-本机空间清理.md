## 要做的

1. **配置**：`config.json` 加一项会话保留天数（名字照现有配置项的写法定，写进 DESIGN），缺省 30，写 0 表示永不删；热重载照现有配置项的规矩。
2. **清理**：服务端启动时跑一次，之后每天跑一次。会话「最后一次用的时间」超过天数的，整个会话目录删掉；回收站里的照同一个天数删（按进回收站的时间或最后一次用的时间，你定，写进 DESIGN）。
   - 不删：正在打开的、有客户端连着的、有轮在跑或等批准、有后台命令或目标续跑的，照 P2-32 进回收站的那套拒绝条件；父子会话一起看（子会话最近用过，父会话也不删；删父会话连子会话一起删）。
   - 删不掉（权限、正在被占用等）跳过、写一行服务端日志，不让服务端出错。
3. **用量摘要**：删一个会话之前，把它按本机时区日期、按模型的 token（含缓存命中、未命中、输出）、花费（含未知金额、ChatGPT 套餐那几种）记进 `CANTER_HOME` 下一个摘要文件；`/v1/usage`（也就是 `canter usage`、`/usage`）按天统计时把摘要和还在的会话合起来算，同一个会话不重复算。写摘要失败就不删这个会话。子会话、分叉会话的用量照现有统计规矩算（不重复、不漏）。
4. DESIGN 第 8 条、第 15 条对应的地方写清：配置项、什么时候跑、什么不删、摘要文件在哪和什么格式、和 Codex 不同的地方（canter 自定扩展）。
