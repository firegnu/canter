## 原来的候选（11-17 前）

1. ~~隧道断了自动重连~~：11-17 用户要求拆成单独任务，见 P2-302。
2. **端到端加密**：现在两段 SSH 隧道在 VPS 上解开，流量和令牌在 VPS 上是明文。P2-302 后隧道一直开着，VPS 被攻破的人截到令牌后随时能经 VPS 的 `127.0.0.1:<端口>` 让 5090 上的 agent 以用户身份干活（拿不到 5090 的 shell：`-R` 只转发那一个端口；VPS 上只有两边的公钥，没有私钥）。
   - **先试不改代码的办法**：5090 把自己的 sshd 也用 `-R` 挂到 VPS 回环地址，Mac 用 `ssh -J <中转>` 直接和 5090 建 SSH，在这条连接里 `-L` 转 canter 端口。VPS 只转发加密的 SSH，看不到令牌；攻破 VPS 还要 5090 的 SSH 私钥才进得去。要改的是两边的隧道服务（P2-302 那几个文件）和 `docs/remote.md`。
   - 不行再做 HTTPS 在 5090 上解密（要改代码）。
   - 顺手可做：VPS `authorized_keys` 给两把公钥加限制（5090 的只许 `permitlisten` 那个端口，Mac 的只许 `permitopen`，都 `restrict`），防的是两边私钥被偷后登 VPS 的 shell，不防 VPS 被攻破。
3. **网页或手机客户端**：网页由 VPS 上的 Caddy 和接口同源提供（服务端不加 CORS，P2-296）；手机上 App 进后台会断 SSE，要配推送（比如「等你批准」）。
4. **`canter-desktop` 连远程服务端**：桌面端照终端的做法加 `--server`（在 canter-desktop 仓库做，canter 这边只提供公开接口）。
5. **令牌分权限、绑定设备**：比如手机只能看和批准、不能跑命令。开放给手机用之前再考虑。
