## 要做的

- **发什么**：请求内容 = 主线下一次请求会发的前缀和历史（照 `context::request()` 的拼法，模型、思考档位用会话当前的设置）+ 末尾一条用户消息，内容是问题原文。不另拼系统提示词，不改前面任何一条，这样能命中主线的缓存。不给工具（工具列表照发，保持前缀一致，但模型调了工具就当答完，不执行）。
- **主线正在跑时也能问**：用此刻已经完整的上下文；最后一条是还没拿到结果的工具调用的，不带那一段，保证发出去的消息序列合法。btw 不等主线、不打断主线，主线也不等 btw。
- **不留痕**：问题和答案不进模型历史、不写会话事件，主线下一次请求的内容和没问过一样。只在发起的那个终端里显示；重开会话后不再显示。
- **记账**：btw 请求的用量和花费照 P2-7 记进本会话（`/usage`、`canter usage`、状态栏都算上），不改状态栏的上下文占用（ctx）。
- **终端显示**：在对话里先显示问题，答案边收边显示，和正常回答一样画 markdown，前面标 `btw`，整块用灰色或别的方式和主线回答区分开：

  ```
  › /btw what does the compact command do?
    btw  It summarizes older messages into one note so the context
         shrinks; recent messages stay as they are.
  ```

  - 答案出来之前显示一行等待提示；出错（模型报错、断网）就在这块里写一句错误，不影响主线。
  - btw 正在答时按 Esc 只停 btw；没有 btw 在答时 Esc 照旧打断主线。
  - 同一时间只答一个 btw；上一个没答完又问，提示一句，不发。
  - `/btw` 后面没写问题就提示用法，不发。
- 加进 `/` 命令列表和 `/help`。
