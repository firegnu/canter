P2-179 子 agent 终端界面 · 线框

4 个问题，每题列出可选样子，橙框是主控的推荐。界面上的字都是英文；子 agent 的名字是 P2-178 现在的做法（取自任务）。批准框标明来源，P2-178 已经做了，放在最后供参考。

主控的推荐，一句话版
  1. 子 agent 列表照「后台命令」那一行：放在输入框上方，平时收成一行，点它或 /agents 展开。
  2. 回车打开一个子 agent，整屏切到它的会话，能看记录、能直接给它发话；/agents 选最上面一条回主会话。
  3. 在列表里按 s 停掉一个子 agent。停掉后不叫醒主 agent，等它下次发请求时告诉它「被用户停了」。
  4. 对话里四个子 agent 工具的卡片专门画，一眼看出开了谁、在等谁、谁回来了。

1. 子 agent 列表放哪

平时怎么看到「有几个子 agent、在不在跑」？

A. 输入框上方一行，可展开推荐

 ● Spawned explorer · Session lock order
 ● Spawned explorer · Rewind cascade
 ◐ Waiting for 2 sub-agents · 0:12

 ⠋ Working (0:18 · esc to interrupt)

 ▸ 2 sub-agents running · 1 done
 ▸ 1 background command
╭──────────────────────────────────────────────╮
│ ›                                            │
╰──────────────────────────────────────────────╯
 deepseek-flash high Ask ~/canter main

点这一行，或输入 /agents，在原位置展开：

 ▾ 3 sub-agents · 2 running
 › ● Session lock order   explorer · running 0:42 
   ● Rewind cascade       explorer · running 0:40
   ✓ Fix lsp wait         general  · completed 2:13
   ↑↓ select · enter open · s stop · esc close
  • 和后台命令、待办清单同一处，用法一样（P2-117 定的「原位置那行可点」）。
  • 没有子 agent 时这一行不出现；做完、关掉的也列，状态写在后面。
  • 主 agent 空闲、子 agent 还在跑时，这一行照样在，看得出还有活没完。

B. 输入框下方一行一个（Claude Code 的样子）

 ⠋ Working (0:18 · esc to interrupt)
╭──────────────────────────────────────────────╮
│ ›                                            │
╰──────────────────────────────────────────────╯
   ● Session lock order   explorer · 0:42
   ● Rewind cascade       explorer · 0:40
   ✓ Fix lsp wait         general · done
 deepseek-flash high Ask ~/canter main
  • 一直摊开，不用点就能看到每一个。
  • 4 个子 agent 就多占 4 行；和输入历史的 ↑↓ 抢键，要另想怎么进列表。
  • 和 canter 现有的后台命令那一行是两种做法。

2. 打开一个子 agent 看什么、能不能给它发话

在列表里按回车之后呢？

A. 整屏切到子会话，能发话推荐

 Sub-agent · Session lock order · explorer · running
 from: Refactor session locks · /agents to go back

 › Trace how session locks are taken in canter-server
 ● Read crates/canter-server/src/agent_sessions.rs
 ● Search "session_locks.lock" · 14 matches
 ⠋ Working (0:44)

╭──────────────────────────────────────────────╮
│ › Message this sub-agent                     │
╰──────────────────────────────────────────────╯
 deepseek-flash high Ask ~/canter main

回主会话：/agents，列表最上面多一条：

 › ← Main session · Refactor session locks 
   ● Session lock order   explorer · running 0:44
   ● Rewind cascade       explorer · running 0:42
  • 就是打开那个子会话（P2-177 已经能按 ID 打开），记录、工具卡片、滚动、搜索都照主会话。
  • 顶上两行固定：哪个子 agent、什么类型、状态；从哪个主会话来、怎么回去。
  • 在这里发的话直接给子 agent（等于用户替主 agent 说了一句）；在这里按 Esc 打断的是子 agent。
  • 子 agent 要批准时，不管你在哪一屏，批准框都照常弹。

B. 弹框只读看记录

 ╭ Session lock order · explorer · running ────────╮
 │ › Trace how session locks are taken ...          │
 │ ● Read crates/canter-server/src/agent_sessions.rs │
 │ ● Search "session_locks.lock" · 14 matches       │
 │                                                  │
 ╰ ↑↓ scroll · s stop · esc close ──────────────────╯
╭──────────────────────────────────────────────╮
│ ›                                            │
╰──────────────────────────────────────────────╯
  • 和 /context、/diff 同一种弹框，不离开主会话。
  • 只能看，不能给子 agent 发话。
  • 记录长时弹框装不下，只能看个大概；跑着的时候要一直刷新。

3. 用户停掉一个子 agent 后，主 agent 怎么知道

在列表里按 s（照后台命令列表的 s stop），子 agent 这一轮停下、标成 interrupted，结果保留。然后：

A. 不叫醒，下次请求时告诉它推荐

 ▾ 3 sub-agents · 1 running
   ● Session lock order   explorer · running 0:52
 › ■ Rewind cascade       explorer · stopped by you 
   ✓ Fix lsp wait         general  · completed 2:13
  • 和主会话按 Esc 时连带停子 agent 一样，不因此开新一轮。
  • 主 agent 下一次发请求时带一句英文说明：这个子 agent 被用户停了。它不会自己再去开同样的子 agent 绕回来。

B. 当成「中断」叫醒主 agent

  • 照 P2-178 子 agent 中断的现有规则：主会话空闲就叫醒开一轮，在忙就附到下一次请求。
  • 主 agent 马上知道，但它可能接着再开一个，等于用户白停。

4. 对话里四个子 agent 工具的卡片

现在 spawn_agent 这些在对话里是普通工具卡片。要不要专门画？

A. 专门画推荐

 ● Spawned explorer · Session lock order
   └ Trace how session locks are taken in canter-server

 ● Waiting for Session lock order, Rewind cascade · 0:31
   └ ✓ Session lock order completed
       Locks are always taken parent first: operation lock, then …
       … +18 lines (ctrl+o to expand)
   └ ● Rewind cascade still running

 ● Sent to Rewind cascade
   └ Also check fork and trash paths

 ● Closed Fix lsp wait

 ◇ Sub-agent Rewind cascade completed — result sent to the model
  • 开、等、发话、关各一种写法；名字加粗，任务、回复灰色、折叠，ctrl+o 展开（照现有工具输出）。
  • 最后一行是子 agent 做完、自动交给主 agent 时，对话里留的一行。
  • 失败、拒绝（比如超过 4 个）照现有失败卡片画红。

B. 照普通工具卡片

 ● spawn_agent {"task":"Trace how session locks are taken in canter-server","type":"explorer"}
   └ {"id":"01M6…","name":"Session lock order"}

 ● wait_agent {"ids":["01M6…","01M6…"],"timeoutMs":30000}
   └ [{"id":"01M6…","status":"completed","result":"Locks are …
  • 不用改，但看到的是参数和 ID，读不出在干什么。
